# 复盘指南

## 什么是复盘

复盘源自围棋术语——对局结束后，棋手将棋局重新摆一遍，逐手分析每一步的优劣和背后的思路。与"总结"不同：**总结说发生了什么，复盘追问为什么和下次怎么做**。

| | 总结 | 复盘 |
|------|------|------|
| 关注点 | 结果 | 过程 + 决策 |
| 问题 | 做了什么？ | 为什么这样做？哪里可以不同？ |
| 产出 | 完成清单 | 可迁移的原则和方法 |

人的学习 70% 来自经验，但未经反思的经验只是时间消耗。复盘是将"做过"转化为"学到"的关键一步。

## 核心方法论速查

| 方法论 | 适用周期 | 核心框架 | 难度 | 耗时 |
|--------|----------|----------|------|------|
| **KPT** | 日/周 | Keep / Problem / Try | 低 | 3-25 min |
| **GRAI** | 阶段/项目 | Goal / Result / Analysis / Improvement | 中 | 30-60 min |
| **PDCA** | 月/年/系统 | Plan / Do / Check / Act | 中 | 45-90 min |
| AAR | 单次事件 | 预期 vs 实际 → 差距原因 → 持续/改进 | 中 | 15-30 min |
| ORID | 深度反思 | Objective / Reflective / Interpretive / Decisional | 高 | 30-45 min |

> 本指南聚焦 KPT、GRAI、PDCA 三种方法，覆盖日/周/阶段/年四个层级。

## 方法一：KPT — 日常持续改进

KPT 源于敏捷开发中的回顾会议，核心是三个问题：

### Keep（保持）
**什么做得好，值得继续？**
- 不只记"做了"，更要挑出有超额回报的行为
- 问自己：本周哪个小时最有效率？哪种方法让理解更深？

### Problem（问题）
**什么阻碍了你？哪里有摩擦？**
- 诚实面对低效和挫败，但不自责——问题是改进的燃料
- 问自己：哪里卡住了？什么消耗了时间却没产出？

### Try（尝试）
**下次可以试试什么不同的做法？**
- **这是 KPT 最关键的一步**——必须是一个具体、可验证的实验
- 错误示范："要多练习" → 正确示范："每天早上 8:30-9:00 用 Anki 复习 Linux 命令"
- 一次不要超过 3 个 Try，精力有限

## 方法二：GRAI — 阶段目标复盘

GRAI 是中文技术圈主流的复盘框架，特别适合学习阶段或项目里程碑结束后的深度回顾。

### Goal（回顾目标）
回到阶段开始时的计划：
- 当时设定了什么目标？关键结果是什么？
- 目标本身是否合理？有没有中途调整？

### Result（评估结果）
用数字说话，不靠感觉：
- 目标完成了多少？（百分比）
- 产出物有哪些？（笔记数、项目成果、证书等）
- 与预期的差距在哪里？

### Analysis（分析原因）
**这是 GRAI 的核心**，区分表面原因和根本原因：
- 做得好的原因：是方法好？精力足？环境合适？还是运气？
- 做得差的原因：用 **5-Why 追问**——连续问 5 个"为什么"，直到触及可操作的根因
- 警惕**基本归因错误**：成功归自己、失败归环境——这是复盘最大的敌人

> 示例：笔记没写完 → 为什么？下班太累不想动 → 为什么？脑子一直在切换任务 → 为什么？没有固定写作时间 → 为什么？没把它当成每天第一件事 → 根因：没有保护黄金时间的习惯 → Action：每天早上第一个 45 分钟写笔记，手机关通知。

### Improvement（总结改进）
产出可复用原则和具体行动：
- "如果重来一次，我会______"
- 将经验提炼为 1-3 条可迁移原则（不是"努力"而是"每天 9 点前完成最难的事"）
- 关联到已有的知识笔记或 MOC

## 方法三：PDCA — 系统级元复盘

PDCA 适合月度或年度时使用的"复盘之上的复盘"——检查复盘体系本身是否有效。

| 步骤 | 含义 | 月/年复盘问题 |
|------|------|--------------|
| **P**lan | 计划 | 上周期目标是否清晰可衡量？是否仍然相关？ |
| **D**o | 执行 | 实际做了什么？哪些习惯坚持了？哪些中断了？ |
| **C**heck | 检查 | 数据说话：笔记数、学习时长、项目完成率、技能仪表盘 |
| **A**ct | 调整 | 下个周期需要改变什么？复盘频率是否合适？方法是否有效？ |

## 分层复盘体系

```
年度（PDCA 元复盘）：方向校准，系统优化
    ↑
月度（PDCA）：进度检查，习惯跟踪
    ↑
阶段（GRAI）：目标达成分析，原则提炼
    ↑
每周（KPT）：模式识别，知识库维护
    ↑
每日（KPT-Lite）：微调，3 分钟快速反思
```

| 层级 | 频率 | 方法 | 模板 | 耗时 | 产出 |
|------|------|------|------|------|------|
| 每日 | 每天 | KPT-Lite | [[01-日常流(日常流层)/02 日记/日记-模板]] | 3 分钟 | 日记条目 |
| 每周 | 每周 | KPT + 知识库维护 | [[周复盘-模板]] | 25 分钟 | 周复盘笔记 |
| 阶段 | 阶段末 | GRAI | [[阶段规划-模板]] 阶段总结区 | 45 分钟 | 阶段总结 |
| 月度 | 月末 | PDCA | 本文 | 45 分钟 | 月度复盘笔记 |
| 年度 | 年末 | PDCA + GRAI | 本文 | 90 分钟 | 年度复盘笔记 |

### 每日复盘

> 模板：[[01-日常流(日常流层)/02 日记/日记-模板]] 的"每日复盘"区块

目标：趁着记忆新鲜，捕捉微观调整信号。

**引导问题：**
- Keep：今天做了什么值得继续的事情？什么方法/习惯有效？
- Problem：今天遇到了什么阻碍或低效时刻？是技能不足还是环境问题？
- Try：明天可以尝试什么不同的做法？（一个具体实验即可）

### 每周复盘

> 模板：[[周复盘-模板]]

目标：放大到模式层面，检查知识与行动的匹配度。

**引导问题：**
- Keep：本周什么带来最大价值？什么习惯展现了复利效应？
- Problem：本周最大的摩擦点在哪里？是精力管理还是技能欠缺？
- Try：下周一个最值得尝试的改变是什么？
- 知识库：Inbox 清空了吗？新笔记挂 MOC 了吗？有内容需要从日记迁移吗？

### 阶段复盘

> 模板：[[阶段规划-模板]] 底部"阶段总结"区块

GRAI 与阶段规划的天然映射：

```
阶段规划字段          GRAI 步骤
─────────────────    ─────
目标 + 里程碑    →    Goal（回顾目标）
产出物          →    Result（评估结果）
反思（为什么）   →    Analysis（分析原因）
后续行动        →    Improvement（总结改进）
```

关键要求：Analysis 步骤必须产出至少一个"如果重来一次，我会______"级别的洞察。

### 月度 / 年度复盘

两个层次：**看数据**（笔记统计、技能仪表盘、项目完成率）→ **问系统**（复盘体系是否在运转？是否需要调整？下周期最应该改变的一件事是什么？）

年度复盘额外加入 **GRAI 的 Analysis** 步骤：这一年最大的教训是什么？这一年有什么决策需要事后检查？（参考 [[01-决策日志-模板]]）

## 决策日志：复盘的特化形式

复盘通常是**定期**的，但重大决策需要**定点**复盘——在决策时就设定未来的复查日期。

> 模板和详细说明：[[01-决策日志-模板]]

何时使用决策日志：
- 不可逆或高成本的决策（跳槽、学习方向选择、大额投入）
- 反馈周期长的决策（六个月后才能看到结果的）
- 容易受认知偏差影响的决策（过度自信、从众）

核心原则：**在决策当下记录预期和信心水平**——这防止了你事后"虚报"自己当初的判断（后见之明偏差），并长期校准你的决策直觉。

## 如何开始：4 周新手上手

| 周次 | 行动 | 注意 |
|------|------|------|
| **第 1 周** | 只做每日复盘 | 不追求质量，先建立"每天 3 分钟"的习惯 |
| **第 2 周** | 每日 + 第一次周复盘 | 周复盘时翻看 7 天的每日复盘，找模式 |
| **第 3 周** | 每日 + 每周，检查每日质量 | 每日 KPT 的 Try 是否真的在 Try？是否有效？ |
| **第 4 周** | 完整三层运转 | 日常节奏稳定后，可以开始记录决策日志 |

常见误区：
- **复盘不是自责**：Problem 描述事实，不加情绪评判
- **Try 不是愿望**：必须有具体行动和可验证标准
- **复盘不是一次性**：复盘本身的发现只有在下一轮行动中验证后才算闭环
