# AI音乐与音频｜项目说明

## 1. 定位

本目录属于 `yeyunby` 总知识工程：

```text
02-Knowledge(知识层)
└─ 20-核心能力-Core_Ability
   └─ 30 创作能力-Creative_Capability
      └─ 02 AIGC
         └─ 03-AI音乐与音频
```

它是 AIGC 创作能力中的**声音能力中心**，不是独立仓库或独立软件工程。GitHub 在这里承担版本管理与知识沉淀作用。

## 2. 建设目标

长期沉淀五类能力：

- **基础知识**：数字音频、响度、编码、音乐结构、跨能力生态与通用部署知识
- **AI 音乐**：歌曲、纯音乐、BGM、OST、风格改编、续写、结构控制与 Prompt
- **AI 语音 / TTS**：浏览器 TTS、本地/在线 TTS、Voice Clone、角色语音、控制模板与长文本旁白
- **AI 音效**：环境音、UI、转场、动漫、游戏、视频音效、Foley 与 Prompt
- **音频处理**：人声分离、降噪、修复、增强、音色转换、ASR、FFmpeg 与命令模板

模型、工具、平台和 Prompt 都是能力的实现手段，不再作为独立顶层知识类别。

## 3. 知识生命周期

```text
基础知识
  ↓
能力领域（02–05，内部包含模型 / 工具 / 方法 / Prompt）
  ↓
08 实验验证
  ↓
单能力成熟内容继续留在 02–05
跨两个以上能力的端到端流程才升格到 07
  ↓
10 资产
```

目录按“我要完成什么能力”组织，而不是按“这是哪个软件 / 项目 / Prompt 类型”组织。

## 4. GitHub 项目与 Prompt 如何收录

发现新的项目、平台、Prompt 或控制模板时，先判断它主要解决什么问题：

- 音乐生成 / 编辑 / 配乐 / 音乐 Prompt → `02-AI音乐`
- TTS / Voice Clone / 配音 / 语音控制模板 → `03-AI语音-TTS`
- SFX / Foley / 环境音 / 音效 Prompt → `04-AI音效`
- 分离 / 降噪 / 增强 / VC / ASR / FFmpeg / 命令模板 → `05-音频处理`
- 同时横跨多个能力的生态索引、通用任务选型、部署基础 → `01-基础知识`
- 参数、Prompt、质量或模型实测对比 → `08-实验室-Lab`
- 横跨两个以上能力、经过验证的稳定生产链 → `07-工作流`
- 最终声音资源 → `10-资产库`

原 `06-工具与模型` 与 `09-提示词库` 已取消。项目技术卡与 Prompt 直接归入它的**主要能力目录**；其他领域只通过双链引用，避免建立第二套分类树。

## 5. 归属判断例子

```text
IndexTTS / CosyVoice / GPT-SoVITS / Kokoro
→ 03-AI语音-TTS/02-本地TTS

TTS 情绪 Prompt / CosyVoice Instruct 模板
→ 03-AI语音-TTS/06-提示词与控制模板

ACE-Step / Stable Audio / MusicGen
→ 02-AI音乐/01-模型与平台

音乐 Prompt / 风格描述模板
→ 02-AI音乐/02-提示词

TangoFlux / AudioGen
→ 04-AI音效

SFX / Foley Prompt
→ 04-AI音效/06-提示词与模板

Demucs / DeepFilterNet / Whisper / RVC / FFmpeg
→ 05-音频处理
```

如果同一个项目同时支持音乐和音效，以当前知识库的**主要研究目标**确定主位置，其他位置链接过去即可。

## 6. 工作流边界

`07-工作流` 不保存“某个单模型怎么安装、怎么生成”这类小流程。

进入 07 的内容必须同时满足：

1. 横跨两个以上能力目录；
2. 已经经过实验或实际项目验证；
3. 可以重复执行；
4. 有明确输入、步骤、输出和验收标准。

例如：

```text
脚本 → TTS → 时长对齐 → 降噪 → FFmpeg 合成
→ 07-工作流

角色对白 → BGM → SFX → 混音 → 输出
→ 07-工作流
```

而 `IndexTTS 安装与生成`、`ACE-Step 歌曲生成`、`Demucs 分离` 等单能力流程继续留在对应 02–05。

## 7. 实验记录建议

每次正式实验至少记录：

- 实验编号与日期
- 目标
- 模型与版本
- 环境 / 硬件
- 输入、Prompt 与参数
- 输出与试听评价
- 音质、自然度、情绪、稳定性、可控性
- 问题与结论
- 下一轮实验

建议编号：`TTS-R001`、`MUSIC-R001`、`VOICE-R001`、`SFX-R001`、`AUDIO-R001`。

## 8. 工具研究模板

工具研究应回答：定位、核心能力、支持语言、部署方式、硬件要求、输入输出、API、优缺点、安装/调用方法、适用场景、许可证，以及“它在 yeyunby 工作流中负责什么”。

区别只在于：**技术卡直接存入对应能力目录，不再集中存入工具目录。**

## 9. 与其他模块的关系

本模块可向 AI 视频、动漫/漫剧、Agent、Python/FFmpeg 自动化等模块提供：配音、BGM、SFX、声音角色资产和音频后处理能力。

## 10. 编号策略

取消 `06-工具与模型`、`09-提示词库` 后，暂时保留 `07`、`08`、`10` 的现有编号，以降低已有双链、脚本和历史记录的迁移成本。目录编号用于稳定导航，不要求强制连续。

## 11. 长期目标

从“寻找 AI 音频工具”逐步升级为：

> **拥有可验证、可复用、可自动化调用的 AI 声音生产体系。**
