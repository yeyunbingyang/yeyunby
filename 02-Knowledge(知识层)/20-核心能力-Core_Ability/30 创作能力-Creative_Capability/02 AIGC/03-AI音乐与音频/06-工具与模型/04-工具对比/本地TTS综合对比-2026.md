## 三、使用成本对比

| 项目 | 初次部署复杂度 | 日常使用复杂度 | 角色资产维护成本 |
|---|---:|---:|---:|
| IndexTTS-2.5 | 中 | 低~中 | 低 |
| Fun-CosyVoice3 | 中~高 | 中 | 中 |
| GPT-SoVITS | 中~高 | 中 | 高，但资产价值也最高 |
| Kokoro-82M | 低 | 低 | 低 |

### 为什么 GPT-SoVITS 维护成本更高

因为它的价值恰恰来自长期角色资产：

```text
录音 → 清洗 → 切片 → ASR → 校对 → 标注 → 训练 → 模型版本 → 推理
```

这不是缺点，而是它与纯零样本引擎的核心分工差异。

## 五、最推荐的组合，而不是四选一

### 内容创作工作流

```text
文案草稿
↓
Kokoro-82M 快速试听
↓
角色原型：IndexTTS-2.5 / CosyVoice3 / GPT-SoVITS Zero-shot
↓
固定角色：GPT-SoVITS few-shot
↓
特殊情绪/跨语言/发音控制：IndexTTS-2.5 / CosyVoice3
↓
统一后处理与响度
```

### 实时应用工作流

```text
LLM 输出文本
↓
Fun-CosyVoice3 Streaming
↓
音频流播放
↓
需要特殊角色音色时再接角色资产层
```

## 六、选择时不要混淆的几个概念

### Zero-shot ≠ 固定角色长期稳定

零样本适合快速克隆；几十集连续内容仍要做重复生成稳定性实验。

### 有 WebUI ≠ 容易生产部署

生产环境还要考虑：

- API
- 并发
- GPU 调度
- 冷启动
- 模型常驻
- 日志
- 队列
- 失败重试

### 可调语速 ≠ 精确时间轴对齐

`duration_factor`、speed 等参数主要控制节奏/时长倍率。真正视频级精确对齐还需要字幕时间轴、分句、重生成或后期伸缩。

### GitHub 开源 ≠ 所有权重和声音资产都可自由商用

必须单独检查代码、权重、Voice 资产和参考音频授权。

## 七、当前推荐优先级

```text
正式角色对白主力：IndexTTS-2.5 / GPT-SoVITS
实时多语言平台：Fun-CosyVoice3
快速预览层：Kokoro-82M
```
