# 开源配音引擎全景

## 一句话结论

不要再用“找一个最强 TTS 包打天下”的方式选型。

当前更实用的是按职责组合：

```text
高质量强可控零样本 → IndexTTS-2.5
多语言/方言/实时流式 → Fun-CosyVoice3
固定角色训练资产     → GPT-SoVITS
轻量快速试听         → Kokoro-82M
浏览器零依赖兜底     → Web Speech API / Edge TTS
视频翻译配音整链     → 专门的视频配音流水线项目
```

## 一、2026-08 本地主线四模型

| 引擎 | 主定位 | 当前关键能力 | 许可提醒 |
|---|---|---|---|
| [IndexTTS](https://github.com/index-tts/index-tts) | 高质量强可控零样本 | IndexTTS-2.5；中英日西阿、音色/情绪解耦、情绪向量、语速、拼音/CMU/Kana、vLLM | bilibili Model Use License |
| [CosyVoice](https://github.com/QwenAudio/CosyVoice) | 多语言/方言/实时平台 | Fun-CosyVoice3；9 语言、18+ 中文方言/口音、双向流式、Instruct、训练/服务 | Apache-2.0（仓库） |
| [GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS) | 固定角色训练与克隆 | ~5 秒 zero-shot、~1 分钟 few-shot、切片/ASR/标注/训练工具链 | MIT（仓库） |
| [Kokoro](https://github.com/hexgrad/kokoro) | 轻量快速预览 | 82M、Python、CPU/端侧友好、多语言管线、speed 控制 | Apache licensed weights |

## 二、按部署位置分类

| 类别 | 代表路线 | 适用场景 |
|---|---|---|
| 本地 GPU 高质量 | IndexTTS-2.5 / Fun-CosyVoice3 / GPT-SoVITS | 正式角色对白、声音克隆 |
| 本地轻量 / CPU | Kokoro / Piper / sherpa-onnx 等 | 草稿、端侧、低资源设备 |
| 浏览器原生 | Web Speech API | 零依赖预览、无障碍朗读 |
| 浏览器模型 | ONNX / WASM / WebGPU 生态 | 完全本地网页试听，需要单独验证具体实现 |
| 在线免密钥路线 | edge-tts | 快速预览，依赖网络服务 |
| 视频配音流水线 | VideoLingo / pyvideotrans / KrillinAI 等 | 翻译、字幕、对齐、配音整链 |

## 三、浏览器与快速预览

### Web Speech API

优势：

- 浏览器直接调用
- 不需要模型部署
- 非关键对白试听成本最低

限制：

- 音色取决于系统/浏览器
- 跨机器一致性差
- 不适合当角色最终声音资产

### Kokoro / ONNX / WebGPU 路线

如果需要比 Web Speech API 更可控、又不想启动重型 GPU TTS 服务，可研究 Kokoro 的社区 ONNX / 浏览器实现。

> 浏览器衍生项目变化快，正式纳入工作流前必须单独验证版本、模型来源、许可证、WebGPU/ONNX Runtime 兼容性。

### Edge TTS

适合：

- 快速生成旁白
- 文案试听
- 浏览器/桌面工具预览

它依赖在线服务，不归入“本地离线模型”。

## 四、本地高质量 / 声音克隆

### IndexTTS-2.5

优先用于：

- 单参考音频快速克隆
- 同音色不同情绪
- 多语言角色对白
- 发音修正
- 视频对白语速控制
- 服务化部署

详见 [[IndexTTS-2.5-项目笔记]]。

### Fun-CosyVoice3

优先用于：

- 多语言 / 跨语言
- 中文方言与口音
- 数字人 / AI 助手 / NPC 实时语音
- 流式 TTS
- 指令控制情绪、速度、音量
- FastAPI / gRPC / vLLM / Docker 等服务化

详见 [[Fun-CosyVoice3-项目笔记]]。

### GPT-SoVITS

优先用于：

- 固定动漫/漫剧/游戏角色
- 角色数据持续积累
- few-shot 微调
- 数据切片、ASR、标注、训练一体化
- 长期角色声音模型资产

详见 [[GPT-SoVITS-项目笔记]]。

## 五、其他高质量候选

以下项目继续保留在研究池，但不与四条主线同等优先：

- F5-TTS
- Chatterbox
- OpenVoice
- Fish Speech
- Qwen 系列 TTS
- VoxCPM
- ChatTTS
- Dia

这些项目版本、仓库状态、权重许可和能力变化较快；需要做项目卡时再以官方仓库重新核验，不在本页硬编码过多动态结论。

## 六、多角色 / 短剧路线

多角色对白不一定要靠“单模型一次生成整场戏”。更稳定的生产方式通常是：

```text
角色 A → 固定 Voice Profile / Model
角色 B → 固定 Voice Profile / Model
角色 C → 固定 Voice Profile / Model
       ↓
逐句生成
       ↓
统一停顿 / 响度 / 空间 / 混音
       ↓
合成最终对白轨
```

一次性多说话人生成模型可用于快速概念验证，但正式漫剧更应优先保证角色身份稳定和可重生成性。

## 七、视频配音流水线

代表性开源路线包括：

- pyvideotrans
- VideoLingo
- KrillinAI
- Linly-Dubbing
- SmartSub
- SoniTranslate

这类项目的核心价值不是 TTS 模型本身，而是串联：

```text
ASR
→ 字幕切分
→ 翻译
→ 时间轴对齐
→ TTS
→ 音频拼接
→ 视频重封装
```

因此应把它们视作“工作流参考项目”，而不是与 IndexTTS / CosyVoice / GPT-SoVITS 直接横向排名。

## 八、任务决策树

```text
只是试听文案？
├─ 是 → Kokoro / Web Speech / Edge TTS
└─ 否
   ↓
是否需要固定角色长期维护？
├─ 是 → GPT-SoVITS
└─ 否
   ↓
是否需要方言 / 实时流式 / 服务平台？
├─ 是 → Fun-CosyVoice3
└─ 否
   ↓
是否需要强情绪 / 发音 / 语速控制？
├─ 是 → IndexTTS-2.5
└─ 否 → IndexTTS-2.5 / CosyVoice3 / GPT-SoVITS Zero-shot A/B
```

## 九、许可检查

“开源”必须拆成多个对象检查：

1. 仓库源代码许可证
2. 模型权重许可证
3. Voice / speaker 资产许可证
4. G2P / ASR / 音频分离等依赖许可证
5. 参考音频与声音克隆授权
6. 输出内容平台规则
7. 商业规模触发条件

尤其不能把 GitHub 仓库的 MIT / Apache 自动等同于所有模型权重和声音资产都可无限制商用。

## 十、下一层实验

全景页只负责“怎么选”。真正的质量结论进入：

```text
08-实验室-Lab/
```

建议建立统一 TTS Benchmark：

- 同一参考音频
- 同一中文/英文/日文测试集
- 同一长文本
- 同一情绪测试句
- 统一记录 RTF / VRAM / 冷启动 / Speaker Similarity / 主观评分 / 失败率

成熟后再将稳定流程升格到 `07-工作流/`。
