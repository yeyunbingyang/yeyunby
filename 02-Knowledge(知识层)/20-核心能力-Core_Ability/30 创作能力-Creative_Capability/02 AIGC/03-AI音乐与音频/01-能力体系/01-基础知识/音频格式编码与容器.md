# 音频格式、编码与容器

## 先区分三件事

```text
音频样本 → Codec 编码 → 封装到文件/容器
```

扩展名不等于编码本身。FFmpeg 的 `-formats` 与 `-codecs` 可以分别查看容器和编解码能力。

## 常见格式

| 格式 | 类型 | 推荐用途 |
|---|---|---|
| WAV/PCM | 无压缩/近似容器思维 | AI 原始输出、编辑母版、交换 |
| FLAC | 无损压缩 | 音频资产库、长期保存 |
| AAC | 有损 | 视频平台、移动端、MP4 |
| Opus | 有损、高效率、低延迟 | Web、语音、实时传输、Discord 类场景 |
| MP3 | 有损、兼容性强 | 老系统或通用交付 |

## 生产建议

### 母版层

优先：WAV 24-bit 或模型原生无损输出；需要节省空间时用 FLAC。

### 发布层

按目标平台再编码，不要对已经有损压缩过的文件反复转码。

```text
生成 WAV
→ 后处理 WAV
→ 母版 WAV/FLAC
→ 发布 AAC/Opus/MP3
```

## Opus 的定位

Opus 是面向互联网交互音频设计的编码器，覆盖语音和音乐，支持低延迟与宽比特率范围。适合浏览器、实时语音和网络传输，但资产母版仍建议保留无损版本。

## FFmpeg 示例

```bash
# WAV → FLAC
ffmpeg -i input.wav output.flac

# WAV → Opus
ffmpeg -i input.wav -c:a libopus -b:a 128k output.opus

# WAV → AAC
ffmpeg -i input.wav -c:a aac -b:a 192k output.m4a
```
