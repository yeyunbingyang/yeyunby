# 在线 TTS 能力与选型

## 什么时候用在线 TTS

- 不想维护 CUDA/Python 环境
- 需要稳定 API
- 需要快速上线 Web/视频生产系统
- 需要多语言与成熟声音库
- 本机 GPU 资源要留给视频/图像模型

## 评估维度

| 维度 | 为什么重要 |
|---|---|
| 自然度 | 单句与长文本都要测 |
| 角色一致性 | 多次生成、跨天、跨语言是否稳定 |
| 情绪控制 | 是否可用文本标签/参数控制 |
| 延迟 | 预览/实时对话和离线成片需求不同 |
| Voice Clone | 参考音频规则、相似度、授权要求 |
| 输出格式 | WAV/PCM/MP3、采样率 |
| API | Streaming、SDK、批量能力 |
| 数据/隐私 | 上传音频如何处理、是否提供保留策略 |
| 商用与成本 | 计划、配额、生成权利会变化，需定期复核 |

## ElevenLabs 作为典型样本

其官方 TTS 文档强调多语言、流式和不同延迟/质量模型；输出具有非确定性，可通过 seed 改善一致性，但仍可能有细微差异。

这提醒我们：**角色一致性不能只靠同一个 voice_id**，还要固定模型、参数、文本规范和后处理。

## 在线 vs 本地

```text
在线：部署简单 / API成熟 / 费用持续 / 数据需外发
本地：初期部署重 / 边际成本低 / 数据可留本机 / 运维更多
```

正式生产可采用混合架构：

- 浏览器/Kokoro：快速预览
- 本地主力：批量成片
- 在线高质量：特殊角色/紧急交付/对照基线
