# 本地 TTS 横向对比：功能与环境要求（2026-08）

> [!abstract] 文档职责
> 这是一份**选型总表**。单项目细节继续放各自项目笔记；这里不重复项目 README，而是回答三个问题：
> 1. 四个模型有什么功能差异？
> 2. 各自需要什么运行环境？
> 3. 面对具体任务应该优先选谁？

## 1. 一眼看懂四条路线

| 项目 | 当前主线 | 核心定位 | 最适合 | 不建议作为首选 |
|---|---|---|---|---|
| **IndexTTS-2.5** | IndexTTS-2.5 | 高质量、强可控零样本 TTS | 角色对白、情绪控制、跨语言、发音修正、视频配音 | 角色训练数据工作台、CPU 轻量试听 |
| **Fun-CosyVoice3** | Fun-CosyVoice3-0.5B-2512 | 多语言/方言 + 流式 + Instruct + 服务平台 | 数字人、AI 助手、NPC、多语言/方言、实时语音服务 | 极简草稿试听 |
| **GPT-SoVITS** | GPT-SoVITS v2 ProPlus / 当前主线 | 固定角色声音克隆 + few-shot + 数据训练工具链 | 动漫/漫剧固定角色、长期音色资产、训练与微调 | 只为了临时一句 TTS 而搭完整训练环境 |
| **Kokoro-82M** | Kokoro-82M | 轻量、快速、本地预览 | 文案试听、CPU、普通旁白、端侧/轻量工具 | 高一致性角色克隆、复杂情绪演绎 |

## 4. 环境要求总表

> [!important] 阅读方法
> “官方明确”只记录当前官方 README 已明确写出的条件；“建议”是工程选型建议，不冒充官方最低要求。显存尤其如此：如果官方没有给出统一最低显存，就不硬写一个假的数字。

| 项目 | OS | Python/环境 | GPU / CUDA | CPU | 额外依赖 | Windows 友好度 |
|---|---|---|---|---|---|---:|
| **IndexTTS-2.5** | Linux / Windows | 官方当前推荐 `uv`，自动建立 `.venv` 和匹配 Python 环境 | NVIDIA 推荐；官方提示 Linux/Windows 遇 CUDA 问题检查 **CUDA Toolkit 12.8+**；支持 BF16 | 非主力路线 | `uv`；可选 WebUI/DeepSpeed/CUDA kernel | ★★★★☆ |
| **Fun-CosyVoice3** | 官方文档以 Linux/服务器环境为主 | Conda + **Python 3.10** | NVIDIA GPU 适合正式推理/流式服务；vLLM/TRT-LLM 为可选加速路线 | 可研究但非主力生产路线 | git submodule、SoX；服务化可加 vLLM/Docker/gRPC | ★★★☆☆ |
| **GPT-SoVITS** | Windows 10+ / Linux / macOS | 官方测试 Python **3.10–3.12**；Windows 源码安装常用 Conda Python 3.10 | 官方测试 CUDA 12.4 / 12.8 组合；安装脚本支持 CU126 / CU128；支持 FP16 | ✅ 官方有 CPU 路线 | FFmpeg；ASR/VAD/标点；可选 UVR5/Roformer | ★★★★★ |
| **Kokoro-82M** | Windows / Linux / macOS | `pip install kokoro`；官方 Conda 示例使用 Python 3.9 | **不要求 CUDA**；GPU 可作为额外加速 | ✅ **核心优势** | `soundfile`、Misaki；部分语言需 `espeak-ng` | ★★★★★ |

## 5. 各项目环境细节

### 5.1 IndexTTS-2.5

官方当前安装主线：

```bash
git clone https://github.com/index-tts/index-tts.git
cd index-tts
pip install -U uv
uv sync --all-extras
```

Windows 注意：

- DeepSpeed 可能比较难装，不应为了“全功能”强行让 Windows 环境变复杂。
- 可改为只安装需要的 extra，例如 WebUI。
- 官方建议遇 CUDA 问题时检查 NVIDIA CUDA Toolkit **12.8 或更高版本**。
- BF16 可降低显存使用并提高推理效率；实际显存以模型版本、文本长度、是否启用 CUDA kernel 等组合实测。

适合的环境策略：

```text
Windows 本地角色配音
→ uv 独立项目环境
→ NVIDIA GPU
→ BF16
→ 先不用 DeepSpeed
→ WebUI / Python API 验证稳定后再加服务化
```

### 5.2 Fun-CosyVoice3

官方安装主线：

```bash
git clone --recursive https://github.com/FunAudioLLM/CosyVoice.git
cd CosyVoice
git submodule update --init --recursive

conda create -n cosyvoice -y python=3.10
conda activate cosyvoice
pip install -r requirements.txt
```

环境特点：

- 官方文档明显偏 Linux / 服务器工作流。
- SoX 在音频处理链中是常见依赖。
- vLLM、TensorRT-LLM、Docker、gRPC 都属于“服务化增强”，不应该在第一次本地试听时一次全装。
- Windows 可以研究，但如果目标是长期低延迟服务，Linux 环境通常更省折腾。

适合的环境策略：

```text
本地实验
→ Conda Python 3.10
→ 先跑 example.py / WebUI

正式实时服务
→ Linux + NVIDIA GPU
→ 再评估 vLLM / FastAPI / gRPC / TensorRT-LLM
```

### 5.3 GPT-SoVITS

官方 Windows 支持最直接，提供整合包和源码安装路线。

源码安装基线：

```powershell
conda create -n GPTSoVits python=3.10
conda activate GPTSoVits
pwsh -F install.ps1 --Device CU128 --Source HF
```

官方当前可选设备路线包括：

```text
CU126
CU128
CPU
```

官方 README 当前列出的测试环境覆盖：

- Python 3.10 / 3.11 / 3.12 等组合
- CUDA 12.4 / 12.8 等 PyTorch 环境
- Apple Silicon
- CPU

额外依赖较多：

```text
FFmpeg
ASR
VAD
标点模型
可选 UVR5 / Roformer
GPT-SoVITS 预训练模型
```

因此它的特点不是“环境最轻”，而是**Windows 路线和完整角色训练工具链最成熟**。

### 5.4 Kokoro-82M

最小安装：

```bash
pip install "kokoro>=0.9.4" soundfile
```

中文：

```bash
pip install "misaki[zh]"
```

日文：

```bash
pip install "misaki[ja]"
```

Windows 上部分语言需要安装 `espeak-ng`。

Kokoro 的优势是：

- 不把 NVIDIA GPU 当成前置条件
- 82M 参数
- 很适合作为 CPU 草稿试听
- 环境独立、破坏性小

如果只是想让编辑器、HTML Preview 或本地工具“马上能念出来”，优先级通常比部署重型角色 TTS 更高。

## 6. GPU 与显存怎么理解

### 不写假的“最低显存”

这四个项目并不存在一个长期稳定、所有版本通用的“最低显存数字”。显存会受以下因素影响：

- 模型版本
- FP32 / FP16 / BF16
- 文本长度
- batch size
- 流式 / 非流式
- CUDA kernel
- DeepSpeed / vLLM / TensorRT-LLM
- 是否同时加载 ASR / 分离 / 训练模型

因此知识库采用两级记录：

```text
官方明确条件
→ 写在本页环境矩阵

具体显存 / RTF / 冷启动
→ 写入 08-实验室-Lab 的本机 Benchmark
```

### 工程分层

| 硬件层 | 推荐路线 |
|---|---|
| 无独显 / CPU 优先 | Kokoro-82M；GPT-SoVITS CPU 仅在需要其生态时考虑 |
| 中端 NVIDIA GPU | IndexTTS-2.5 / GPT-SoVITS / CosyVoice3 均进入实测池 |
| 高性能 NVIDIA GPU | 三个高质量模型都可测试，并进一步尝试 vLLM / TRT-LLM / 并发服务 |
| 浏览器/端侧 | Kokoro / ONNX / WebGPU 衍生路线单独验证 |

## 8. 按任务直接选

| 需求 | 第一选择 | 第二选择 | 原因 |
|---|---|---|---|
| 文案快速试听 | **Kokoro** | Edge/Web Speech | 启动轻、成本低 |
| 5–30 秒参考音频快速克隆 | **IndexTTS-2.5** | GPT-SoVITS Zero-shot | Index 控制维度更丰富 |
| 固定角色长期做几十集 | **GPT-SoVITS** | CosyVoice3 | 可积累数据并微调 |

| 专有名词发音修正 | **IndexTTS-2.5** | CosyVoice3 | 拼音/CMU/Kana 控制 |

| CPU 普通旁白 | **Kokoro** | GPT-SoVITS CPU | Kokoro 更轻 |
| 视频对白语速调整 | **IndexTTS-2.5** | CosyVoice3 | 直接控制 duration/speed 路线 |

## 11. 下一步验证标准

本页只记录**官方能力 + 工程选型**，不把未测试内容写成“本机表现”。

真正需要通过 `08-实验室-Lab` 得到的数字包括：

| 指标 | 说明 |
|---|---|
| 峰值显存 | 相同测试文本、相同精度 |
| RTF | 生成时长 / 推理耗时 |
| 冷启动时间 | 模型加载到首段可生成 |
| 首包延迟 | 流式模型重点 |
| Speaker Similarity | 同参考音频克隆一致性 |
| 情绪辨识度 | 喜怒哀惧等控制是否真正可听辨 |
| 长文本稳定性 | 漏字、重复、断句、音色漂移 |
| 跨语言稳定性 | 同音色跨中英日等是否漂移 |
| 失败率 | 相同输入重复 N 次的异常比例 |
