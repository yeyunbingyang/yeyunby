## 标准工作流

```text
明确任务 → 选择模板与术语 → 调用参考资产 → 生成与验收 → 记录实验 → 交付或归档
```

## 内容归属

| 内容 | 归属 | 判断标准 |
|---|---|---|
| 通用表达方法和可复制模板 | `01-提示词` | 不绑定具体角色或项目，回答“如何表达” |
| 镜头、光影、材质和风格等视觉词义 | `02-视觉术语` | 回答“词是什么意思、何时使用” |
| 人物、姿势、场景、参数、过程和交付 | `03-资产与工作流` | 可调用或可追溯的生产事实 |
| A/B 测试、跨项目验证和稳定结论 | `04-实验与结论` | 回答“规律是否成立” |
| 当前状态、ADR、审计和历史版本 | `90-维护与归档` | 治理知识库本身，不作为日常入口 |

## 提示词权威结构

所有现行提示词统一继承以下五段，不再建立平行母版：

```text
【任务】本轮做什么、允许改变什么
【保持】什么不能改变、每张参考图负责什么
【画面】主体、场景、风格、镜头和光线
【限制】最可能出现的问题及冲突优先级
【输出】数量、比例、完整性和用途
```

## 维护规范

- 同目录编号只表达推荐使用顺序：`01–89` 为活动内容，`90` 为维护与归档。
- 状态、平台、成熟度和“常用/按需”等易变属性写入 Frontmatter 或 MOC，不写进目录名。
- 一个内容只保留一个权威正文；历史拆分版放入维护区，通过链接追溯。
- 具体项目经验不能直接覆盖通用规则，应先在实验与结论中复验。
- 当前目录和运行状态以 [[CURRENT]] 为准；历史规划不覆盖当前结构。

## 内容安全边界

- 精确文字、品牌 Logo、人物身份和多视图结构必须在生成后验收。
- 提示词不能保证绝对一致性；复杂任务应结合参考职责、区域控制、分步生成和后期修复。
- 来源、身份授权或商业使用状态未知的媒体，不默认进入商业交付。
