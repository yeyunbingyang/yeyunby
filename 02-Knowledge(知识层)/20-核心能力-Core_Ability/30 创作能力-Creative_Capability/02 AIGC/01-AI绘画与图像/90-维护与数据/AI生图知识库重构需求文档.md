# AI生图知识库重构需求文档

> [!abstract] 文档定位
> 本文是 AI 生图知识库重构的启动文档（PRD v1.1），由 grill-with-docs 需求审查会话逐项决策修订，可直接作为后续实施的规格依据。本文件仅记录需求，不含实施计划。

> [!important] 版本说明
> v1.1 相对 v1.0 的关键变化均来自逐项审查决策（标 ★ 处）：主目标改为**学习优先**；**撤销独立"平台规则层"**——平台差异由平台执行模板承担；**提示词模板层提升为领域根最顶层 01**；**新增三层场景分类导航**（7 类场景 × 7 种操作 × L1-L5 难度，见 [[AI生图场景分类]]）作为需求入口；**模板分为两层**——方法论母版（槽位协议，含镜头与构图、渲染与质感，验收移出，不直接执行）+ **平台执行模板**（GPT/即梦 可直接粘贴）；**内容要素融入槽位**，专业名词=填空位可选值；**"问题→槽位调整"对照表提为全库最高价值资产**；**新增素材图库（姿势/站位/场景/道具）并入 03，作为"媒体跟项目"的显式例外并记 ADR**；专业名词速查扩展为九大维度；**升级"终极工作流"为学习闭环**；**新增学习路径/练习菜单（04 层）**；人物资产库按方法→模板层、资产→03 项目拆分；丝袜商品效果图生成重命名为丝袜效果图归入 03；模板与词典用结构化 frontmatter 支持 AI 读取；词典种子集随用随建并标难度阶梯；词-图对照为实验自然产物；实验层提前。

## 一、项目背景与目标

### 1.1 现状

现有知识库已具备：人物身份资产库-MOC、丝袜效果图-MOC、一致性控制、图片生成提示词最佳实践（任务协议方法论）、通用生图提示词模板（六槽位×双轴）。**缺的是"可学习"而非"可参考"的内容组织。**

### 1.2 核心缺口

1. 术语层缺失：无图片设计专业名词速查表。
2. 模板层空心化：有六槽位骨架，但无"可选值词典"。
3. 平台差异未内嵌：GPT Image-2 / 即梦 语法差异未落入模板，使用时需跨处比对。
4. 视觉参考层缺失：无"快速查看生成效果"。

### 1.3 项目目标（★ 主目标改为"学习优先"）

> **主目标：学会 AI 生图提示词及相关操作。** 知识库重构是支撑学习的手段，不是目的。

逻辑二层架构（供理解，物理布局见 §三）：

```text
Layer 1 执行层 → 提示词模板（使用的提示词 + 方法论总结）——最顶层，直接打开即用
                平台差异内嵌为模板注释（GPT:/即梦:），不单独成层
Layer 2 词汇层 → 专业名词速查词典（查词→选词→填模板）
```

**战略定位（★ 与 08-02 重构不冲突）**：提示词模板层、名词速查层均为**纯知识层（不含媒体）**；平台差异下沉为模板内嵌注释。媒体仍跟随 10/20 项目，不推翻"媒体跟项目"原则。现有 10/20 项目结构保留，仅入口外迁。

**学习闭环（★ 升级原"终极工作流"）**：生产流程只是环的一半，完整的学习闭环如下：

```text
理解概念 → 选模板（填好的示例照抄）→ 生成 → 人工看图
   ↑                                            ↓
   └──── 反哺（每3次成功修复→补1个词典词条/素材图） ← 查"问题→槽位"表调整
```

每绕一圈 = 一次学习；积累到 **3 次成功修复** → 反哺一个词典词条或素材图（触发"随用随建"）。学习闭环使整库"练习驱动"而非"存储驱动"。

## 二、功能需求

### 2.1 平台差异（★ 撤销独立"平台规则层"，内嵌模板）

> 平台语法差异**不作为独立目录层**，而是**内嵌在每个模板里**（`GPT: …` / `即梦: …` 注释）。模板打开即用，平台差异就在手边，不必跨层跳转。本节保留两平台知识素材，供模板内嵌时引用。

#### 2.1.1 GPT Image-2 语法与最佳实践

| 模块 | 规格 |
|---|---|
| 语法偏好 | 结构化自然语言（完整句子）优于关键词堆叠 |
| 长度限制 | 即时模式 100–300 词，思考模式 ≤500 词 |
| 文字渲染 | 精确文字放引号内 + 反文字负面词 |
| 迭代限制 | 同一提示词迭代 ≤3 次，否则退化 |
| 写实强化 | 摄影术语（焦距/光圈/光线方向/拍摄角度） |
| 风格锁定 | 复用同一段风格说明做多张图 |

#### 2.1.2 即梦（Jimeng）语法与最佳实践

| 模块 | 规格 |
|---|---|
| 语法偏好 | 模块化公式：`[主体]+[动作/运镜]+[环境/光影]+[风格质感]` |
| 专业术语 | Cinematic lighting / Dolly zoom / 4k resolution 等英文术语 |
| 学习路径 | 看"灵感"板块优质提示词 → 做同款 → 修改 |
| 负面提示词 | 独立输入字段，按场景分类填充 |

#### 2.1.3 平台差异对照（内嵌模板用）

差异内容保留为知识素材，落库形式是**模板内嵌注释**——模板正文用平台无关中性写法，每处差异用一行 `GPT: …` / `即梦: …` 标注。学到哪个平台展开哪个，避免一开始背差异表。

| 维度 | GPT Image-2 | 即梦 |
|---|---|---|
| 提示词格式 | 完整描述性句子 | 模块化公式 |
| 权重语法 | 不支持（语序/重复强调） | 部分支持 |
| 负面提示词 | 写入正文或独立字段 | 独立输入框 |
| 文字渲染 | 引号+反文字负面词 | 引号+排版描述 |
| 最佳长度 | 100–500 词 | 中等长度 |
| 默认风格 | 照片级写实 | 偏艺术化 |
| 一致性控制 | 参考图+详细描述 | 参考图+@角色引用 |

#### 2.1.4 平台适配策略（★ 内嵌注释 vs 双版本）

平台差异**大小不同**，适配方式分两级：

- **通用模板（人物创作/氛围创意）**：结构差异小 → **内嵌注释**（GPT:/即梦:）即可，正文平台无关中性写法。
- **结构差异大的模板（商品视觉/故事板）**：文字/版式、序列帧在不同平台跑不通 → 提供**平台双版本**（GPT 版 / 即梦版各一）。
- 验收标准③"每模板≥3处差异注释"适用于内嵌注释类；双版本模板以"两版本均可用"为验收。

### 2.2 专业名词速查词典（★ 种子集 + 随用随建）

- **九大维度（★ 由六维扩展）**：
  1. 画幅与分辨率（9:16 / 16:9 / 1:1 / 4K / 8K）
  2. **景别（★ 新增）**：远景/全景/中景/近景/特写/大特写
  3. 镜头与焦距（广角 / 50mm / 85mm / 长焦 / 微距）
  4. 构图法则（三分法 / 引导线 / 负空间）
  5. **人物九大角度（★ 新增）**：取景（全身/半身/胸像）× 机位（正面/45°/侧面），补充背面/仰视/俯视
  6. 光影与布光（伦勃朗光 / 蝴蝶光 / 逆光）
  7. 景深与焦点（浅景深 / 超焦距 / 焦外虚化）
  8. **艺术风格（★ 拆分）**：油画 / 水彩 / 赛博朋克 / 极简
  9. **材质与质感（★ 拆分）**：金属 / 织物 / 石材 / 玻璃
- **P0 只建种子集**：每维度 5–8 个最高频词条，共约 **40 词**，跑通三套用途模板案例。
- **随用随建**：实验遇到新词，按卡片格式补齐（Karpathy 原则，不为"未来的 80 词"提前建）。
- **词条卡片格式**：中文名｜英文名｜定义｜适用场景｜效果特征｜推荐搭配词｜参考图。
- **参考图 = 实验自然产物（★）**：每个词条在实验用到时，顺带把该次生成图存为参考——图是自己验证过的，最贴学习需求；不设独立生成里程碑。
- **难度阶梯（★）**：每维度种子词标注 **入门/进阶** 两级，模板示例也标注难度。学习从"入门词 + 入门示例"起步，逐步进阶，避免一开始被专业术语淹没。

### 2.3 提示词模板库（★ 场景分类导航 + 槽位协议 + 平台执行）

#### 2.3.0 场景分类导航（★ 需求入口，三层正交）

模板库的**入口层**是 [[AI生图场景分类]]，从需求出发导航到模板。三层正交维度：

| 维度 | 内容 | 决定什么 |
|---|---|---|
| **一级·7 类场景** | 人物 / 商品商业 / 场景概念 / 插画艺术 / 平面品牌 / 建筑空间 / 素材制作 | 固定对象 |
| **二级·7 种操作** | 文生图 / 图生图 / 局部重绘 / 扩图 / 主体替换 / 风格转换 / 批量变体 | 可变项 |
| **三级·L1-L5 难度** | 自由创意 / 单主体 / 参考一致性 / 多参考融合 / 复杂编辑 | 约束量（L5 需蒙版/LoRA） |

**核心原则（★）**：**场景决定固定对象，操作决定可变项，难度决定约束，输出决定规格。** 用户从需求（场景）→ 操作 → 难度 → 选模板，四个维度独立。

#### 2.3.1 通用提示词模板（★ 需满足三类主用途）

**需求**：通用提示词模板必须同时覆盖三类**主用途**——**人物创作、商品视觉、氛围创意**，三类共用同一份模板直接可用。**完整 7 类场景（插画/平面/建筑/素材等）由 [[AI生图场景分类]] 导航**，本模板覆盖最常用的三类为主入口。

**分类说明（★ 按用途分，非按主体分）**：
- 分类依据是**你要完成的任务用途**，不是生成对象的物理类别。
- **人物创作** = 以人物为主体，重身份一致性（角色/模特/头像/三视图）。
- **商品视觉** = 以商品为主体，重文字/版式/卖点（电商主图/详情页/海报/包装）。
- **氛围创意** = 以场景/风格/概念为主体，重氛围与风格（环境/背景/概念图/风格化）。
- 纯物品按意图归入：商业用途→商品视觉；艺术/审美用途→氛围创意；不再有孤立的"物品"类。

**模板的定义（★）**：提示词模板 = **使用的提示词 + 方法论总结**。它不是一堆可复制粘贴的句子，而是把"可粘贴的提示词正文"与"怎么用/何时用/怎么调的使用说明"封装在同一个文件里。使用者打开模板既能直接复制正文，也能在遇到问题时按方法论部分排查调整。

**模板的可执行性 = 完成示例（★）**：每个模板必须配 **1-2 个填好的完整示例**——含真实参数、可直接复制的最终提示词。用户照抄改改就能用；模仿是学习的起点，空骨架不可执行。

**填空式融合架构（★ 更新：母版 + 执行模板两层）**：
- **模板分为两层（★ 外部审查采纳）**：
  - **方法论母版**（通用生图提示词模板）：槽位协议 + 问题定位表 + 迭代流程 + 实验日志。**不直接执行**，是给人/维护者看的协议。
  - **平台执行模板**（GPT/即梦）：从母版派生，落为平台可直接粘贴的提示词。日常使用者直接用执行模板，不需读母版。
- **槽位 = 填空位（★ 升级为 5 主槽 + 可选槽）**：
  - **五主槽**：固定项/可变项/优先级/限制项/输出规格。
  - **镜头与构图独立成槽**：视角不只决定输出，更改变画面内容（正面变侧面改五官、俯仰改透视）。图生图时可能属固定项，文生图可能属可变项，不能固定塞进输出。
  - **渲染与质感（可选正向槽）**：精度不只靠负面排除，更需正向告诉模型质感（natural skin texture 等）。
  - **验收完全移出模板正文**，仅作方法论一部分（人工看图→查对照表→调槽）。
- **固定项槽必须保留**：它是主体一致性的来源（身份/商品本体），简化不可砍。
- **内容要素 = 填空项的分类**：主体→固定项槽；环境/风格/媒介→可变项槽；视角→镜头与构图槽；精度→渲染与质感（正向）+ 限制项（反向）。
- **专业名词（九大维度）= 填空位的可选值词典**：每个空位旁标注"可选值见 XX 词典"。

**满足方式**：母版 = 五主槽填空协议（题材无关）+ **槽位 × 三类用途填充映射** + **三类负面词包**；平台执行模板从母版派生并落为平台语法。**入口层** = [[AI生图场景分类]]（7 类场景 × 7 操作 × L1-L5），用户从需求导航到对应模板。

**文档结构（四段式）**：
1. **文档说明**：母版定位、读者、与平台执行模板的边界。
2. **是什么**：五槽位 + 镜头/质感 × 双轴协议的"为什么"。
3. **提示词说明**：母版槽位怎么填——含三类用途填充映射、内容要素对应、负面词体系、三变体、图生图特化。
4. **方法论**：如何使用母版——**验收与"问题→槽位"对照表归此层**（见 2.3.2）。

#### 2.3.2 "问题 → 槽位调整"对照表（★ 全库最高价值资产，优先建设）

**定位（★）**：用户最痛的不是"没词典"，而是"生成不对不知道怎么改"。**"问题→槽位调整"对照表**是解决这个痛点的核心资产，其价值高于词典与模板本身——应置于通用模板**方法论的第一部分**（最显眼处），而非埋在末尾。

**需求**：验收 = 人工看图 → 发现图片存在的问题 → 查对照表定位根因 → 调整提示词对应槽位 → 重新生成。

**实现**：
- 验收循环：生成 → 看图 → 查"问题→槽位"表 → 调整对应槽位 → 重新生成。
- **对照表按三类用途各一组**，每条含：问题现象 → 根因 → 调整动作 → 涉及槽位。例：
  | 用途 | 看图发现 | 根因 | 调整动作 | 槽位 |
  |---|---|---|---|---|
  | 人物 | 脸不像/换脸 | 固定项弱或参考权重不足 | 加强固定项或提高 R1 权重 | ①固定项 |
  | 商品 | 文字错乱 | 未引号圈定 | 引号圈定+补文字负面 | ④约束 |
  | 氛围 | 平淡 | 变量/风格槽太泛 | 细化风格词与光线 | ②变量 |
- 迭代规则：一次只改一个变量；连续 3 轮无改善→降难度/换参考/换控制；累积漂移→回退最近通过版本。
- 对照表随实验**增量扩充**（每次成功修复 = 新增一行），成为"看得见的经验积累"。

**验收的定位（★ 补充）**：验收属于**使用模板的方法论**，**完全移出模板正文**——提示词本体只含固定项/可变项/优先级/限制项/镜头与构图/输出规格/渲染与质感等槽位，不含验收；验收（生成后人工看图→查对照表→调槽）作为方法论的一部分，写入通用模板文档的"方法论"部分，而非单独成篇、也不进提示词。

#### 2.3.3 模板库（★ 用途模板 + 特殊形态模板）

模板层由**两类模板**组成，均建立在通用模板槽位协议之上：

**① 用途模板（按生成内容分）**——回答"生成什么"：

```text
人物创作模板 = 槽位骨架 × 人物填充（身份/外貌/服装/表情/姿势/镜头/光影）
  → 重心：固定项/一致性（换姿势不换脸）
商品视觉模板 = 槽位骨架 × 商品填充（主体/卖点可视化/使用情境/版式/品牌/文案占位）
  → 重心：限制项（文字）/输出规格（版式）
氛围创意模板 = 槽位骨架 × 氛围填充（场景/环境/风格/光线/色彩/情绪）
  → 重心：可变项/风格
```

**② 特殊形态模板（按输出版式分，★ 新增）**——回答"输出什么形态"，是槽位协议的变体，固定输出规格槽（⑥）与镜头与构图槽（⑤）的版式部分，其余槽位照填：

```text
视图生成提示词模板     ← 三视图/多视图/九宫格视图（固定输出为多视图版式）
角色设定图提示词模板   ← 人设板/表情图集（固定输出为设定板版式）
四格漫画提示词模板     ← 分镜/场景（固定输出为四格分镜版式）
故事板提示词模板       ← ★ 视频分镜序列帧 + 镜头表（固定输出为多帧序列）
```

> 两维正交：一个"人物"任务可用"人物创作模板"，也可用"角色设定图模板"产出多视图人设。库内已有 `四格场景提示词`、`角色设定板提示词`、`真人身体与三视图提示词` 可提炼为素材。

**故事板模板（★）**：以故事板（Storyboard）为例——把一段视频拆成序列关键帧，每帧标注镜头、景别、机位、动作、对白、时长。槽位协议变体：
```text
故事板模板 = 槽位协议 × 分镜填充（场景/镜头/景别/机位/角色/动作/对白/运镜/时长）
  → 固定输出：多帧序列（每帧一个景别机位）+ 镜头表（镜头号/内容/对白/时长）
```
衔接：与 `02-AI视频与动效/AI短剧` 项目联动（先出故事板帧 → 喂给视频模型做镜头）；库内归档区有 `AI漫剧人物身份锁定与多角度参考图工作流` 可参考。

每套模板：
- 正文 = 平台无关中性写法 + 内嵌平台差异注释（GPT:/即梦:）。
- 负面带 = 基础包（失败类型四分类）+ 对象包 + 风格包。

#### 2.3.4 素材图库：姿势 / 站位 / 场景 / 道具（★ 可变项槽的高价值填充项）

**需求**：除提示词模板外，还需**看图选用的素材库**支撑可变项槽（②）的填充——人物姿势、多主体站位、场景设计、道具搭配。这类内容需要图例（词-图对照），是"看图选词填模板"的典型场景。

**定位（★）**：姿势/站位/场景 = 槽位协议**可变项槽（②）的高价值填充项**，不是独立模板；每个需要图例 → 进"词-图对照"（实验自然产物）。

**结构**（并入 `03-资产与工作流层/素材图库`）：
```text
素材图库/
├── 人物姿势库/      ← 站立/行走/坐姿/动态/道具互动
├── 人物站位图库/    ← ★ 多主体构图站位（谁前谁后/主次/朝向/间距）
├── 场景氛围图库/    ← 室内/室外/都市/自然/氛围场景
└── 场景道具库/      ← 道具搭配参考
```

**首批发源地**：丝袜项目的 `姿势动作参数`、`构图场景参数`、`模特服装与姿势`（含"腿部服饰姿势素材库"4 类）提炼为"商品视觉"场景下的姿势/场景素材；研究角色 CN02/JP04 的"近景-全身-环境-动作"序列可作场景氛围参考。

**与"媒体跟随项目"原则的关系（★ 显式例外）**：`素材图库` 是 **"媒体跟随项目"铁律的显式例外**——它服务多用途的可变项槽填充（同一姿势图可被人物与商品模板引用），而非单一项目专属。此例外**已记录为 [[0001-AI生图知识库学习优先重构]] 第 4 条关键决策**，明确边界：只收"跨用途可复用"的姿势/站位/场景/道具图；项目专属媒体仍跟随项目。

#### 2.3.5 现有资产归位到三类用途（★ 拆分 / 重命名）

**AI人物身份参考资产库 → 拆分（★）**：
- **方法/提示词部分**（动漫化与风格、古风写实、真人身体与三视图、四格场景、表情与换装、角色设定板、身份与角度 7 篇提示词 + 生产方法 + 验收修复）提炼并入 `01-提示词模板` —— 其中四格场景→四格漫画模板、角色设定板→角色设定图模板、身体与三视图→视图模板，其余并入人物创作模板。
- **人物资产部分**（角色与实验：JULIA/墨衣少年/真人仙侠/研究角色；过程资产；失败与版本；最终交付物；JSON/ADR/验证报告）保留为 `03-资产与工作流层/人物资产` 项目。

**丝袜商品效果图生成 → 重命名为 `丝袜效果图`（★）**，归入 `03-资产与工作流层/丝袜效果图`。其内部**提示词库/参数库提炼进商品视觉模板作参考**（通用槽位协议 + 丝袜专属参数填充），**SOP/生产资产/实测与失败/交付样张留在丝袜项目**。

**丝袜专属提示词的位置（★）**：商品视觉模板只写**通用商品**槽位协议 + 填充映射；**丝袜专属提示词**（参数库/生产SOP/提示词库）写在 `03/丝袜效果图` 项目内，在商品视觉模板中加一行指引："丝袜专属提示词 → 见 [[丝袜商品效果图-MOC]]"。

**按三类用途归位（★ 方案 B）**：

| 商品视觉 | `01-提示词模板/【用途模板】/商品视觉提示词模板`（通用方法）+ `03/丝袜效果图`（专属资产） |

### 2.5 负面提示词体系（★ 失败类型为主 + 对象/风格叠加）

```text
基础包（必加，来自最佳实践第 5 节四分类）
  结构负面：多指/错关节/多腿/肢体扭曲
  身份负面：换人/换脸/年龄/眼型变化
  渲染负面：模糊/低清/塑料肤/劣质光
  版式负面：裁头/错误角度/缺视图
对象包（按用途叠加）：人物专项 / 商品专项（错字、多余标签、塑料感）/ 氛围专项（杂乱、平光、无层次）
风格包（按目标风格叠加）：写实排除动漫 / 动漫排除写实 / 商业干净风 / 古典油画
使用原则：基础包+场景包组合后 ≤15 词，过多削弱模型表现力
```

## 四、非功能需求
