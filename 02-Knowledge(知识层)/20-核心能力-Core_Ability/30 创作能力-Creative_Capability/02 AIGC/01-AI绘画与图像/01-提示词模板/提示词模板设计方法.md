# 提示词模板设计方法

> [!abstract] 核心结论
> 本文是**提示词模板设计方法**（七槽位母版 / 设计规范）：把任意图像生图任务收敛为一份填空式槽位骨架，用"恒定轴 vs 可变轴"的双轴决定哪些保留、哪些变化；内容要素（主体/动作与状态/环境与背景/风格与媒介/光线与色彩/镜头与构图/材质与细节）融入各槽位作为填空项，专业名词为填空位可选值。人物创作、商品视觉、氛围创意三类用途通过**填空映射 + 负面包**落地。

> [!warning] 使用边界
> **本文是设计规范，不是"打开即复制"的模板**。日常使用者请直接进 [[生图任务模板库]]（按任务分类、可直接复制的 A-H 模板）或 [[GPT 图像生成执行模板]] / [[即梦图像生成执行模板]]（平台可粘贴版本）。只有需要**设计新模板、理解槽位原理、排查失败**时才读本文。模型能力随版本变化，具体效果需在项目中复测。**验收不是提示词本体，已完全移出模板正文**，归使用方法论（见第四部分）。

## 二、是什么：七槽位 × 双轴协议

### 2.1 槽位总览（★ 填空式命名）

任意生图任务 = 七个槽位（六个基础槽 + 一个可选渲染项），缺哪个槽，模型就在那个维度自由发挥：

| 槽位    | 原协议名 | 填空含义       | 缺失的后果          |
| ----- | ------- | ----------- | -------------- |
| ① 固定项 | Anchor  | 最高保留什么      | 主体漂移（换脸/产品变样）  |
| ② 可变项 | Variable | 本轮要改的（变量/变量组） | 模型自行取舍，丢弃你的目标  |
| ③ 优先级 | Priority | 冲突时听谁的      | 低优先级项覆盖核心要求    |
| ④ 限制项 | Constraint | 禁止什么、格式是什么  | 结构崩坏、文字水印、错误版式 |
| ⑤ 镜头与构图 | Framing | 景别/机位/角度/构图  | 视角错、透视错、构图失衡 |
| ⑥ 输出规格 | Output  | 数量/画幅/用途    | 比例错、数量错、不可用    |
| ⑦ 渲染与质感（可选） | Render  | 材质/光线/表面的正向描述 | 塑料感、无质感、假 |

> **镜头与构图独立成槽（★）**：视角不只决定输出格式，更会改变画面内容——正面变侧面改变可见五官、近景变全身影响身体补全、俯仰改变透视。图生图时镜头可能属固定项，文生图时可能属可变项，不能固定塞在输出里。

> **渲染与质感为可选正向项（★）**：精度不只靠负面词排除，更要正向告诉模型"正确质感长什么样"（natural skin texture / realistic fabric folds…）。

> **日常用法**：复制模板正文 → 直接替换各槽位的 `{空位}` 即可，无需理解协议术语。原协议名（锚点/变量/约束/输出/Framing/Render）仅在对照表与后续映射中保留为参照。

> 验收已从模板正文移出（原第六槽），归第四部分方法论（人工看图→查对照表→调槽）。

### 2.2 双轴模型：恒定轴 × 可变轴

```
恒定轴（Anchor 轴）   ←—— 冻结 ——→   可变轴（Variable 轴）
身份母版 / 商品效果本体          姿势 / 服装 / 场景 / 光线 / 效果
```

- **恒定轴**：必须显式声明为"最高保留优先级"，否则模型会在换变时连它一起漂移。
- **可变轴**：诊断模式每轮只取一个变量（单变量原则）；正式生成可按变量组（如"服装与配饰"）成组修改。跨组并非绝对禁止——换服装+匹配配饰、换场景+匹配光线都是合理组合，但要控制变量数量与耦合程度（同时换脸+姿势+服装+场景+风格=风险过高）。
- **换轴规则**：恒定轴优先级最高，可变轴改变时恒定轴保持（作为最高保留目标，而非像素级锁定）。

### 2.3 为什么是协议而不是文案

普通写法（描述）："生成一个漂亮女孩，穿黑色裙子，很高级，真实摄影"——"漂亮""高级"是低精度信息。
协议写法（指令）：明说优先级、禁止项、验收标准，模型知道怎么执行、怎么取舍。**核心目标与保留项前置**——通常有助于降低长提示词中的信息稀释；但模型仍会综合整段提示词、参考图与平台控制参数，不保证只按前几行执行。

## 三、提示词说明：怎么填（填空式）

### 3.1 内容要素 ↔ 槽位对应（★ 融合核心）

内容要素是"画面描述什么"的**七类**，**不是独立层**，而是各槽位的填空项。专业名词（九大维度）为每个空位的**可选值**：

| 内容要素 | 对应槽位 | 专业名词可选值（见 02-专业名词速查） |
|---|---|---|
| **主体**（身份/商品本体/场景基调） | ① 固定项 | 人物九大角度 / 画幅 |
| **动作与状态**（姿势/动作/表情/状态） | ② 可变项 | 人物姿势库（03）/ 人物九大角度 |
| **环境与背景**（场景/背景/氛围） | ② 可变项 | 景别 / 构图法则 / 光影布光 |
| **风格与媒介**（艺术风格/媒介/画风） | ② 可变项 | 艺术风格 / 材质与质感 |
| **光线与色彩**（光向/光质/色调/影调） | ② 可变项 + ⑦ 渲染与质感 | 光影与布光 / 景深与焦点 |
| **镜头与构图**（景别/机位/角度/构图/焦距） | ⑤ 镜头与构图 | 景别 / 人物九大角度 / 镜头与焦距 / 构图法则 |
| **材质与细节**（表面/质感/纹理/细节） | ⑦ 渲染与质感（正向）+ ④ 限制项（反向） | 材质与质感 / 光影布光 |

> 固定项是身份一致性的来源，**最高保留优先级**——它是槽位协议的灵魂。

### 3.2 模板正文（填空式骨架）

```text
【固定项｜恒定轴】——最高保留优先级（缺失→主体漂移）
主体：{主体描述 或 参考图编号}
      填法：① 纯文字描述主体（身份/商品本体/场景基调）
            ② 有参考图：写"参考 R1"，并声明职责与权重
  参考 R1 → 只负责{脸/商品本体}，最高语义优先级（冲突以此为准；权重为逻辑排序，非平台参数）
  参考 R2 → 只负责{身体/材质}（次之，不得覆盖 R1 身份特征）
冻结项：{脸型、比例、商品纹理……}——明确列出"最高保留"的部分
      技巧：冻结项越具体越好（"眼型"优于"五官"），换变量时才不会连带漂移

【可变项｜可变轴】——本轮要改的（缺失→模型替你取舍）
本轮只改变：{单一变量 或 变量组}
      填法（★ 两种执行模式）：
        诊断模式：只改一个变量（如仅"艺术风格"），用于定位问题
        正式生成：允许改一个变量组（如"服装与配饰"、下划线成组），用于一次出成品
      关键：诊断时只改一个变量；正式生成控制变量数量与耦合（换服装可配饰同组；同时换脸+姿势+服装+场景=风险过高）
变量取值：{库编号 或 参数表}（无库时直接写描述）
      例：变体C用"丝袜效果E001→服装→场景"，单次任务直接写"傍晚咖啡店，暖光"

【优先级｜冲突取舍】——冲突时听谁的（缺失→低优先级覆盖核心要求）
P0 {固定项一致性}  >  P1 {人体/商品结构}  >  P2 {风格材质}  >  P3 {场景氛围}
      说明：P0 最高保留优先级，不可主动重设计；P1~P3 按任务重要性调整
      注：P0~P3 是语义排序与文档结构，帮助模型理解重要程度，不是模型可验证的硬性控制权重
      例：商品图 P0=商品本体不变，P1=文字正确，P2=材质真实

【限制项】——禁止什么、格式是什么（缺失→结构崩坏/文字水印/错版式）
结构负面：{多指/错关节/商品变形}    ← 防解剖/结构错误
身份负面：{换人/商品漂移}          ← 防主体改变
渲染负面：{模糊/塑料感/劣光}       ← 防画质问题
版式负面：{裁切/多格/文字水印}     ← 防布局错误
格式：{单图/独立图/拼版}          ← 决定输出形态
      技巧：可选值见 §3.4；超 15 词按 §5.1 砍

【镜头与构图】——视角/机位/构图（缺失→视角错/构图失衡）
景别：{远景/全景/中景/近景/特写}      ← 可选值见 景别词典
机位：{平视/俯拍/仰拍}              ← 可选值见 人物九大角度词典
构图：{三分法/居中/引导线}           ← 可选值见 构图法则词典
焦距：{广角/50mm/85mm/长焦}         ← 可选值见 镜头与焦距词典
      说明：图生图锁主体时，镜头通常随参考图（属固定项）；文生图自由时属可变项

【输出规格】——数量/画幅/用途（缺失→比例错/数量错）
数量：{N}  画幅：{比例}  用途：{平台/场景}  版式：{无/格子}
      例：数量1 / 画幅3:4 / 用途小红书头像 / 版式无

【渲染与质感】——正向质感描述（可选，缺失→塑料感/假）
材质：{natural skin texture / realistic fabric folds / polished metal surface}
光线：{soft directional lighting / controlled highlights / warm golden-hour glow}
表面：{individual hair strands / clean edge definition / physically plausible material}
      说明：追求高画质时必填；告诉模型"要什么样"（正向），与限制项互补
```

**普通描述 → 填空映射示例**（新手照此把"感觉"翻译成"填空"）：

```text
普通描述："生成一个漂亮女孩，穿黑色裙子，很高级，真实摄影"

【固定项】主体：年轻女性，圆脸，杏眼，直鼻梁，肤色偏白（明确五官=低精度词"漂亮"的落地）
【可变项】本轮只改变：服装——黑色连衣裙，及膝，收腰
【优先级】P0 人脸不变 > P1 人体结构 > P2 裙子质感 > P3 背景
【限制项】结构负面：bad hands, extra fingers；身份负面：换脸；渲染负面：blurry, plastic skin
【镜头与构图】景别：半身；机位：平视；构图：居中
【输出规格】数量1 画幅3:4 用途社交头像 版式无
【渲染与质感】皮肤 natural skin texture，裙子 fabric folds 自然
```

### 3.3 槽位 × 三类用途填空映射（★ 核心）

三类最常用用途的填空映射如下。**完整 7 类场景（插画/平面/建筑/素材等）见 [[AI生图场景分类]] §一**，此处三类为主入口。差异全部收进**填空映射 + 负面包**：

| 槽位        | 人物创作               | 商品视觉              | 氛围创意              |
| --------- | ------------------ | ----------------- | ----------------- |
| **① 固定项** | 人物身份：脸/五官/体型（或参考图R1） | 商品本体：外观/配色/品牌元素 | 场景基调：环境/氛围/情绪 |
| **② 可变项** | 姿势/服装/表情/场景          | 使用情境/版式/光影/文案    | 场景元素/光线/色彩/细节     |
| **③ 优先级** | 身份>结构>材质>场景          | 商品>卖点>版式>品牌       | 风格>氛围>场景>细节       |
| **④ 限制项** | 结构负面+身份负面            | 商品负面（错字/多余标签/塑料感） | 氛围负面（杂乱/平光/无层次）  |
| **⑤ 镜头与构图** | 头像/全身/三视图/动作板视角   | 主图/详情页/海报视角      | 环境/概念图/风格化视角     |
| **⑥ 输出规格** | 头像单张/三视图拼版          | 主图1张/详情页多张       | 概念图/氛围参考          |
| **⑦ 渲染与质感** | 皮肤自然纹理/发丝            | 商品材质真实/布光专业     | 氛围层次/细节丰富         |

### 3.4 负面词体系（四分类 + 对象/风格叠加）

**基础包（三级策略第三层；已发生对应失败时必加）**：
```text
结构负面：多指、错关节、多腿、肢体扭曲
身份负面：换人、换脸、年龄、眼型变化
渲染负面：模糊、低清、塑料肤、劣质光
版式负面：裁头、错误角度、缺视图
```

**对象包（按用途叠加）**：
| 用途 | 追加负面 |
|---|---|
| 人物创作 | bad anatomy, bad hands, extra fingers, missing fingers, fused fingers, long neck, cross-eyed, mutated hands, deformed, disfigured, extra limbs |
| 商品视觉 | deformed product, extra labels, wrong text, misspelled words, harsh shadows, overexposed highlights, color cast, jpeg artifacts |
| 氛围创意 | cluttered, messy background, flat lighting, no depth, noisy, jpeg artifacts, floating elements |

**风格包（按目标风格叠加）**：
| 目标风格 | 排除词 / 控制写法 |
|---|---|
| 写实照片 | cartoon, anime, illustration, 3d render, cgi, sketch, painting |
| 纯二维动漫 | realistic, photorealistic, 3d render, oil painting |
| 半写实动漫（★） | 不排除 `realistic`，改为**限制写实程度**：`semi-realistic anime, anime-inspired facial refinement, realistic human proportions, natural skin shading, stylized but recognizable eyes, not fully photorealistic, not flat cel-shading` |
| 商业干净风 | messy background, cluttered, extra objects, floating elements, text |
| 古典油画 | digital art, vector, flat design, modern graphic, photo |

> **半写实动漫注意（★）**：半写实/动漫写实融合需要部分现实特征（真实比例、细腻皮肤、真实发丝），**不能排除 `realistic`**——应控制"适度写实"而非"完全排除写实"。

**使用原则（★ 修订）**：
- **三级策略**：
  1. **第一层**：明确正向目标与固定项（保持什么优先）。
  2. **第二层**：只添加已经发生的高频失败限制（对应实际失败问题）。
  3. **第三层**：平台支持独立负面框时，再使用精简负面包。
- 负面词不是越多越好。**每个负面词必须对应一个实际高频失败问题**；没出现过的失败，不提前加入。
- 约 15 词是**控制冗余的经验参考值**，非硬性规则。平台有独立负面框（即梦）时，可适当放宽。
- 图像编辑任务更宜"明确保持什么"（固定项），而非堆积"不要什么"。
- 不同平台对负面词支持差异大：有独立负面框、只理解自然语言限制、对传统扩散模型词组反应有限，或更重视编辑区/蒙版/参考图——母版不要求所有任务都带传统英文负面包。
- 超限时按 §5.1 砍。

### 3.5 渲染与质感（★ 正向写法，可选槽 ⑦）

负面词只能"排除错误"，不能告诉模型"正确质感长什么样"。**渲染与质感槽用正向描述**告诉模型目标质感（见 §2.1 槽 ⑦）：

```text
【渲染与质感】（可选，按需填）
材质：{natural skin texture / realistic fabric folds / polished metal surface}
光线：{soft directional lighting / controlled highlights / warm golden-hour glow}
表面：{individual hair strands / clean edge definition / physically plausible material}
风格化程度：{subtle film grain / crisp commercial render}
```

**何时用**：追求高画质（写实皮肤、商品质感、布料真实感）时必填；简单任务可省略。
**与限制项的关系**：渲染与质感=告诉模型"要什么样"（正向）；限制项=告诉模型"不要什么"（反向）。两者互补，不替代。

### 3.6 三变体（按输入条件分化）

模板按"固定项和可变项的形式"分化，共用同一槽位协议：

**变体 A：无参考图（纯文生图）** —— 固定项退化为文字锚点，无图兜底。结构词 ≥ 描述词规则更严（如"清冷孤傲"→ `neutral expression / slightly lowered eyelids / cool color grading`）；优先级必须写明。

**变体 B：有参考图（图生图）** —— 固定项升级为参考职责表，强制声明"冲突时参考图优先于文字"。**参考权重为逻辑优先级（人理解），非平台实际参数**（各平台参考强度见对应执行模板）：
```text
参考 R1（身份/主体）→ 最高语义优先级，冲突时以此为准
参考 R2（身体/材质）→ 次之，不得覆盖 R1 身份特征
参考 R3（姿势/氛围）→ 仅提供风格参考
```
首轮用最小充分参考集，失败归因到具体细节时才补充。

**变体 C：批量 / 参数化（库驱动）** —— 可变项升级为参数表 + 联动规则：
```text
变量取值：{库编号}，按依赖链联动随机
  丝袜效果 → 服装 → 姿势/构图 → 背景 → 道具 → 光线
同页至少出现 {N} 种背景、{N} 种服装、{N} 种姿势
相邻格不得重复完整组合
```
参数化时增加"批次级检查"（缺编号、重复组合、遗漏格）。

| 条件 | 选型 |
|---|---|
| 没有参考图、一次性创作 | 变体 A |
| 有参考图、要锁定主体 | 变体 B |
| 有库、要批量/可复现 | 变体 C |

### 3.7 图生图特化场景（★ 日常高频：局部编辑 / 扩图 / 替换 / 转换）

变体 B 有参考图的基础上，高频操作特化映射到槽位。**完整 7 种操作方式见 [[AI生图场景分类]] §二**，此处列最常用的四种：

**操作方式速查**：
| 操作 | 固定什么 | 变什么 |
|---|---|---|
| 局部编辑 | 非编辑区保持 | 编辑区 |
| 扩图 | 整张原图 | 扩展区 |
| 主体替换 | 姿势/场景/构图 | 主体身份 |
| 风格转换 | 身份/构图 | 艺术风格 |

**① 主体保留型局部编辑（★ 最常用）** —— 保留参考图主体，只替换其他部分。命名区分：
| 操作 | 含义 | 示例 |
|---|---|---|
| **换装编辑** | 保留身份，换衣物/配饰 | 固定人脸换西装 |
| **换景编辑** | 保留主体，换场景/背景 | 商品换场景 |
| **身份替换** | 保留姿势/构图/服装，换成人 | 真换人（逆向） |

以**换装编辑**为例：

```text
【固定项】参考图 R1（脸部/主体），最高保留优先级
          不得主动重设计：人物身份、脸型、五官结构、头部角度
          允许最小局部适配：衣物与身体交界、遮挡边缘、局部阴影
【可变项】本轮只改：{换装组}：衣物/配饰      ← 换哪个写哪个，成组
【限制项】身份负面：换人/换脸/改年龄/改眼型   ← 关键：只防主体漂移
          结构负面：多指/错关节
【镜头与构图】沿用参考图机位/构图（随固定项）
【输出规格】画幅沿用原图比例（或指定新比例）
```

**关键写法**：局部编辑时**固定项为"最高保留优先级"而非"绝对冻结"**——身份/脸型/五官不得主动重设计，但允许编辑区域边缘做最小适配（避免衣物与身体交界断裂）。可变项只列"要换的那一组"，限制项集中防"主体漂移"（换衣物最易连带换脸）。完整填好示例见 §3.9。

**② 扩图（向外扩展）** —— 已有画面整体保留，向指定方向延伸：

```text
【固定项】整张原图（最高保留优先级）：内容、风格、光线
          不允许主动重设计：原图内主体、构图、色调
          允许在扩展边界做无缝过渡
【可变项】扩展区域内容：{新背景 / 新场景元素}
【限制项】衔接：扩展区域与原图风格/光线/纹理无缝延续，无接缝、无断层
【镜头与构图】构图沿原图延伸方向
【输出规格】新画幅：{如 3:4→16:9}  扩展方向：{向左/向右/向上}
```

**关键写法**：扩图的固定项是"**整张原图**"（非单个主体）但同为"最高保留优先级"（原图内容不主动重设计，仅边界无缝过渡）；限制项必须写"无缝衔接/风格延续"；输出规格指定新画幅 + 扩展方向。

### 3.8 平台适配（内嵌注释）

模板正文用平台无关中性写法，每处差异用一行注释标注，学到哪个平台展开哪个：

```text
GPT: 用完整描述性句子，文字放引号内+反文字负面词；长度 100-500 词为经验参考（局部编辑可从简）
即梦: 用模块化公式，负面词填独立输入框；术语中英文均可，中文出现理解偏差时补英文专业词（Cinematic lighting 等），避免中英文重复堆叠
```

> 平台数值（长度、术语偏好）是**带模型版本与任务类型的经验建议，非硬性规则**——详见 frontmatter `model_version` 与 `review_after`，模型大版本更新时需复测。复杂任务与简单任务的长度需求不同：局部编辑几十个清晰词句可能比长描述更有效。

## 四、方法论：如何使用本文（★ 验收归此层）

### 4.1 使用流程

```text
① 选变体（A/B/C）
② 填槽位（用 §3.3 映射选对固定项/可变项/负面包，按需加镜头/渲染）
③ 粘贴生成
④ 验收循环：生成 → 看图 → 查对照表 → 调整对应槽位 → 重新生成
⑤ 收敛后按输出用途交付
```

### 4.2 "问题 → 槽位调整"对照表（★ 全库最高价值资产，优先查看）

看图发现问题后，按此表定位根因并调整对应槽位。此表随实验**增量扩充**——每次成功修复 = 新增一行，成为"看得见的经验积累"。

| 用途 | 看图发现 | 根因 | 调整动作 | 涉及槽位 |
|---|---|---|---|---|
| 人物创作 | 脸不像/换脸 | 固定项弱或参考权重不足 | 加强固定项或提高 R1 权重 | ①固定项 |
| 人物创作 | 多指/肢体扭曲 | 结构限制缺失 | 补结构负面词 | ④限制项 |
| 人物创作 | 换姿势后身材漂移 | 冻结区未声明 | 明确列出"最高保留"项 | ①固定项 |
| 商品视觉 | 文字错乱 | 文字未引号圈定 | 引号圈定 + 补文字负面词 | ④限制项 |
| 商品视觉 | 卖点不突出 | 优先级未标 | 卖点提为 P0/P1 并放顶部 | ③优先级 |
| 商品视觉 | 商品材质像塑料 | 可变项材质写得太泛 | 细化材质词（缎面/磨砂/金属拉丝） | ②可变项 |
| 氛围创意 | 氛围平淡 | 可变项/风格太泛 | 细化风格词与光线 | ②可变项 |
| 氛围创意 | 场景杂乱 | 无氛围负面包 | 补氛围负面（cluttered/杂乱） | ④限制项 |
| 全用途 | 光线生硬 | 光影槽未写 | 指定光源方向/强度/时段 | ②可变项 |
| 全用途 | 整体低清/塑料感 | 渲染负面缺失 或 无正向质感 | 补渲染负面词 或 加渲染与质感槽（natural skin texture 等） | ④限制项 / ⑦渲染 |
| 全用途 | 构图不理想 | 镜头与构图槽未写 | 明确景别/机位/构图（三分法/居中/引导线） | ⑤镜头与构图 |

### 4.3 验收循环（人工看图 → 调提示词）

**验收不是提示词本体，而是使用模板的操作方法**：生成后由人看图、发现偏差、查对照表定位根因、调整对应槽位、重生成。

### 4.4 迭代收敛规则

- **一次只改一个变量**：多问题同时出现时，按优先级从高到低逐个修，不一次堆叠多个调整。
- **连续 2-3 轮无改善** → 不继续堆叠提示词，改为降低任务难度、替换冲突参考或切换控制机制（建议阈值，可按任务调整）。
- **回退原则**：连续多轮编辑累积漂移时，回到最近一次通过的版本，而不是继续补提示词。
- **反哺触发**：积累到 3 次成功修复 → 补一个词典词条或素材图（见 [[AI生图知识库重构需求文档]] 学习闭环）。

## 五、填充层操作细则（★ 怎么把模板用顺）

槽位骨架解决"填什么"，本节解决"填的时候遇到具体问题怎么操作"。

### 5.1 怎么砍负面词（负面词超过 15 词时）

负面词不是越多越好，超限时按**保强度、砍冗余**顺序砍：

```text
保留（不可砍）→ 结构负面（多指/错关节）> 渲染负面（模糊/低清）
可砍（先砍）  → 版式负面（裁头/多格）> 风格包（写实排除动漫等）
```

- **砍负面的优先级**：结构 > 渲染 > 身份 > 版式 > 风格。结构崩坏最致命，风格包最冗余。
- **同一含义去重**：`low quality` 与 `worst quality` 只留一个；`deformed` 与 `mutated` 同类去重。
- **超限判断**：基础包（~8 词）+ 对象包（~6 词）已接近上限；风格包**只在风格漂移时**才叠加，否则不填。

### 5.2 怎么降级难度（连续 2-3 轮无改善时）

"降难度"不是笼统概念，是按阶梯逐级退，退到能过为止。**控制难度分 L1-L5**（完整分类见 [[AI生图场景分类]] §三）：

```text
难度阶梯（从难到易，L5 需额外控制手段）
L5 复杂编辑/连续资产（多角度一致、连续角色）→ 需蒙版/LoRA/固定种子/专用工作流，提示词不够用
L4 多参考融合（人脸+姿势+服装+风格）        → 参考职责表（母版 §3.6），失败减参考
L3 单参考一致性（同人换装/同商品换景）      → 固定项"最高保留优先级"
L2 单主体控制（一个人物/商品/建筑）         → 主体结构 + 清晰度
L1 自由创意（未来城市/梦幻森林）            → 提示词可偏描述性
```

- **每级只降一个维度**：先减参考图数量（最常是参考冲突），再减场景复杂度，最后去参考图。
- **L5 的降级**：从"需要蒙版/LoRA"降到"单参考 L3"，而不是硬扛提示词。
- **降级不是失败**：L1 通过后，再逐级加回复杂度（每次加一个维度），比硬扛 L4 更稳。
- **记录降级路径**：把"L4→L2 才过"写进实验日志，下次同类任务直接从 L2 起（见 §六）。
- **换装/换景/扩图的降级路径不同**：这类任务**必须有参考图**，不能降到"无参考"的 L1。它们的降级是**缩小编辑幅度**：换装先只换一个部件（如只换上衣）→ 再换整套 → 最后才换配饰；扩图则先少扩（如只扩 10%）→ 再大扩。切勿照搬"从零生成"的降参考阶梯。

### 5.3 跨文档导航约定（从模板到库、到素材）

模板不是孤岛，填槽时按统一约定跳转，避免"词不知道去哪找"：

```text
需要领域填充词  → 跳对应用途的领域库（人物→人物资产库，商品→丝袜效果图）
需要专业名词    → 跳 02-专业名词速查（九大维度词典）
需要姿势/场景图 → 跳 03/素材图库（看图选词）
需要平台差异    → 看本规范 §3.8 内嵌注释（不跨文档）
需要经验对照    → 看本规范 §4.2 问题→槽位表（不跨文档）
```

- **导航原则**：模板自包含（协议+差异+对照表都在本文件），只有"领域词/素材图"才外跳库。

## 六、演化层维护机制（★ 让模板长青）

模型在变（GPT/即梦 更新），模板会失效。本节定义"何时、怎么"更新模板及其依赖。

### 6.1 版本绑定（模板与模型能力绑定）

- **frontmatter `model_version`**：记录模板验证时所用的模型版本（如 `gpt-image-2`、`jimeng-v3`）。模型大版本更新时，模板需复测。
- **frontmatter `review_after`**：设置下次复测日期（如 90 天后）。到期未复测，模板状态降级为"待复测"。
- **失效信号**：① 同一提示词从"可用"变"不可用"；② 平台更新说明提及语法变化；③ 连续多次生成不再符合验收。任一触发 → 标记 `status: 待复测` 并走更新流程。

### 6.2 实验日志（记录"怎么改才成功"）

实验日志是学习闭环的落地点，格式约定（见 `04-实验与迭代层/提示词A-B测试日志.md`）：

```text
日期 | 用途 | 变体 | 初始提示词摘要 | 失败现象 | 对照表定位 | 调整动作 | 结果 | 反哺产物
```

- **每次成功修复 = 一行**，积累 3 行 → 触发一次反哺（补词条/素材图/对照表行）。
- **失败也记**：失败路径（如"L4→L2 才过"）比成功更有复用价值，供下次降级参考。

### 6.3 回链网络（改一个不坏一片）

模板和词典有依赖（模板引用词条、对照表引用库），改动前查引用：

- **改动前**：Obsidian 中查看"反向链接"，确认哪些模板/文档引用了被改内容。
- **改字段/词条**：优先在源头（词典/参数库）改，模板通过链接自动跟随，不逐个模板改。
- **改模板正文**：确认是否影响其引用的库（若模板不再需要某词条，不改词典，只删模板引用）。
- **回链异常**：若反向链接断（`[[xxx]]` 变红），优先恢复被引文件名，而非删链接。
