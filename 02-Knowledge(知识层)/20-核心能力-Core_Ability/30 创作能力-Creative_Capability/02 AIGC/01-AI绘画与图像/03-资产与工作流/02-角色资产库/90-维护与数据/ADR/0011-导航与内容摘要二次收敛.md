# 导航与内容摘要二次收敛

## 决策

保留当前 `00` 至 `99` 的职责结构，不移动约 500 MB 的媒体资产；本轮只收敛阅读入口、摘要与活跃区状态。主 MOC 按“用户要完成的任务”组织，新增[[角色资产库-MOC|资产库内容摘要]]解释全库核心方法和案例结论，并把已删除聚合页的链接改为现存权威笔记。

## 自问自答

### 1. 是否再次大规模设计目录？

**建议答案：否。** 当前结构已经把规范、提示词、实验、媒体、JSON、失败和交付物分开，满足稳定职责边界。再次移动媒体的收益低于链接和 JSON 路径风险。

**可调整项：** 当单个角色形成独立规范、实验、数据与交付生命周期时，再评估角色子项目化。

### 2. 当前最影响可读性的是什么？

**建议答案：导航漂移。** 唯一 MOC 仍指向已删除的“提示词库导航”和“正式案例”，读者无法沿推荐顺序完成阅读。

**可调整项：** 后续若恢复聚合页，必须明确其仅做链接与摘要，不复制正文。

### 3. 内容总结应放在哪里？

**建议答案：放在 `00-导航与说明`。** 它负责解释核心方法、案例结论、成熟度与阅读边界；主 MOC 继续保持任务导航职责。

**可调整项：** 当摘要超过约 10 个稳定主题时，再拆子 MOC，而不是继续增长单页。

### 4. 子目录说明页是否立即删除？

**建议答案：否。** 它们包含职责说明和 Dataview 查询，当前仍有维护价值；本轮只修复其中失效入口，避免把“提高可读性”扩大为无依据删文档。

**可调整项：** 若后续 Obsidian 实测确认主 MOC 已覆盖全部入口，可将子目录说明页设为归档。

### 5. 活跃目录里的归档重定向是否保留原位？

**建议答案：不保留。** `表情换装与场景提示词.md` 已拆分且无引用，应移入 `99-归档/02-提示词库`，让活跃提示词目录只呈现当前可用内容。

### 6. 是否处理本轮新增的真人仙侠实验？

**建议答案：只纳入导航，不改写内容或媒体。** 这些文件是工作区未提交资产，必须保护其正文和哈希。

### 7. 是否修复历史归档中的旧链接？

**建议答案：本轮不批量改写。** 历史正文保留当时语境；只保证活跃阅读路径无旧入口。若做全库断链治理，应单独建立迁移映射。

## 路径语义

- Wikilink 以 Obsidian vault 根解析；同名文件出现时使用带目录的 Wikilink 消歧。
- Markdown 中以 `./` 或 `../` 开头的路径相对当前文件解析。
- JSON 中外部 HTTP(S) 地址不作为本地路径；本地媒体字段按项目根或字段既有约定解析。
- 本轮不改变 JSON 和媒体路径。

## 验收标准

- 活跃区不再引用已删除的“提示词库导航”和“正式案例”。
- 新摘要与主 MOC 均有合法 Frontmatter，并链接回上级入口。
- 文件总数变化与“新增两篇、移动一篇”一致；媒体文件数、字节数与哈希集合不变。
- JSON 可解析，活跃 Wikilink 与媒体嵌入可解析，`git diff --check` 通过。

## 实施与复验记录

### 文本补丁匹配失败

- **操作**：首次批量更新 MOC、活跃链接和新增文档。
- **症状**：补丁无法匹配目录树中 `99-归档` 一行。
- **根因**：补丁上下文中的空格宽度与原文件不一致。
- **影响**：补丁原子失败，没有产生部分修改，也没有影响二进制资产。
- **解决方案**：缩小补丁粒度，避开依赖空格宽度的目录树行。
- **复验结果**：第二次补丁完整应用，`git diff --check` 通过。

### 空目录清理

- **操作**：扫描迁移后的空目录。
- **症状**：发现 `04-图片与视频资产/JULIA/06-最终动漫资产` 与 `99-失败与标注` 两个空目录。
- **根因**：此前媒体已按职责迁出，旧阶段目录骨架没有同步移除。
- **影响**：不影响内容，但会误导读者认为过程媒体仍按阶段保存。
- **解决方案**：确认目录内无文件后移除空目录，不移动任何媒体。
- **复验结果**：目标范围不再存在空目录。

### 最终对账

- 文件共 331 个：77 篇 Markdown、4 个 JSON、250 个媒体文件。
- 4 个 JSON 全部通过语法解析；77 篇 Markdown 的 Frontmatter、`domain`、`status` 与 `summary` 均通过检查。
- 活跃区不再引用已删除的旧入口，Wikilink 与媒体嵌入扫描无断链。
- 250 个媒体文件对应 250 个唯一 SHA-256，无重复哈希；本轮未修改媒体内容。
- 新增两篇 Markdown，移动并改名一篇归档重定向；文件总数由 329 增至 331，与迁移映射一致。
