# 资产与工作流-MOC

> [!tip] 使用原则
> 本页是资产与工作流子集的唯一入口。公共复用内容进入公共资产库；围绕人物身份和一致性的内容进入角色资产库；具有独立需求、参数、实测和交付链的内容进入专项生产库。

### 资产生命周期

```text
输入或来源
→ 候选资产
→ 测试与过程证据
→ 验收门禁
→ 通过交付或失败回退
→ 版本替代
→ 归档与维护
```

### 四条边界

1. 通用表达方法归提示词层；与资产字段绑定的执行模板归本层。
2. 公共资产只收跨项目复用内容；角色和项目专属内容跟随所属项目。
3. 过程、失败、交付和归档分开管理，不以“最终版”覆盖历史证据。
4. 新规律先在项目内实测，稳定后再提炼到公共库或通用模板。

## 快速开始与任务路由

> [!info] 笔记关系
> **常用 · 合并优化（2026-08-06）**

### 一、先选择生产入口

| 判断问题 | 选择 |
|---|---|
| 是否只做一次、无需固定人物或商品？ | [[公共资产库-MOC|公共资产库]] |
| 是否必须保持同一角色身份？ | [[角色资产库-MOC]] |
| 是否存在稳定参数、批量生产和明确验收？ | [[专项生产库-MOC|专项生产库]] |
| 是否要建立新的专项生产项目？ | [[00-专项项目模板]] |

### 二、再判断内容归属

| 内容 | 应放位置 | 判断依据 |
|---|---|---|
| 通用提示词结构、权重、平台写法 | `01-提示词/` | 解释如何表达，与具体资产无绑定 |
| 跨项目姿势、镜头、场景、道具 | `01-公共资产库/` | 已分类、可检索、可复用 |
| 固定角色身份与生产证据 | `02-角色资产库/` | 与角色身份和版本绑定 |
| 成熟垂直项目的 SOP、参数和样张 | `03-专项生产库/` | 可重复生产且有明确门禁 |
| A/B 测试和开放探索 | `04-实验与结论/` | 尚未稳定，不应视为权威资产 |
| 注册表、审计、ADR、迁移 | `90-维护与归档/` | 服务于治理，不直接参与生成 |

#### 快速判断

- 文章在解释“如何写”——进入提示词层。
- 文件在回答“调用什么”——进入资产层。
- 内容仍在探索“是否有效”——进入实验层。
- 文件只记录“为什么这样改、如何维护”——进入维护层。

### 三、最小执行闭环

```text
定义交付物与不可变项
→ 选择权威资产
→ 组合可变变量
→ 生成首轮候选
→ 按清单验收
→ 单变量返修
→ 通过后交付
→ 登记资产与版本
```

### 四、推荐模板

- 需求：[[AI图像任务定义模板]]
- 验收：[[通用图像验收清单]]
- 实测与失败：[[实测与失败记录模板]]
- 交付：[[专项项目交付物清单模板]]

### 五、回流规则

```text
实验发现
→ 项目内复验
→ 形成稳定资产或执行模板
→ 跨项目再次验证
→ 提升为公共资产或通用方法
```

### 六、禁止规则

1. 未通过身份、结构或商品门禁的结果不得进入下游。
2. 过程图、失败图和交付图不得混放。
3. 专项结论未经复验不得直接提升为通用规则。
4. 不使用“最终版、真正最终版、最新版”表达版本关系。

## 资产入库与命名规范

### 1. 归属

| 范围 | 目录 |
|---|---|
| 跨项目复用 | `01-公共资产库/` |
| 固定角色 | `02-角色资产库/` |
| 垂直专项生产 | `03-专项生产库/` |
| 通用任务与自动化模板 | `04-工作流模板与自动化/` |

### 2. 文件名

```text
资产ID-对象-资产类型-变量-状态-v01.扩展名
```

状态短码：

```text
CAND 候选｜PASS 通过｜FAIL 失败｜FIX 待修｜ARCH 归档
```

示例：

```text
CHAR-JULIA-身份母版-正面-PASS-v03.png
CHAR-JULIA-三视图-侧面-FAIL-脸型漂移-v02.png
POSE-DUO-双人并列-PASS-v01.png
SPEC-HOSIERY-E02-09-放射阶梯几何-PASS-v01.png
```

### 3. 生命周期与成熟度分离

```yaml
status: active       # draft / active / deprecated / archived
status_cn: 使用中
maturity: stable     # idea / testing / usable / stable
maturity_cn: 稳定
```

### 4. 版本规则

- 统一使用两位版本：`v01`、`v02`、`v03`。
- 内容变化才升级版本；仅移动目录不升级素材版本。
- 失败版本保留问题短词，不覆盖。
- 旧通过版被替代后进入 `99-归档/`，并记录 `replaces`。
- 禁止使用“最终版、真正最终版、最新版”作为版本号。

### 5. 最低元数据

```text
asset_id｜asset_type｜scope｜project/character｜tags
status｜maturity｜version｜canonical｜source｜license
replaces｜used_by｜created｜updated｜hash
```

### 6. 图片引用

优先链接事实源，不为索引复制高清文件。需要视觉入口时使用缩略图或联系表；源文件移动时同步修复引用和资产注册表。

## 资产来源与授权规范

### 原则

目录中存在不等于可以商业使用。任何进入公开发布或商业交付的图片、视频、角色身份和品牌素材，都必须登记来源与授权状态。

### 推荐字段

```yaml
source_type: self_created | ai_generated | licensed | third_party | unknown
source_reference:
rights_status: self_created | licensed | study_only | restricted | unknown
commercial_use: allowed | prohibited | unconfirmed | not_applicable
identity_consent: confirmed | not_required | unconfirmed
usage_scope:
rights_reviewed_by:
rights_reviewed_at:
```

### 使用门禁

- `unknown`、`study_only`、`restricted` 或 `commercial_use: unconfirmed` 不得默认进入商业交付。
- 真人身份参考必须确认使用目的和身份授权；无法确认时仅限内部研究。
- 品牌 Logo、包装文字和现有影视动漫角色应单独审查。
- AI 生成图片仍需记录模型、输入来源和可能包含的第三方参考。
- 替换或衍生资产必须继承上游限制，不能因重新生成而自动获得商业权利。
