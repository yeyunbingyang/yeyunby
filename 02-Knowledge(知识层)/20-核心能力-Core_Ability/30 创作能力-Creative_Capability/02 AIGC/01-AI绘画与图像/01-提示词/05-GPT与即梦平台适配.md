> [!important] 首先区分入口
> - **ChatGPT Images**：自然语言对话、选区编辑、画幅选择和连续修改；
> - **OpenAI API**：通过 Image API 或 Responses API 调用 GPT Image，并用真实参数控制尺寸、质量和格式。

### 一、当前能力基线（2026-08-05）

#### 1.1 ChatGPT Images

- 当前产品为 ChatGPT Images 2.0；
- 支持从文字生成图片，也支持上传现有图片后自然语言编辑；
- 可以框选区域后编辑，也可以不框选直接说明修改；
- 可使用画幅选择器改变画幅；
- 官方帮助页说明可以请求图中文字、图片细节和透明背景；
- 选区不是精确蒙版，编辑可能延伸到选择范围之外；
- Plus、Pro、Business 可使用 images with thinking；其他计划和可用范围以当前产品为准。

#### 1.2 OpenAI GPT Image API

- 新工作流推荐 `gpt-image-2`；
- Image API 提供 generations 和 edits；
- Responses API 更适合多轮编辑和带上下文的图像工作流；
- 支持一张或多张参考图；
- 支持 mask，但 mask 是语义引导而不是严格像素边界；
- `gpt-image-2` 对输入图自动使用高保真处理，不能设置 `input_fidelity`；
- 支持精确设置尺寸、质量、输出格式和压缩；
- 当前 `gpt-image-2` API 不支持透明背景。

### 二、ChatGPT Images 提示词规则


#### 2.1 推荐结构

```text
【任务】
任务类型：{生成 / 编辑 / 扩图 / 局部重绘 / 风格转换}
目标：{本轮要完成什么}
只改变：{允许变化的内容}

【保持】
保持不变：{身份、结构、姿势、构图、背景和光线}
参考图职责：{每张图负责什么；无参考图则删除}

【画面】
主体与动作：{主体、动作和状态}
场景与风格：{环境、服装、材质和风格}
镜头与光线：{景别、角度、构图、光线与色彩}

【限制】
避免：{当前最可能发生的1–4个问题}
优先级：{冲突时优先保证什么}

【输出】
数量：{数量}
比例：{画幅；API真实像素在参数层设置}
要求：{完整性、留白、文字或版式要求}
用途：{最终用途}
```

#### 2.2 选区编辑

```text
只编辑选中的{区域或对象}。
把它改为{正确目标}。
延续周围的{光线、纹理、透视、遮挡和材质}。
选区外的{人物身份、姿势、背景、构图}保持。
```

> 选区只负责缩小语义范围；仍需说明“选中的是什么、应该改成什么、边界如何衔接”。

#### 2.3 多轮编辑

每轮只保留三类信息：

1. 本轮修改目标；
2. 当前必须保持项；
3. 上一轮仍未解决的问题。

不要在每轮重复粘贴全部历史提示词。若结果开始漂移，回到原始图或最近一次正确版本，不要继续在错误版本上叠加修改。

#### 2.4 图中文字

```text
图片中只出现以下文字：
“{准确文字}”

位置：{区域}
层级：{主标题 / 副标题 / 标签}
字体方向：{无衬线 / 手写 / 书法 / 几何字体}
排版：{一行 / 两行 / 居中 / 左对齐}
不要出现其他文字、乱码或重复字符。
```

即便文字能力提高，仍应逐字校对；长文案、表格、品牌 Logo 和正式海报排版交给设计工具完成。

### 三、OpenAI API 入口选择


| 工作流 | 推荐 API | 说明 |
|---|---|---|
| 单次文生图 | Image API generations | 请求简单、参数明确 |
| 单次编辑 | Image API edits | 可附输入图和 mask |
| 多图参考合成 | Image API edits / Responses API | 明确每张图职责 |
| 多轮连续修改 | Responses API | 图像输入输出与对话状态可组合 |
| 生产批量任务 | Image API | 易固定模型、参数和输出格式 |

### 四、`gpt-image-2` 参数速查

| 参数 | 值或规则 | 使用建议 |
|---|---|---|
| `model` | `gpt-image-2` 或固定快照 | 生产验证后可锁快照 |
| `size` | 任意满足官方约束的像素尺寸 | 使用真实像素；不要用“8K”代替 |
| `quality` | `low / medium / high / auto` | low 做草稿，medium/high 做终稿 |
| `output_format` | `png / jpeg / webp` | PNG 默认；JPEG 更快；WebP 兼顾体积 |
| `output_compression` | 0-100，仅 JPEG/WebP | 按传输和体积需求设置 |
| `background` | `opaque / auto` | 当前不支持 transparent |
| `mask` | 编辑范围引导 | 与提示词同时说明对象与衔接 |
| `input_fidelity` | 对 gpt-image-2 不可设置 | 删除旧模板中的该参数 |
| `moderation` | `auto / low` | 属安全策略参数，不是视觉词 |

#### 4.1 尺寸约束

`gpt-image-2` 的 `size` 需同时满足：

- 最大边不超过 3840px；
- 两边都是 16 的倍数；
- 长边与短边比例不超过 3:1；
- 总像素不少于 655,360，且不超过 8,294,400；
- 超过常规 2K 总像素的结果应视为更需要测试的输出范围。

常用示例：

```text
1024x1024
1024x1536
1536x1024
2048x2048
2048x1152
3840x2160
2160x3840
```

#### 4.2 代码层与提示词层分离

```text
提示词层：描述视觉任务。
参数层：model、size、quality、format、compression、background。
验收层：身份、结构、文字、构图、尺寸和文件格式检查。
```

### 五、五段式任务示例

> [!note] 示例边界
> 以下示例是五段式母版的场景化简写；没有显示的空段视为删除，不构成另一套模板结构。


#### 5.1 文生图

```text
生成一张用于{用途}的图片。

主体：{主体与可观察特征}
动作或状态：{动作、表情、使用状态}
环境：{地点、时间、天气和空间关系}
风格：{摄影、插画、动漫、CG、平面设计等}
镜头：{景别、机位、角度、构图和留白}
光线与色彩：{光向、光质、主色和影调}
材质与细节：{皮肤、发丝、布料、金属、玻璃等}

必须：{2-5项核心要求}
不要：{2-5项当前风险}
输出：{画幅、用途和文字区域}
```

#### 5.2 人物换装

```text
编辑上传的图片，只更换人物服装与指定配饰。

保持人物身份、脸型、五官比例、年龄感、发型轮廓、表情、姿势、头部角度、摄影机位、背景、构图和整体光线。

新服装：
上衣：{款式、颜色、面料、版型}
下装：{款式、颜色、面料、长度}
配饰：{内容；没有则写无}

允许衣领、袖口、腰线、裙摆、发丝交界、布料褶皱、遮挡和阴影随当前姿势自然适配。
不要重新设计面部、改变年龄或身材比例、改变背景、增加文字或水印。
保持原图画幅和主体位置。
```

#### 5.3 商品换景

```text
编辑商品参考图，只更换背景、使用场景和环境光线。

保持商品外形、结构、比例、主配色、材质和包装布局。
目标场景：{场景、台面、道具、时间和光线}
构图：{机位、景别、商品位置和留白}
不要改变商品结构、增加多余标签、遮挡卖点或生成无关文字。
商品文字和 Logo 生成后逐项校对；要求完全准确时保留原商品图层并后期合成。
```

#### 5.4 局部修复

```text
只编辑{具体区域或 mask 区域}。
问题：{当前错误}
正确结果：{修复后的结构、材质和外观}
衔接：延续周围的{光线、纹理、透视、遮挡和边缘}
保持：编辑区外的{主体身份、姿势、背景和构图}
不要：{扩大编辑范围或引入的新错误}
```

#### 5.5 扩图

```text
将图片向{方向}扩展到{目标比例或尺寸}。
原图内部主体、位置、透视、风格、色调、光线和纹理保持。
扩展区域补充：{背景、地面、天空、环境元素或人物补全部分}
延续原图透视、景深、光线方向和空间关系，避免接缝、重复纹理和结构断裂。
```

### 七、限制与误区

- ChatGPT 的透明背景能力不能推导为 `gpt-image-2` API 支持透明背景；
- mask 不是传统图像软件中的严格像素锁定；
- 自动高保真输入不等于人物永远不漂移；
- “4K、8K、杰作”不能替代 `size` 和 `quality`；
- 即使文字能力增强，也不能跳过校对；
- 没有固定 seed 或权重百分比时，不要虚构参数；
- 复杂提示可能增加延迟；多图输入和高质量输出会增加成本。

### 一、官方公开能力基线（2026-08-05）

- 支持中文提示词创作；

### 二、图片生成 / 智能参考提示词规则

> [!note] 片段边界
> 标为“片段”的代码块用于填入五段式母版中的对应段落，不是新的完整模板。



#### 2.1 【画面】段推荐顺序

```text
主体与行为
→ 环境与空间
→ 风格与媒介
→ 色彩与光影
→ 镜头与构图
→ 材质与细节
→ 保持与避免
→ 输出用途
```

#### 2.2 中文为主，术语按需补充

推荐：

```text
半写实动漫，保留真实面部比例，自然皮肤纹理，真实发丝，柔和电影侧光，浅景深。
```

不推荐：

```text
半写实动漫，semi-realistic anime，anime realism，realistic anime，best quality，masterpiece，8K，ultra HD……
```

中文已经明确时，不必为“模型识别”重复堆叠英文同义词。英文术语只在镜头、材质或特定艺术媒介更精准时补充。

#### 2.3 文生图五段式模板

```text
【任务】
任务类型：生成
目标：生成一张用于{用途}的图片
只改变：从零生成，无既有画面

【保持】
保持不变：核心主体必须为{主体定义和关键特征}

【画面】
主体与动作：{主体外观、动作、表情或状态}
场景与风格：{地点、时间、天气、背景、媒介、主色和材质}
镜头与光线：{景别、平视/俯视/仰视、构图、留白、光向与光质}

【限制】
避免：{无关物体、结构错误、无关文字、水印或风格漂移}
优先级：主体与结构 > 指定动作 > 风格与背景

【输出】
数量：{单张 / 组图}
比例：{在界面中选择}
要求：{完整主体、留白或文字区域}
用途：{用途}
```

#### 2.4 单参考图【保持】片段

```text
参考图负责人物或主体的{身份、结构、姿势、构图、风格中的具体职责}。

本轮只改变：{单一变量或变量组}
目标结果：{具体可观察描述}

保持：{身份、脸部、商品结构、姿势、机位、背景、光线等}
允许：{边缘、遮挡、褶皱、阴影和透视的自然适配}
不要：{当前高风险错误}
```

#### 2.5 多图参考【保持】片段

```text
参考图1：只负责{人物脸部身份 / 商品本体}。
参考图2：只负责{姿势和摄影角度}。
参考图3：只负责{服装款式和材质}。
参考图4：只负责{背景场景和光线氛围}。

冲突顺序：
{主参考职责} > {结构} > {本轮目标} > {风格和背景}

不要让参考图2、3、4覆盖参考图1的主体身份。
```

**使用方法**

1. 先用最少参考图验证主体；
2. 每增加一张参考图，只增加一个明确职责；
3. 结果混淆时，先移除最低价值参考；
4. 不写未经当前界面确认的 `100% / 70%` 权重；
5. 是否需要使用“图1、图2”或界面生成的引用标记，以当前输入框真实显示为准。

### 三、人物任务

#### 3.1 身份保持片段

```text
参考图负责人物身份。
保持脸型、五官比例、年龄感、发型轮廓和主要辨识特征。

只改变：{服装 / 姿势 / 表情 / 场景 / 风格}
目标：{具体结果}

人物仍应能被识别为同一人；不要重新设计面部、改变年龄、性别表达或基础体型。
```

#### 3.2 换装任务示例

```text
编辑人物参考图，只更换服装和指定配饰。

人物保持：
身份、脸型、五官比例、年龄感、发型轮廓、表情、姿势和头部角度。

新服装：
上衣：{款式、颜色、面料、版型}
下装：{款式、颜色、面料、长度}
配饰：{内容；没有则写无}

环境保持：
原图背景、摄影机位、构图、色调和光线方向。

自然适配：
衣领、袖口、腰线、裙摆、发丝交界、布料褶皱、遮挡和阴影符合当前姿势。

不要重新设计人物面部、明显改变年龄或身体比例、改变背景、增加文字或水印。
```

#### 3.3 姿势参考片段

```text
参考图1负责人物身份和脸部。
参考图2只负责身体姿势、四肢方向和摄影角度。

生成结果保持参考图1的人物身份；采用参考图2的姿势，但根据人物体型和服装自然适配受力、遮挡和衣物褶皱。
不要复制参考图2的脸、发型或服装。
```

### 四、商品任务

```text
参考图负责商品本体。
保持商品外形、结构、比例、主配色、材质和包装布局。

只改变：背景、使用场景、辅助道具和环境光线。
目标场景：{内容}
构图：{机位、景别、商品位置和留白}

不要改变商品结构、增加多余标签、遮挡核心卖点或生成无关文字。
商品 Logo、包装文案和规格数字生成后逐项校对；要求完全准确时保留原商品图层并后期合成。
```

### 五、图片 4.x 与界面参数使用

- 模型标识使用当前界面可选版本，不在模板中永久写死“4.0最好”或“4.1必然更强”；
- 切换模型后重新测试身份、文字、构图、材质和多图职责；
- 比例、大小、质量、超清等使用界面设置；
- “4K、8K、高清、杰作”只能作为视觉描述，不能替代实际输出选项；
- 若当前入口有独立负面词框，只放与当前任务相关的少量错误；
- 若没有负面框，在正文写“不要”，不要为了兼容旧模型附加长串英文负面词。

### 六、智能画布执行规则


#### 6.1 工具与文字的分工

| 操作 | 画布工具 | 提示词重点 |
|---|---|---|
| 局部重绘 | 框选或蒙版区域 | 正确结果、边缘衔接、区外保持 |
| 删除物体 | 图像消除 / 局部重绘 | 删除后应补出的背景和纹理 |
| 扩图 | 一键扩图 / 调整画布 | 新增区域如何延续透视、光线和空间 |
| 多图融合 | 图层摆放、缩放和遮挡 | 比例、透视、光线、阴影和风格统一 |
| 抠图 | 抠图工具 | 发丝、半透明边缘、轮廓完整度 |

#### 6.2 局部修复指令片段

```text
只重绘选中区域。
当前问题：{断裂、缺失、变形、错误物体等}
正确结果：{修复后的结构、材质和外观}
衔接：延续周围的{光线、纹理、透视、遮挡和边缘}
选区外保持：{人物身份、姿势、背景、构图}
不要扩大编辑范围或新增无关元素。
```

#### 6.3 消除物体指令片段

```text
移除选区内的{物体}。
删除后补全为{墙面、地面、天空、布料、背景环境等}。
延续周围纹理、透视、光线和阴影，避免重复图案、模糊块和明显修补边缘。
选区外不变。
```

#### 6.4 扩图指令片段

```text
向{方向}扩展画面，目标比例为{比例}。
原图主体、位置、透视、风格、色调和光线保持。
扩展区域补充：{具体背景或环境内容}
延续原图前中后景、地平线、景深、光线方向和材质，避免接缝、重复纹理和结构断裂。
```

#### 6.5 多图融合指令片段

```text
把画布中的{主体A、主体B、背景C}融合成一张完整图片。

主体A保持：{身份或商品结构}
主体B负责：{姿势、道具或第二对象}
背景C负责：{场景和光线}

统一：比例、透视、视线高度、光线方向、色温、阴影软硬和清晰度。
修复：边缘、遮挡、接触阴影和图层交界。
不要出现漂浮、比例失衡、光源冲突或明显拼贴边缘。
```

#### 6.6 抠图素材指令片段

```text
提取{主体}，轮廓完整。
保留发丝、薄纱、透明或半透明边缘的自然过渡。
去除背景颜色污染和残留阴影；不要裁切主体，不要把内部孔洞错误填满。
```

### 七、图片生成与智能画布的选择

| 需求 | 使用入口 |
|---|---|
| 从零生成完整画面 | 图片生成 |
| 一张或多张参考图生成新画面 | 智能参考 |
| 只修改具体区域 | 智能画布局部重绘 |

| 拼接多个素材并统一风格 | 智能画布多图融合 |
| 提取独立主体 | 智能画布抠图 |

### 八、常见误区

- 不把视频入口的引用语法直接套到所有图片入口；
- 不把公开作品中的个人提示词视为官方推荐语法；
- 不把某个版本标签永久写成固定最优模型；
- 不用大量英文同义词覆盖清晰中文；
- 不把“4K、8K”当作实际分辨率设置；
- 不用负面词替代局部重绘、消除、扩图和抠图工具；
- 不承诺多参考图可以百分百锁定人物身份；
- 不把生成的 Logo、包装文字和长文案直接当成正式终稿。

#### 2.10.1 四个执行入口总览

| 维度 | ChatGPT Images（聊天界面） | OpenAI GPT Image API | 即梦图片生成 / 智能参考 | 即梦智能画布 |
|---|---|---|---|---|
| **核心交互** | 对话式生成与连续修改 | 程序化单次生成、编辑或多轮工作流 | 表单式生成，选择模型、比例、质量和参考图 | 画布式多图层编辑与区域操作 |
| **当前模型标识** | ChatGPT Images 2.0；付费计划可使用 images with thinking | `gpt-image-2` 为当前推荐默认模型 | 公开作品可见图片 4.0、4.1 等标识；以实际界面为准 | 底层模型随当前画布入口与账号配置变化 |
| **提示词语言** | 中英文自然语言均可；适合任务说明和追问修正 | 任意自然语言文本；生产环境建议固定字段和模板版本 | 官方明确强调中文语义理解；中文可直接作为主提示词 | 区域操作使用简短中文动作指令更合适 |
| **提示词形态** | 可以较完整地说明“目标—保持—改变—约束—输出” | 结构化字符串 + 明确 API 参数 | 主体、行为、场景、风格、光影、构图依次描述 | “对哪里做什么”优先，不宜粘贴过长母版 |
| **参考图** | 可上传现有图片并描述修改；多图时应人工声明职责 | 支持一张或多张输入图；`gpt-image-2` 自动高保真处理输入 | 官方产品入口支持参考图与多图参考；公开作品可见“图一负责场景、图二负责脸”等写法 | 可在画布中放置多元素、多图层并进行融合 |
| **局部编辑** | 可选择区域后描述修改，也可不选区直接编辑；选区并非像素级精确 | 支持 mask；mask 只是引导，可能越过边缘；多图时 mask 作用于第一张输入图 | 公开作品与产品页可见“局部重绘” | 官方明确提供局部重绘、图像消除、抠图等工具 |
| **扩图 / 改画幅** | 支持画幅选择器，也可在提示词中指定比例 | 通过输出 `size` 生成目标尺寸；扩图需使用编辑工作流和合适画布/蒙版 | 画幅与质量选项以当前界面为准 | 官方明确提供一键扩图，适合可视化控制扩展方向 |
| **多轮迭代** | 强项；可以在同一会话逐步修正 | Responses API 适合多轮；Image API 更适合单次生成或编辑 | 可重新生成、用作参考图、做同款；连续语义上下文不应假定与聊天式系统相同 | 通过画布操作逐步修改，空间状态比长对话更重要 |
| **负面词** | 无需传统负面词长串；在自然语言中写关键“不要” | 没有必须使用的传统负面词语法；将限制写入 prompt | 独立负面框是否存在随模型和入口变化；正文先写自然语言限制 | 对删除、消除类任务优先使用区域工具，不靠负面词 |
| **文字生成** | 可在图中加入文字，但复杂文案仍需校对 | 文本表现已增强，但官方仍提示精确位置和清晰度可能失败 | 公开作品可见中英文文字和字体设计，但不能视为文字终稿 | 适合修正局部视觉，不替代专业排版工具 |
| **输出尺寸** | 可选择任意画幅；界面不等同于 API 精确像素参数 | 可传任意满足约束的尺寸：边长不超过 3840、均为 16 的倍数、长宽比不超过 3:1、总像素在规定区间 | 选择比例、大小、质量等界面选项；公开资料未给出稳定的全量像素约束 | 受画布尺寸、导出设置和当前功能入口影响 |

| **透明背景** | 官方帮助页明确支持请求透明背景 | 当前 `gpt-image-2` API 不支持 `background: transparent` | 不把“透明背景”仅写进提示词；优先使用抠图或后期 | 官方提供抠图，更适合获得独立主体素材 |
| **自动化能力** | 适合人工创作与对话修改 | 强项；可记录模型、参数、请求 ID、成本和结果 | 面向消费级创作界面；本次公开资料未确认通用图片生成 API | 以人工画布操作为主 |
| **最适合** | 复杂需求澄清、自然语言编辑、连续迭代、文字与结构较多的视觉 | 批量生产、固定尺寸、格式和质量、系统集成、可追踪实验 | 中文创意生成、人物/主体参考、风格与场景尝试、系列组图 | 多元素合成、局部修复、扩图、消除、抠图和可视化编辑 |

#### 2.10.2 ChatGPT Images：对话式执行规则

> [!note] 表达示例边界
> 本页的短指令是五段式母版在具体界面中的压缩表达；语义仍需覆盖任务、保持、画面、限制和输出。


**五段式平台简写**

```text
请编辑这张图，只修改{目标区域或对象}。

保持：{身份、结构、姿势、构图、背景、光线中的关键项}。
改为：{目标结果的具体可观察描述}。
允许：{边缘、遮挡、阴影和材质的必要自然适配}。
不要：{最可能出现的 2-5 个错误}。
输出：{画幅、用途和留白要求}。
```

**界面操作优先级**

1. 能用选区明确区域时，先选区，再写简短编辑指令；
2. 选区只是引导，仍要在文字中说明对象和边界；
3. 需要改画幅时优先使用画幅选择器，同时说明新增区域应该延续什么；
4. 多轮编辑每轮保留一份“当前必须保持项”，避免会话越长要求越模糊；
5. 复杂任务先让模型总结它识别到的主体、姿势和背景，再提交修改要求。

**不要照搬 API 参数**

ChatGPT 聊天界面不需要写 `quality=high`、`output_format=png`、`input_fidelity=high` 等参数式文本。它们不会等同于 API 参数；界面能设置的内容使用界面，不能设置的内容用自然语言表达意图。

#### 2.10.3 OpenAI GPT Image API：参数化执行规则

**Image API 与 Responses API 的选择**

| 需求 | 推荐入口 |
|---|---|
| 单次文生图 | Image API generations |
| 单次图像编辑 | Image API edits |
| 一张或多张参考图生成新图 | Image API edits 或 Responses API |
| 需要多轮连续编辑 | Responses API |
| 需要把图片输入、工具调用和对话状态放在同一流程 | Responses API |
| 需要固定模型、尺寸、格式和质量进行批量生产 | Image API |

**`gpt-image-2` 当前关键参数**

| 参数 | 当前规则 | 模板写法 |
|---|---|---|
| `model` | 新工作流推荐 `gpt-image-2` | 固定记录模型别名或快照 |
| `size` | 支持满足约束的任意尺寸；高于常规 2K 的输出更应实测 | 用真实像素，不写“8K”代替参数 |
| `quality` | `low / medium / high / auto` | 草稿用 low，终稿再升 medium/high |
| `output_format` | PNG、JPEG、WebP | 透明需求不能由当前 gpt-image-2 API满足；按用途选格式 |
| `output_compression` | JPEG/WebP 可设 0-100 | 仅在体积和传输重要时调整 |
| `background` | `opaque / auto`；当前模型不支持 transparent | 不提交无效透明参数 |
| `mask` | 编辑区域引导，不保证像素级严格边界 | prompt 仍需描述修改对象和周围衔接 |
| `input_fidelity` | `gpt-image-2` 自动高保真，不能手动切换 | 从模板中删除该参数占位 |
| `moderation` | API 支持 `auto / low` | 属应用策略参数，不写入视觉提示词 |

**生产模板建议分成两层**

```text
视觉 prompt：任务、保留项、变化项、画面设计、限制。
API 参数：模型、尺寸、质量、格式、压缩、背景、数量等。
```

不要把这两层混成一段提示词。例如，“3840×2160、JPEG、quality high”应由代码参数提交，而不是依赖模型从自然语言推断。

**API 特有风险**

- 多输入图会增加输入图像 token 与成本；
- `gpt-image-2` 自动高保真处理全部图片输入，不能通过降低 `input_fidelity` 节省；
- mask 只作用于多输入图中的第一张图；
- 高分辨率、高质量和复杂提示会提高延迟与成本；
- 结构化海报、连续人物和品牌元素仍应建立自动或人工验收。

#### 2.10.4 即梦图片生成 / 智能参考：中文生成规则

**官方公开能力可以确认的部分**

- 支持中文提示词；
- 支持文字或图片生成图片；
- 支持对现有图片进行创意改造；
- 可表达保留人物或主体特征、背景替换、风格联想、画风保持和姿势保持；
- 当前产品入口展示多图参考和系列组图能力；
- 公开作品可见“智能参考”“局部重绘”以及图片 4.0、4.1 等模型标识。

**【画面】段推荐顺序**

```text
主体与动作 → 环境与空间 → 风格与色彩 → 光影与材质 → 镜头与构图 → 保持/不要 → 输出用途
```

**【保持】段多图参考写法**

```text
参考图1：只负责人物脸部身份和发型轮廓。
参考图2：只负责身体姿势和摄影角度。
参考图3：只负责服装款式与材质。
参考图4：只负责背景场景和光线氛围。

冲突时：人物身份以参考图1为准，姿势不得覆盖脸部身份。
```

不建议写未经界面确认的固定权重百分比，也不应把视频入口中可能出现的 `@图片1` 等引用方式直接视为所有图片生成入口的固定语法。先观察当前输入框如何标记参考图，再采用界面真实标识。

**界面参数规则**

- 比例、质量、大小、超清等优先使用界面选项；
- “4K、8K、最佳质量”只能表达视觉期待，不能替代真实输出设置；
- 若当前入口显示独立负面词框，可把少量排除项移入；若没有，就保留在正文；
- 模型版本切换后应重新测试人物一致性、文字、构图和参考图跟随度。

#### 2.10.5 即梦智能画布：区域编辑规则

智能画布更接近“AI 图像编辑工作台”，而不是单纯的提示词输入框。官方产品页明确展示多图 AI 融合、多图层编辑、局部重绘、一键扩图、图像消除和抠图。

**操作与提示词分工**

| 任务 | 工具负责 | 文字负责 |
|---|---|---|
| 局部修复 | 选定编辑区域 | 描述修复后的正确结构与材质 |
| 删除物体 | 消除工具或局部重绘 | 描述删除后应补出的背景 |
| 扩图 | 指定扩展方向和画布 | 描述透视、光线、纹理如何延续 |
| 多图合成 | 图层位置、缩放、遮挡 | 描述统一光线、比例、透视和风格 |
| 独立主体 | 抠图 | 描述边缘、发丝、透明材质的处理目标 |

**画布指令应更短**

```text
只重绘蒙版区域：把断裂的黑色裙摆补全为自然垂落的布料，
褶皱符合当前坐姿，延续原图暖色侧光和布料高光；
蒙版外人物脸部、姿势、背景和构图不变。
```

不要在一次局部重绘中同时粘贴完整的七类场景说明、平台历史和大段负面词。画布已经通过空间选择提供了部分控制，提示词只需补充目标、衔接和保持项。

#### 2.10.6 同一五段式任务的跨平台表达示例

**任务：只更换人物服装，保持人物和场景**

ChatGPT Images：

```text
编辑这张图，只更换人物服装。保持人物身份、脸部、发型、表情、姿势、摄影角度、背景和整体光线。新服装为{描述}。衣领、袖口、腰线、布料褶皱和阴影允许随姿势自然适配。不要改变人物年龄、脸型、身材比例或背景。
```

OpenAI API：

```text
prompt = 与 ChatGPT 版本相同的视觉任务说明
mask = 服装区域（如有）
size = 真实目标像素
quality = 草稿 low；终稿 medium/high
output_format = png/jpeg/webp
```

即梦智能参考：

```text
参考图负责人物身份、姿势、背景和原始光线。只更换服装为{描述}；人物脸部、发型、表情、姿势、机位和背景保持。布料褶皱与当前坐姿一致，不增加无关配饰和文字。
```

即梦智能画布：

```text
先框选服装区域，再输入：
只重绘选区，将服装改为{描述}。延续原图光线、遮挡和人体姿势；选区外不变。
```

#### 2.10.7 平台选择决策表

| 需求 | 优先选择 | 原因 |
|---|---|---|
| 用自然语言不断讨论、改稿 | ChatGPT Images | 对话和连续编辑更直接 |
| 精确控制像素、格式、压缩和质量 | OpenAI API | 参数可记录、可复现、可批量 |
| 大量中文创意探索和风格尝试 | 即梦图片生成 | 中文创作入口和社区同款工作流方便 |
| 多图素材摆放、融合与局部修复 | 即梦智能画布 | 空间图层与区域工具比纯提示词更合适 |
| 精确 Logo、长文案、表格和最终排版 | 专业设计工具 + AI 素材 | 所有平台都不应直接视为准确排版终稿 |
| 连续角色或系列商品资产 | 任一平台 + 统一参考资产 + 分阶段验收 | 平台本身不能替代资产管理和一致性验收 |

#### 2.10.8 迁移模板时只改四处

从一个平台迁移到另一个平台，不重写整套视觉提示词，只调整：

1. **输入方式**：对话、表单、API 或画布；
2. **参考图标识**：自然语言职责、文件数组或界面引用；
3. **控制参数**：画幅、尺寸、质量、格式、蒙版、透明背景；
4. **编辑策略**：整图自然语言、局部选区、API mask 或画布区域。

主体、场景、风格、镜头、光线、材质和核心保持项应继续复用五段式母版。
