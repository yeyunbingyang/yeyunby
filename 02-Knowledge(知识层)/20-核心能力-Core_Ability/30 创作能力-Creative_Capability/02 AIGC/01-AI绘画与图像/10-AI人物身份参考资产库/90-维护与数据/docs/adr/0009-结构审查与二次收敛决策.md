# 结构审查与二次收敛决策

## 决策结论

本项目继续作为 `01-AI绘画与图像/` 下的独立生产型项目单元。项目一级目录按七类交付职责组织：操作规范、提示词、实验记录、图片与视频资产、JSON 数据、版本与失败记录、最终交付物；导航和归档作为支撑目录。角色编号只在实验、媒体、失败和交付物内部使用，不作为全库一级目录。

不采用共享对话提出的“人物档案、面部特征、身体比例、发型、服装、姿态等13个横向目录”方案。该方案按资产属性拆散角色；本项目改按职责分区，再在媒体和实验区按角色聚合。

## 现状证据

- 目标库共 293 个文件，其中 50 篇 Markdown、239 个媒体附件，约 454 MB。
- 当前已有唯一 MOC、执行手册、跨图像与视频一致性控制、附录 A-D、`90-维护与数据`、`99-历史归档` 和 `attachments`。
- 当前扫描未发现完全重复哈希文件。
- 工作区存在本轮之前的未提交迁移痕迹；执行迁移前必须保留现状基线，不得覆盖或重置。

## 自问自答审查记录

### 1. 是否重构整个知识库？

否。本轮范围限定为本项目；“丝袜商品效果图”和“古风角色图像与视频生成”继续作为同级独立项目。

### 2. 本项目属于知识、资源还是项目？

它是知识领域下的生产型项目单元，因为同时包含方法、规范、实验、媒体、JSON 数据和交付物。

### 3. 是否采用13个横向资产目录？

否。正文按职责组织，媒体按角色或研究对象聚合；面部、身体、服装和姿态是生产阶段或变量，不是全库一级目录。

### 4. 是否为每个生产阶段建立物理目录？

暂不建立。阶段由执行手册表达；只有阶段形成稳定且大量的独立笔记时才拆分。

### 5. MOC 应有几个？

当前只保留一个项目 MOC。正式角色达到约5个，或人工链接超过10条并形成稳定子主题后，再考虑子 MOC。

### 6. 核心正文如何划分？

保留执行手册、一致性控制、附录A提示词、附录B验收修复、附录C风格研究、附录D正式案例六篇权威正文，不创建平行总指南或重复提示词库。

### 7. 角色资产如何组织？

继续以角色为中心：过程媒体在 `04-图片与视频资产/角色-001/` 下按阶段组织，失败和最终资产分别进入 `06` 与 `07` 的角色目录。

### 8. 是否立即改用 `CHAR-001`？

否。当前链接和 JSON 路径大量使用“角色-001”，先保持兼容；未来新角色继续使用“角色-002”序列，除非未来有跨工具交换需求再整体迁移。

### 9. 是否立即创建角色身份档案目录？

否。当前只有一个正式角色；启动第二个正式角色时再统一引入角色档案模板。

### 10. 提示词按角色保存还是统一保存？

通用模板统一放附录A，角色参数放正式案例，单次完整 Prompt 由 `experiments.json` 保存，旧模板归档。

### 11. 失败资产是否删除？

不删除，隔离在角色的 `99-失败与标注` 中；只有确认完全重复且无引用时才考虑删除。

### 12. 是否把 `attachments` 改成中文目录名？

否。该路径已被 Wikilink、嵌入和 JSON 使用，继续作为历史兼容例外。

### 13. `90-维护与数据` 是否进入普通阅读路径？

否。它只保存 CONTEXT、ADR、JSON 和验证说明；普通阅读从 MOC 和执行手册开始。

### 14. 历史归档保留什么？

保留被当前权威正文取代、但仍有复盘价值的旧流程、旧提示词、失败版本和实验；统一标记 `status: 归档`，不参与默认导航。

### 15. 游离目录如何处理？

`古风玄幻写实/` 和 `角色设定规范页/` 先逐篇判定：通用模板并入附录A，风格结论并入附录C，规范并入执行手册或附录B，具体案例并入附录D；对应媒体归入角色或研究对象目录。合并并修复引用后，原目录才可归档。

### 16. 是否迁出作品研究？

暂不迁出。作品研究与原创生成保持双层呈现，`works.json`、`sources.json`、`styles.json` 和 `experiments.json` 继续作为结构化事实源；未来扩展为跨项目风格数据库时再独立化。

## 执行前置条件

## 失败分析规范

`06-版本与失败记录/` 不只是图片堆放区。每条失败记录必须说明：目标阶段、输入资产、使用工具和提示词版本、可观察失败现象、失败原因假设、验证证据、单变量解决方案、修复结果、是否准入下游，以及最终回退点。失败图片与分析笔记使用同一实验 ID 关联；解决方案验证通过后，通用规则回写 `01-操作规范/` 或 `02-提示词/`，角色特有结论留在角色实验记录中。

## 验收门禁

- 当前阅读入口唯一且 MOC 链接完整。
- 原有 Markdown、JSON、媒体和失败版本没有无依据减少。
- Wikilink、媒体嵌入和 JSON 本地路径无断联。
- 历史笔记具有归档状态和替代关系。
- 权威正文没有重复维护同一长内容。
- Frontmatter 的 `domain` 和 `status` 合法。
- 迁移前后媒体哈希一致。
