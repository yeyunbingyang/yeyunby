# 02-笔记序号与关系标识

> [!info] 笔记关系
> **导航 · 新增（2026-08-06）**

## 一、序号表示什么

序号只表示**同一目录中的推荐阅读或使用顺序**，不表示重要程度，也不代表文件版本。

```text
00  模块入口或 MOC
01  最常用的起点
02–89  按使用顺序排列的活动笔记
90  附件、索引或维护数据
99  历史归档
```

## 二、关系标识表示什么

| 标识 | 含义 | 使用方式 |
|---|---|---|
| **常用** | 高频入口或基础概念 | 日常优先阅读和调用 |
| **按需** | 排错、研究、维护或专项内容 | 遇到对应问题时进入 |
| **导航** | MOC、入口或说明页 | 用于定位，不承担完整知识正文 |
| **新增（日期）** | 最近加入的知识或结构 | 日期说明加入时间，不永久把“新增”写入文件名 |
| **本轮增强（日期）** | 既有笔记近期补充了配图、结构或内容 | 保留原知识身份，同时标记近期变化 |

## 三、为什么不把“常用、最新”写进文件名

- “常用”可能因工作重点变化而调整；
- “新增”会随时间失效；
- 文件名频繁变化会造成链接迁移和历史引用失效。

因此文件名只保留稳定序号，关系写入 YAML、页首提示和 MOC 表格。

## 四、统一 YAML 字段

```yaml
order: 1
usage: common
usage_cn: 常用
change: new
change_cn: 新增
introduced_in: 2026-08-06
```

固定值：

```text
usage: common / on_demand / navigation
change: existing / new / enhanced
```

## 五、维护规则

1. 同一目录新增笔记时，优先插入空余序号，不整体重排大量文件。
2. “新增”必须带日期；旧笔记不需要补写“既有”提示。
3. 内容升级但主题未变时使用“本轮增强”，不要伪装成新笔记。
4. `99-归档` 中的历史文件不强制补序号。
5. 项目过程资产以阶段和版本为主，不机械套用阅读序号。
