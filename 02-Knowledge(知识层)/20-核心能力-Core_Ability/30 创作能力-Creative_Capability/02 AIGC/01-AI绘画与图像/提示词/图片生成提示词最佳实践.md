# 图片生成提示词最佳实践

> [!abstract] 核心结论
> 稳定出图靠的不是堆形容词，而是把"描述"升级为"任务协议"。五个杠杆：**一次只做一个目标、参考图声明优先级、冻结不可变项、负面词分类、量化验收**。信息很多但缺少机器执行层结构，是高级用户最常见的瓶颈。

> [!warning] 适用范围
> 本文整理通用的图像生成提示词方法论，综合人物身份、三视图、商品效果与漫剧角色等多次实测复盘。模型能力随版本变化，具体参数需在项目中复测；框架本身跨项目复用。

## 1. 提示词是任务协议，不是文案

普通写法（模型只能随机发挥）：

```text
生成一个漂亮女孩，穿黑色裙子，很高级，真实摄影
```

- 什么叫"漂亮"？"高级"指什么？摄影参数是什么？优先级？哪些不能改变？——模型不知道。

协议写法（模型知道怎么执行、怎么取舍）：

```text
【角色】成年女性时装模特
【目标】生成高级商业摄影视觉资产
【优先级】1.身份一致 2.结构正确 3.材质表现 4.摄影质感
【禁止】改变脸型、改变年龄、错误人体结构
【验收】五官稳定、双腿正确、材质明显
```

区别：前者是"描述"，后者是"验收标准 + 取舍规则"。

## 2. 常见问题清单（按影响排序）

| 排名 | 问题 | 影响 | 典型表现 |
|---|---|---|---|
| 1 | **一次要求太多目标** | ★★★★★ | 三视图同时锁脸+服装+背景+商业感，模型自动丢弃低优先级项（通常是身份） |
| 2 | **参考图没有优先级** | ★★★★★ | 叠加 A/B/C/D 多张参考，模型不知道谁说了算 |
| 3 | **没有阶段拆分** | ★★★★★ | 直接生成"最终成品"，失败后只能整张重来 |
| 4 | **描述词多于结构词** | ★★★★ | "绝美、清冷、高级"——对模型是低精度信息，应换成眼型、眉形、表情强度 |
| 5 | **缺少冻结区域** | ★★★★ | 换服装时连五官也一起漂移，因为没说清"哪些永久不变" |
| 6 | **负面词未分类** | ★★★ | 结构、身份、渲染、版式问题混在一个列表，难以定位 |
| 7 | **缺少 QA 机制** | ★★★ | 凭"感觉不好"判断，没有可复用的评分与重生成规则 |
| 8 | **资产未完全模块化** | ★★★ | 想直接要 E001–E200，而不是先建模特库→场景库→姿势库→材质库再组合 |
| 9 | **过度追求完整输出** | ★★★ | 跳过中间资产（身份证→身体模板→服装→动作），一步到位 |
| 10 | **缺少提示词单元测试** | ★★★ | 直接跑最终版；应先单独测脸、测身体、测融合 |

## 3. 任务协议模板（提示词骨架）

```text
【任务】
基于{输入}生成{目标产物}。

【优先级】
P0 {最高优先级，例如身份一致}
P1 {第二优先级，例如人体比例}
P2 {服装材质}
P3 {背景与环境}

【参考】
R1 {身份参考}——只负责{脸/五官}，权重最高
R2 {身体参考}——只负责{比例/体型}
R3 {服装参考}——只负责{款式/材质}

【必须保持】
列不可变项（冻结区域）。

【本轮只改变】
只改变{一个变量}，其余沿用参考。

【禁止】
负面约束（按下面第 5 节分类）。

【验收】
可量化检查项；不满足则{重生成/修复}。
```

关键：**重要内容放顶部**。模型注意力有限，头部几行决定取舍；发饰、纹理、光影等细节放后面，防止覆盖核心要求。

## 4. 参考图优先级体系

不要只说"参考"，必须声明"谁控制什么"。推荐分级：

```text
R1 身份参考（脸、五官）          权重 100%
R2 肤色 / 肤质                    权重  90%
R3 身体比例 / 体型                权重  70%
R4 服装款式 / 材质                权重  50%
R5 姿势 / 场景 / 氛围             权重  30%
```

- 参考图不是越多越好：低质量、冲突光照、不同年龄的图会提供矛盾证据。
- 首轮用"最小充分参考集"；只有失败明确归因于某角度或细节缺失时，才补充对应参考。

## 5. 负面提示词分类

把负面词按职责分组，便于定位失败原因，也避免互相污染：

| 分类 | 内容 | 定位用途 |
|---|---|---|
| **结构负面** | 多指、错关节、多腿、肢体扭曲 | 解剖结构崩坏 |
| **身份负面** | 换人、换脸、年龄变化、眼型变化 | 身份漂移 |
| **渲染负面** | 模糊、低清、塑料肤、劣质光 | 画质问题 |
| **版式负面** | 裁头、错误角度、缺视图 | 布局/多视图问题 |

## 6. 量化验收（QA 评分）

把"感觉不好"换成可执行评分，低于阈值即重生成：

| 项目 | 0–10 | 低于 8 分处理 |
|---|---|---|
| 身份一致性 | | 回到母版，减少/替换参考图 |
| 人体结构 | | 修复或重生成 |
| 服装材质 | | 调整材质参考 |
| 构图 | | 改版式 |
| 商业/成品感 | | 调整光影与场景 |

> 关联：更细的评分锚点与单变量回退见 [[AI人物跨图像与视频一致性控制]] 与 [[验收与失败修复规范]]。

## 7. 阶段拆分（工业流程）

错误：一步生成最终角色（目标互相竞争，失败难定位）。

正确：拆成独立阶段，每阶段验收后进入下一阶段：

```text
阶段1 锁身份（脸、五官）
阶段2 锁身体（比例、体型）
阶段3 服装与发型设计
阶段4 三视图 / 多角度
阶段5 商业渲染（光影、场景、氛围）
```

同理适用于商品效果：先建 **模特库 → 场景库 → 姿势库 → 材质库**，再组合出 E001–E200，而不是直接批量生成最终效果图。

## 8. 冻结区域（Frozen Features）

人物一致性最大的漂移来源，是没有声明"哪些永久不变"。

```text
永久冻结（Never change）:
- 眼型、鼻梁、下颌线
- 肤色
- 发际线 / 发型轮廓

允许变化（Allowed change）:
- 服装、姿势、背景、光线
```

换装、换姿势前先确认冻结区没被动摇；连续多轮编辑出现累积漂移时，回到最近一次通过的版本，而不是继续补提示词。

## 9. 从 Prompt 升级到 Agent 的路径

你的瓶颈不是"不会写提示词"，而是"在做一个生产系统，却用单次 Prompt 控制"。

```text
Prompt → 结构化 Prompt → Prompt 模板 → Skill → Agent → 自动生产流水线
```

- 每类重复任务沉淀为 Skill：身份锁定、角色资产、商品视觉、提示词优化、质检。
- 失败时记录**症状 → 根因 → 解决方案 → 复验**，形成回归用例，而不是每次重新 debug。
- 相同失败连续三轮无改善时，不继续堆叠提示词，改为降低任务难度、替换冲突参考或切换控制机制。
