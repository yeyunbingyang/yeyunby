# 短剧与漫剧调研操作工作流

> [!abstract] 一句话流程
> 从 [[短剧资源目录-每日同步]] 找片，在红果免费短剧核对或收藏，下载后登记到 [[本地短剧目录]]，再抽取关键帧、拆解前三集，最终沉淀为单部调研笔记和横向对比结论。

## 一、目标与适用范围

本工作流用于完成以下任务：

- 从金山文档全量目录查找短剧及网盘入口。
- 从红果免费短剧的收藏目录、剧场或漫剧入口确认候选作品。
- 管理“在线可获取”“已收藏”“已下载”“已抽帧”“已拆解”等状态。
- 对封面、题材、剧情结构、评论反馈和商业节点进行证据化调研。
- 将本地视频抽帧并写成可复用的 Obsidian 笔记。

不用于自动点赞、评论、关注、分享、充值或购买。涉及登录、支付、授权、外部提交或验证码时，应停止并由用户确认。

## 二、信息架构

| 数据层 | 唯一入口 | 维护内容 | 是否允许自动覆盖 |
| --- | --- | --- | :---: |
| 在线来源层 | [[短剧资源目录-每日同步]] | 日期、来源行、当日序号、作品信息、夸克和百度入口 | 是 |
| 人工决策层 | [[本地短剧目录]] | 收藏、本地状态、路径、调研进度和备注 | 否 |
| 视频证据层 | 本地短剧文件夹 | 原视频、关键帧、封面、字幕和元数据 | 仅新增 |
| 研究结论层 | 单部调研笔记、横向对比笔记 | 剧情结构、评论、商业节点和结论 | 否 |

> [!warning] 编号规则
> 来源表中的短剧序号会按日期重新编号，不能作为全局唯一编号。定位作品时使用“来源行 + 更新日期 + 当日序号 + 作品名”。

## 三、完整操作流程

### 阶段 0：明确本轮调研任务

| 项目 | 必填内容 |
| --- | --- |
| 调研入口 | 红果收藏、红果剧场、漫剧频道或全量资源目录 |
| 样本范围 | 明确作品名或明确前 N 部的排序口径 |
| 观看范围 | 默认前三集；需要扩展时单独说明 |
| 证据范围 | 封面、详情、评论、关键剧情、广告或解锁节点 |
| 输出位置 | 默认当前工作流目录下的调研笔记及附件目录 |
| 数据日期 | 所有热度、评论、排序均标明采集日期 |

完成标准：能够用一句话说明“从哪里选、选哪些、看几集、采集什么、写到哪里”。

### 阶段 1：在全量目录检索候选作品

1. 打开 [[短剧资源目录-每日同步]]。
2. 根据更新时间进入对应的月度目录。
3. 搜索完整作品名；没有结果时依次尝试：
   - 删除“第一季”“第二季”等季数。
   - 删除括号中的集数、清晰度和演员名。
   - 使用标题中连续四个以上的关键字。
4. 记录来源行、更新日期、当日序号、作品信息及网盘入口。
5. 同名作品出现多次时，优先核对集数、演员、清晰度和更新时间，不直接合并。

完成标准：候选作品拥有可追溯的来源记录；找不到时明确写“全量目录未检索到”，不得猜测链接。

### 阶段 2：在红果免费短剧核对和收藏

优先顺序：

1. 先进入“我的 → 收藏”，从用户已收藏作品中选样。
2. 收藏中没有目标时，再通过搜索、剧场或漫剧频道核对。
3. 目录采集顺序固定为从上到下、从左到右。
4. 先采集整个收藏目录或目标列表的连续截图，证明选样范围和顺序。
5. 再进入单部作品采集详情和内容。

每部至少核对：

- 作品名及封面。
- 热度、标签、榜单位置等页面可见数据。
- 简介、总集数、单集时长、账号或制作方。
- 评论区是否可访问。
- 分享入口是否提供链接、海报或浏览器 H5。

> [!note] 收藏操作
> 未经用户明确指示，不新增或取消收藏。知识库中的“收藏=是”代表用户选择，不等同于平台收藏按钮当前状态。

### 阶段 3：选择高质量采集路径

| 路径 | 适用场景 | 优点 | 局限 |
| --- | --- | --- | --- |
| App 直接截图 | 目录顺序、热度、评论和商业节点 | 页面证据最完整 | 投屏画质可能偏低 |
| 分享链接 → 浏览器 H5 | 详情页、封面、标题和可见介绍 | 通常比投屏截图清晰 | 可能强制跳 App 或缺少评论 |
| 分享海报 → 微信文件传输助手 | 获取清晰封面或宣传海报 | 清晰度较稳定 | 通常不包含完整详情和评论 |
| 网盘下载 → 本地抽帧 | 剧情画面和前三集结构 | 原画质、可重复抽帧 | 需要先下载，且动态评论无法获取 |

推荐组合：

1. App 负责目录、详情、评论和商业节点。
2. H5 或分享海报负责高清封面。
3. 网盘文件负责剧情抽帧和结构拆解。

完成标准：每种证据使用最清晰且可追溯的入口，不用低清投屏图替代可获取的原始画面。

### 阶段 4：下载与本地归档

下载前：

- 核对作品名、集数和链接是否与来源目录一致。
- 优先测试夸克入口；不可用时再测试百度入口。
- 不进行充值、扩容、绕过限制或对外转存。

建议本地目录：

```text
本地短剧根目录/
└─ 作品名/
   ├─ 原视频/
   │  ├─ 第01集.mp4
   │  ├─ 第02集.mp4
   │  └─ 第03集.mp4
   ├─ 截图/
   ├─ 字幕/
   └─ 来源说明.md
```

文件到达本地后，立即更新 [[本地短剧目录]]：

| 字段 | 填写要求 |
| --- | --- |
| 来源编号 | 填“来源行”，不是每日序号 |
| 作品名 | 与来源表一致 |
| 收藏 | 是 / 否 |
| 本地状态 | 完整 / 部分集数 / 待下载 / 路径失效 |
| 集数/文件数 | 填实际检测数量 |
| 本地路径 | 使用完整绝对路径 |
| 调研状态 | 未开始 / 抽帧中 / 已抽帧 / 已拆解 |
| 最后核验 | 实际核验日期 |

完成标准：本地文件夹、知识库目录和来源记录三者可以相互定位。

### 阶段 5：抽帧与截图

默认优先拆解前三集。每集至少采集：

1. 开场钩子。
2. 主角首次清晰出场。
3. 本集核心冲突。
4. 爽点、反转或情绪峰值。
5. 集尾悬念。
6. 广告、解锁、付费或跳转提示。

抽帧原则：

- 优先保留字幕完整、人物表情清晰、动作处于有效瞬间的画面。
- 同一场景连续截图只保留最有分析价值的一张。
- 不用片头、黑场、模糊转场或重复构图充数。
- 前三集没有商业节点时记录“样本范围内未发现”，不推断后续不存在。
- 涉及关键反转的图片统一放入折叠式剧透区。

截图命名：

```text
序号-作品名-页面类型-编号.png
```

页面类型建议统一为：

- 目录
- 封面
- 详情
- 评论
- 第01集-开场
- 第01集-冲突
- 第01集-集尾
- 广告
- 解锁

### 阶段 6：评论与商业节点采集

评论优先保留三类代表性反馈：

| 类型 | 判断标准 |
| --- | --- |
| 高赞正面 | 明确说明人物、画面、节奏或爽点为何有效 |
| 代表性负面 | 指出剧情、配音、画风、节奏或逻辑问题 |
| 剧情讨论 | 对反转、人物关系或后续走向有具体讨论 |

记录评论时必须包含采集日期。无法进入评论区、评论为空或只能看到部分评论时，直接记录限制。

商业节点需要区分：

- 平台广告。
- 单集解锁。
- 会员或付费提示。
- 跳转到其他页面或 App。
- 网盘会员、容量或保存限制。

### 阶段 7：前三集结构拆解

每部使用同一张结构表：

| 集数 | 开场钩子 | 主角目标 | 核心冲突 | 爽点/反转 | 集尾悬念 | 节奏判断 |
| --- | --- | --- | --- | --- | --- | --- |
| 第 1 集 |  |  |  |  |  |  |
| 第 2 集 |  |  |  |  |  |  |
| 第 3 集 |  |  |  |  |  |  |

分析时区分“画面证据”和“研究者判断”：

- 画面证据：截图中直接可见的动作、台词、页面信息。
- 研究者判断：根据证据归纳出的钩子类型、冲突强度和节奏规律。

### 阶段 8：编写单部调研笔记

建议文件名：

```text
短剧调研-作品名.md
```

推荐正文顺序：

1. 来源与采集日期。
2. 基础信息。
3. 封面和标题策略。
4. 前三集结构表。
5. 评论反馈。
6. 商业节点。
7. 可复用制作规律。
8. 局限性。
9. 剧透折叠区。

剧透区格式：

```markdown
> [!warning]- 剧透截图与剧情说明
> ![[01-作品名-第01集-集尾-01.png]]
> 剧情说明……
```

### 阶段 9：形成横向对比

样本达到 5 部以上时增加横向表：

| 作品 | 题材 | 标题公式 | 封面策略 | 首集钩子 | 三集主冲突 | 高频评论 | 商业节点 |
| --- | --- | --- | --- | --- | --- | --- | --- |

结论必须满足：

- 至少由 3 部样本共同支持，才能称为“样本规律”。
- 只在 1 部出现的现象标为“个案观察”。
- 热度、榜单位置和评论数量只代表采集日。
- 不根据缺失页面或不可访问内容作反向推断。

- [ ] 评论区三类反馈或明确不可访问
- [ ] 分享链接、H5 或海报测试结果
- [ ] 广告、解锁或付费节点

### 视频采集

- [ ] 核对本地文件数量和路径

- [ ] Frontmatter 日期和来源正确
- [ ] 图片使用 Obsidian 嵌入语法
- [ ] 剧透内容已折叠
- [ ] 动态数据标明采集日期
- [ ] 内部链接有效

## 五、异常处理

| 异常 | 处理方式 |
| --- | --- |
| 网页只返回部分目录 | 导出完整 Excel，不把网页截断内容当作全量 |
| 同名作品多条 | 用日期、集数、演员、清晰度和链接共同核对 |
| 夸克链接受限 | 记录限制并测试百度入口，不充值或绕过限制 |
| H5 强制跳 App | 保留 App 证据，改用分享海报获取高清封面 |
| 投屏截图模糊 | 使用海报、H5 或本地视频原画抽帧替代 |
| 评论区不可访问 | 标记“无法访问”，不生成虚构评论 |
| 本地只有部分集数 | 标记“部分集数”，仅分析实际样本 |
| 来源链接失效 | 保留原记录并标记核验日期，不直接删除 |

## 六、每日维护规则

- 每日 09:00 检查完整源工作簿。
- 在线月度目录允许自动新增和修正。
- [[本地短剧目录]] 的收藏、路径、调研状态和备注属于人工字段，自动任务不得覆盖。
- 新下载文件只在能够明确匹配作品时登记。
- 每次同步追加记录；来源不可访问时保持原数据不变。

## 七、完成定义

一次调研只有在以下条件全部满足时才算完成：

1. 来源记录可追溯。
2. 收藏和本地状态已登记。
3. 前三集已拆解，或写明无法观看的具体原因。
4. 封面、详情、评论和商业节点均已检查。
5. 截图与文字一一对应。
6. 结论能够回指到具体样本证据。
7. 笔记已链接回 [[内容创作-MOC]] 和 [[AI漫剧制作全流程]]。
