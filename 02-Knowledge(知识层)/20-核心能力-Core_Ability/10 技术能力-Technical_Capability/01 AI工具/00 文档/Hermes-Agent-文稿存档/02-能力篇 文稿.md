# 能力篇 文稿

## 11. 能力篇_会话管理

大家好，在完成了基本的安装部署及配置之后，模块一入门篇的内容就结束了。接下来我们进入模块二能力篇的课程学习。

能力篇主要包括以下几部分内容：会话管理、工具使用、MCP 服务器使用、上下文记忆和持久记忆功能。

首先来学习第一个——**会话管理**，这是最基础的内容。在使用 Hermes Agent 时，每一次让智能体执行相关任务，都需要让它处于不同的会话当中。

在官方网站中有关于会话的相关介绍。Hermes Agent 每次会将会话对话保存成一个 Session，这个 Session 支持恢复功能。每次的会话不管来自哪里，都会以历史消息的形式存储起来，保存在一个 SQLite 数据库里面。这是比较低量级、轻量级的，直接保存在本地磁盘上的数据库，使用起来比较简洁方便。

在 SQLite 中存储的其实只有一个标题，是人类可读的名称。如果使用 Desktop 桌面应用，会话的标题就在界面上，是 Hermes 自己总结的标题。其他信息以底层编码形式存储在数据库中。

**哪些内容会被纳入上下文？** 每次保存 Session 时，存储的 Session 历史帮助你非常方便地恢复对话，但不会在每次对话时重新发送所有的历史字节。它是保存在数据库里面的，数据库的内容会是它自己总结的。每轮对话时，模型看到的是所选的系统提示词、当前对话的窗口以及 Hermes 为该轮显示注入的内容。

图片、音频、文本文档都会额外添加。例如，如果用户发送了一张图片要求 Hermes 制作成表情包，Hermes 会使用视觉能力检查该图片并运行图像处理脚本。后续轮次不会自动将原始图片带入上下文，只会携带对话内容请求和简短的图片描述，以及本地缓存的路径。上下文增长最长原因不是媒体本身，而是冗长的文本。

如果会话内容变长，可以使用 `compress` 压缩或使用 `-new` 开启新线程。

**会话来源：** 会话会标记下来它是在哪个地方显示出来的。Hermes 不一定都是在桌面客户端或命令行来调用，使用 email 或其他平台也可以直接调用。

**命令行会话管理命令：**
- `session list`：列出会话
- `session browse`：选择之前的会话
- `continue` / `-c`：继续会话

在桌面应用中更加方便，直接点击即可选择之前的会话。还支持创建分支——保留当前问题之前的上下文，截取下面的内容。

## 12. 能力篇_会话存储和跨会话搜索

大家好，我们继续来看能力篇的会话管理内容。

**会话存储：** 文档中的会话存储与官方页面中的内容一致，都是将整理出来的内容保存到 SQLite 数据库中。保存的位置在 `%LOCALAPPDATA%\HERMES\state.db`。

为什么要存到数据库里？主要是为了实现一个非常强大的功能——**跨会话搜索**。存不是目的，搜索使用才是目的。

**上下文压缩：** 大多数 Agent 都有这个功能，但 Hermes 的上下文压缩是完全自动的，并且设计得比较好。它有一些优化的算法，上下文压缩的配置在 `config.yaml` 文件中。

主要参数：
- 上下文压缩必须开启
- 50% 时进行压缩（可修改）
- 最近消息保留预算：最近 20% 的消息不进行压缩（即总上下文的 10% 永远不压缩）
- 最近的 20 条消息数也不压缩

也可以在桌面应用的设置中修改这些参数（小齿轮 → 记忆和上下文 → 自动压缩、压缩阈值、压缩目标、保护最近消息）。

**跨会话搜索（Session Search）：** 这是 0.15 版本重建后的重大更新功能。Hermes Agent 内置了 Session Search 工具，可以在保存的数据库中进行全文搜索，实现跨会话的全文检索。

使用时直接用自然语言与 Agent 交流即可，它会自动识别参数。例如："上次我们讨论的那个 Docker 部署方案，后来怎么解决的？" Agent 内部会通过关键词找到相关的会话，读取内容并简化，围绕命中的信息翻看完整内容进行截取，最后给出回答。

**演示案例：** 先让 Hermes 安排一个从上海到北京的十一国庆七天家庭旅游计划。然后新建一个会话，问"之前帮我安排的国庆北京家庭旅游计划中，第四天是去哪里玩的？" 它能通过 Session Search 找到之前的会话内容，知道第四天是颐和园加圆明园。这是跨会话的能力，非常强大。

相比之下，其他工具如果新建会话，就没有之前的聊天记录，没有这个记忆。只有像 Hermes 这样把每个会话的上下文保存到本地数据库，才能实现跨会话效果。

**会话导出：** Hermes 还提供了会话导出功能。在桌面应用中，直接点击会话 → 导出，会生成一个文件。文件详细记录了问题、时间戳、附加内容以及工具调用过程。导出的文件可以在 Hermes 中直接导入（点击加号 → 文件），然后问"我导入的这个线性会话是一个什么样的内容？"

## 13. 能力篇_Dashboard 浏览器使用

大家好，接下来学习 Hermes Agent 能力篇的另一个功能——**仪表盘（Dashboard）**。

Dashboard 是 Hermes 提供的基于浏览器的 Web 管理界面，我们不用再在命令行里操作，直接在网页端就可以执行。启动命令：`hermes dashboard`，会在本地的 Web 服务器上启动仪表盘，通过 `http://localhost:PORT` 访问。数据不会离开你的电脑，比较安全。

可以设置不同的端口号和绑定不同的地址，默认有默认值。

**使用体验：** 启动后进入 Web 界面，可以切换语言（简体中文）和主题。在桌面应用端也可以直接使用。Dashboard 可以监控本地的 Hermes 文件，输入目录或上传文件。

**Dashboard 的优势：**
- 信息内容特别多，包括底层 Agent 的日志也会全部显示出来
- 可以在里面执行配置，查看系统信息
- 可以实现跨网络使用——把 Hermes 部署在公司，下班后用自己的电脑访问地址即可连接

**注意事项：** Dashboard 缺少权限校验，如果实现远端登录，一定要配置好防火墙和黑白名单 IP，否则被别人使用了，token 一跑起来账单就特别长。

个人使用的话，Dashboard 和桌面应用区别不大，根据个人使用习惯选择即可。

## 14. 能力篇_工具集切换 FireCrawl 的 Key

大家好，我们继续学习能力篇的内容。接下来学习**工具集（Tools）**。

工具集是 Hermes 里面非常核心的能力。工具是扩展 Agent 能力的函数，Hermes 内置了非常丰富的工具注册表，包括网页搜索、浏览器自动化、终端执行、文件编译、记忆、委托等等。

在桌面应用中，点击左上方"技能和工具" → "工具集"，可以看到哪些已经配置、哪些没有配置。

**配置 FireCrawl（网页搜索）：**
1. 在设置中打开"工具和密钥"
2. 找到 FireCrawl，点击"获取密钥"
3. 跳转到 FireCrawl 官方网站，使用 GitHub 账号登录
4. 点击 "Start for Free"，复制 API Key
5. 回到 Hermes 粘贴并保存
6. 设置 `web_use_gateway` 为 `false`（使用自己的配置而非官方网关）
7. 重置会话使其生效

配置完成后，可以通过询问"现在使用的 FireCrawl 对应的地址是什么？"来验证是否生效。当看到搜索不再消耗官方额度时，说明已经配置好了自己的 Key。

大多数工具是免费的，有部分收费。收费部分可以自己配置成官方的，官方有免费额度。

## 15. 能力篇_工具集扩展使用

大家好，我们继续来看能力篇工具的内容。

除了网页搜索，Hermes 还有一些其他工具：
- **X Search**：推特搜索，直接打开就可以用，不需要额外配置
- **元宝**：直接打开就可以用
- **视频生成**：需要付费

**浏览器自动化工具（Browser Use）：** 这是一个专用的浏览器 Agent，可以模仿人进行浏览器访问并抓取内容。默认是付费的，可以替换成官方的（有免费额度）。配置方式类似 FireCrawl——获取 API Key，设置 `use_gateway` 为 `false`。

配置完成后，可以通过修改 `config.yaml` 文件中的 `browser_use_gateway` 参数来切换。

**演示：** 使用 X Search 搜索"纽约最近有什么音乐活动"，可以看到搜索结果和完整总结。

## 16. 能力篇_终端后端切换介绍

大家好，继续学习能力篇的内容。接下来是一个非常特别的功能——**终端后端（Terminal Backend）**。

Hermes 设计了一个独特的功能：在 Hermes 里面运行的所有本地电脑指令，可以在一个虚拟环境中执行，不一定非要在本地电脑上执行。

**默认情况：** 终端后端被配置为 `local`，即在本机上直接执行。可以通过检查当前工作目录来确认。

**为什么设计这个功能？**
- 本地开发时，值得信任的任务在 local 环境执行（默认设置）
- 想要进行相对危险的脚本测试（如删库操作），可以让它在 Docker 上跑
- Docker 是容器技术，相当于在电脑上开了一个小电脑，完全隔离。在 Docker 里执行任何删除操作，只删除隔离出来的容器里的数据，不会删除 Windows 电脑或生产环境服务器上的数据

**其他终端后端选项：**
- **SSH**：远程连接协议，让 Hermes 执行云服务器上的操作，实现沙箱化
- 其他容器技术

**切换设置：** 在桌面应用中，打开设置 → 高级 → 执行后端，选择 local 或 docker。切换后需要修改配置文件中的 `cwd`（工作目录），然后重启 Hermes 使其生效。

## 17. 能力篇_终端后端在 Docker 中使用

大家好，在介绍完终端后端切换的内容后，接下来演示如何把终端后端切换到 Docker 中。

**Linux 电脑：** 安装 Docker 非常方便，搜索一个命令就能一键安装。

**Windows 电脑：** 需要使用 Docker Desktop 这个软件。

**安装 Docker Desktop 步骤：**
1. 双击安装程序，点击下一步即可
2. 安装完成后会弹窗要求安装 Linux 虚拟环境（Windows 10 以上版本都有这个功能）
3. 启动 Docker Desktop

**配置 Docker 引擎：** 点击设置齿轮 → Docker 引擎，配置国内镜像源，否则拉取容器镜像时会非常慢且容易卡死。

**切换到 Docker 后端：**
1. 在高级设置中把执行后端改为 docker
2. 在配置文件中把 `cwd` 改为 `/workspace`（Linux 没有 Windows 的 C 盘目录）
3. 重启 Hermes
4. Hermes 会自动拉取 Docker 镜像（如果配置了国内镜像源就不容易失败）
5. 可以通过对话让 Hermes 检查是否切换完成

切换完成后，在 Docker Desktop 中可以看到启动的 Hermes 容器。在容器中创建的文件都保存在 Docker 的 `/workspace` 目录下。

**适用场景：** 需要使用危险命令或工具时，切换到 Docker 隔离容器中执行。

## 18. 能力篇_其他工具扩展功能

大家好，最后关于工具相关的内容，官方介绍了几个比较特别的功能：

1. **并行工具执行**：Hermes 可以通过线程池执行，并行执行多个独立的工具调用，最多 8 个并行 worker。这是 Hermes Agent 本身自带的，不需要用户考虑。

2. **智能审批**：受 Codex CLI 影响，Hermes 会学习哪些命令是安全的。当你不断对一个命令点击确认，说明你认为这个命令是安全的，后续 Hermes 会逐步减少审批提示。

3. **写入后检查**：每次通过 patch 或 write_file 写入文件时，会自动进行格式检查，减少格式上的错误。

这几个功能都是 Hermes 智能体自带的功能，不需要用户做任何事情，了解一下即可。

## 19. 能力篇_MCP 本地服务

大家好，我们继续学习能力篇的下一个内容——**MCP 协议**。

MCP（Model Context Protocol）是现在智能体 Agent 非常重要的功能，它可以把一些第三方的外部工具服务器接入到当前的 Agent 智能体中。例如接入高德地图的 MCP 服务器，它就可以帮你查地图、查回家的路径；接入 12306 的 MCP 服务器，就可以帮你查中国铁路的余票情况。

**在 Hermes 中配置 MCP：**
1. MCP 的支持在标准安装脚本中已经装好了
2. 在 `config.yaml` 文件中添加 MCP 服务器
3. 需要切换为 local 环境（Docker 环境无法使用本机 MCP 服务器）

**配置本地文件系统 MCP：**
1. 在设置 → MCP 中添加新服务器
2. 使用 `npx` 命令，配置参数和文件路径
3. 保存并重新加载
4. 之后 Hermes 可以直接操作该目录下的文件，不需要逐个管理权限

## 20. 能力篇_MCP 远程服务器工具使用

大家好，在演示完本地 MCP 文件系统服务器之后，接下来演示**远程 URL 访问的 MCP 服务器**。这是更好用、更常用的方式。

**两种 MCP 服务器形式：**
1. **stdio**：服务器已在本地安装，用 npx 直接访问。需要在本地部署，对 Windows 个人用户不太实用。
2. **HTTP 服务器**：直接连接远程端点，提供 URL 地址即可。非常常用。

**MCP 服务器平台：** 阿里巴巴公司已经帮我们做好了 MCP 服务器平台——**魔搭广场**（ModelScope）。只需要到这个平台上面找自己想要使用的 MCP 服务器即可。

**以 12306 MCP 车票查询工具为例：**
1. 在魔搭广场找到 12306 MCP 车票查询工具
2. 点击"服务配置" → "配置"
3. 使用 HTTP 服务，可以加鉴权（Token），设置有效期
4. 复制配置信息（URL 和 Token）
5. 在 Hermes 设置 → MCP 中添加新服务器
6. 填写名称、URL 和 handlers（Token）
7. 保存并重新加载

**对比效果：**
- **不使用 MCP 服务器**：Hermes 使用浏览器工具访问 12306 官网，填表单、查余票，流程很长，速度很慢
- **使用 MCP 服务器**：直接调用 MCP 服务，马上出结果，速度天差地别

**注意：** 配置时如果加了 Token 授权，有可能连不上。可以尝试不加鉴权（无键权），连接会更顺畅。

## 21. 能力篇_MCP 服务扩展介绍

大家好，我们继续看 MCP 相关的内容。

**MCP 管理与重加载：** 在桌面应用中直接点击 MCP 即可看到列表和配置。命令行中可以使用 `hermes mcp list` 查看，`mcp reload` 重新加载。

**MCP Server Mode（反向暴露）：** 0.8/0.6 版本推出的功能，Hermes Agent 也可以被反过来当做一个 MCP 服务器。这意味着你可以在 Claude Code、VS Code 等支持 MCP 工具的地方，把 Hermes 当做一个工具服务器来使用。

**MCP Catalog（精选服务器目录）：** 使用 `hermes mcp catalog` 命令可以查看官方精选的 MCP 服务。在国内使用魔搭平台添加起来更方便。

## 22. 能力篇_上下文文件 Soul.md

大家好，接下来学习能力篇中的**上下文文件**。

在智能体中，上下文文件通常决定了当前智能体在与你协作时的一些规范——比如它是什么样的实例人格、沟通风格，或者回答问题和处理工作时的注意事项。

**Hermes 支持的上下文文件格式：**
- `HERMES.md` / `HERMES.markdown`：Hermes 主要的上下文文件，最高优先级
- `AGENTS.md`：Codex（OpenAI）的上下文文件
- `CLAUDE.md`：Claude Code 的上下文文件
- `SOUL.md`：定制当前个性和语气，只在安装目录下生效
- `.cursorrules`：Cursor IDE 的规范文件

Hermes 完全兼容这些格式，方便从其他智能体工具迁移过来。

**SOUL.md（个性定制）：**
- 控制 Agent 的个性、语气和沟通风格
- 存放在 Hermes 安装根目录下
- 是系统提示词里的第一项内容，定义 Agent 是谁
- 每次新建会话时加载

**设置方法：**
1. 编辑 `SOUL.md` 文件
2. 写入想要的个性描述，如"你是一个卡哇伊的助手，喜欢用可爱的表情"
3. 保存后新建会话即可生效

官方推荐好的 SOUL.md 应该：风格直截了当但不冷漠，避免谄媚和炒作语言。

## 23. 能力篇_上下文文件的工作目录

大家好，我们继续学习上下文文件的内容。

**启动目录（工作目录）：** 非常关键。后续让 Agent 执行的所有写代码或实际工作场景，都会在启动目录里加载上下文文件。在哪儿启动就是哪儿的启动目录。

**命令行方式：** 在对应的位置打开 PowerShell，输入 `hermes`，工作目录就是当前目录。可以通过询问"当前的工作目录是哪里？"来确认。

**桌面应用方式：** 桌面端没有很好地设置切换启动目录，它默认使用桌面端启动时的目录。可以通过"工作区"来设置，但加载较慢。

**工作目录的作用：** 加载支持的上线文文件是根据启动目录来的。在启动目录中创建 `HERMES.md`、`AGENTS.md` 或 `CLAUDE.md` 文件，写入规范，启动 Hermes 后就会自动加载。

**加载流程：**
1. 会话开始时，扫描当前工作目录
2. 按优先级加载上下文文件（HERMES.md > AGENTS.md > CLAUDE.md）
3. 以 UTF-8 文本格式读取
4. 执行安全扫描
5. 如果文字太长，保留头部和尾部

**渐进加载：** 会话进行时，Agent 调用工具如果有文件路径，Hermes 会从这些路径推断当前访问的目录，检查最多五层，按优先级加载上下文文件。

**额外引用：** 可以使用 `@file` 或 `@url` 的方式加载其他位置的文件或 URL 地址。

## 24. 能力篇_持久化记忆介绍

大家好，继续学习能力篇的内容。接下来是一个非常核心的能力——**持久记忆**。

智能体 Agent 如果想要实际使用效果特别好，一定要有非常强大的记忆能力。Hermes Agent 提供了两种：一种是自身自带的记忆管理功能，另一种是可以提供外部记忆提供商。

**本地持久记忆系统：** 主要功能是跨会话保存用户的偏好、项目环境、工作习惯和经验教训，也就是所谓的"越用越智能"。

默认开启持久记忆和用户档案功能。在设置 → 记忆与上下文中，有两个开关：持久记忆和用户画像。下面还有记忆预算和画像预算（存储字符上限）。这两个会被保存为 `memory.md` 和 `user.md` 文件，存放在 Hermes 安装目录的 `memories/` 文件夹中。

**自动记忆的内容：**
- 用户偏好（如"用户倾向于使用 MCP 文件系统服务器"）
- 环境事实（如"服务器运行在 Debian 12"）
- 用户纠正（如"Docker 命令不要用 sudo"）
- 项目约定（如"项目使用 Tab 键，120 字符行宽"）
- 显示要求（如"记住 API Key 要每月轮换"）

**不被记忆的内容：**
- 太模糊的信息（如"用户问过 Python 相关内容"）
- 容易重新查询的通用知识
- 具有及时性的信息（如"今天天气怎么样"）
- 临时任务、一次性文件
- 已经写在 SOUL.md 或 AGENTS.md 中的内容

**记忆 vs 跨会话搜索：**
- **持久记忆**：保存以后经常要用到的稳定事实（如用户习惯），每次会话固定占用，容量小但速度快
- **Session Search**：回答"上次讨论过什么"，按需查询，保存所有历史会话，不固定占用上下文

## 25. 能力篇_外置记忆提供商

大家好，在了解完 Agent 自带的本地记忆功能之后，接下来看**外部记忆提供商**。这可以让你的智能体更聪明，相当于外挂了一个插件。

Hermes Agent 内置了 8 个外部记忆提供者插件，可以为 Agent 提供跨会话的持久性知识，超越了内置的 `memory.md` 和 `user.md`。同一时间只能激活一个。

**工作原理：** 激活记忆提供者后，Hermes 会自动注入提供者上下文到系统中，每轮对话前提前读取相关记忆，每次响应后将对话同步给提供者，相当于一个外接大脑。

**提供者选项：**
- **Honcho**：AI 原生的跨会话用户建模，具备辩证推理等能力（有价格，自托管免费）
- **OpenVac**：提供上下文数据库的外部记忆（免费）
- **Holographic**：免费，配置简单

**配置 Holographic（免费）：**
1. 执行安装命令 `hermes memory provider install holographic`
2. 选择对应的提供者
3. 配置 SQLite 数据库路径（默认位置）
4. 设置自动提取事实等参数
5. 配置完成后，在 `config.yaml` 的 `memory` 部分可以看到配置信息

配置完成后，使用方式与之前一样，但会有更完整的记忆存储和实时提取，使用起来显得更加智能。
