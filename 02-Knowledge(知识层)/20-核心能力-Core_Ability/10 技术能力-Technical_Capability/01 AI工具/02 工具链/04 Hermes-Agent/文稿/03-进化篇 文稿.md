# 进化篇 文稿

## 26. 进化篇_技能体系简介

大家好，接下来我们进入模块三——**进化篇**的内容讲解。进化篇主要包括四部分内容：Skills 技能系统、Hooks 钩子系统、Plugins 插件系统和 Cron 定时任务。

很多其他 Agent 也具备类似的进化能力，但 Hermes 明显做得更好。

**Skills 技能系统：** 很多智能体都支持 Skills 技能，但大多数智能体对于 Skill 是一个开放的态度——智能体本身没有对 Skill 进行总结归纳，也没有很好地直接调用或查看列表，需要用户自己到对应文件夹里管理，自己调用命令行去安装。

**Hermes Skills 的两大优势：**

1. **官方管理做得好**：不管是列表、自带的大量 Skill，还是安装新的 Skill，都在 Hermes 智能体里面完成，不需要再调外部命令。

2. **自进化功能**（最核心的差异化功能）：当 Agent 解决了复杂问题之后，会把可复用的流程自己保存为 Skill，下次再遇到类似任务时自动加载。并且这个 Skill 是 Hermes 自己总结出来的、人类可读的 Markdown 文件，用户可以随时查看、编辑或删除。

**Skill 数量：** 当前系统包含 166 个已追踪的技能。并不是安装时全部装上，而是区分了内置和可选。可以通过 `skills list` 查看已安装的技能。

在桌面应用中，点击"技能与工具"即可查看已安装的技能（约 62 个），可以开启或关闭。但桌面应用只支持查看和开关，不支持下载。命令行支持更多操作。

**Skill 目录结构：** 在 Hermes 安装目录的 `skills/` 文件夹下。每个 Skill 是一个文件夹，核心文件是 `SKILL.md`。复杂的 Skill 还可以包含辅助参考资料、输出模板、可调用脚本、图片等附加资源。

**SKILL.md 结构：**
- YAML 头部：名称、描述（告诉智能体什么时候使用这个 Skill）、版本、作者、证书、支持的操作系统
- 正文：纯文本内容，告诉大模型如何实现这个技能
- 包含具体的使用方法、命令行命令等

**条件激活：** Skill 会根据工具可用性自动显示或隐藏。例如，如果 FireCrawl API Key 缺失，会自动回退到另一个搜索技能。不需要告诉 Agent 使用什么技能，直接让它执行工作即可。

## 27. 进化篇_使用技能读取 PDF 编写 PPT

大家好，在介绍完技能的目录之后，接下来展示技能的使用。

**技能的条件激活：** 技能是根据工具可用性自动显示或隐藏的。不需要告诉 Agent 使用什么技能，直接让它执行工作即可。

**PDF 处理演示：**
1. 把 PDF 放到工作目录，或在应用中点击加号上传文件
2. 让 Hermes "提取 PDF 中的具体内容"
3. Agent 会自动调用 PDF 处理技能，使用 Python 库进行处理
4. 对于 URL 上的 PDF，同样可以处理

**PDF 转 PPT 演示：**
1. 让 Hermes "将刚才的 PDF 内容写成一个 PPT"
2. Agent 会搜索到 PPT 技能（PowerPoint），自动调用
3. 在工作目录中创建 PPT 文件
4. 生成的 PPT 质量非常不错

可以在运行过程中查看用量（token 消耗），监控花费。

## 28. 进化篇_扩展技能模块

大家好，在演示完技能的使用之后，接下来看 Hermes 还支持的其他技能功能。

1. **Skill Bundles**：通过 Skill Bundles 创建一个斜杠命令，这个命令可以同时包含多个技能。例如，把"加载 PDF 文件"和"制作 PPT"合成一个斜杠命令，同时执行全部操作。

2. **Skill Shop（俱乐部）**：Hermes Skill 兼容开源标准，可以在公开社区里任意浏览和安装社区技能。0.16 版本精简了内置技能集——并不是安装得越多越好，要根据实际使用的工作情况来安装。

3. **条件激活**：如果技能中某一步不能使用（如 API Key 缺失），会自动回退使用另一个工具。

4. **指定操作系统**：每个 Skill 都写明了支持的操作系统。

**Agency Manager（技能管理）：** 这是 Hermes 对比其他智能体最能体现差异化的地方。Hermes 可以通过 `skill manager` 工具创建、修改和删除自己的技能。

当解决了一个有复杂价值的问题时，它会把这个流程自己沉淀为 Skill。使用久了，它会在 `dev/` 目录下自己创建技能。后续如果使用到类似功能，它会以打补丁的形式修改已有技能，而不是从头创建。

**演示：** 完成 PDF 提取到 PPT 生成的工作流后，可以让 Hermes "保存为技能"。它会运行 Skill Manager，把流程保存为 Skill。下次再遇到类似需求时，直接根据这个 Skill 来执行。

## 29. 进化篇_Curator 技能维护

大家好，接下来看 Hermes 关于技能维护的专门管理——**Curator（园长管理）**。

Curator 可以帮助管理技能。其他智能体没有 Curator 管理，会把所有技能标记为同等级别。而 Hermes 想到了技能需要分门别类进行归档管理。

**Curator 的功能：**
- 及时追踪所有安装部署的技能，哪些使用多、哪些使用频繁
- 长期不使用的技能，从 active（活跃）变为 stale（不新鲜）
- 再长时间不使用，归档存起来

**目的：** 防止长期使用智能体后，技能不断累积，最终导致 Agent 里面有大量功能重复、使用范围窄的复杂技能。垃圾技能会浪费 token，因为大语言模型每次都要去读取这些技能。

**保护机制：**
- 如果某个技能很重要，会被保护住，不会自动迁移到 stale
- 大语言模型 review 时会跳过它
- Skill Manager 不能删除它，只能打补丁或修改

**运行机制：** 在 Hermes 启动时检查，需要在配置文件中设置 `curator.enable: true`。

**参数：**
- 检查时间间隔：168 小时
- 最小空闲间隔：2 小时
- 标记为不新鲜：30 天未使用
- 归档：90 天未使用

**处理范围：** Curator 只处理同时满足以下条件的技能：
1. 位于本地技能目录
2. 不是内置技能
3. 不是从 Skill Hub 安装的
4. 被标记为 `created_by_agent: true`（由 Agent 自己创建的）

也就是说，Curator 主要处理自定义和 Agent 自己定义的技能，对于系统内置或社区平台下载的大佬技能，不会轻易修改。

## 30. 进化篇_钩子函数

大家好，继续学习进化篇的内容。接下来是**Hooks 钩子系统**。

钩子系统是程序员一直使用的概念——程序执行到某一个特定位置时，额外执行一个提前留好的特定代码。这个特定代码可以在后续进行修改和编辑。

Hermes 提供了三种钩子系统，允许在关键的生命周期节点上执行自定义代码：
1. **Shell Hooks**：执行本地命令时
2. **Plugin Hooks**：执行插件时
3. **Gateway Hooks**：执行网关时

**常见钩子事件：**
- 工具执行前 / 工具执行后
- 大语言模型调用前 / 大语言模型调用后
- 会话开始时 / 会话结束时
- 网关启动、网关创建、网关 Agent 处理消息等

**Shell Hook 示例——会话结束时弹出桌面通知：**
1. 在 `config.yaml` 文件的 `hooks` 部分添加 `on_session_end` 事件
2. 配置执行的命令（Windows 下需要指定 Git Bash 的执行程序和脚本地址）
3. 创建对应的脚本文件（在 `%LOCALAPPDATA%\HERMES\hooks\` 目录下）
4. 设置脚本的执行权限

配置完成后，每次会话结束时就会弹出桌面通知。

**注意：** Windows 对底层命令的适配不是特别理想，因为 Hermes 虽然是安装在 Windows 上，但走了一个虚拟 Linux 环境。不过 Windows 上也很少用到 Shell 方面的钩子函数，所以了解即可。

## 31. 进化篇_钩子系统的安全保护功能

大家好，再来介绍钩子系统里一个常用的钩子函数——**工具调用前的安全防护**。

这个钩子函数可以在工具执行前阻止工具执行，起到安全防护的作用。它可以让 Agent 在执行一些危险的终端命令时被阻止，例如：
- `rm -rf /`（删除整个文件系统）
- 数据库删表操作
- 未授权的远程连接（会导致别人控制你的电脑）

**实现方式：** 在工具执行前执行一个钩子脚本，检查是否有危险操作。如果有危险操作，就拉入黑名单。

**返回值：** 这个钩子函数是系统里明确声明可以有返回值的。返回 `block` 表示阻止操作，没有返回 `block` 则正常执行。

**适用场景：** 个人 Windows 电脑上使用不多，但如果是在服务器或公司生产环境运行 Agent，钩子系统会非常有用，可以添加安全保护机制。

## 32. 进化篇_插件功能

大家好，接下来看进化篇的第三部分——**Plugins 插件系统**。

插件系统对比钩子系统非常推荐，因为它不需要改配置文件，也不涉及各种 Shell 脚本。它是直接用 Python 代码执行的，在 Windows 和 Linux 上都能很好地运行。

**插件能做什么：** 通过 Python 代码里的注册函数接入到 Hermes 中，基本上所有的 API 都可以直接使用。插件也可以外部扩展非常多的能力。它与工具和技能有一定重叠，但插件更底层，因为可以直接运行 Python 代码。

**插件目录：** 在 Hermes 安装根目录下的 `plugins/` 文件夹中。每个插件是一个文件夹，最少需要两个文件：
1. `plugin.yaml`：描述插件
2. `__init__.py`：Python 代码，包含注册函数

**演示——创建"摇晃窗口"插件：**
1. 在 `plugins/` 下创建 `shake_window/` 文件夹
2. 创建 `plugin.yaml`，填写名称、版本、描述
3. 创建 `__init__.py`，编写 Python 代码（包含 `register` 注册函数）
4. 在 Hermes 中启用插件（`plugin enable shake_window`）
5. 进入 Hermes 对话，告诉它"使用插件摇晃一下窗口"
6. Agent 会调用插件，窗口开始摇晃

**安装其他插件：** 可以到 GitHub 上查找，也可以在 `plugin list` 中查看已有的插件，使用 `plugin enable` 启用。

## 33. 进化篇_Cron 定时任务

大家好，接下来看进化篇的最后一个内容——**Cron 定时任务**。

Hermes 的定时任务系统做得非常好，使用起来很方便。有两种方式启动定时任务：
1. **自然语言**：让大模型帮你处理（推荐）
2. **Cron 表达式**：直接使用程序员的 Cron 表达式

**实际应用场景：** 做自媒体非常火。如果你每天能做一个早报，收集消息、整理消息、最后出视频，就可以创建定时任务，每天早上固定时间收集相关信息，整理出来，做成视频每天发布。

**调度格式：** 推荐使用自然语言，告诉它一个稳定的时间即可。Cron 表达式是五个数字表示"分时日月周"：
- `*` 表示不做限制
- `0 9 * * *` 表示每天 9 点
- `*/6 * * * *` 表示每 6 小时执行一次

**管理命令：** 在 Hermes 中可以使用 `/cron` 命令查询、暂停、恢复、删除定时任务。

**运行结果投递：** 如果对接了消息平台，可以把结果直接发到微信、钉钉、邮箱等。如果没有配置投递方式，默认保存到本地文件。

**No Agent 模式：** 如果不需要大语言模型推理，可以设置 `no_agent=true`，像传统电脑定时任务一样直接运行并输出。

**任务链接：** 多个定时任务之间默认隔离，但可以使用 `context_from` 把上一个任务的最新输出接到下一个任务的提示词中。

**演示——创建每日 AI 资讯汇总：**
1. 进入 Hermes 对话
2. 告诉它"创建一个定时任务，每天早上九点搜索网络上关于最新的 AI 大模型资讯，将信息总结归纳，保存在本地"
3. Hermes 会自动创建 Cron 任务
4. 可以手动触发一次查看效果
5. 运行完成后，在本地可以看到 AI 资讯汇总文件

经过测试，定时任务跑出来的资讯质量不错，足够用来做短视频内容。
