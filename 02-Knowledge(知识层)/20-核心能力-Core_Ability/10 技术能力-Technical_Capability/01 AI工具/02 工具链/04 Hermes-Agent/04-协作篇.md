## 1. Gateway 消息网关

> 官方文档：<https://hermes-agent.nousresearch.com/docs/user-guide/messaging/>

Gateway 是 Hermes 的消息平台接入层，可以作为前台进程或后台服务运行。它负责连接 Telegram、Discord、Slack、微信等平台，接收消息，维护每个聊天对应的会话，把消息转发给 Hermes Agent 处理，再把回复发回原平台。

Gateway 和 CLI 模式使用同一套 Hermes 程序、配置、会话、记忆、技能和工具。区别在于：CLI 是终端里的单次交互入口，Gateway 是长期运行的消息平台适配进程。Gateway 还会运行 cron 调度循环，用来触发到期的计划任务。

> 📺 **课程讲解要点** — 网关的核心价值：
>
> 老师强调：配置网关后，你就不需要待在计算机旁使用 Agent 了。例如公司出了 bug 需要重启服务器，以前得爬起来开电脑连接公司网络，现在直接给 Hermes 发个邮件或微信消息，让它来做就可以了。这就是网关消息平台最大的意义。

### 1.1 命令

```bash
hermes gateway setup                 # 交互式配置消息平台
hermes gateway                       # 前台启动 Gateway
hermes gateway install               # 安装为用户服务（Linux）/ launchd 服务（macOS）
sudo hermes gateway install --system # 仅 Linux：安装为开机启动的系统服务
hermes gateway start                 # 启动默认服务
hermes gateway stop                  # 停止默认服务
hermes gateway status                # 查看默认服务状态
```

#### Telegram Bot 端到端搭建

以 Telegram 为例，完整的 Gateway 接入流程如下：

**步骤 1：创建 Bot**

在 Telegram 中搜索 `@BotFather`，发送 `/newbot`，按提示设置名称和用户名，获得 Bot Token。

**步骤 2：配置 Hermes**

```bash
echo "TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz" >> ~/.hermes/.env
hermes gateway setup
```

**步骤 3：启动 Gateway**

```bash
hermes gateway           # 前台运行（调试用）
hermes gateway install   # 安装为系统服务（推荐生产环境）
hermes gateway start
```

**步骤 4：验证配对**

首次与 Bot 私信时，Bot 会回复配对码。管理员在本机批准：

```bash
hermes pairing list          # 查看待审批的配对请求
hermes pairing approve telegram XKGH5N7P
```

### 1.2 支持的消息平台（23+）

Hermes Gateway 支持 **23 个以上的消息平台**：

Telegram、Discord、Slack、WhatsApp、Signal、DingTalk、SMS (Twilio)、Mattermost、Matrix、Webhook、Email (IMAP/SMTP)、Home Assistant、Feishu/Lark、WeCom、Weixin（微信）、BlueBubbles (iMessage)、QQBot、Yuanbao、IRC、Microsoft Teams、Google Chat、LINE、SimpleX Chat、**ntfy**（v0.15+，无需账号的推送通知）

#### 邮箱配置参考（.env）

```bash
EMAIL_PASSWORD=QHaqxxxxxxxxxxxxxxxxxxxxx
EMAIL_IMAP_HOST=imap.163.com
EMAIL_SMTP_HOST=smtp.163.com
EMAIL_SMTP_PORT=465
EMAIL_ADDRESS=yaohm7788@163.com

```

> 📺 **课程讲解要点** — 邮箱网关配置完整实操：
>
> **配置步骤：**
> 1. 登录 163 邮箱 → 设置 → POP3/SMTP/IMAP
> 2. 开启授权服务功能
> 3. 新增授权密码，复制作为密码使用
> 4. 在 Hermes 设置 → 消息平台 → 邮箱中填写：邮箱账号、IMAP 地址、SMTP 地址、允许的用户、SMTP 端口号（163 为 465）
> 5. 保存配置
>
> **安装和启动网关：**
> ```bash
> hermes gateway install   # 安装网关服务
> hermes gateway start     # 启动网关
> ```
>
> **基础功能演示 — 发送邮件：**
> 让 Hermes "将定时任务收集的 AI 资讯作为邮件发送到 QQ 邮箱"。Hermes 会检查定时任务的输出数据，编写 Python 脚本来发送邮件。
>
> **高阶功能演示 — 接收邮件并回复：**
> 1. 登录 QQ 邮箱，写信给部署了 Hermes 网关的邮箱
> 2. 主题写"Hermes 消息"，正文写"帮我写一篇 800 字的作文，题目是科技创新"
> 3. 发送后，网关接收到消息并处理
> 4. 处理完成后，QQ 邮箱收到回复邮件
>
> **⚠️ 踩坑**：修改了 env 配置后，需要重启网关才能生效。使用 `hermes gateway restart` 命令。

### 1.3 网关配对

默认情况下，网关会拒绝所有不在允许列表中或未通过私信配对的用户。

#### 允许列表

在 `~/.hermes/.env` 中配置：

```bash
# 按平台限制用户
TELEGRAM_ALLOWED_USERS=123456789,987654321
WEIXIN_ALLOWED_USERS=123456789,987654321

# 或配置通用允许列表
GATEWAY_ALLOWED_USERS=123456789,987654321

# 显式允许所有用户（不推荐给有终端访问权限的机器人使用）
GATEWAY_ALLOW_ALL_USERS=true
```

#### 私信配对

无需手动配置用户 ID，未知用户在私信机器人时会收到一次性配对码，例如 `Pairing code: XKGH5N7P`。之后管理员在本机批准：

```bash
hermes pairing approve telegram XKGH5N7P  # 批准配对
hermes pairing list                       # 查看配对列表
hermes pairing revoke telegram <user_id>  # 撤销配对
```

配对码 1 小时后过期，有速率限制，并使用加密随机数生成。

## 2. Profile 多实例

> 官方文档：<https://hermes-agent.nousresearch.com/docs/user-guide/profiles>

通过 Profile 运行多个独立的 Hermes Agent，每个 Agent 有独立的配置、会话、技能和记忆。

### 2.1 什么是 Profile

Profile 是一个独立的 Hermes home 目录。其中包含各自的 `config.yaml`、`.env`、`SOUL.md`、记忆、会话、技能、cron 任务、状态数据库和 Gateway 状态。

通过 Profile 可以运行用于不同用途的 Agent 而不会混淆 Hermes 状态。

创建 Profile 后，Hermes 会自动生成同名命令别名。例如创建 `coder` 后，可以直接使用 `coder chat`、`coder setup`、`coder gateway start`，本质上等价于 `hermes -p coder ...`。

> 📺 **课程讲解要点** — Profile 的实际意义：
>
> 老师解释：默认的多个会话使用的是同一套配置、同一套环境文件、同一套 SOUL.md。本质上还是一个 Agent。而 Profile 可以复制出多个完全不同、完全独立的 Hermes Agent，各自有独立的配置、会话、技能和记忆。
>
> **使用场景**：当你希望 Agent 实现完全独立的效果时——比如一个用于写代码（coder），一个用于日常聊天（default），两者互不干扰。

### 2.2 创建 Profile

```bash
hermes profile create coder                     # 创建空白 Profile，内置技能会初始化
hermes profile create coder --description "负责阅读源码、实现已明确的代码修改..."
hermes profile create coder --clone             # 克隆当前 Profile 的 config.yaml、.env、SOUL.md
hermes profile create backup --clone-all        # 克隆完整状态
hermes profile create coder --clone --clone-from backup  # 从指定 Profile 克隆
hermes profile delete coder                     # 删除 Profile
```

> 📺 **课程讲解要点** — Profile 创建实操：
>
> 老师演示了创建 Profile 的完整过程：
>
> 1. 执行 `hermes profile create coder --description "写代码专用" --clone`
> 2. 创建完成后，在 `~/.hermes/profiles/coder/` 下可以看到独立的配置文件
> 3. 使用 `coder` 命令（不再是 `hermes`）进入这个独立的 Agent
> 4. 可以为 coder 设置不同的人格（如卡哇伊），而 default 保持专业风格
> 5. 两者互不影响——会话历史、配置、记忆完全独立

### 2.3 使用 Profile

```bash
coder chat                                      # 启动 coder profile 的交互式对话
coder setup                                     # 运行 coder profile 的配置向导
coder gateway start                             # 启动 coder profile 的 Gateway 服务
coder doctor                                    # 检查 coder profile 的健康状态
coder skills list                               # 查看已安装的 skills
```

### 2.4 工作原理

Profile 使用 `HERMES_HOME` 环境变量。运行 `coder chat` 时，包装脚本会在启动 Hermes 前设置 `HERMES_HOME=~/.hermes/profiles/coder`。每个 Profile 都可以作为独立进程运行自己的 Gateway，拥有自己的 bot token。

## 3. Delegation 任务委派

> 官方文档：<https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation>

Hermes 可以创建子 Agent 来处理独立的任务。子 Agent 有自己的对话和终端环境，互不干扰。

### 3.1 单任务与并行批量

**单任务：**

```text
delegate_task(
    goal="Debug why tests fail",
    context="Error: assertion in test_foo.py line 42",
    toolsets=["terminal", "file"],
)
```

**并行批量（默认最多 3 并发）：**

```text
delegate_task(tasks=[
    {"goal": "Research topic A", "toolsets": ["web"]},
    {"goal": "Research topic B", "toolsets": ["web"]},
    {"goal": "Fix the build", "toolsets": ["terminal", "file"]},
])
```

> 📺 **课程讲解要点** — Delegation 实操演示：
>
> 老师演示了使用任务委派同时搜索 ChatGPT、Claude、DeepSeek 最新模型参数的过程：
>
> 1. 告诉 Hermes "使用任务委派的方式，同时启动多个 Agent，同时搜索 ChatGPT、Claude、DeepSeek 最新模型的参数"
> 2. Hermes 会创建三个子任务同时执行搜索
> 3. 完成后回收结果进行总结
>
> **效果对比**：不用委派的话，需要第一个 Agent 执行完再执行第二个，再执行第三个，最后总结。使用委派后三个同时执行，效率高很多。

### 3.2 子 Agent 上下文

子 Agent 启动时拥有全新对话，不知道父会话之前的任何内容。唯一上下文来自接收的 `goal` 和 `context` 两个字段。子 Agent 完成后，只有结构化摘要回传到父会话，详细对话过程不保留，以此控制 token 开销。

### 3.3 工具集限制

| toolsets | 适用场景 |
|----------|---------|
| `["terminal", "file"]` | 编码、调试、文件编辑 |
| `["web"]` | 调研、查文档 |
| `["terminal", "file", "web"]` | 全栈任务（默认） |

子 Agent 无法使用：`delegation`（禁止再次委派）、`clarify`（不能与用户交互）、`memory`（不写入共享持久记忆）、`code_execution`、`send_message`。

### 3.4 配置

```yaml
# ~/.hermes/config.yaml
delegation:
  max_concurrent_children: 3
  max_spawn_depth: 1
  orchestrator_enabled: true
```

## 4. Kanban 多 Agent 协作

> 官方文档：<https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban>

Hermes Kanban 是一个多 Agent 协作层：一个可恢复、可审计、可中途介入的工作队列。它把任务、依赖、评论、运行记录和工作目录放进一个持久任务板里，让多个具名 profile 以异步方式协作。

### 4.1 从 delegate_task 到 Kanban

`delegate_task` 适合短的、自包含的推理子任务，但无法覆盖：

1. **研究分流与综合**：多个专家型 Agent 并行产出候选发现
2. **定时循环工作流**：日报、周报等跨运行积累知识
3. **数字分身 / 持久助手**：具名、长期存在的 Agent 身份
4. **端到端工程流水线**：拆解、并行实现、审查、迭代、提交

> 📺 **课程讲解要点** — Kanban 的定位：
>
> 老师用一个比喻解释三者关系：
> - **Profile 多实例**：构建出完全不一样环境、不一样配置的多个 Agent
> - **任务委派**：在一个 Agent 里面委派子任务，实现并发
> - **看板**：让多个 Profile 以异步方式协作，实现更复杂的拓扑结构
>
> 看板适合企业级大型复杂任务，但要注意 Token 消耗——多 Agent 运行时缓存命中率低（约 70-80%），而单 Agent 可达 99%。命中率直接影响价格（命中 0.025 元/百万 Token，未命中 3 元/百万 Token，差 100 多倍）。

### 4.2 架构

三层架构：

- **Control Plane（控制层）**：CLI、Gateway、Dashboard — 用户交互入口
- **State Plane（状态层）**：SQLite board + dispatcher — 唯一事实来源
- **Execution Plane（执行层）**：独立 profile worker 进程

所有协调都通过任务板流转，profile 之间没有直接的进程间通信。

### 4.3 核心概念

#### Board（任务板）

Board 是一个独立的任务队列，拥有自己的 SQLite 数据库、workspaces 目录和调度循环。默认 board 数据库位于 `~/.hermes/kanban.db`。

#### Task（任务）

Task 是 Kanban 的基本工作单元。一个 task 只有一个 `assignee`，通常是 Hermes profile 名称。

Task 状态：`triage` → `todo` → `ready` → `running` → `done` / `blocked` / `archived`

#### Link（任务依赖）

Link 是 task 之间的父子依赖。父任务完成之前，子任务保持在 `todo`；所有父任务完成后，dispatcher 推进子任务到 `ready`。

#### Comment（评论 / 交接记录）

Comment 是人类和 Agent 在 task 上追加的持久消息，也是 Kanban 的跨 Agent 交接协议。

#### Event（任务事件）

Event 是 Kanban 的审计日志，记录 task 生命周期里的状态变化、人工编辑和 worker 执行遥测。

#### Workspace（工作目录）

Task 绑定的工作目录，worker 执行时所在位置。支持 `scratch`（临时）、`dir:<path>`（指定路径）、`worktree`（git worktree）三种模式。

### 4.4 协作模式

| 模式 | 说明 | 典型场景 |
|------|------|---------|
| **Fan-out（扇出）** | 一个目标拆成多个同级 task，并行执行 | 多角度研究、并行实现 |
| **Pipeline（流水线）** | 上游完成 → 下游启动 | researcher → writer → reviewer |
| **Fan-in（扇入）** | 多个 task 汇总到一个聚合 task | 研究综合、方案评审 |
| **Long-running journal** | 同一 profile 通过定时任务反复处理 | 日报、周报、监控巡检 |
| **Human-in-the-loop** | worker 阻塞 → 人工评论 → unblock | 不确定决策、需要审批 |
| **Fleet farming** | 一个 profile 管理 N 个对象 | 多账号管理、多服务器巡检 |

### 4.5 Dispatcher 调度器

Dispatcher 是一个长期循环，默认运行在 Gateway 内部。每 N 秒（默认 60 秒）扫描 board，执行四类动作：

1. **stale recovery**：处理异常的 `running` 任务
2. **recompute ready**：推进依赖满足的任务到 `ready`
3. **atomic claim**：通过 SQLite 原子 CAS 更新认领任务
4. **启动 worker**：认领成功后启动 assignee 对应的 profile worker

### 4.6 看板实操

> 📺 **课程讲解要点** — Kanban 初始化与任务执行：
>
> **初始化看板：**
> ```bash
> hermes kanban init
> ```
>
> **创建看板任务：**
> ```bash
> hermes kanban create '阅读 Hermes Agent 文档并小结,永久保存到桌面' --body '重点看 agent loop、skills、gateway 三个部分' --assignee default
> ```
>
> **查看任务：**
> ```bash
> hermes kanban list
> hermes kanban show <task_id>
> ```
>
> **⚠️ 踩坑**：默认输出保存在临时位置，任务完成后可能被删除。需要明确告诉任务"永久保存到桌面"。
>
> **⚠️ 踩坑**：电脑上不能有 Python 的其他版本，否则会导致虚拟环境 Python 3.11 的包损坏。可以让 Hermes 帮忙解决。
>
> **一键实现拓扑（v0.15+ Swarm）：**
> ```bash
> hermes kanban swarm "研究 Hermes Agent 的架构并写一份分析报告,输出到桌面" \
>   --worker "default:Agent Loop 分析" \
>   --worker "default:Skills 系统分析" \
>   --worker "default:Gateway 架构分析" \
>   --verifier default \
>   --synthesizer default
> ```
>
> 这个命令会一次性创建 5 个任务（3 个调研 + 1 个校验 + 1 个总结），同时分配给不同的 Worker 执行。完成后在桌面上生成多个结果报告。

### 4.7 Orchestrator Profile

Kanban 把编排分成两个阶段：

1. **Decomposer 处理 `triage` task**：判断目标是否需要拆分、创建子任务图
2. **Orchestrator profile 承接 root task**：子任务完成后，汇总结果

创建 orchestrator profile：

```bash
hermes profile create orchestrator --clone \
```

## 5. 高级特性集锦

> 📺 **课程讲解要点** — 老师总结的实用技巧：
>
> **Token 消耗监控**：使用多 Agent（看板）时，Token 消耗很大。缓存命中率低（约 70-80%），而单 Agent 配置好可达 99%。只有特别大型、特别复杂的任务才适合用看板。
>
> **看板阻塞处理**：第一次执行看板任务时，Agent 经常把自己阻塞住（如"我要标记完成，但我自己没法标记完成"）。需要人工使用 `hermes kanban unblock <task_id>` 解除阻塞。运行完成后，让 Hermes 把整个流程记忆下来做成 Skill，后续就会更加顺畅。
