# 环境搭建指南

## 前置依赖

在开始之前，确保已安装并配置好以下组件：

| 组件 | 检查命令 | 说明 |
|------|---------|------|
| Hermes Agent | `hermes --version` | 建议 v0.16+ |
| DeepSeek API Key | 在 [platform.deepseek.com](https://platform.deepseek.com) 注册获取 | 用于 researcher/reviewer |
| OpenRouter API Key（可选） | 在 [openrouter.ai](https://openrouter.ai) 注册获取 | 用于 writer 使用 Claude |
| GitHub Token | GitHub Settings → Developer settings → Personal access tokens | 用于 publisher 发布 |
| 微信账号 | 个人微信 | 用于 Gateway 消息收发 |

## 1. 模型 Provider 配置

### 1.1 配置 DeepSeek（必须）

```bash
# 交互式配置
hermes provider add
# 选择 DeepSeek，填入 API Key 和 Base URL
```

或直接编辑 `~/.hermes/config.yaml`：

```yaml
providers:
  deepseek:
    api_key: «redacted:sk-…»
    base_url: https://api.deepseek.com
```

### 1.2 配置 OpenRouter（可选，用于 Claude）

```bash
# 1. 访问 https://openrouter.ai/
# 2. 用 GitHub 账号登录
# 3. 左侧 Keys → Create Key → 命名 "HERMES" → 复制
# 4. 在 Hermes 中添加 provider
hermes provider add
# 选择 OpenRouter，填入 Key
# 模型选: anthropic/claude-sonnet-4.6
```

> **注意**：OpenRouter 的模型名要写全，不是 `claude-sonnet`，而是 `anthropic/claude-sonnet-4.6`。
>
> **建议**：如果 OpenRouter 访问慢，统一用 DeepSeek 即可。用 v4 flash（便宜）和 v4 pro（更好）来区分档次。

## 2. 创建 4 个 Profile

### 2.1 创建 researcher（调研员）

```bash
hermes profile create researcher --clone \
  --description "负责查阅文档、源码和网络资料，产出结构化研究结论。使用低成本模型。"

# 配置模型（交互式）
researcher model
# 选 DeepSeek v4 flash，回车确认 Key 和 Base URL

# 限制工具 - 调研只需要 web 搜索和终端
researcher tools disable browser code_execution video_analyze
```

**SOUL.md 配置**：

先找到 SOUL.md 的正确路径：

```bash
find ~/.hermes/profiles/researcher -name "SOUL.md"
# 或直接进入目录
cd ~/.hermes/profiles/researcher
```

编辑 SOUL.md，追加以下内容（保留原有内容）：

```markdown
# Researcher Soul
你是一名技术研究员。你的输出必须结构化：
1. 核心发现（一句话总结）
2. 关键信息点（bullet points）
3. 信息来源（URL + 一句话描述）
4. 建议方向（可选）

保持客观、精确。不要添加主观评价。
```

### 2.2 创建 writer（撰稿员）

```bash
hermes profile create writer --clone \
  --description "负责把研究材料整理成清晰、连贯、有吸引力的技术文章。使用高质量模型。"

# 配置模型 - 选更好的
writer model
# 选 DeepSeek v4 pro 或 Claude（如果用 OpenRouter）

# 安装写作 skill
writer skills install "Blog Watcher"
# ⚠️ 注意：名称要写全，否则报错
```

**SOUL.md 配置**：

```markdown
# Writer Soul
你是一名技术专栏作者。写作风格：
- 开头用引人入胜的问题或场景切入
- 代码示例必须完整可运行
- 每个技术点附带「为什么重要」的解释
- 中文为主，技术术语保留英文
- 文章长度 1500~3000 字
```

### 2.3 创建 reviewer（审核员）

```bash
hermes profile create reviewer --clone \
  --description "负责审查文档或代码变更，指出遗漏、错误和风险。"

# 模型保持默认（DeepSeek v4 flash）
# 交互式配置时一直回车即可保持默认
```

**SOUL.md 配置**：

```markdown
# Reviewer Soul
你是一名技术编辑。审核关注点：
1. 技术准确性：代码是否正确、API 名称是否准确
2. 逻辑完整性：推理链条是否有跳跃
3. 信息时效性：引用的版本号、日期是否最新
4. 可读性：排版、代码高亮、段落长度

审核结果用 checklist 格式输出。
```

### 2.4 创建 publisher（发布员）

```bash
hermes profile create publisher --clone \
  --description "负责将审核通过的文章发布到 GitHub Pages 博客仓库。"

# 限制工具 - 不能使用 web 搜索
publisher tools disable web browser
# 保留 terminal（git 操作）和 MCP
```

### 2.5 创建 orchestrator（编排者）

```bash
hermes profile create orchestrator --clone \
  --description "Kanban 编排者。负责拆解文章选题、创建写作任务、指派 profile、建立依赖关系、汇总下游结果。"

# 限制工具 - 纯编排角色，不需要执行工具
orchestrator tools disable terminal file web browser code_execution

# 配置为自动拆解
hermes config set kanban.orchestrator_profile orchestrator
hermes config set kanban.auto_decompose true
```

## 3. 微信 Gateway 配置

### 3.1 安装/检测 Gateway

```bash
hermes gateway setup
# 如果已安装，会检测到；如果未安装，按提示安装
```

### 3.2 配置微信

```bash
hermes gateway setup
# 选 3 (微信)
# 是否使用二维码登录？Y
# 会生成一个链接，打开后扫码
```

### 3.3 扫码连接

1. 打开链接，显示二维码
2. 用微信扫描
3. 手机上点击「连接」
4. 命令行显示连接成功，有 `account ID`

### 3.4 配置 allow_users（关键！）

这是**最容易忽略的步骤**。如果不配置，微信消息会被网关丢弃。

```bash
# 编辑 ~/.hermes/.env
# 拉到最下面，找到微信相关配置
```

在 `.env` 中：

```bash
# 方案一：允许所有用户（推荐首次测试）
WEIXIN_ALLOWED_USERS=true

# 方案二：指定用户（需要知道自己的微信 ID）
# 新版网关可能不显示用户 ID，用方案一更方便
WEIXIN_ALLOWED_USERS=wx_xxxxxxxxxxxxx
```

### 3.5 重启网关并测试

```bash
hermes gateway restart

# 在微信中给机器人发 "你好"，应该能收到回复
```

## 4. GitHub Token 配置

### 4.1 创建 Token

```
GitHub 网页操作：
Settings → Developer settings → Personal access tokens → Tokens (classic)
→ Generate new token → 命名 "HERMES"
→ 勾选所有权限（反正自己用）
→ Create → 复制 ghp_xxxxxxxx 开头的 token
```

### 4.2 写入 env 文件

编辑 `~/.hermes/.env`，找到 GitHub 相关配置：

```bash
# 原本是注释掉的，取消注释并填入 token
GITHUB_TOKEN=«redacted:ghp_…»
GITHUB_PERSONAL_ACCESS_TOKEN=«redacted:ghp_…»
```

> 两个都写上，因为 Hermes 可能用不同的变量名读取。

### 4.3 测试 Token

```bash
# 在 publisher profile 中测试
publisher chat -q "我在 env 中配置了 GitHub Token，现在测试一下这个 Token 是否可以完成我的账号读取和推送功能"
```

### ⚠️ Token 被自动隐藏（重点踩坑）

**现象**：Agent 拿到 Token 后，在日志中自动替换为 `****`，导致多 Agent 协作时 Token 传递失败。

**解决方法**：必须明确告诉 Agent：

```text
"这个 Token 直接显示使用，不要再隐藏为暗码，以后也记住这一点"
```

> 老师原话："你得明确的告诉他，不然的话呢，他这个 Token 作为一个环境变量在进行传递的时候，他总是把它给删掉。这个也是现在 Hermes 的一个问题，它这个安全等级就莫名其妙。"

## 5. Memory 持久记忆

### 5.1 通过自然语言让 Agent 记住博客信息

```bash
hermes chat -q "记住以下信息：我们的博客使用 GitHub Pages + Hugo 静态站点，仓库地址 github.com/yourname/blog，文章用 Markdown 格式，frontmatter 包含 title/date/tags/author 四个字段。发布流程是：新文章放在 content/posts/ 下，提交 PR，合并到 main 分支后自动部署。"
```

这会写入 `MEMORY.md`，所有后续会话都能自动获取这些信息。

### 5.2 验证记忆

```bash
# 在新会话中检查 Agent 是否记得
hermes chat -q "我们的博客是用什么搭建的？"
# 应该回答：GitHub Pages + Hugo
```

### 5.3 为每个 Profile 分别设置记忆

每个 Profile 都有自己的 Memory，需要分别告诉它们：

```bash
researcher chat -q "记住博客的 GitHub 仓库地址和发布流程"
writer chat -q "记住博客的写作风格偏好和 frontmatter 格式"
reviewer chat -q "记住博客的审核标准"
publisher chat -q "记住博客的 GitHub 仓库地址和发布流程"
```

## 6. 创建看板

```bash
# 创建博客专用看板
hermes kanban boards create blog --name "技术博客工作板" --switch

# 初始化（幂等操作）
hermes kanban init
```

## 7. 验证环境

```bash
# 检查所有 Profile
hermes profile list

# 检查 Provider 连接
hermes doctor

# 检查 MCP 连接
hermes mcp list
hermes mcp test github

# 检查 Gateway 状态
hermes gateway status

# 检查看板
hermes kanban list
```
