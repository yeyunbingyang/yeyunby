## 一、意图识别不准

### 问题现象

- 用户说"我要退款"，被识别为"产品咨询"
- 用户说"你好"，被识别为"投诉建议"
- 不同用户说同一句话，识别结果不一致

### 根因分析

| 原因 | 说明 |
|------|------|
| Few-shot 示例不足 | 每个意图只给了 2-3 个示例，覆盖不全 |
| 未考虑上下文 | 只分析单条消息，忽略对话历史 |
| Prompt 设计模糊 | 意图定义不够清晰，边界重叠 |
| 模型温度过高 | temperature=0.7 导致输出随机性大 |

### 解决方案

#### 1. 丰富 Few-shot 示例

```yaml
# 每个意图至少 10 个高质量示例
intents:
  - id: complaint
    name: 投诉退款
    examples:
      - "我要退款"
      - "退钱！"
      - "你们产品太差了，我要投诉"
      - "再不退款我就去315投诉"
      - "这质量也太差了吧，退货"
      - "客服呢？我要投诉客服"
      - "申请售后"
      - "东西坏了，怎么处理"
      - "我不满意，要投诉"
      - "给我转投诉部门"
```

#### 2. 降低模型温度

```bash
# 意图识别专用配置，降低随机性
hermes config set profile.intent-classifier.temperature 0.1
hermes config set profile.intent-classifier.top_p 0.9
```

#### 3. 引入上下文感知

```python
INTENT_PROMPT = """
你是一个智能客服意图分类器。

对话历史（最近3轮）：
{recent_history}

当前用户消息：{message}

分析规则：
1. 结合对话历史判断意图连续性
2. 如果用户在前一轮已经表达了某个意图，优先保持
3. 只有当新消息明显改变话题时才切换意图
4. 注意代词指代（"它"、"那个"等）

可用意图：
{intent_definitions}

返回 JSON：
{{"intent": "...", "confidence": 0.0~1.0, "reason": "..."}}
"""
```

#### 4. 添加否定词检测

```python
# 否定词和情绪词检测
NEGATIVE_KEYWORDS = [
    "退款", "投诉", "退货", "差评", "垃圾", "太差",
    "举报", "315", "维权", "赔偿", "不满意"
]

def detect_negative_intent(message: str) -> bool:
    """快速预检，命中否定词直接提高投诉意图权重"""
    return any(kw in message for kw in NEGATIVE_KEYWORDS)
```

## 二、知识库检索质量差

### 问题现象

- 检索到的文档与问题不相关
- 重要知识被遗漏
- 回答引用错误文档

### 根因分析

| 原因 | 说明 |
|------|------|
| 文档分块不合理 | chunk 太大（>1000 tokens）或太小（<100 tokens） |
| Embedding 模型不匹配 | 英文 Embedding 处理中文文档 |
| 未做重排序 | 向量相似度 ≠ 语义相关性 |
| 知识库覆盖不全 | 关键文档未入库 |

### 解决方案

#### 1. 优化文档分块策略

```python
# 智能分块策略
def smart_chunk(document: str, chunk_size: int = 512, overlap: int = 64) -> list:
    """
    按语义段落分块，而非简单按字符数截断
    """
    paragraphs = document.split("\n\n")
    chunks = []
    current_chunk = ""
    
    for para in paragraphs:
        if len(current_chunk) + len(para) < chunk_size:
            current_chunk += para + "\n\n"
        else:
            if current_chunk:
                chunks.append(current_chunk.strip())
            # 保留 overlap 内容
            current_chunk = current_chunk[-overlap:] + para + "\n\n"
    
    if current_chunk:
        chunks.append(current_chunk.strip())
    
    return chunks
```

#### 2. 使用中文优化的 Embedding

```bash
# 推荐的中文 Embedding 模型
# OpenAI: text-embedding-3-small（中文效果不错）
# 国产: BAAI/bge-large-zh-v1.5（中文最优之一）
# 国产: moka-ai/m3e-large（轻量级）

hermes config set knowledge.embedding.model "BAAI/bge-large-zh-v1.5"
hermes config set knowledge.embedding.provider local
```

#### 3. 必加重排序

```python
# 重排序可以显著提升检索质量
def rerank_results(query: str, results: list, top_k: int = 3) -> list:
    """
    使用交叉编码器重排序
    """
    pairs = [(query, doc["text"]) for doc in results]
    scores = reranker.predict(pairs)  # 返回相关性分数
    
    # 按分数排序
    scored_results = [
        {**doc, "relevance_score": score}
        for doc, score in zip(results, scores)
    ]
    scored_results.sort(key=lambda x: x["relevance_score"], reverse=True)
    
    return scored_results[:top_k]
```

## 三、多轮对话丢失上下文

### 问题现象

- 用户说"那价格呢"，Agent 不知道"那"指什么
- 对话超过 5 轮后，Agent 开始答非所问
- 用户换话题后，Agent 仍纠缠旧话题

### 根因分析

| 原因 | 说明 |
|------|------|
| 上下文窗口溢出 | 超过 LLM 的 max_tokens 限制 |
| 未做指代消解 | 代词"它/那个/这个"未替换为实体 |
| 历史压缩丢失关键信息 | 摘要算法丢失了实体和数字 |
| 未区分话题边界 | 新旧话题混淆在一起 |

### 解决方案

#### 1. 显式指代消解

```python
# 在进入主流程前，先做指代消解
def resolve_references(message: str, context: dict) -> str:
    """将代词替换为具体实体"""
    
    entities = context.get("entities", {})
    
    # 简单规则替换
    replacements = {
        "它": entities.get("product", "它"),
        "那个": entities.get("last_topic", "那个"),
        "这个": entities.get("current_topic", "这个"),
        "你们": "贵公司",
    }
    
    for pronoun, entity in replacements.items():
        if pronoun in message and entity != pronoun:
            message = message.replace(pronoun, entity)
    
    return message
```

#### 2. 分层上下文管理

```python
class ConversationManager:
    def __init__(self, max_recent_turns: int = 5):
        self.max_recent_turns = max_recent_turns
    
    def build_prompt_context(self, session_id: str) -> str:
        recent = self.get_recent_history(session_id)
        summary = self.get_compressed_summary(session_id)
        entities = self.get_entities(session_id)
        
        context_parts = []
        
        # 1. 早期对话摘要
        if summary:
            context_parts.append(f"[对话背景]: {summary}")
        
        # 2. 已知实体
        if entities:
            context_parts.append(f"[已知信息]: {json.dumps(entities, ensure_ascii=False)}")
        
        # 3. 最近对话
        if recent:
            context_parts.append("[最近对话]:")
            for msg in recent:
                role = "用户" if msg["role"] == "user" else "客服"
                context_parts.append(f"{role}: {msg['content']}")
        
        return "\n".join(context_parts)
    
    def detect_topic_change(self, message: str, context: dict) -> bool:
        """检测话题是否切换"""
        if not context.get("history"):
            return False
        
        last_intent = context.get("current_intent")
        new_intent = classify_intent(message)
        
        return last_intent and new_intent and last_intent != new_intent
```

#### 3. 话题边界标记

```python
# 在上下文中显式标记话题切换
TOPIC_MARKER = "--- [话题切换] ---"

def mark_topic_boundary(context: dict, new_intent: str) -> dict:
    """检测到话题切换时插入分隔符"""
    if context.get("current_intent") and context["current_intent"] != new_intent:
        context["history"].append({
            "role": "system",
            "content": TOPIC_MARKER,
            "timestamp": current_timestamp()
        })
    context["current_intent"] = new_intent
    return context
```

## 四、转人工条件不合理

### 问题现象

- 简单问题也被转人工，失去自动化意义
- 用户明显不满却未触发转人工
- 转人工后坐席接到的上下文不完整

### 根因分析

| 原因 | 说明 |
|------|------|
| 阈值设置过松 | 置信度阈值 0.8 太高，频繁触发转人工 |
| 缺少情绪检测 | 只靠意图置信度判断，忽略用户情绪 |
| 上下文传递不全 | 只传了最后一条消息，坐席需要重头问起 |

### 解决方案

#### 1. 分级兜底策略

```python
HANDOFF_RULES = {
    "immediate": {  # 立即转人工
        "conditions": [
            "用户明确说'转人工'",
            "涉及法律/财务/医疗",
            "检测到愤怒情绪",
        ],
        "priority": "P0"
    },
    "conditional": {  # 条件触发
        "conditions": [
            "意图置信度 < 0.5",
            "同一问题重复 ≥ 3 次",
            "连续 2 次不满意",
        ],
        "priority": "P1"
    },
    "suggested": {  # 建议转人工（先询问用户）
        "conditions": [
            "对话超过 8 轮未解决",
            "知识检索无结果",
            "用户表现出困惑",
        ],
        "action": "先询问'是否需要转接人工客服？'"
    }
}
```

#### 2. 情绪检测集成

```python
SENTIMENT_PROMPT = """
```

## 五、Gateway 消息乱序

### 问题现象

- 用户连续发送多条消息，顺序错乱
- Agent 回复与用户问题不匹配

### 解决方案

```python
# 消息队列 + 顺序保证
from collections import deque
import asyncio

class MessageQueue:
    def __init__(self):
        self.queue = deque()
        self.processing = False
    
    async def enqueue(self, message: dict):
        self.queue.append(message)
        if not self.processing:
            await self.process()
    
    async def process(self):
        self.processing = True
        while self.queue:
            message = self.queue.popleft()
            await handle_message(message)
        self.processing = False
```

## 六、LLM 回答幻觉

### 问题现象

- Agent 编造不存在的产品功能
- 回答中包含错误的价格信息
- 引用不存在的文档

### 解决方案

```python
# 幻觉检测与抑制
HALLUCINATION_PROMPT = """
验证以下回答是否基于提供的知识片段。

知识片段：
{knowledge}

回答：{answer}

请检查：
1. 回答中的每个事实是否都能在知识片段中找到依据
2. 是否有编造的信息
3. 是否有超出知识范围的推测

返回 JSON：
{{"has_hallucination": true/false, "hallucinated_parts": [...], "verdict": "..."}}
"""

# 在回复用户前执行幻觉检测
def safe_reply(knowledge: list, draft_answer: str) -> str:
    check = detect_hallucination(knowledge, draft_answer)
    if check["has_hallucination"]:
        # 重新生成，加入更强的约束
        return regenerate_with_constraints(knowledge, check["hallucinated_parts"])
    return draft_answer
```

## 七、性能与延迟问题

### 常见问题

| 问题 | 影响 | 解决 |
|------|------|------|
| LLM API 延迟 3-5s | 用户体验差 | 使用流式输出（SSE） |
| 向量检索慢 | 响应超时 | 建立索引 + 缓存热门查询 |
| Memory 读写频繁 | I/O 瓶颈 | 引入本地缓存层 |
| 多 Agent 串行调用 | 累积延迟 | 并行化独立 Agent 调用 |

### 优化方案

```bash
# 1. 启用流式输出
hermes config set llm.streaming true

# 2. 配置缓存
hermes config set cache.enabled true
hermes config set cache.ttl 3600  # 1小时缓存
hermes config set cache.max_size 1000

# 3. 知识库查询缓存
hermes config set knowledge.cache.enabled true
hermes config set knowledge.cache.ttl 300  # 5分钟
```

## 八、用户隐私与安全

### 注意事项

1. **敏感信息脱敏**：手机号、身份证号在日志中自动脱敏
2. **对话数据隔离**：不同用户的数据严格隔离
3. **API Key 管理**：使用环境变量而非硬编码
4. **审计日志**：所有转人工操作记录可追溯

```python
# 敏感信息脱敏
def desensitize(text: str) -> str:
    import re
    # 手机号
    text = re.sub(r'1[3-9]\d{9}', lambda m: m.group()[:3] + '****' + m.group()[7:], text)
    # 身份证
    text = re.sub(r'\d{17}[\dXx]', lambda m: m.group()[:6] + '********' + m.group()[-4:], text)
    # 邮箱
    text = re.sub(r'[\w\.-]+@[\w\.-]+\.\w+', lambda m: m.group()[:2] + '***@***' + m.group()[-4:], text)
    return text
```
