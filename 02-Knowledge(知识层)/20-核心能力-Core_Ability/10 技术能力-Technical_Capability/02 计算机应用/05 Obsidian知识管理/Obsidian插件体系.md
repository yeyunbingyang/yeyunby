# Obsidian 插件体系

## 一句话结论

> Obsidian 的插件生态是其最强大的竞争力——核心插件提供基础功能开关，社区插件提供无限扩展能力。插件按需安装，避免臃肿。

## 核心插件 vs 社区插件

| 维度 | 核心插件 | 社区插件 |
|------|---------|----------|
| 来源 | Obsidian 内置 | 第三方开发者 |
| 安装 | 预装，只需开关 | 需要在社区插件市场浏览安装 |
| 安全性 | 官方维护，完全可信 | 经过官方审核，沙箱限制 |
| 更新 | 随 Obsidian 版本更新 | 独立更新，在设置中一键升级 |
| 数量 | 33 个 | 2000+ 个 |

### 当前启用的核心插件（22 个）

文件浏览器、全局搜索、快速切换器、图谱、反向链接、白板、出链、标签窗格、属性、页面预览、日记、模板、笔记重组器、命令面板、编辑器状态、书签、大纲、字数统计、文件恢复、同步、Bases、显示行号

### 当前禁用的核心插件（11 个）

脚注、斜杠命令、Markdown 导入器、ZK 前缀器、随机笔记、幻灯片、录音机、工作区、发布、Web 查看器、严格换行符

## 社区插件安装流程

```
设置 → 社区插件 → 关闭"安全模式" → 浏览 → 搜索插件名 → 安装 → 启用 → 配置
```

1. **关闭安全模式**：首次使用社区插件需要确认
2. **浏览市场**：搜索插件名或浏览分类
3. **安装**：点击安装，文件下载到 `.obsidian/plugins/插件名/`
4. **启用**：安装后在插件列表开启
5. **配置**：每个插件有自己的配置面板（设置 → 该插件的选项）

## 插件安全

- 社区插件须经过 Obsidian 官方审核才能上架
- 插件运行在沙箱环境中，限制了对系统的访问
- 插件代码开源，可在 GitHub 审查
- 安装前可查看插件下载量、评分、更新频率

## 插件管理

### 目录结构

```
.obsidian/plugins/
├── dataview/           # 每个插件一个文件夹
│   ├── main.js         # 插件代码
│   ├── manifest.json   # 插件元信息
│   ├── styles.css      # 样式
│   └── data.json       # 插件配置（用户自定义）
├── calendar/
└── ...
```

### 备份说明

- `plugins/` 整个目录被 `.gitignore` 排除（不随 Git 备份）
- 插件列表通过 `community-plugins.json` 记录
- 新设备上 Obsidian 会读取 `community-plugins.json`，自动提示安装
- 插件配置（`data.json`）也随之排除，新设备需重新配置
- 详见 [[Obsidian设置与个性化#备份策略]]

## 反例与边界

- ❌ 插件不是越多越好——每个插件增加启动时间和潜在冲突
- ❌ 不要安装功能重叠的插件（如 Claudian + SuperMind）
- ⚠️ 插件更新后可能出现兼容问题，注意看更新日志
- ⚠️ 启动慢时，先排查是否为插件过多（设置 → 插件 → 查看加载时间）

## 可行动建议

- 定期审查已安装插件，禁用不常用的（减少启动时间）
- 关注核心插件的更新——Obsidian 版本升级时可能新增核心插件
- 建议启用 Templater，激活模板中的动态日期功能
