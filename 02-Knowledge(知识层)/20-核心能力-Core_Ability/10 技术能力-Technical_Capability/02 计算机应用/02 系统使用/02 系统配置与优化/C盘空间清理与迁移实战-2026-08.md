# C盘空间清理与迁移实战-2026-08

> [!success] 本次结果
> C盘总容量 268.02 GB；可用空间从 0.16 GB 恢复至 17.99 GB。核心措施是清理临时文件、NVIDIA 旧驱动缓存、rclone VFS 缓存，并将 Ubuntu WSL 迁移到 D 盘。

## 一、问题与诊断结论

| 项目 | 初始发现 | 处理结论 |
|---|---:|---|
| C盘可用空间 | 0.16 GB | 已恢复至 17.99 GB |
| rclone/OpenList VFS 缓存 | 逻辑 51.15 GB；真实占盘约 8.34 GB | 已清空并迁移到 D 盘 |
| NVIDIA App OTA 驱动包 | 3.64 GB | 已清理 |
| 用户临时目录 | 约 6.29 GB | 清理约 4.88 GB；锁定文件保留 |
| Ubuntu WSL 虚拟磁盘 | 2.51 GB | 已迁移到 D 盘 |
| Docker 虚拟磁盘 | 3.75 GB | 待通过 Docker Desktop 官方界面迁移 |

### rclone 缓存为什么会暴涨

OpenList Desktop 的多个挂载均使用 `--vfs-cache-mode=full`。播放或浏览远程视频时，rclone 会把读取过的数据块写入本地 VFS 缓存；未设置缓存目录时，默认落在：

```text
C:\Users\h2967\AppData\Local\rclone\vfs
```

`full` 模式会保留完整文件缓存。缓存文件通常是稀疏文件，因此“文件逻辑大小”可能远大于实际占盘；评估时要同时看实际分配空间，不能只看文件长度。

清理前必须检查 `vfsMeta` 中是否存在 `Dirty: true`。本次 435 个元数据条目均为 `Dirty: false`，说明没有待上传的本地修改，才可安全清空缓存。

## 二、已实施配置

### 1. rclone/OpenList 视频缓存迁移

缓存目录已改为：

```text
D:\rclone-cache
```

三个挂载（夸克、PikPak、all）均加入以下参数：

```text
--cache-dir=D:\rclone-cache
--vfs-cache-mode=full
--vfs-cache-max-size=20G
--vfs-cache-max-age=24h
```

这会将视频缓存限制在 D 盘 20 GB 内，并在 24 小时后自动淘汰。配置备份位于：

```text
C:\Users\h2967\AppData\Roaming\OpenList Desktop\settings.json.bak-20260814
```

### 2. Ubuntu WSL 迁移

Ubuntu 使用 WSL 官方导出/导入流程迁移：

```powershell
wsl --shutdown
wsl --export Ubuntu D:\WSL\Ubuntu-pre-migration-20260814.tar
wsl --unregister Ubuntu
wsl --import Ubuntu D:\WSL\Ubuntu D:\WSL\Ubuntu-pre-migration-20260814.tar --version 2
```

迁移后需要恢复默认用户；本机用户为 `h2967`（UID 1000）。验证命令：

```powershell
wsl --distribution Ubuntu --exec sh -lc "whoami; df -h /"
```

最终位置：`D:\WSL\Ubuntu`；导出归档保留在 `D:\WSL\Ubuntu-pre-migration-20260814.tar`，可作为回退备份。

> [!warning] Docker 不要手动移动 VHDX
> `C:\Users\h2967\AppData\Local\Docker\wsl\disk\docker_data.vhdx` 不能直接剪切或改名。应在 Docker Desktop 中通过 **Settings → Resources → Advanced → Disk image location** 选择 `D:\Docker`，再点击 **Apply & Restart**。详见 [Docker 官方设置说明](https://docs.docker.com/desktop/settings-and-maintenance/settings/)。

## 三、C盘长期容量策略

### 容量红线

| C盘可用空间 | 状态 | 行动 |
|---:|---|---|
| < 10 GB | 危险 | 立即诊断和清理 |
| 10–25 GB | 警戒 | 清理缓存并安排迁移 |
| 25–50 GB | 健康 | 每月维护 |
| > 50 GB | 充足 | 保持数据盘分流 |

268 GB 的 C 盘建议长期保持至少 40–55 GB 空闲。系统、驱动、常用软件留在 C 盘；媒体、下载、缓存、容器与虚拟机数据放到 D/F 盘。

### 本机分盘建议

| 盘符 | 建议用途 |
|---|---|
| C: | Windows、驱动、办公软件、常用轻量应用 |
| D: | rclone 缓存、Docker、WSL、开发缓存与临时工作区 |
| F: | 视频、课程、素材、剪映原始媒体、项目归档与大文件 |
| X: | 知识库与文档资产 |

## 四、后续维护清单

- [ ] 在 Docker Desktop 将 Disk image location 迁移到 `D:\Docker`，完成后核验 C 盘旧镜像是否释放。
- [ ] 每月在关闭大型应用后清理 `%LOCALAPPDATA%\Temp`；跳过正在使用的文件。
- [ ] 每季度检查 OpenList 的 `D:\rclone-cache` 是否遵守 20 GB 上限；如频繁满额，可减少缓存时长或调低上限。
- [ ] 在 Adobe Camera Raw、剪映等应用内清理媒体缓存，避免直接删除项目或素材。
- [ ] 若不使用休眠，可评估 `powercfg /h off`；这会释放约 12.65 GB，但会禁用休眠和快速启动。
