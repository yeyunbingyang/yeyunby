# 踩坑记录

> 记录在实施「个人知识库自动整理 Agent」过程中遇到的各种问题及其解决方案。持续更新。

## 1. Hermes 环境相关

### 1.1 Windows 路径中文乱码

**问题**：在 Windows 上使用 `terminal` 工具执行 `find` 命令时，包含中文的路径显示为乱码或无法匹配。

```
# 错误现象
find: 'X:/KMS/yeyunby/03-Knowledge(????????)/...': No such file or directory
```

**原因**：git-bash（MSYS2）的字符编码问题，部分 locale 设置不兼容 UTF-8 中文路径。

**解决方案**：

```bash
# 方案一：在 terminal 命令前设置编码
export LANG=zh_CN.UTF-8
export LC_ALL=zh_CN.UTF-8

# 方案二：使用 MSYS2 路径格式（推荐）
# 将 X:/ 替换为 /x/
find "/x/KMS/yeyunby" -name "*.md"

# 方案三：使用双引号包裹路径
find "X:/KMS/yeyunby" -name "*.md"
```

**最佳实践**：统一使用带双引号的 Windows 路径格式 `"X:/KMS/yeyunby"`。

### 1.2 Hermes 工具集未启用

**问题**：调用 `terminal`、`memory` 等工具时提示 "Tool not available"。

**原因**：新安装的 Hermes 默认只启用核心工具集，部分工具需要手动启用。

**解决方案**：

```bash
# 查看当前启用的工具集
hermes tools list

# 启用缺失的工具
hermes tools enable terminal
hermes tools enable memory
hermes tools enable cronjob
hermes tools enable session_search

# 重要：工具变更需要重启会话
# 在 CLI 中输入 /reset
# 或在 Gateway 中重启
```

### 1.3 Cron 任务不触发

**问题**：配置的 Cron 任务到期未执行。

**原因**：

1. Hermes 调度器未运行
2. Cron 任务语法错误
3. 任务被暂停

**排查步骤**：

```bash
# 1. 检查调度器状态
hermes cron status

# 2. 列出所有任务及状态
hermes cron list

# 3. 手动触发测试
hermes cron run frontmatter-check

# 4. 如果调度器未运行，重启 Hermes
# CLI 模式：退出重进
# Gateway 模式：hermes gateway restart
```

### 1.4 Memory 不生效

**问题**：Agent 无法记住用户偏好和标签历史。

**原因**：Memory 功能默认关闭，需要显式启用。

**解决方案**：

```bash
# 启用 Memory
hermes config set memory.memory_enabled true
hermes config set memory.user_profile_enabled true

# 确认状态
hermes memory status

# 如果使用外部 Memory 提供者（如 Honcho）
hermes config set memory.provider honcho
```

## 2. Obsidian 相关

### 2.1 Dataview 查询无结果

**问题**：Dataview 查询返回空结果，但笔记确实存在。

```dataview
TABLE file.ctime
FROM "00-Inbox(收件箱)"
```

**原因**：

1. 笔记缺少 frontmatter（Dataview 依赖 frontmatter 字段）
2. 路径格式错误（大小写敏感）
3. 笔记在排除目录中

**排查方法**：

```dataview
-- 先确认笔记是否存在
TABLE file.folder
FROM ""
LIMIT 5

-- 检查是否有 frontmatter
TABLE file.frontmatter.title
FROM ""
WHERE file.frontmatter.title != null
LIMIT 5
```

**解决方案**：确保笔记有完整的 YAML frontmatter。

### 2.2 Templater 模板变量不展开

**问题**：使用 Templater 模板创建笔记时，`<% tp.* %>` 变量未被替换。

**原因**：

1. 模板文件不在 Templater 配置的模板目录中
2. 使用了错误的触发方式（需要手动触发 Templater 而不是粘贴模板内容）

**解决方案**：

```yaml
# 在 Templater 设置中确认
Template folder location: _templates/

# 使用快捷键触发模板
Alt + E (默认) → 选择模板

# 或使用命令面板
Ctrl/Cmd + P → "Templater: Insert template"
```

### 2.3 Vault 路径包含括号导致脚本失败

**问题**：Shell 脚本中 vault 路径包含 `(` 和 `)` 导致解析错误。

```
# 错误
find X:/KMS/yeyunby/02-Knowledge(知识层) -name "*.md"
# bash: 语法错误 near unexpected token `('
```

**解决方案**：

```bash
# 始终使用双引号包裹路径
find "X:/KMS/yeyunby/02-Knowledge(知识层)" -name "*.md"

# 或转义括号
find X:/KMS/yeyunby/03-Knowledge\(知识层\) -name "*.md"
```

## 3. Git 操作相关

### 3.1 Vault 未初始化 Git 仓库

**问题**：Agent 执行 `git log` 或 `git status` 时提示 "not a git repository"。

**原因**：vault 目录未执行 `git init`。

**解决方案**：

```bash
cd "X:/KMS/yeyunby"
git init
git add .
git commit -m "chore: 初始化知识库 Git 仓库"
```

### 3.2 大文件导致 Git 操作缓慢

**问题**：vault 中包含图片、PDF 等大文件，导致 `git status` 和 `git add` 极慢。

**解决方案**：

```bash
# 创建 .gitignore 排除非 Markdown 文件
cat > "X:/KMS/yeyunby/.gitignore" << 'EOF'
# 排除附件（可选，视需求而定）
*.png
*.jpg
*.jpeg
*.gif
*.pdf
*.xlsx
*.docx

# Obsidian 工作区
.obsidian/workspace
.obsidian/cache

# 临时文件
.trash/
*.tmp
.DS_Store
EOF
```

### 3.3 Git 换行符警告

**问题**：Windows 上 Git 提示 "LF will be replaced by CRLF"。

**原因**：跨平台换行符处理差异。

**解决方案**：

```bash
# 配置 Git 换行符处理
git config core.autocrlf input

# 或在 vault 根目录创建 .gitattributes
echo "* text=auto" > "X:/KMS/yeyunby/.gitattributes"
```

## 4. Agent 流程相关

### 4.1 LLM 标签推荐偏差

**问题**：Agent 推荐的标签过于宽泛（如 "technology"、"knowledge"），或完全脱离已有标签体系。

**原因**：LLM 缺乏对 vault 已有标签体系的了解，倾向于生成通用标签。

**解决方案**：

1. 在提示词中注入已有标签列表
2. 使用 Memory 存储用户偏好的标签风格
3. 添加后处理规则过滤过宽泛的标签

```bash
# 提取 vault 中所有已有标签
find "X:/KMS/yeyunby" -name "*.md" -not -path "*/.obsidian/*" | \
  xargs grep -h "^tags:" | \
  sed 's/tags: \[//;s/\]//;s/, /\n/g' | \
  sort -u > /tmp/existing_tags.txt
```

### 4.2 链接检查误报

**问题**：Agent 报告死链，但目标文件实际存在。

**原因**：

1. Obsidian 支持 `[[target|alias]]` 和 `[[target#section]]` 格式，解析不完整
2. 文件名大小写不匹配（Windows 不区分大小写，但 `find` 区分）
3. 目标文件在排除目录中（如归档目录）

**解决方案**：在链接检查脚本中添加更完善的解析逻辑：

```bash
# 改进的链接解析
extract_target() {
  local link="$1"
  # 去除别名 [[target|alias]] → target
  target=$(echo "$link" | sed 's/\[\[//;s/\]\]//' | cut -d'|' -f1)
  # 去除章节锚点 [[target#section]] → target
  target=$(echo "$target" | cut -d'#' -f1)
  echo "$target"
}

# 不区分大小写的查找
find_target() {
  local name="$1"
  find "X:/KMS/yeyunby" -iname "${name}.md" 2>/dev/null | head -1
}
```

### 4.3 关联推荐重复

**问题**：每次运行的关联推荐结果高度重复，缺乏新鲜感。

**原因**：基于关键词和标签的相似度计算方式导致同一组笔记反复被推荐。

**解决方案**：

1. 记录已推荐的关联，避免重复
2. 引入随机采样，每次从 Top N 中随机选择
3. 增加时间衰减因子，优先推荐近期修改的笔记

```bash
# 记录已推荐的关联
hermes chat -q "
将以下关联推荐记录保存到 Memory：
已为笔记 A 推荐了笔记 B、C，推荐日期 2026-07-07
下次为笔记 A 推荐时，排除这些已推荐的笔记。
"
```

### 4.4 Cron 任务输出过长

**问题**：Cron 任务生成的报告过长，超出消息长度限制。

**原因**：全库扫描时发现大量问题，一次性输出所有结果。

**解决方案**：

1. 分批处理：每次只扫描一个子目录
2. 汇总统计：只输出统计摘要，详细列表保存到文件
3. 设置优先级：只报告严重问题（缺失 frontmatter），忽略轻微问题

```bash
# 分批处理示例：按目录逐层扫描
hermes cron create "every 6h" \
  --name "frontmatter-check-inbox" \
  --prompt "仅扫描 00-Inbox(收件箱) 目录的 frontmatter 完整性" \
  --deliver chat

hermes cron create "every 12h" \
  --name "frontmatter-check-core" \
  --prompt "仅扫描 20-核心能力-Core_Ability 目录的 frontmatter 完整性" \
  --deliver chat
```

## 5. 性能相关

### 5.1 全库扫描耗时过长

**问题**：首次全库扫描数千个文件耗时数分钟。

**原因**：Agent 逐文件读取并分析内容。

**优化方案**：

```bash
# 1. 使用 find + grep 快速扫描（秒级）
find "X:/KMS/yeyunby" -name "*.md" | wc -l

# 2. 只扫描最近修改的文件
find "X:/KMS/yeyunby" -name "*.md" -mtime -7

# 3. 分批扫描，每次 50 个文件
find "X:/KMS/yeyunby" -name "*.md" | head -50
```

### 5.2 Memory 查询超时

**问题**：Agent 在查询 Memory 时长时间无响应。

**原因**：Memory 存储了大量历史记录，查询未加限制。

**解决方案**：在提示词中明确限制 Memory 查询范围：

```
## Memory 查询限制
- 只查询最近 30 天的标签偏好记录
- 只查询与当前笔记标签相关的历史
- 最多返回 10 条记录
```

## 6. 其他

### 6.1 路径格式混用

**问题**：Windows 路径格式 `X:\...`、`X:/...`、`/x/...` 混用导致混乱。

**约定**：统一使用带双引号的 `"X:/KMS/..."` 格式（正斜杠 + 引号），在所有 Hermes 命令和脚本中保持一致。

### 6.2 Agent 幻觉：建议不存在的 Obsidian 功能

**问题**：Agent 有时会建议使用 Obsidian 不存在的功能或插件。

**原因**：LLM 训练数据中包含其他笔记软件的功能，产生混淆。

**解决方案**：在提示词中明确约束：

```
## 约束
- 只推荐 Obsidian 社区插件市场存在的插件
- 只使用 Dataview 官方文档支持的查询语法
- 只使用 Templater 官方文档支持的模板语法
- 不确定的功能先说明 "请查阅官方文档确认"
```

### 6.3 多个 Agent 同时修改同一文件

**问题**：Frontmatter 检测 Agent 和标签推荐 Agent 同时修改同一笔记，导致冲突。

**解决方案**：

1. 使用 Kanban 任务板协调：一个文件同时只能被一个 Agent 处理
2. 串行化流程：Frontmatter 补全 → 标签推荐 → 关联推荐（依赖链）
3. 使用 Git 检测冲突：`git diff` 检查是否有未合并的变更

```bash
# 在操作前检查 Git 状态
cd "X:/KMS/yeyunby"
git status --short
# 如果有未提交的变更，先提交再操作
```
