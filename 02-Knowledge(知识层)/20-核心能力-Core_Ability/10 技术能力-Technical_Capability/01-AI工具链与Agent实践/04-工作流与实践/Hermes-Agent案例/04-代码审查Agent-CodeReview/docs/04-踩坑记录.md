# 踩坑记录

## 1. API 限流

### 问题描述
GitHub API 返回 `403 rate limit exceeded` 错误，导致审查流程中断。

### 原因分析
- GitHub API 未认证请求限制 60 次/小时
- 认证用户限制 5000 次/小时
- 多个 PR 同时触发时，请求量激增
- Webhook 重试机制导致重复请求

### 解决方案

**方案一：配置 Token 认证**
```bash
# 确保使用认证 Token
hermes config set github.token "ghp_xxxxxxxxxxxxxxxxxxxx"

# 验证 Token 是否生效
curl -H "Authorization: token ghp_xxxxxxxxxxxxxxxxxxxx" \
  https://api.github.com/rate_limit
```

**方案二：实现请求缓存**
```yaml
# .hermes/config.yaml
github:
  cache:
    enabled: true
    ttl: 300  # 缓存 5 分钟
    max_size: 1000
```

**方案三：请求队列与限流**
```python
# 伪代码：请求队列实现
import asyncio
from aiolimiter import AsyncLimiter

# 创建限流器：每秒最多 10 个请求
rate_limiter = AsyncLimiter(10, 1)

async def github_api_call(endpoint, params):
    async with rate_limiter:
        return await call_github_api(endpoint, params)
```

**方案四：Webhook 去重**
```yaml
# .hermes/webhooks/github-pr.yaml
config:
  deduplication:
    enabled: true
    window: 60  # 60 秒内的重复事件忽略
    key: "pull_request.head.sha"  # 基于 commit SHA 去重
```

## 2. 大文件审查超时

### 问题描述
审查包含大量文件变更或超大文件的 PR 时，分析过程超时（> 30 秒）。

### 原因分析
- ESLint/PyLint 对大型文件分析耗时
- AI 审查的 Token 消耗过大
- 网络传输大文件耗时
- Hermes Webhook 默认超时 30 秒

### 解决方案

**方案一：分片处理**
```yaml
# .hermes/config.yaml
review:
  max_diff_size: 500000  # 最大审查文件大小（500KB）
  max_files_per_pr: 50   # 单次 PR 最大审查文件数
  chunk_size: 10         # 每批处理文件数
  chunk_delay: 2         # 批次间隔（秒）
```

**方案二：异步处理**
```yaml
# .hermes/webhooks/github-pr.yaml
config:
  async_mode: true  # 异步模式：立即返回 200，后台处理
  callback_url: "http://your-server:8080/webhook/callback"
```

**方案三：增量审查**
```python
# 伪代码：增量审查逻辑
async def incremental_review(pr_number, base_sha, head_sha):
    # 获取新增变更（相对于上次审查）
    diff = await get_diff_between(base_sha, head_sha)
    
    # 仅审查新增/修改的部分
    if is_incremental:
        results = await review_changes(diff)
        # 合并到已有审查结果
        await append_to_existing_review(pr_number, results)
    else:
        results = await full_review(pr_number)
```

**方案四：跳过大型二进制文件**
```yaml
# .hermes/config.yaml
review:
  excluded_paths:
    - "*.min.js"
    - "*.min.css"
    - "*.map"
    - "*.png"
    - "*.jpg"
    - "*.svg"
    - "*.ico"
    - "vendor/"
    - "node_modules/"
    - "dist/"
    - "build/"
    - "package-lock.json"
    - "yarn.lock"
```

## 3. 误报率高

### 问题描述
AI 审查报告了大量误报（false positives），开发者对审查结果信任度降低。

### 原因分析
- LLM 对代码上下文理解不足
- 审查规则过于严格
- 未考虑项目特定的编码规范
- 缺乏项目历史数据的校准

### 解决方案

**方案一：降低 AI 审查温度**
```bash
# 降低 LLM 温度，减少随机性
hermes profile config reviewer set temperature 0.2
```

**方案二：配置项目特定规则**
```yaml
# .hermes/skills/code-review-rules.yaml
rules:
  # 项目特定的允许模式
  allow_patterns:
    - "console.log"  # 开发阶段允许
    - "TODO"         # 跟踪待办事项
    - "FIXME"        # 跟踪修复项
    - "eslint-disable"  # 明确禁用的规则
  
  # 项目特定的忽略路径
  ignore_paths:
    - "**/__tests__/**"
    - "**/*.test.*"
    - "**/*.spec.*"
    - "**/migrations/**"
    - "**/generated/**"
```

**方案三：建立反馈循环**
```yaml
# .hermes/config.yaml
review:
  feedback_loop:
    enabled: true
    # 开发者可以通过评论标记误报
    dismiss_command: "/review-dismiss"
    # 记录误报到 Memory，用于后续校准
    learn_from_dismissals: true
```

**方案四：分级审查策略**
```yaml
# 根据文件变更类型使用不同的审查严格度
review:
  severity_levels:
    production:
      - "src/**"
      - "lib/**"
      strictness: high
    test:
      - "tests/**"
      - "__tests__/**"
      strictness: low
    config:
      - "*.config.*"
      - ".eslintrc*"
      strictness: medium
    documentation:
      - "*.md"
      - "docs/**"
      strictness: low
```

## 4. 权限不足

### 问题描述
审查 Agent 无法执行合并操作、无法读取私有仓库、无法添加标签。

### 原因分析
- GitHub Token 权限不足
- Token 未授予必要的 Scope
- 仓库设置限制了机器人操作
- 分支保护规则阻止自动合并

### 解决方案

**方案一：配置正确的 Token Scope**
```bash
# GitHub Token 需要以下权限
# - repo (全部) — 私有仓库访问
# - pull_requests — PR 读写
# - issues — 评论和标签

# 在 GitHub Settings → Developer settings → Personal access tokens 中创建
# 或使用 GitHub CLI
gh auth login --scopes "repo,workflow"
```

**方案二：配置仓库权限**
```yaml
# 仓库 Settings → Actions → General → Workflow permissions
# 勾选 "Read and write permissions"
# 勾选 "Allow GitHub Actions to create and approve pull requests"
```

**方案三：处理分支保护**
```yaml
# 如果分支有保护规则，自动合并可能失败
# 解决方案：使用 GitHub API 的 merge 方法绕过部分限制
# 或配置分支保护规则允许机器人合并

# 分支保护规则配置：
# Settings → Branches → Branch protection rule
# - 取消勾选 "Require pull request reviews before merging"
# - 或添加机器人到豁免列表
```

**方案四：使用 GitHub App（推荐）**
```bash
# GitHub App 提供更细粒度的权限控制
# 相比 Personal Access Token，GitHub App 支持：
# - 按仓库授权
# - 更细粒度的权限
# - 独立的速率限制配额

# 创建 GitHub App 后，安装到目标仓库
# 使用 App 的 Installation Token 替代 Personal Token
```

## 5. Webhook 未触发

### 问题描述
提交 PR 后，Hermes 未收到 Webhook 事件，审查流程未启动。

### 原因分析
- Webhook URL 不可达（内网环境）
- Webhook Secret 不匹配
- 事件类型未正确配置
- GitHub 端网络问题
- Hermes Webhook 服务未启动

### 解决方案

**方案一：检查 Webhook 投递状态**
```bash
# 在 GitHub 仓库中查看 Webhook 投递记录
# Settings → Webhooks → 点击对应 Webhook → Recent Deliveries

# 查看响应状态码和响应体
# 200 = 成功
# 其他 = 查看错误信息
```

**方案二：内网穿透**
```bash
# 如果 Hermes 运行在内网，使用内网穿透工具
# 方案 A：ngrok
ngrok http 8080
# 输出：https://xxxx.ngrok.io → http://localhost:8080
# 将 Webhook URL 设置为 https://xxxx.ngrok.io/webhook/github

# 方案 B：frp
# frps.ini（服务端）
[common]
bind_port = 7000

# frpc.ini（客户端）
[common]
server_addr = your-server
server_port = 7000

[web]
type = http
local_port = 8080
custom_domains = your-domain.com
```

**方案三：验证 Webhook 配置**
```bash
# 测试 Webhook 端点
curl -X POST http://localhost:8080/webhook/github \
  -H "Content-Type: application/json" \
  -H "X-GitHub-Event: pull_request" \
  -H "X-Hub-Signature-256: sha256=..." \
  -d '{"action": "opened", "number": 1, "pull_request": {...}}'

# 查看 Hermes 日志
hermes logs --tail 50
```

**方案四：Webhook 配置检查清单**
```markdown
## Webhook 配置检查清单

- [ ] Webhook URL 是否可从公网访问？
- [ ] Secret 是否与 Hermes 配置一致？
- [ ] 事件类型是否勾选了 Pull requests？
- [ ] Content type 是否为 application/json？
- [ ] SSL verification 是否配置正确？
- [ ] Hermes Webhook 服务是否正在运行？
- [ ] 防火墙是否开放了 8080 端口？
- [ ] GitHub 端是否有投递失败记录？
```


### 6.2 并发冲突

**问题**：多个 PR 同时触发审查导致资源竞争。

**解决方案**：
```yaml
# .hermes/config.yaml
review:
  concurrency:
    max_parallel: 3  # 最大并行审查数
    queue_mode: fifo  # 先进先出队列
```

### 6.3 Memory 数据膨胀

**问题**：Hermes Memory 存储了大量审查记录，影响检索性能。

**解决方案**：
```yaml
# .hermes/config.yaml
memory:
  retention:
    max_entries: 10000
    ttl_days: 90  # 90 天后自动清理
    archive_after_days: 30  # 30 天后归档
```

### 6.4 语言检测失败

**问题**：无法识别某些文件的语言类型，跳过分析。

**解决方案**：
```yaml
# .hermes/config.yaml
languages:
  unknown:
    fallback: "ai-only"  # 未知语言仅使用 AI 审查
    extensions: [".vue", ".svelte", ".astro", ".liquid"]
```
