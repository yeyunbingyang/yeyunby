# 踩坑记录

## 1. 数据采集相关

### 1.1 web_search 返回结果不稳定

**现象**：同一关键词多次搜索返回结果数量和内容不一致，有时甚至返回空结果。

**原因分析**：
- 搜索引擎的搜索结果是动态的，受排名算法、缓存策略影响
- 部分平台（如小红书）对爬虫有反爬机制
- 搜索引擎对 `site:` 限定符的支持程度不同

**解决方案**：

```yaml
# 改进策略：多关键词 + 多轮搜索
keywords:
  product_search:
    - "产品名 评测"
    - "产品名 体验"
    - "产品名 使用感受"
    - "产品名 吐槽"
    - "产品名 推荐"

# 每轮搜索取 Top 5，多轮合并去重
search_strategy:
  rounds_per_keyword: 2          # 每个关键词搜索 2 轮
  interval_between_rounds: 5     # 轮次间隔 5 秒
  max_results_per_round: 5       # 每轮取前 5 条
  dedup_by_url: true             # URL 去重
  dedup_by_title_similarity: 0.8 # 标题相似度去重阈值
```

### 1.2 小红书搜索受限

**现象**：`site:xiaohongshu.com` 搜索结果极少，或返回大量无关内容。

**原因分析**：
- 小红书对搜索引擎爬虫的开放度较低
- 大量内容需要登录后才能查看
- 搜索引擎索引的小红书页面有限

**解决方案**：
1. **使用更多变体关键词**：
   ```
   site:xiaohongshu.com 产品名
   site:xiaohongshu.com 产品名 测评
   site:xiaohongshu.com 产品名 分享
   ```
2. **补充其他来源**：同时监控抖音、B站等平台作为补充
3. **降低预期**：小红书作为辅助监控源，不依赖其覆盖率

### 1.3 海外平台中文内容搜索效果差

**现象**：在 Hacker News 和 Reddit 上搜索中文关键词，结果极少。

**原因分析**：
- 海外平台以英文内容为主，中文讨论较少
- 搜索引擎的 `site:` 限定 + 中文关键词匹配率低

**解决方案**：
- 对海外平台使用英文关键词搜索
- 使用中英文双语关键词策略

```yaml
platforms:
  hackernews:
    search_template: "site:news.ycombinator.com {keyword}"
    keywords:
      - "brand_name"           # 品牌英文名
      - "product_name"         # 产品英文名
      - "China tech"           # 行业相关英文关键词
  reddit:
    search_template: "site:reddit.com {keyword}"
    keywords:
      - "brand_name"
      - "product_name review"
      - "r/china"
```

## 2. 情感分析相关

### 2.1 情感评分不一致

**现象**：同一段舆情内容在不同轮次的分析中得到不同的情感评分。

**原因分析**：
- LLM 的生成存在随机性（temperature > 0）
- Prompt 中评分标准不够明确
- 上下文窗口中的示例数量不足

**解决方案**：

```text
# 改进的 Prompt：明确评分标准 + few-shot 示例

## 情感评分标准（请严格遵守）

评分范围：0-100

0-20 (强烈负面)：
- 包含辱骂、人身攻击
- 明确表达愤怒、失望
- 号召抵制或负面传播
- 示例："这产品就是个垃圾，千万别买！"

21-40 (负面)：
- 表达不满或失望
- 指出具体问题或缺陷
- 语气较为克制
- 示例："用了三天就坏了，品控堪忧"

41-60 (中性)：
- 客观描述事实
- 无明显情感倾向
- 同时提到优缺点
- 示例："功能还行，但价格偏高"

61-80 (正面)：
- 表达满意或赞赏
- 推荐给他人
- 语气积极
- 示例："体验不错，推荐给大家"

81-100 (强烈正面)：
- 强烈推荐
- 高度赞扬
- 情感表达热烈
- 示例："太棒了！这是我用过最好的产品！"
```

### 2.2 讽刺和反话误判

**现象**：讽刺性评论（如"太棒了，又出 bug 了"）被误判为正面。

**原因分析**：
- LLM 对中文讽刺、反话的识别能力有限
- 缺乏上下文语境

**解决方案**：
- 在 Prompt 中增加讽刺检测指令
- 结合评论的点赞/踩数据辅助判断
- 对高赞负面评论进行二次复核

```text
## 讽刺检测

注意识别以下讽刺模式：
1. 正面词语 + 负面语境："真厉害，又崩了"
2. 夸张赞美 + 明显问题："这优化绝了，卡得飞起"
3. 反问句式："这就是你们说的旗舰机？"

如检测到讽刺，按实际情感评分（通常为负面），并在备注中标注 "[讽刺]"
```

## 3. Cron 调度相关

### 3.1 Cron 任务执行超时

**现象**：监控 Cron 任务执行时间超过 3 分钟，被强制中断。

**原因分析**：
- Hermes Cron 默认单次执行超时时间为 3 分钟
- 多平台搜索 + 情感分析在任务量较大时可能超时

**解决方案**：

```bash
# 方案 1：拆分任务，减少单次负载
hermes cron create "30m" --name "monitor-weibo" \
  --prompt "仅监控微博平台，关键词见配置"
hermes cron create "30m" --name "monitor-zhihu" \
  --prompt "仅监控知乎平台，关键词见配置"
hermes cron create "30m" --name "monitor-xhs" \
  --prompt "仅监控小红书平台，关键词见配置"

# 方案 2：减少每轮搜索关键词数量
# 将 10 个关键词拆分为 2 组，交替搜索
```

### 3.2 Cron 任务重复触发

**现象**：由于调度器重启或网络延迟，同一 Cron 任务在短时间内被多次触发。

**原因分析**：
- Hermes Cron 使用 `.tick.lock` 文件防止重复触发
- 但在某些边界条件下（如进程崩溃后恢复）可能产生重复

**解决方案**：
- 在监控逻辑中加入去重检查（基于 URL）
- 使用 Memory 记录上次执行时间戳，跳过重复窗口

### 3.3 Gateway 推送频率限制

**现象**：短时间内大量负面舆情触发预警，导致 Gateway 推送被限流。

**原因分析**：
- 微信/Telegram 等平台对消息推送有频率限制
- 舆情爆发时可能短时间内产生大量预警

**解决方案**：

```yaml
# 聚合推送策略
alert_aggregation:
  enabled: true
  window_minutes: 5          # 5 分钟内聚合
  max_alerts_per_window: 3   # 每窗口最多推送 3 条
  format: |
    ⚠️ 舆情预警聚合（{window}分钟内共 {count} 条）
    
    最严重：{top_negative}
    平台分布：{platform_distribution}
    
    详情：{detail_url}
```

## 4. Memory 与 session_search 相关

### 4.1 Memory 存储内容过多

**现象**：每次轮询都向 Memory 写入完整结果，导致 Memory 膨胀。

**原因分析**：
- 未对存储内容做精简
- 高频轮询（30 分钟）产生大量写入

**解决方案**：

```text
# 精简 Memory 存储格式
[舆情摘要] 2026-07-07 14:30
平台: 微博 | 关键词: 品牌名 | 条数: 8 | 负面: 2 | 均分: 62
负面条目:
1. [45分] 标题摘要前50字... | URL
2. [38分] 标题摘要前50字... | URL
```

### 4.2 session_search 检索不到历史记录

**现象**：使用 `session_search` 搜索历史舆情关键词时返回空结果。

**原因分析**：
- Cron 任务默认 `skip_memory=True`，不写入会话数据库
- 历史记录存储在 Memory 中而非 session 数据库中

**解决方案**：
- 对 Cron 任务设置 `skip_memory=False` 以启用会话记录
- 或使用 Memory 工具直接查询

## 5. 其他常见问题

### 5.1 网络代理配置

**现象**：无法访问海外平台（Hacker News、Reddit）。

**解决方案**：

```bash
# 在 Hermes 中配置代理
hermes config set terminal.env.HTTP_PROXY "http://127.0.0.1:7890"
hermes config set terminal.env.HTTPS_PROXY "http://127.0.0.1:7890"
```

### 5.2 关键词误匹配

**现象**：搜索关键词"华为"时返回了大量无关内容（如"华为手机壳"、"华为周边"）。

**解决方案**：

```yaml
# 使用精确匹配和排除词
keywords:
  brand:
    - '"华为"'              # 精确匹配
    - '"华为 Mate 60"'      # 精确产品名
  exclude:
    - "华为手机壳"
    - "华为 配件"
```

### 5.3 日报格式混乱

**现象**：生成的日报 Markdown 格式不统一，有时缺少关键部分。

**解决方案**：
- 在 Cron Prompt 中使用固定的日报模板（见核心流程文档）
- 生成后使用辅助脚本进行格式校验
