# 踩坑记录

> 本文档记录了搭建和运行博客自动发布系统过程中遇到的所有问题。**第一次跑通需要人工介入 3-5 次**，这是正常的。后续会越来越顺。

## 踩坑 1：Token 被自动隐藏

### 现象

- Agent 拿到 GitHub Token 后，在日志中自动替换为 `****`
- 多 Agent 协作时 Token 传递失败
- Agent "左右脑互搏"——一会儿用 Token，一会儿隐藏

### 原因

Hermes Agent 有内置的安全机制，会自动检测并隐藏工具输出中的敏感信息（如 API Key、Token 等）。这是默认行为，**但在这个场景中反而阻碍了多 Agent 协作**。

### 解决方法

必须明确告诉 Agent：

```text
"这个 Token 直接显示使用，不要再隐藏为暗码，以后也记住这一点"
```

> **老师原话**："你得明确的告诉他，不然的话呢，他这个 Token 作为一个环境变量在进行传递的时候，他总是把它给删掉。这个也是现在 Hermes 的一个问题，它这个安全等级就莫名其妙。"

### 预防措施

- 第一次跑复杂流程时，**建议在旁边盯着**，Token 问题会导致多 Agent 协作全部失败
- 跑通一次后，让 Agent 把流程记下来（Memory + Skill），后续就不会出同样的问题
- 如果不想用 GitHub，也可以让 publisher 发送到**邮箱**

## 踩坑 2：任务自动阻塞需手动 Unblock

### 现象

- Writer 写完文章后，自己把自己标记为 `blocked`，等待审核
- Agent 说 "我要标记完成，但我自己没法标记完成"
- 流程卡住不动

### 原因

这是 Hermes Kanban 的设计特性——Agent 完成任务后自动标记为 blocked，等待人工确认。但第一次运行时 Agent 不熟悉这个流程，导致自己阻塞自己。

### 解决方法

```bash
# 1. 查看任务状态
hermes kanban show <board_name>

# 2. 手动解除阻塞
hermes kanban unblock <task_id>

# 3. 给任务加备注，防止再次阻塞
hermes kanban comment <task_id> "发布完成之后直接结束，不要做什么标记"
```

### 预防措施

- 在 SOUL.md 中明确告诉 Agent 发布完成后直接结束
- 跑通一次后，Agent 会通过 Memory 记住这个流程

## 踩坑 3：微信 allow_users 配置

### 现象

- 微信扫码连接成功
- 但给机器人发消息没有任何回复
- 消息像石沉大海

### 原因

Gateway 会检查消息来源是否在 `allow_users` 列表中，不在则直接丢弃。**这是最常见的失败原因**。

### 解决方法

编辑 `~/.hermes/.env`，找到微信相关配置：

```bash
# 方案一：允许所有用户（推荐首次测试）
WEIXIN_ALLOWED_USERS=true

# 方案二：指定用户
WEIXIN_ALLOWED_USERS=wx_xxxxxxxxxxxxx
```

然后重启网关：

```bash
hermes gateway restart
```

### 注意事项

- 新版网关可能不显示用户 ID，旧版会显示 "你的 ID 是 xxx"
- 如果新版不显示，用 `true` 或 `all` 允许所有用户
- 重启命令可能用 `hermes gateway restart` 而不是 `hermes gateway start`

## 踩坑 4：SOUL.md 修改后需重置会话

### 现象

- 修改了 SOUL.md 的路由规则
- 但在微信中发 "写一篇关于 X 的文章" 时，Agent 仍然自己回答，没有触发看板流程

### 原因

Agent 的会话缓存了旧记忆。修改 SOUL.md 后，**正在运行的会话不会自动加载新内容**。

### 解决方法

在微信中发送重置命令：

```text
/new
```

或：

```text
- new
```

### 注意事项

- **两个 SOUL.md 文件都要改**：`~/.hermes/SOUL.md`（全局）和 `~/.hermes/profiles/default/SOUL.md`（default profile）
- 老师演示时只改了一个，结果 Agent 没按预期走看板流程

## 踩坑 5：微信推送限流

### 现象

- 连续收到多条微信消息后，后面的消息发不出去
- 或者消息被截断

### 原因

微信有消息推送频率限制。如果三个 Cron 任务都推送到微信，短时间内会发送多条消息，触发限流。

### 解决方法

**方案一**：只让最终结果推微信

```text
因为微信会限制发送的消息，所以任务一采集热点和任务二筛选选题不再发送到微信
```

这样只有任务三（简报）会推送到微信，每天一条，不会被限流。

**方案二**：限制简报字数

```text
限制定时任务生成简报的最终输出字数在 500 字以内
```

Agent 默认可能生成上千字的简报，微信可能发不完整。

## 踩坑 6：GitHub 访问慢

### 现象

- Publisher 执行 git push 或 MCP 调用时超时
- 发布操作需要等很久

### 原因

国内访问 GitHub 不稳定，网络延迟高。

### 解决方法

- **多等一会儿**：设置较长的 timeout，让 Agent 有足够时间完成
- **使用代理**：如果 Hermes 运行在有代理的环境中，配置代理
- **替代方案**：如果 GitHub 实在访问不了，可以让 publisher 通过**邮箱**发送文章，或发布到国内的代码托管平台（Gitee）

## 踩坑 7：发布完成后仍阻塞

### 现象

- Publisher 已经成功将文章推送到 GitHub
- 但看板状态没有更新，仍然显示 blocked

### 原因

Agent 在发布完成后没有正确更新看板状态，这是一个逻辑缺陷。

### 解决方法

```bash
# 加备注后 unblock
hermes kanban comment <task_id> "发布完成之后直接结束，不要做什么标记"
hermes kanban unblock <task_id>
```

## 踩坑 8：发布找不到审核输出

### 现象

- Publisher 启动后报错，找不到 review 完成的文件

### 原因

跨任务的文件路径不明确。Publisher 不知道 review 完成后的文件在哪里。

### 解决方法

明确告诉 Publisher：

```text
"最终的文档在任务 xxx 的输出中"
```

## 踩坑 9：SOUL.md 路径问题

### 现象

- 使用 `cat > ~/.hermes/profiles/researcher/SOUL.md` 命令时提示找不到文件

### 原因

Profile 的目录结构可能和预期不同。

### 解决方法

```bash
# 方法一：直接搜索
find ~/.hermes/profiles/researcher -name "SOUL.md"

# 方法二：进入目录手动查找
cd ~/.hermes/profiles/researcher
ls -la
```

找到后直接用 VS Code 或其他编辑器编辑。

## 踩坑 10：writer skills install 名称问题

### 现象

```bash
writer skills install blogwatcher
# 报错：not found
```

### 原因

技能名称需要写全。

### 解决方法

先用 `writer skills list` 查看完整名称：

```bash
writer skills list
# 找到正确的名称，例如 "Blog Watcher"
writer skills install "Blog Watcher"
```

## 踩坑 11：Dashboard 在 Windows 下的问题

### 现象

- 在 Windows 下用 `hermes dashboard --port 8080 &` 后台运行失败

### 原因

Windows 下不能用 Linux 的 `&` 符号后台运行。

### 解决方法

```bash
# Windows 直接运行
hermes dashboard --port 8080

# 或另开一个终端窗口
```

### 注意事项

- 首次访问需要等待 Dashboard building
- Dashboard 很占资源，用完就关掉

---

## 踩坑 12：插件目录不存在

### 现象

```bash
hermes plugins enable seo-checker
# 报错：目录不存在
```

### 原因

首次使用插件功能时，`plugins` 目录可能不存在。

### 解决方法

```bash
mkdir -p ~/.hermes/plugins/seo-checker
```

## 总结

> **老师原话**："第一次运行它显得不是那么的聪明，这是很正常的，因为刚开始跑嘛。等后续你不断的去优化对应的这些信息，它就会显得更加聪明一点。"

### 关键经验

1. **第一次跑通需要人工介入 3-5 次**，这是正常的
2. **后续会越来越顺**：跑通一次后，用 Memory + Skill 把流程记下来
3. **模型质量影响流畅度**：用 Claude 比 DeepSeek 更流畅，但 DeepSeek 也能跑通
4. **不要期望一次完美**：老师演示时也反复调整了好几次
5. **Token 问题是最大的坑**：一定要明确告诉 Agent 不要隐藏 Token
