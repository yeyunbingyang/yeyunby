# 踩坑记录

> 本文档记录在搭建和使用 CI/CD 自动化运维 Agent 过程中遇到的常见问题及解决方案。

---

## 一、Webhook 相关问题

### 1.1 Webhook 收不到 GitLab 事件

**现象**：GitLab 推送代码后，Hermes Agent 未触发。

**原因分析**：
1. Webhook URL 不可达（网络/防火墙问题）
2. Secret Token 不匹配
3. Hermes Gateway 未运行

**解决方案**：

```bash
# 1. 检查 Webhook 路由是否创建
hermes webhook list

# 2. 测试 Webhook 路由
hermes webhook test gitlab-push

# 3. 检查 Gateway 日志
grep -i "webhook\|error" ~/.hermes/logs/gateway.log | tail -20

# 4. 确保 Gateway 正在运行
hermes gateway status

# 5. 如果使用内网，检查 GitLab 能否访问 Hermes 地址
# 可使用 ngrok 暴露本地服务
ngrok http 8080
# 然后将 Webhook URL 更新为 ngrok 地址
```

### 1.2 Webhook 签名验证失败

**现象**：收到 `signature verification failed` 错误。

**原因分析**：GitLab/GitHub 的 HMAC 签名与 Hermes 配置不一致。

**解决方案**：

```yaml
# config.yaml 中设置正确的 Secret Token
webhook:
  secrets:
    gitlab-push: "your-gitlab-secret-token"
    github-push: "your-github-secret-token"
```

```bash
# GitLab 侧：Settings → Webhooks → Secret Token 填入相同值
# GitHub 侧：Settings → Webhooks → Secret 填入相同值
```

## 二、Cron 定时任务问题

### 2.1 Cron 任务未按时执行

**现象**：设定的 Cron 任务没有在预期时间触发。

**原因分析**：
1. Hermes 后台进程未运行
2. Cron 调度器未启动
3. 时区设置不正确

**解决方案**：

```bash
# 1. 检查 Cron 任务状态
hermes cron status

# 2. 检查 Cron 列表
hermes cron list

# 3. 手动触发测试
hermes cron run <job-id>

# 4. 检查调度器日志
grep -i "cron\|scheduler" ~/.hermes/logs/gateway.log | tail -20

# 5. 确认时区设置
# Hermes 默认使用系统时区，确保服务器时区正确
timedatectl status
```

### 2.2 No-Agent Cron 脚本执行失败

**现象**：No-Agent 模式的脚本任务执行报错。

**原因分析**：
1. 脚本路径错误
2. 脚本无可执行权限
3. 环境变量未传递

**解决方案**：

```bash
# 1. 使用绝对路径
hermes cron create "0 3 * * *" \
  --script "/opt/cicd-agent/scripts/cleanup.sh" \
  --no-agent

# 2. 确保脚本可执行
chmod +x /opt/cicd-agent/scripts/cleanup.sh

# 3. 在脚本中显式设置 PATH
#!/bin/bash
export PATH="/usr/local/bin:/usr/bin:/bin:$PATH"

# 4. 先在终端中手动测试
bash /opt/cicd-agent/scripts/cleanup.sh
```

## 三、Docker 构建问题

### 3.1 Docker 构建缓存导致问题

**现象**：使用缓存构建的镜像包含旧代码。

**原因分析**：Docker 层缓存未正确失效。

**解决方案**：

```bash
# 1. 构建时禁用缓存（调试用）
docker build --no-cache -t myapp:latest .

# 2. 使用 BuildKit 更精确的缓存策略
export DOCKER_BUILDKIT=1
docker build \
  --cache-from=registry.example.com/myapp:latest \
  -t registry.example.com/myapp:latest .

# 3. 在 Dockerfile 中合理排列指令顺序
# 先 COPY 变化不频繁的文件
COPY package*.json ./
RUN npm ci
# 后 COPY 源代码
COPY . .
```

### 3.2 Docker Registry 推送失败

**现象**：`docker push` 返回认证错误或超时。

**原因分析**：
1. 未登录 Registry
2. Token 过期
3. 镜像标签格式错误

**解决方案**：

```bash
# 1. 登录 Registry
echo "$DOCKER_PASSWORD" | docker login registry.example.com \
  -u "$DOCKER_USERNAME" --password-stdin

# 2. 检查认证信息
cat ~/.docker/config.json | grep registry.example.com

# 3. 确保镜像标签符合 Registry 要求
# 正确: registry.example.com/myapp:v1.2.3
# 错误: myapp:v1.2.3（缺少 Registry 地址）

# 4. 配置 Docker 凭证定时刷新（Token 有效期短的情况）
hermes cron create "0 */6 * * *" \
  --script "/opt/cicd-agent/scripts/docker-login-refresh.sh" \
  --no-agent
```

## 四、Kubernetes 部署问题

### 4.1 镜像拉取失败 (ImagePullBackOff)

**现象**：Pod 状态为 `ImagePullBackOff` 或 `ErrImagePull`。

**原因分析**：
1. 镜像不存在或标签错误
2. K8s 节点无 Registry 访问权限
3. imagePullSecret 未配置

**解决方案**：

```bash
# 1. 检查 Pod 详细错误
kubectl describe pod <pod-name> -n <namespace>

# 2. 检查镜像名称是否正确
kubectl get deployment myapp -n production \
  -o jsonpath='{.spec.template.spec.containers[0].image}'

# 3. 创建 imagePullSecret
kubectl create secret docker-registry regcred \
  --docker-server=registry.example.com \
  --docker-username=$DOCKER_USERNAME \
  --docker-password=$DOCKER_PASSWORD \
  -n production

# 4. 将 Secret 添加到 Deployment
kubectl patch deployment myapp -n production \
  -p '{"spec":{"template":{"spec":{"imagePullSecrets":[{"name":"regcred"}]}}}}'
```

### 4.2 滚动更新卡住 (Rollout 超时)

**现象**：`kubectl rollout status` 长时间无响应后超时。

**原因分析**：
1. 新 Pod 启动失败（CrashLoopBackOff）
2. Readiness 探针配置不当
3. 资源不足（CPU/Memory 不够）

**解决方案**：

```bash
# 1. 查看 Pod 状态
kubectl get pods -n production -l app=myapp

# 2. 查看新 Pod 日志
kubectl logs -n production -l app=myapp --tail=50

# 3. 检查事件
kubectl get events -n production --sort-by='.lastTimestamp' | tail -20

# 4. 调整 Readiness 探针参数
# 初始等待时间加长
initialDelaySeconds: 15
periodSeconds: 10
failureThreshold: 6  # 允许更多次失败

# 5. 检查资源配额
kubectl describe nodes | grep -A5 "Resources"
```

### 4.3 回滚失败

**现象**：`kubectl rollout undo` 执行后新 Pod 仍异常。

**原因分析**：
1. 上一版本也存在相同问题
2. ConfigMap/Secret 同时被修改
3. 数据库 Schema 不兼容

**解决方案**：

```bash
# 1. 回滚到更早的版本
kubectl rollout undo deployment/myapp -n production --to-revision=1

# 2. 同时回滚 ConfigMap
kubectl rollout undo configmap/myapp-config -n production

# 3. 查看所有历史版本
kubectl rollout history deployment/myapp -n production

# 4. 如果自动回滚也失败，直接手动修复
kubectl set image deployment/myapp \
  myapp=registry.example.com/myapp:known-good-version \
  -n production
```

## 五、Hermes Gateway 通知问题

### 5.1 Telegram 消息发送失败

**现象**：Agent 无法通过 Telegram 发送通知。

**原因分析**：
1. Bot Token 无效
2. Chat ID 错误
3. 网络无法访问 Telegram API

**解决方案**：

```bash
# 1. 检查 Gateway 状态
hermes gateway status

# 2. 查看 Gateway 日志
grep -i "telegram\|send\|error" ~/.hermes/logs/gateway.log | tail -30

# 3. 测试 Telegram Bot Token
curl -s "https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getMe"

# 4. 获取正确的 Chat ID
curl -s "https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates" | jq

# 5. 如果网络受限，配置代理
# config.yaml
gateway:
  platforms:
    telegram:
      proxy: "http://proxy.example.com:8080"
```

### 5.2 微信通知配置问题

**现象**：企业微信/微信通知无法送达。

**原因分析**：
1. Webhook URL 配置错误
2. 消息格式不被支持
3. 频率限制

**解决方案**：

```yaml
# 企业微信机器人 Webhook 配置
gateway:
  platforms:
    wecom:
      enabled: true
      webhook_url: "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=YOUR_KEY"
```

```bash
# 测试企业微信 Webhook
curl -X POST "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"msgtype": "markdown", "markdown": {"content": "CI/CD 测试消息"}}'
```

## 六、Hermes Agent 运行问题

### 6.1 Agent 会话超时

**现象**：长时间运行的 CI/CD 流水线被中断。

**原因分析**：
1. Hermes 默认 max_turns 限制（90）
2. Terminal 工具默认超时（180s）
3. 流水线步骤过多

**解决方案**：

```bash
# 1. 增加 max_turns
hermes config set agent.max_turns 200

# 2. 增加 Terminal 超时
hermes config set terminal.timeout 600

# 3. 将长任务拆分为多个短任务
# 使用 Cron 链式任务
hermes cron create "build" --prompt "执行构建..."
hermes cron create "deploy" --prompt "执行部署..." --context-from build

# 4. 使用 background 模式运行耗时任务
terminal(command="bash scripts/long-running-task.sh", background=true, notify_on_complete=true)
```

### 6.2 工具集未启用

**现象**：Agent 提示 `tool not found` 或无法使用特定功能。

**原因分析**：所需工具集未启用。

**解决方案**：

```bash
# 1. 查看当前启用的工具集
hermes tools list

# 2. 启用缺失的工具集
hermes tools enable terminal
hermes tools enable cronjob
hermes tools enable web

# 3. 重启会话使配置生效
# 在 CLI 中执行 /reset
```

### 6.3 命令审批拦截

**现象**：Agent 执行 `kubectl` 等命令时被审批提示阻断。

**原因分析**：Hermes 安全机制将命令标记为高危。

**解决方案**：

```bash
# 1. 临时使用 --yolo 模式（仅用于自动化场景）
hermes --yolo chat -q "执行部署..."

# 2. 调整审批模式为 smart
hermes config set approvals.mode smart

# 3. 或将审批完全关闭（生产环境不推荐）
hermes config set approvals.mode off
```

## 七、脚本执行问题

### 7.1 Shell 脚本路径问题

**现象**：脚本中引用相对路径导致找不到文件。

**原因分析**：Agent 执行脚本时工作目录与预期不符。

**解决方案**：

```bash
#!/bin/bash
# 在脚本开头切换到脚本所在目录
cd "$(dirname "$0")"

# 或使用绝对路径
SCRIPT_DIR="/opt/cicd-agent/scripts"
CONFIG_DIR="/opt/cicd-agent/configs"
```

### 7.2 环境变量未传递

**现象**：脚本中使用的环境变量为空。

**原因分析**：Hermes 子进程环境变量隔离。

**解决方案**：

```bash
# 1. 在 Hermes .env 中配置全局变量
hermes config env-path
# 编辑文件添加：
# DOCKER_REGISTRY=registry.example.com
# K8S_NAMESPACE=production

# 2. 在脚本中显式读取
source /etc/cicd-agent.env

# 3. 或通过 Terminal 命令传递
terminal(command="export DOCKER_REGISTRY=registry.example.com && bash scripts/deploy.sh")
```

## 八、性能与资源问题

### 8.1 Agent 响应变慢

**现象**：Agent 处理 Webhook 事件响应时间过长。

**原因分析**：
1. 上下文过长（累积了过多历史）
2. 模型推理速度慢
3. 并发任务过多

**解决方案**：

```bash
# 1. 启用上下文压缩
hermes config set compression.enabled true
hermes config set compression.threshold 0.50
hermes config set compression.target_ratio 0.20

# 2. 使用更快的模型处理 CI/CD 任务
hermes config set model.default "anthropic/claude-sonnet-4"

# 3. 限制并发
hermes config set delegation.max_concurrent_children 2

# 4. 定期压缩会话
# 在会话中使用 /compress 命令
```

### 8.2 磁盘空间不足

**现象**：Docker 镜像和日志占满磁盘。

**原因分析**：未及时清理旧镜像和日志。

**解决方案**：

```bash
#!/bin/bash
# scripts/cleanup-old-images.sh
# 清理 7 天前的镜像

echo "=== 清理旧 Docker 镜像 ==="
docker image prune -a -f --filter "until=168h"

echo "=== 清理构建缓存 ==="
docker builder prune -f

echo "=== 清理 Hermes 日志 ==="
find ~/.hermes/logs/ -name "*.log" -mtime +7 -delete

echo "=== 清理完成 ==="
```

```bash
# 创建定时清理任务
hermes cron create "0 3 * * 0" \
  --script "/opt/cicd-agent/scripts/cleanup-old-images.sh" \
  --no-agent
```

## 九、排查 Checklist

当 CI/CD 流水线异常时，按以下顺序排查：

```markdown
- [ ] 检查 Hermes Agent 是否正常运行：`hermes doctor`
- [ ] 检查 Gateway 状态：`hermes gateway status`
- [ ] 检查 Webhook 是否收到事件：`hermes webhook list`
- [ ] 检查 Cron 任务状态：`hermes cron status`
- [ ] 查看 Gateway 日志：`tail -50 ~/.hermes/logs/gateway.log`
- [ ] 查看 K8s 事件：`kubectl get events --sort-by='.lastTimestamp'`
- [ ] 查看 Pod 状态：`kubectl get pods -A`
- [ ] 查看 Docker 构建日志：`docker logs <container>`
- [ ] 手动测试脚本：`bash scripts/deploy.sh myapp v1.0.0 test`
```

## 十、预防措施

1. **灰度发布** — 先部署到测试环境，验证通过后再推生产
2. **版本锁定** — 生产环境使用明确版本号而非 `latest`
3. **资源预留** — 为关键 Pod 设置 resource requests/limits
4. **监控告警** — 配置多维度健康检查，覆盖应用、基础设施各层面
5. **备份策略** — 定期备份 K8s 资源定义和持久化数据
6. **回滚演练** — 定期在测试环境演练回滚流程
7. **日志保留** — 配置合理的日志轮转策略，避免磁盘写满
