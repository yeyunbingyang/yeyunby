# 环境搭建指南

## 一、前置依赖

### 1.1 硬件要求

| 资源 | 最低配置 | 推荐配置 |
|------|----------|----------|
| CPU | 2 核 | 4 核 |
| 内存 | 4 GB | 8 GB |
| 磁盘 | 20 GB | 50 GB (SSD) |
| 网络 | 可访问 Git 仓库和 Docker Registry |

### 1.2 软件依赖

| 软件 | 版本要求 | 用途 |
|------|----------|------|
| Hermes Agent | ≥ 最新版 | Agent 框架 |
| Docker | ≥ 20.10 | 容器构建 |
| Kubernetes | ≥ 1.24 | 容器编排 |
| kubectl | 匹配 K8s 版本 | K8s 管理 |
| Git | ≥ 2.30 | 代码管理 |
| Python | ≥ 3.10 | 辅助脚本 |
| Shell | Bash 4+ | 自动化脚本 |

## 二、Hermes Agent 安装

### 2.1 安装 Hermes Agent

```bash
# 一键安装（Linux / macOS）
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

# Windows（使用 git-bash 或 WSL）
# 或从 GitHub Releases 下载最新版
```

### 2.2 验证安装

```bash
hermes doctor
hermes --version
```

### 2.3 配置模型提供商

```bash
# 交互式配置
hermes setup model

# 或直接设置
hermes config set model.default "anthropic/claude-sonnet-4"
hermes config set model.provider "openrouter"
```

### 2.4 启用必要工具集

```bash
# 查看工具状态
hermes tools list

# 确保以下工具集已启用
hermes tools enable terminal
hermes tools enable web
hermes tools enable cronjob
```

## 三、Webhook 配置

### 3.1 订阅 GitLab Webhook

```bash
# 创建 Webhook 路由
hermes webhook subscribe gitlab-push

# 查看 Webhook 列表
hermes webhook list
```

### 3.2 GitLab 侧配置

1. 进入项目 → Settings → Webhooks
2. URL: `http://<your-hermes-host>:<port>/webhooks/gitlab-push`
3. 勾选触发事件: Push events, Tag push events, Merge request events
4. Secret Token: 设置与 Hermes 配置一致的 Token

### 3.3 GitHub 侧配置

1. 进入项目 → Settings → Webhooks → Add webhook
2. Payload URL: `http://<your-hermes-host>:<port>/webhooks/github-push`
3. Content type: `application/json`
4. Secret: 设置共享密钥
5. Events: 选择 `Just the push event` 或自定义

### 3.4 验证 Webhook

```bash
# 测试 Webhook 路由
hermes webhook test gitlab-push

# 或手动发送测试请求
curl -X POST http://localhost:8080/webhooks/gitlab-push \
  -H "Content-Type: application/json" \
  -d '{"ref": "refs/heads/main", "user_username": "test"}'
```

## 四、Cron 定时任务配置

### 4.1 创建定时健康检查

```bash
# 每 5 分钟检查一次集群健康
hermes cron create "*/5 * * * *" \
  --prompt "执行 K8s 集群健康巡检：
1. 检查所有 Namespace 下 Pod 状态
2. 检查 Node CPU/内存使用率
3. 检查关键 Service 端点连通性
4. 如有异常，尝试自动修复并发送告警" \
  --channel telegram \
  --skills "cicd-ops"
```

### 4.2 创建定时日志清理（No-Agent 模式）

```bash
# 每天凌晨 3 点清理旧镜像，不启动 Agent
hermes cron create "0 3 * * *" \
  --script "/opt/scripts/cleanup-old-images.sh" \
  --no-agent
```

### 4.3 创建证书续期任务

```bash
# 每周一检查证书过期
hermes cron create "0 9 * * 1" \
  --prompt "检查所有 Ingress 证书过期时间，如 7 天内过期则自动续期" \
  --channel telegram
```

### 4.4 管理 Cron 任务

```bash
# 列出所有任务
hermes cron list

# 暂停任务
hermes cron pause <job-id>

# 手动触发
hermes cron run <job-id>

# 删除任务
hermes cron remove <job-id>
```

## 五、Gateway 消息平台配置

### 5.1 配置 Telegram

```bash
# 交互式配置
hermes gateway setup

# 或手动配置 config.yaml
```

```yaml
# config.yaml 相关配置
gateway:
  platforms:
    telegram:
      enabled: true
      bot_token: "YOUR_BOT_TOKEN"
      chat_id: "YOUR_CHAT_ID"
    wechat:
      enabled: true
      # 微信配置（需配合 WeCom 或个人微信适配器）
```

### 5.2 启动 Gateway

```bash
# 前台运行（调试）
hermes gateway run

# 安装为后台服务
hermes gateway install
hermes gateway start

# 查看状态
hermes gateway status
```

## 六、Kubernetes 环境准备

### 6.1 配置 kubectl

```bash
# 配置 K8s 集群访问
kubectl config set-cluster production --server=https://k8s-api.example.com
kubectl config set-credentials deployer --token=<token>
kubectl config set-context production --cluster=production --user=deployer
kubectl config use-context production

# 验证连接
kubectl cluster-info
kubectl get nodes
```

### 6.2 创建部署用 ServiceAccount

```yaml
# configs/k8s-sa.yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: hermes-deployer
  namespace: default
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: hermes-deployer-role
rules:
  - apiGroups: ["apps"]
    resources: ["deployments", "deployments/scale"]
    verbs: ["get", "list", "watch", "update", "patch"]
  - apiGroups: [""]
    resources: ["pods", "services", "events"]
    verbs: ["get", "list", "watch"]
  - apiGroups: ["extensions", "networking.k8s.io"]
    resources: ["ingresses"]
    verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: hermes-deployer-binding
subjects:
  - kind: ServiceAccount
    name: hermes-deployer
    namespace: default
roleRef:
  kind: ClusterRole
  name: hermes-deployer-role
  apiGroup: rbac.authorization.k8s.io/v1
```

```bash
kubectl apply -f configs/k8s-sa.yaml
```

## 七、项目初始化

### 7.1 创建项目目录结构

```bash
mkdir -p /opt/cicd-agent/{configs,scripts,references}
cd /opt/cicd-agent
```

### 7.2 配置 Hermes 技能

```bash
# 创建 CI/CD 运维技能
hermes skills create cicd-ops \
  --description "CI/CD 自动化运维流程技能"
```

### 7.3 环境变量配置

```bash
# 编辑 Hermes .env 文件
hermes config env-path
# 添加以下变量
# GITLAB_TOKEN=your_token
# GITHUB_TOKEN=your_token
# DOCKER_REGISTRY=registry.example.com
# DOCKER_USERNAME=deployer
# DOCKER_PASSWORD=your_password
# K8S_CONFIG_PATH=/path/to/kubeconfig
```
