# 踩坑记录与解决方案

## 一、ComfyUI 相关

### 坑 1：CUDA Out of Memory

**现象**：批量生成时 ComfyUI 报 `CUDA out of memory`，进程崩溃。

**原因**：
- 并发数过高，VRAM 耗尽
- 未释放前一批的显存缓存
- SDXL + ControlNet + IP-Adapter 同时加载

**解决方案**：

```yaml
# 1. 降低并发数
BATCH_SIZE: 4 → 2  # RTX 4090 建议 ≤ 4

# 2. 启用 ComfyUI --lowvram 模式
python main.py --lowvram --listen 0.0.0.0

# 3. 每次生成后清理缓存
import torch
torch.cuda.empty_cache()

# 4. 使用 --gpu-only 避免 CPU 回退
```

### 坑 2：去背结果边缘粗糙

**现象**：RMBG 去背后边缘锯齿明显，白色背景残留。

**原因**：
- RMBG-1.4 对某些材质（透明/反光）处理不佳
- 后处理不足，未做边缘羽化

**解决方案**：

```python
# ComfyUI 工作流中添加后处理节点
# 1. 添加 Mask 边缘羽化（Feather 1-2px）
# 2. 添加 Alpha 合成节点，使用纯白背景
# 3. 对透明/玻璃材质使用 BRIA RMBG 替代

# Python 后处理脚本
from PIL import Image, ImageFilter

def refine_alpha(image: Image, feather_px: int = 1) -> Image:
    """边缘羽化优化"""
    if image.mode != "RGBA":
        return image
    r, g, b, a = image.split()
    a = a.filter(ImageFilter.GaussianBlur(radius=feather_px))
    return Image.merge("RGBA", (r, g, b, a))
```

### 坑 3：ComfyUI API 超时

**现象**：`httpx.ReadTimeout` 或 `websocket 连接断开`。

**原因**：
- 生成队列过长，等待超时
- 单张图片生成时间超过默认 timeout（60s）
- 网络不稳定导致 WebSocket 断连

**解决方案**：

```python
# 增加超时时间
client = ComfyUIClient(timeout=180)  # 默认 120 → 180

# 添加重试机制
from tenacity import retry, stop_after_attempt, wait_exponential

@retry(stop=stop_after_attempt(3), wait=wait_exponential(multiplier=1, min=4, max=10))
def safe_generate(workflow):
    return client.generate(workflow)

# 检查队列长度，避免堆积
def check_queue():
    resp = httpx.get(f"{base_url}/queue")
    return len(resp.json()["queue_running"])
```

### 坑 4：模型下载失败

**现象**：首次运行 ComfyUI 时模型下载中断或报错。

**原因**：
- HuggingFace 被墙（国内网络）
- 模型文件过大（SDXL ~7GB）中途断连
- 磁盘空间不足

**解决方案**：

```bash
# 1. 使用 HuggingFace 镜像
export HF_ENDPOINT=https://hf-mirror.com

# 2. 使用 aria2c 断点续传
aria2c -x 4 -s 4 https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0/resolve/main/sd_xl_base_1.0.safetensors

# 3. 检查磁盘空间
df -h /path/to/ComfyUI/models/
```

## 二、平台 API 相关

### 坑 5：淘宝 API 限流

**现象**：上传图片时返回 `isv.rate-limit` 错误。

**原因**：
- 淘宝开放平台 API 调用频率限制（QPS）
- 批量上传时并发过高

**解决方案**：

```python
# 限速上传
import time

def rate_limited_upload(adapter, images, qps=2):
    """QPS 限制，每次调用间隔至少 0.5s"""
    for img in images:
        adapter.upload_image(img)
        time.sleep(1.0 / qps)  # 0.5s 间隔

# 使用令牌桶算法
from token_bucket import Limiter
limiter = Limiter(rate=2, burst=5)  # 2 QPS, 突发 5
```

### 坑 6：Shopify 图片尺寸要求

**现象**：Shopify 上传后图片被自动裁剪或压缩。

**原因**：
- Shopify 对主图有最小尺寸要求（800×800）
- 宽高比偏离 1:1 时自动裁剪

**解决方案**：

```python
def shopify_safe_resize(image: Image, min_size=1024) -> Image:
    """确保图片满足 Shopify 要求"""
    w, h = image.size
    # 1. 确保最小尺寸
    if min(w, h) < min_size:
        scale = min_size / min(w, h)
        image = image.resize((int(w*scale), int(h*scale)), Image.LANCZOS)
    # 2. 居中裁剪为正方形
    w, h = image.size
    side = min(w, h)
    left = (w - side) // 2
    top = (h - side) // 2
    return image.crop((left, top, left + side, top + side))
```

### 坑 7：拼多多 API 签名错误

**现象**：调用拼多多 API 返回 `sign check fail`。

**原因**：
- 参数排序问题
- 中文字符未正确编码

**解决方案**：

```python
def pdd_sign(params: dict, secret: str) -> str:
    """拼多多签名算法"""
    # 1. 按 key 排序
    sorted_params = sorted(params.items(), key=lambda x: x[0])
    # 2. 拼接字符串
    raw = secret + "".join(f"{k}{v}" for k, v in sorted_params) + secret
    # 3. MD5 并转大写
    return hashlib.md5(raw.encode("utf-8")).hexdigest().upper()
```

## 三、数据处理相关

### 坑 8：CSV 中文乱码

**现象**：Pandas 读取 CSV 后中文显示为乱码。

**原因**：
- CSV 文件编码不是 UTF-8（常见 GBK/GB2312）
- Excel 导出默认 GBK

**解决方案**：

```python
# 读取时指定编码
df = pd.read_csv("products.csv", encoding="utf-8-sig")  # UTF-8 BOM

# 或自动检测编码
import chardet
with open("products.csv", "rb") as f:
    encoding = chardet.detect(f.read(10000))["encoding"]
df = pd.read_csv("products.csv", encoding=encoding)
```

### 坑 9：图片路径跨平台问题

**现象**：Windows 生成的路径在 Linux 上不可用。

**原因**：
- Windows 使用反斜杠 `\`，Linux 使用正斜杠 `/`
- 硬编码路径导致跨平台失败

**解决方案**：

```python
from pathlib import Path

# 始终使用 Path 处理路径
image_dir = Path("./images")
sku_path = image_dir / f"{sku}.png"  # 自动处理分隔符

# 统一使用正斜杠
path_str = str(sku_path).replace("\\", "/")
```

## 四、Hermes 相关

### 坑 10：Cron 任务未触发

**现象**：配置的 Cron 定时任务没有按时执行。

**原因**：
- Hermes 后台服务未运行
- 时区配置错误
- Cron 表达式语法错误

**解决方案**：

```bash
# 1. 检查 Hermes 服务状态
hermes status

# 2. 启动后台服务
hermes daemon start

# 3. 验证 Cron 表达式
hermes cron validate "0 2 * * *"

# 4. 测试手动触发
hermes cron run ecommerce-batch-generate

# 5. 查看 Cron 日志
hermes cron logs ecommerce-batch-generate
```

### 坑 11：Kanban 状态不同步

**现象**：Delegation 子任务完成但 Kanban 状态未更新。

**原因**：
- Kanban 更新命令在子任务中未正确执行
- 并发写入导致状态覆盖

**解决方案**：

```python
# 在 Delegation 回调中显式更新 Kanban
def on_task_complete(sku: str, status: str):
    # 使用 Hermes CLI 更新
    Terminal.run(f"hermes kanban move {sku} --to '{status}'")

    # 或使用 SDK
    Kanban.move(sku, status)

# 添加事务锁防止并发覆盖
from filelock import FileLock
with FileLock("kanban.lock"):
    Kanban.move(sku, new_status)
```
