## 1. 选题阶段

### 1.1 热点数据源不稳定

**问题**: 微博/知乎 API 频繁限流或改版，导致热点数据获取失败。

**原因**: 
- 第三方 API 未授权或 Token 过期
- 频率限制（如微博开放平台单日调用上限）
- 反爬机制升级

**解决方案**:
```yaml
# 1. 多数据源冗余
sources:
  primary: "微博热搜 API"
  backup_1: "知乎热榜 RSS"
  backup_2: "百度指数"
  backup_3: "今日热榜聚合站 (tophub.today)"
  fallback: "LLM 基于近期新闻生成选题"

# 2. 降级策略
strategy:
  - 主源可用: 使用主源
  - 主源限流: 切换到备用源
  - 全部不可用: LLM 基于 Memory 中的历史趋势生成选题
```

**经验**: 至少配置 3 个独立数据源，并实现自动降级。

### 1.2 AI 选题同质化

**问题**: 连续几天生成的选题高度相似，缺乏多样性。

**原因**:
- LLM 的惯性输出
- 数据源本身同质化
- 缺少多样性约束

**解决方案**:
```bash
# 在 Memory 中记录近期选题，避免重复
hermes memory add --profile topic-agent \
  --key "recent-topics-7d" \
  --value "['选题A', '选题B', '选题C', ...]"

# 在 Prompt 中增加多样性约束
# "请确保今日选题与过去 7 天的选题重复率不超过 20%"
```

## 2. 文案生成阶段

### 2.1 多平台文案风格漂移

**问题**: 生成的小红书笔记像公众号文章，公众号文章像知乎回答。

**原因**:
- 同一 Profile 处理多风格时 Prompt 冲突
- LLM 对风格指令的理解偏差
- 缺少风格示例（Few-shot）

**解决方案**:
```yaml
# 1. 为每个平台创建独立 Skill，明确风格
skills:
  wechat-article:
    style_example: "附一篇真实公众号爆文作为参考"
    forbidden: ["小红书式emoji", "知乎式分点论述"]
    
  xiaohongshu-note:
    style_example: "附一篇真实小红书爆款笔记"
    required: ["emoji装饰", "短段落", "真实分享感"]
    
  zhihu-answer:
    style_example: "附一篇高赞知乎回答"
    required: ["专业引用", "逻辑论证"]
    
  toutiao-news:
    style_example: "附一篇头条爆文"
    required: ["短句", "高信息密度"]

# 2. 使用 Few-shot 示例
hermes skill run xiaohongshu-note \
  --param few_shot_examples="参考笔记1.md, 参考笔记2.md"
```

### 2.2 文案事实性错误

**问题**: 生成的文案包含错误数据、虚构引用或过时信息。

**原因**:
- LLM 幻觉
- 知识截止日期限制
- 缺少事实核查步骤

**解决方案**:
```yaml
# 1. 增加事实核查 Agent
pipeline:
  - step: 文案生成
  - step: 事实核查 (使用联网搜索验证关键数据)
  - step: 修正并输出

# 2. Prompt 中加入约束
# "所有数据和引用必须标注来源。如果不确定，使用'据业内人士透露'等模糊表述"

# 3. 启用联网搜索
hermes config set model.copy-agent.tools "web_search"
```

### 2.3 Token 消耗过大

**问题**: 同时生成 4 平台文案导致单次 Token 消耗过高，成本飙升。

**原因**:
- 一次性生成多篇长文
- 未使用 Token 优化策略

**解决方案**:
```yaml
# 1. 分步生成，先大纲后填充
strategy:
  - step: 生成统一大纲 (500 tokens)
  - step: 各平台并行扩写 (每篇 1000-2000 tokens)
  - step: 合并输出

# 2. 使用 cheaper model 做初稿
models:
  draft: "gpt-4o-mini"  # 初稿用便宜模型
  polish: "gpt-4o"      # 润色用强模型

# 3. 缓存相似内容
cache:
  enabled: true
  ttl: 24h
```

## 3. 配图生成阶段

### 3.1 DALL-E 生成质量不稳定

**问题**: 同一提示词每次生成结果差异大，部分图片不符合要求。

**原因**:
- 提示词不够精确
- 未指定风格和构图
- 缺少负面提示词

**解决方案**:
```yaml
# 结构化提示词模板
prompt_template:
  subject: "主体描述"
  style: "摄影/插画/3D/扁平"
  composition: "特写/全景/三分法"
  color: "暖色/冷色/高对比"
  lighting: "自然光/戏剧光/柔光"
  mood: "专业/温馨/科技感"
  negative: "文字, 水印, 模糊, 变形"

# 示例
prompt: |
  A professional workspace with a laptop showing AI writing interface,
  warm lighting, minimalist desk setup, soft shadows,
  photorealistic style, 4K quality
  --no text, watermark, blurry, distorted
```

### 3.2 Midjourney 风格一致性

**问题**: 同一系列文章配图风格不统一，视觉体验割裂。

**原因**:
- 每张图独立生成，未保持风格参数一致
- 缺少风格参考图

**解决方案**:
```yaml
# 1. 使用 Style Reference (--sref)
mj_params:
  style_consistent: true
  style_reference: "https://example.com/style-guide.png"
  stylize: 250  # 固定风格化参数
  
# 2. 使用 Seed 控制
mj_params:
  use_fixed_seed: true
  seed_range: [1000, 9999]  # 同一系列使用相近 seed

# 3. 定义视觉风格指南
visual_style_guide:
  brand: "内容工厂"
  primary_colors: ["#2B5C8A", "#E8F0FE"]
  font: "思源黑体"
  image_style: "扁平插画 + 渐变背景"
```

### 3.3 ComfyUI 工作流管理

**问题**: 本地 ComfyUI 工作流复杂，不同配图需求需要切换不同工作流。

**解决方案**:
```yaml
# 预定义工作流模板
comfyui_workflows:
  cover_image:
    workflow: "cover_gen.json"
    model: "sd_xl_base.safetensors"
    steps: 30
    cfg: 7
    
  illustration:
    workflow: "illustration.json"
    model: "realistic_vision.safetensors"
    steps: 25
    cfg: 5.5
    
  thumbnail:
    workflow: "thumbnail.json"
    model: "sd_xl_base.safetensors"
    steps: 20
    cfg: 4
```

## 4. 发布阶段

### 4.1 平台 API 限制

**问题**: 微信公众号每天只能群发 1 次，头条号每天 5 次。

**解决方案**:
```yaml
# 发布策略
publish_strategy:
  wechat:
    max_daily: 1
    strategy: "精选最佳文章每日推送"
    
  zhihu:
    max_daily: 10
    strategy: "分时段发布，避免集中"
    
  xiaohongshu:
    max_daily: 3
    strategy: "早中晚各一篇"
    
  toutiao:
    max_daily: 5
    strategy: "错峰发布，覆盖不同时段"
```

### 4.2 排版格式丢失

**问题**: Markdown 转各平台富文本时格式丢失（代码块、表格、引用）。

**解决方案**:
```yaml
# 平台格式转换映射
format_conversion:
  wechat:
    input: "markdown"
    output: "wechat-html"
    limitations:
      - "不支持代码块 → 改用截图"
      - "表格 → 改用图片"
      - "引用 → 改用加粗"
      
  zhihu:
    input: "markdown"
    output: "zhihu-rich-text"
    limitations:
      - "支持大部分 Markdown"
      - "图片需上传到知乎 CDN"
      
  xiaohongshu:
    input: "markdown"
    output: "plain-text + emoji"
    limitations:
      - "不支持 Markdown"
      - "所有格式需用 emoji 和换行替代"
      
  toutiao:
    input: "markdown"
    output: "toutiao-html"
    limitations:
      - "支持基础 Markdown"
      - "图片需上传到头条 CDN"
```

## 5. 数据回采阶段

### 5.1 平台数据口径不一致

**问题**: 各平台数据指标定义不同，无法直接对比。

| 指标 | 公众号 | 知乎 | 小红书 | 头条 |
|------|--------|------|--------|------|
| 阅读量 | 打开次数 | 浏览数 | 小眼睛数 | 阅读量 |
| 互动 | 在看+留言 | 赞同+评论 | 点赞+收藏+评论 | 阅读完成率+评论 |

**解决方案**:
```yaml
# 统一指标映射
metrics_mapping:
  engagement_rate:
    wechat: "(在看数 + 留言数) / 阅读量 * 100"
    zhihu: "(赞同数 + 评论数) / 浏览数 * 100"
    xiaohongshu: "(点赞 + 收藏 + 评论) / 小眼睛 * 100"
    toutiao: "(评论数 + 转发数) / 阅读量 * 100"
    
  viral_threshold:
    wechat: "阅读量 > 10000"
    zhihu: "赞同数 > 500"
    xiaohongshu: "小眼睛 > 5000"
    toutiao: "阅读量 > 50000"
```

### 5.2 数据回采失败

**问题**: 部分平台 API 返回数据延迟或为空。

**原因**:
- 平台数据 T+1 更新
- Token 过期
- API 版本变更

**解决方案**:
```bash
# 重试机制
retry:
  max_attempts: 3
  delay: 3600  # 1小时后重试
  fallback: "使用预估数据并标记"

# 回采时间调整
hermes cron update daily-analytics-collect \
  --schedule "0 10 * * *"  # 改为上午10点，确保T+1数据到位
```

## 6. 系统层面

### 6.1 Hermes Cron 任务堆积

**问题**: 多个 Cron 任务同时触发导致资源竞争。

**解决方案**:
```yaml
# 错峰调度
cron_schedule:
  topic_pick: "0 8 * * *"       # 8:00
  content_create: "30 8 * * *"   # 8:30（选题完成后）
  image_gen: "0 9 * * *"         # 9:00
  publish_morning: "0 11 * * *"  # 11:00
  publish_afternoon: "0 15 * * *" # 15:00
  publish_evening: "0 20 * * *"  # 20:00
  analytics: "0 10 * * *"        # 10:00（次日）
```

### 6.2 Profile 切换开销

**问题**: 频繁切换 Profile 导致上下文丢失。

**解决方案**:
```yaml
# 使用 Delegation 而非手动切换
# 错误做法：
hermes profile use copy-agent
hermes chat "生成文案"
hermes profile use image-agent
hermes chat "生成配图"

# 正确做法：
hermes delegate --profile copy-agent --task "生成文案"
hermes delegate --profile image-agent --task "生成配图"
```

### 6.3 成本控制

**问题**: 大规模内容生产导致 API 费用快速增长。

**解决方案**:
```yaml
# 成本优化策略
cost_control:
  daily_budget: 10  # 每日 API 预算（美元）
  
  tier_strategy:
    tier_1:  # 高价值内容
      model: "gpt-4o"
      budget_ratio: 0.4
    
    tier_2:  # 常规内容
      model: "gpt-4o-mini"
      budget_ratio: 0.4
    
    tier_3:  # 批量处理
      model: "deepseek-chat"
      budget_ratio: 0.2
  
  caching:
    enabled: true
    similar_title_threshold: 0.85  # 相似度超过85%复用缓存
  
  image_gen:
    daily_limit: 20  # 每日配图上限
    fallback: "使用免费图库（Unsplash API）"
```
