# 模型评测与榜单指南

模型榜单回答的是“某个模型配置在某套任务和 Harness 下表现如何”。它不能直接回答哪个厂家适合长期采购，也不能替代自己的生产验收。可靠的选型顺序是：厂家与服务边界、具体模型配置、独立评测、成本和时延、自有任务回归。

## 来源分层

| 层级 | 来源 | 能确认什么 | 不能单独确认什么 |
| --- | --- | --- | --- |
| 一手规格 | 厂家模型页、价格页、模型卡、技术报告 | 型号、模型 ID、上下文、价格、接口、许可证、发布日期 | 跨厂家真实优劣 |
| 独立客观评测 | LiveBench、SWE-rebench、Terminal-Bench、ARC Prize | 固定任务上的正确率、解决率、成本和复现配置 | 用户偏好、业务分布和产品体验 |
| 人类偏好与真实使用 | Arena Text、WebDev、Agent | 真实用户选择、页面效果、Agent 使用信号 | 事实正确率和严格可复现性 |
| 综合指数 | Artificial Analysis、HELM | 多任务横向比较和能力结构 | 任意业务的一维“智力” |
| 聚合与路由平台 | OpenRouter、第三方镜像 | 可用地区、临时报价、供应商覆盖 | 厂家最终价格和模型真实身份 |
| 厂商自报 | 发布博客、模型卡中的 Benchmark | 厂家定位、测试配置和新增能力 | 与其他厂商完全公平的比较 |

## 推荐榜单网站

### 综合能力

| 网站 | 测试内容 | 适合回答的问题 | 局限 |
| --- | --- | --- | --- |
| [Artificial Analysis](https://artificialanalysis.ai/models) | 综合指数、速度、首 Token 延迟、输出速度、每任务成本 | 哪些模型同时处于质量和成本前沿 | 当前 Intelligence Index 是英文文本测试，且 Agent 权重较高 |
| [Artificial Analysis Methodology](https://artificialanalysis.ai/methodology/intelligence-benchmarking) | v4.1.1 的 9 项评测、权重、重复次数和评分方法 | 综合分由什么构成，是否适合自己的任务 | 指数版本变化后，历史分数不能无条件横比 |
| [LiveBench](https://livebench.ai/) | 推理、编码、Agentic Coding、数学、数据分析、语言、指令遵循 | 客观题和新题上的综合能力 | 固定发布快照，不能代表交互体验；推理档位影响很大 |
| [Stanford HELM](https://crfm.stanford.edu/helm/) | 多场景、多指标、标准化提示和透明结果 | 查某类能力是否有系统评测 | 模型更新通常慢于商业榜单，不适合追逐当天新品 |

Artificial Analysis v4.1.1 的权重是 Agent 34%、编码 24%、科学推理 24%、通用能力 18%。这意味着它更像“Agent 时代的综合指数”，不是传统知识问答总分。LiveBench 2026-06-25 则包含 23 个客观任务和 7 个类别，答案以规则或标准答案自动评分，减少了 LLM Judge 偏差。

### 人类偏好与产品效果

| 网站 | 测试内容 | 适合回答的问题 | 局限 |
| --- | --- | --- | --- |
| [Arena Text](https://arena.ai/leaderboard/text/overall) | 匿名两两对战，覆盖写作、数学、代码和开放问题 | 哪个模型更容易被用户整体偏好 | 风格、篇幅和品牌揭盲都可能影响选择，不等于事实正确率 |
| [Arena WebDev](https://arena.ai/leaderboard/code/webdev) | 网页生成、前端设计和多步编码工作流 | 哪个模型更会做可见网页和交互原型 | Harness 与渲染环境影响大，新模型样本少时会标 Preliminary |
| [Agent Arena](https://arena.ai/leaderboard/agent) | 完成确认、用户褒贬、可纠正性、命令恢复和工具幻觉 | 真实 Agent 会话中哪个模型更可控 | 任务不是统一试卷，流量结构和产品界面会影响信号 |
| [Arena Changelog](https://arena.ai/blog/leaderboard-changelog/) | 模型加入、分数重置和方法变化 | 某次名次变化来自模型还是榜单更新 | 只能解释已记录的变动 |

Arena 的 Elo 或百分比必须连同页面日期、票数或会话数、置信区间一起保存。两个模型的置信区间重叠时，只能说处于同一梯队。

### 编码与软件工程

| 网站 | 测试内容 | 适合回答的问题 | 局限 |
| --- | --- | --- | --- |
| [SWE-rebench](https://swe-rebench.com/) | 持续加入的新 GitHub Pull Request 修复任务 | 新模型能否修真实代码库，成本和 Pass@5 如何 | 主要覆盖 Python，Harness 和缓存比例会显著影响结果 |
| [SWE-bench](https://www.swebench.com/) | 给定真实 Issue 和仓库，生成补丁并跑测试 | 软件工程 Agent 的标准对比 | 老测试可能饱和或进入训练数据，需看 Verified、Pro 等版本 |
| [Terminal-Bench](https://www.tbench.ai/leaderboard/terminal-bench/2.0) | 在隔离终端完成安装、调试、构建和系统任务 | 模型能否连续用命令解决工程问题 | Agent Harness、超时、容器资源和命令权限都会改变成绩 |
| [LiveCodeBench](https://livecodebench.github.io/) | 持续更新的竞赛代码题与代码执行 | 纯代码生成和算法能力 | 与跨文件修改、需求澄清和生产代码审查不同 |

SWE 类成绩不能写成“编程能力”。它主要测读仓库、定位问题、编辑补丁和跑测试。LiveCodeBench 更接近算法题；Terminal-Bench 更接近命令行工程执行。三类测试应分开看。

### Agent、电脑操作与长任务

| 网站 | 测试内容 | 适合回答的问题 | 局限 |
| --- | --- | --- | --- |
| [Terminal-Bench](https://www.tbench.ai/) | 真实终端任务和自动测试 | 命令行 Agent 的执行能力 | 不能代表图形界面和企业 SaaS 工作流 |
| [OSWorld](https://os-world.github.io/) | 桌面应用和操作系统交互 | Computer Use 是否能操作真实 GUI | 分辨率、视觉定位和最大步数影响很大 |
| [τ-bench](https://github.com/sierra-research/tau-bench) | 多轮用户与工具交互，检查数据库最终状态 | 客服、零售、航空等工具调用是否完成业务目标 | 场景范围有限，需检查使用的是 τ、τ² 还是后续版本 |
| [METR Time Horizons](https://metr.org/time-horizons/) | 按人类专家完成时长估计模型 50% 和 80% 成功边界 | 模型能可靠完成多长的软件任务 | 当前任务集对 16 小时以上的估计不可靠 |

Agent 测试必须记录模型和 Harness。`GPT-5.6 Sol + Codex`、`Fable 5 + Claude Code` 与裸 API 调用不是同一个系统。

### 高难推理、开放权重与中文

| 网站 | 测试内容 | 适合回答的问题 | 局限 |
| --- | --- | --- | --- |
| [ARC Prize](https://arcprize.org/leaderboard) | 抽象图形规则归纳和泛化 | 模型是否能解决训练分布外的抽象任务 | 任务窄，不代表日常知识与软件工程 |
| [OpenCompass](https://opencompass.org.cn/) | 中文、英文、知识、推理、代码和安全等多维评测 | 中文与开放权重模型的横向参考 | 榜单版本和模型提交配置需要逐项核验 |
| [Hugging Face Open LLM Leaderboard](https://huggingface.co/spaces/open-llm-leaderboard/open_llm_leaderboard) | 可下载权重模型的标准化评测 | 开源模型基础能力和可复现结果 | 与闭源旗舰、工具增强 Agent 不完全可比 |
| [Artificial Analysis Multilingual](https://artificialanalysis.ai/) | Global-MMLU-Lite 等多语言评测 | 同一测试方法下比较中文与其他语言 | 多项选择题不能代表中文写作和行业术语 |

## 如何记录一条榜单数据

每条数据至少保留以下字段：

| 字段 | 示例 | 原因 |
| --- | --- | --- |
| 抓取日期 | 2026-08-11 | 榜单会动态刷新 |
| 榜单版本 | LiveBench 2026-06-25 | 不同测试集不能直接比较 |
| 模型精确名称 | `gpt-5.6-sol-xhigh` | 家族名不足以复现 |
| 推理档位 | medium、high、xhigh、max | 质量、Token 和延迟不同 |
| Harness | Codex、Claude Code、Terminus 2 | 工具、提示和循环策略会改变结果 |
| 工具配置 | Web Search disabled | 工具开关会带来不公平优势 |
| 样本量 | 5,242 votes | 样本少时名次不稳定 |
| 置信区间 | 1625 +10/-10 | 判断差距是否显著 |
| 成本口径 | 每题成本、输入输出价 | 便宜模型可能输出更多 Token |
| 来源 URL | 榜单详情页 | 便于下次复核 |

建议在笔记中保存“事实”和“判断”两列。事实写原始成绩和实验条件；判断只用“领先、强、可用、证据不足”四档，并附适用场景。

## 处理榜单冲突

不同榜单得出不同结论很常见，可以按以下顺序排查：

1. 比较日期和测试集版本，新模型加入或题库刷新会改变名次。
2. 比较模型精确 ID 和推理档，`high` 与 `max` 不能合并。
3. 比较 Harness、工具、系统提示、最大轮次和超时。
4. 比较任务分布。Text Arena、SWE-rebench 与 ARC 测的不是同一件事。
5. 比较样本量、置信区间和 Preliminary 标记。
6. 检查是否为厂家自报、独立复现或第三方镜像。
7. 冲突仍无法解释时并列保留，不选一个结果冒充真相。

本轮调研中有三个实际例子：OpenAI 搜索缓存保留了 GPT-5.6 首发价格，实时官方模型页已经降价；Arena 的 WebDev 和 Agent 名次随日期、样本和 Max 变体变化；MiniMax 与 MiMo 的“开放权重”状态在发布文案和下载落地之间存在时间差。这些都应写进快照边界。

## 从厂家出发的选型流程

1. 列出厂家边界：地区、数据保留、API 协议、服务等级、开放权重和采购渠道。
2. 在厂家内部选档：旗舰、均衡、高吞吐或专项模型。
3. 用两类独立证据验证。通用任务看 AA 或 LiveBench，具体任务再选 SWE-rebench、Arena、Terminal-Bench 等。
4. 计算真实成本：输入、输出、推理 Token、缓存、工具调用、失败重试和人工复核都计入。
5. 建立 20 至 50 个自有任务，保存期望结果、失败类型、时延和单任务成本。
6. 把结果写入 [[04-模型路由策略]]，主模型、便宜模型和回退模型分别配置。

## 常见误读

- 把综合榜第一写成所有场景第一。
- 用模型家族名替代精确模型 ID 和推理档。
- 把 Arena 偏好当事实正确率。
- 把 SWE-bench 解决率当全部编程能力。
- 把厂家自报成绩和独立榜单混在同一列。
- 把不同测试集的百分数相加，制造统一综合分。
- 忽略输出 Token、缓存和重试，只比较每百万输入价。
- 用 OpenRouter 或搜索摘要覆盖厂家正式价格页。
- 新模型样本很少时就下稳定结论。
- 只看英文榜单，直接推断中文、行业术语或本地合规能力。
