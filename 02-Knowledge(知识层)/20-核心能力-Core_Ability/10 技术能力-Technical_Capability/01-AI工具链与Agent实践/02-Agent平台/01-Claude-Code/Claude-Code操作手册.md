 # Claude Code 完全操作手册

> 基于终端的 AI Agent 深度使用指南，从入门到高阶系统化掌握

---

## 一、Claude Code 核心认知

### 1.1 本质定位
Claude Code（简称 CC）是 Anthropic 推出的**终端原生 AI Agent**，不同于传统对话式 AI 的一问一答，它具备**自主规划与执行能力**，通过 **LM Loop（大模型循环）** 持续迭代完成任务。

**核心差异点：**
- **本地运行**：直接读写本地文件、执行终端命令、访问系统资源
- **Harness 工程**：Agent 框架设计优秀，即使使用相同底层模型，表现也显著优于其他 Agent

### 1.2 适用场景
- **编程开发**：全栈应用开发、代码重构、Bug 修复
- **知识工作**：文案撰写、资料整理、数据分析、报告生成
- **系统操作**：文件管理、批量处理、自动化脚本

## 二、安装与模型配置

### 2.1 安装方式

**方式一：命令行安装（推荐）**
```bash
# 从官网复制安装命令执行
curl -fsSL https://claude.ai/install | bash

# 验证安装
claude --version
```

**方式二：让 Agent 安装**
在 IDE（Cursor/Windsurf/Trae）的 Agent 中直接输入：
> "帮我安装 Claude Code"

Agent 会自动处理依赖、网络问题并完成配置。

### 2.2 模型配置

Claude Code 支持自定义底层模型，不仅限于 Claude 官方模型。

**推荐方案：使用 CC Switch 管理多模型**
1. 下载安装 [CC Switch](https://github.com/jawerty/claude-switch)
2. 配置 API Key 与 Base URL（支持国产模型及转发渠道）
3. 设置高/中/低三档模型对应关系

**启动前检查**：确保 Switch 配置在启动 CC 之前完成，否则默认要求登录 Claude 官方账号。

## 三、基础交互与权限模式

### 3.1 启动与初始化
```bash
claude
```
首次启动会引导配置主题色、安全提示、推荐设置及项目信任确认。

### 3.2 四种权限模式

| 模式            | 切换方式          | 特点               |
| ------------- | ------------- | ---------------- |
| **Plan Mode** | `Shift + Tab` | 仅输出计划，不执行，等待用户确认 |
| **默认模式**      | `Shift + Tab` | 智能判断何时询问，平衡效率与安全 |
| **Auto-edit** | `Shift + Tab` | 修改文件不询问，执行命令仍询问  |
| **YOLO Mode** | 启动时加参数        | 完全自动，零确认（高风险高时效） |

**YOLO 模式启动：**
```bash
claude --dangerously-skip-permissions
```

> **建议**：新手从默认模式开始，熟练后使用 YOLO 模式提升效率。93% 的情况下用户本就会直接同意所有操作。

### 3.3 交互方式

**1. 文本对话**
- 直接输入自然语言指令
- **注意**：终端内换行需用 `Option + Enter`（Mac）或 `Ctrl + Enter`（Windows），`Shift + Enter` 会直接发送

**2. @ 文件引用**
```bash
@src/main.js 请解释这个文件的逻辑，并添加详细中文注释
```
- 精准注入指定文件到上下文
- 避免 CC 自行检索文件的 Token 消耗
- 支持拖拽文件路径

**3. 图片输入**
- 拖拽图片或 `Ctrl + V`（Mac 也是 `Ctrl + V`，非 `Cmd + V`）
- 利用多模态能力进行 UI 还原、设计稿分析等

**4. 文件作为指令**
当提示词过长时，先写入本地文件：
```bash
# 在 prompt.md 中写好详细需求
@prompt.md 请按照上述要求执行
```

> **关键认知**：指令越短，CC 探索文件的 Token 消耗可能越高；描述越具体，执行越精准。

### 3.4 常用斜杠命令

| 命令             | 功能                        |
| -------------- | ------------------------- |
| `/help`        | 查看所有命令                    |
| `/model`       | 切换高中低模型档位                 |
| `/btw`         | 临时提问（与项目上下文隔离）            |
| `/simplify`    | 代码审核与优化（质量、效率、复用性）        |
| ==`/compact`== | 压缩上下文，保留关键信息              |
| `/clear`       | 彻底清空当前对话上下文               |
| `/context`     | 查看详细上下文占用情况               |
| `/rewind`      | 回滚到之前状态                   |
| `/memory`      | 管理 Cloud.md 与 Auto Memory |
| `/init`        | 初始化项目级 Cloud.md           |
| `/agent`       | 手动创建子 Agent               |
| `/plugin`      | 插件管理                      |

## 四、命令执行与进程管理

### 4.1 运行系统命令
在 CC 对话中直接输入命令会被视为对 CC 说话，而非执行命令。

**正确方式：**
1. **新开终端**：在 IDE 中新建终端标签页运行
2. **Bash 模式**：命令前加 `!`
   ```bash
   !npm run dev
   ```

### 4.2 后台运行
当命令阻塞对话时（如启动开发服务器）：
```bash
# 按 Ctrl + B
```
进程将转入后台，可通过 `jobs` 查看，按 `Esc` 返回对话。

## 五、版本控制与回滚（后悔药机制）

### 5.1 快速回滚（CC 级）
- **双击 `Esc`** 或输入 `/rewind`
- 支持回滚对话、回滚文件编辑、或两者同时回滚
- **局限**：无法撤销终端命令（如 npm install、文件下载）

### 5.2 Git 版本管理（系统级）
**必须养成习惯**：每完成一个功能节点，让 CC 提交一次代码。

**CC 可全程代劳的 Git 操作：**
```bash
# 让 CC 执行
帮我初始化 Git 仓库，绑定 GitHub 账号，提交当前代码到远程仓库
```

**回滚到任意版本：**
```bash
帮我回滚到上一个稳定版本
```

> **最佳实践**：将 Git 提交作为"存档点"，让 CC 大胆尝试各种方案，随时可恢复。

## 六、上下文管理（解决"变笨"问题）

### 6.1 上下文瓶颈
大模型上下文窗口虽大（100万-200万 Token），但有效利用率仅 60%-80%，且随上下文增长，能力会下降。

### 6.2 管理策略

**主动压缩：**
```bash
/compact
```
将历史对话精简为关键摘要，释放 Token 空间。

**彻底重置：**
```bash
/clear
```
或新建终端标签页开启新对话。

**查看占用：**
```bash
/context
```
显示各模块（MCP、Skills 等）的 Token 占用详情。

**开启余量监控：**
```bash
# 让 CC 开启上下文百分比显示（需重启终端生效）
```
重启后底部会显示上下文余量百分比，**建议超过 60% 时主动压缩**。

### 6.3 对话恢复⭐
```bash
# 方式一：恢复历史对话
/resume

# 方式二：启动时继续上次对话
claude -c
# （-c 即 --continue）
```

## 七、个性化记忆机制（三层体系）

### 7.1 Cloud.md（主动规则）

**三层架构：**

| 层级       | 位置                  | 作用范围 | 用途             |
| -------- | ------------------- | ---- | -------------- |
| **全局级**  | `~/.cloud/cloud.md` | 所有项目 | 个人习惯、语言偏好、身份设定 |
| **项目级**  | `项目根目录/.cloud.md`   | 当前项目 | 技术架构、文件结构、开发规范 |
| **文件夹级** | `子文件夹/.cloud.md`    | 该文件夹 | 局部规则           |

**创建方式：**
- **项目级**：`/init` 自动分析项目并生成
- **全局级**：直接命令 CC "记住永远用中文回答，并写入全局 Cloud.md"
- **编辑**：`/memory` 选择对应层级编辑

**生效机制**：CC 会在每次对话开始时自动读取对应层级的 Cloud.md，全局与项目级规则可叠加。

**维护原则：**
- 只放最顶层、最稳定的原则
- 持续添加 CC 常犯的错误及纠正规则
- 随项目演进同步更新项目级规则

### 7.2 Auto Memory（自动记忆）

**开启方式：**
```bash
/memory
# 选择开启 Auto Memory
```

**记录内容：**
- 用户偏好（如"不喜欢浅色 UI"）
- 用户反馈（"不要这样，要那样"）
- 项目决策与技术选型
- 外部资源索引

**存储位置**：`.cloud/memory/` 下的项目专属文件夹

**调用机制**：通过 `memory.md` 索引按需加载，不会一次性占用全部上下文。

**管理**：若记忆错误，可直接说"忘掉刚才说的 XXX"，CC 会自动删除对应记忆文件。

### 7.3 自定义文档记忆

自行创建规范文档（如品牌视觉规范、语言风格指南），在 claude.md 中规定：
> "当你修改前端视觉时，参考 `docs/brand-guidelines.md`"

## 八、高级拓展功能

### 8.1 Skills（技能手册）

**本质**：特定领域的专业说明书，按需调用，避免 Cloud.md 过度膨胀。

**分类：**
- **知识型**：设计规范、代码规范
- **流程型**：报销流程、发布流程
- **工具型**：调用特定 API 的方法
- **混合型**：完整工作流（如公众号排版发布）

**安装方式：**
1. **手动放置**：将 Skill 文件夹放入
   - 全局：`~/.claud/skills/`
   - 项目级：`项目/.claud/skills/`

2. **智能安装**：使用 Find Skill 让 CC 自动搜索安装
   ```bash
   # 先安装 Find Skill
   # 然后
   帮我找一个生成图片的 Skill 并安装到项目
   ```

**调用方式：**
- 自动调用：CC 根据任务自动判断
- 手动调用：`/skill-name`
- 提示词指定："使用 frontend-optimize Skill 优化 UI"

**创建 Skill：**
使用 Skill Creator（通过 Find Skill 安装），用自然语言描述需求，CC 自动生成标准格式的 Skill 文件夹。

### 8.2 MCP（模型上下文协议）

**定位**：AI 与外部工具/服务的"转接头"

**现状**：Token 消耗较大，不宜同时挂载过多。轻量级功能建议转为 Skill，重量级功能保持 MCP。

**典型场景**：
- 连接 Notion 读取笔记资料
- 连接 Figma 获取设计稿
- 连接数据库直接查询

### 8.3 CLI 工具（命令行接口）

**趋势**：越来越多厂商将网页功能封装为 CLI 工具，供 Agent 精准调用。

**代表工具：**
- **Open CLI**：社交媒体、网页接口的 CLI 化
- **飞书 CLI**：文档、表格、邮件、日历操作
- **FFmpeg**：音视频处理

**使用方式**：将安装链接发给 CC，CC 自动配置后通过命令行调用。

**优势**：相比模拟浏览器点击，CLI 更精准、高效、稳定。

### 8.4 Sub-agent（子代理）

**核心价值**：
- **独立上下文**：避免主 Agent 被无关信息污染
- **并行执行**：多个子 Agent 同时处理不同任务
- **专业化分工**：调研、编码、测试可分配给不同 Agent

**创建方式：**
1. **自动派生**：CC 判断任务可并行时自动创建（如多项目调研）
2. **手动创建**：
   ```bash
   /agent
   ```
   按引导用自然语言描述子 Agent 职责。

**调度方式**：
- 主 Agent 自行分配任务
- 用户直接指定："让调研 Agent 去分析竞品"

### 8.5 Hooks（自动触发器）

**机制**：条件-动作反射，"当 X 发生时，自动执行 Y"

**典型配置：**
- 任务完成时播放提示音 + 发送飞书通知
- 提交代码前自动运行格式检查
- 文件修改后自动执行测试

**配置方式**：直接自然语言描述需求，CC 协助完成配置。

### 8.6 Plugins（插件）

**本质**：Skills、MCP、Hooks 的打包集合，或单一功能的封装。

**管理：**
```bash
/plugin
```
进入插件市场，可浏览、安装、管理插件，选择安装范围（全局/项目）。

## 九、实战工作流与最佳实践

### 9.1 标准项目流程
1. **初始化**：`claude` 进入项目，`/init` 生成 Cloud.md
2. **需求输入**：用 `@需求文档.md` 或图片给出详细要求
3. **计划确认**：Plan Mode 下审阅方案，确认后切 Auto-edit
4. **开发迭代**：YOLO 模式自动执行，定期 `/compact` 压缩上下文
5. **节点存档**：每完成一个功能，让 CC 执行 `git commit`
6. **代码审查**：`/simplify` 自动优化代码质量
7. **收尾**：最终检查，提交到远程仓库

### 9.2 效率技巧
- **上键复用**：YOLO 模式命令按 `↑` 快速调出，无需重复输入
- **后台运行**：长任务用 `Ctrl + B` 转入后台，不阻塞对话
- **隔离提问**：临时问题用 `/btw`，问完 `Esc` 退出，不污染项目上下文
- **精准投喂**：明确知道修改哪个文件时，直接用 `@文件` 指定，节省 Token

### 9.3 风险控制
- **Git 兜底**：任何实验性操作前确保代码已提交
- **模式切换**：高风险操作切回默认模式，常规开发用 YOLO
- **记忆校准**：定期检查 Auto Memory，删除错误记忆
- **上下文监控**：保持余量低于 60%，避免模型"变笨"

### 9.4 持续进化
- **Cloud.md 迭代**：将 CC 反复犯的错误转化为规则写入
- **Skill 积累**：将重复工作流固化为个人 Skill 库
- **工具链整合**：逐步引入 CLI 工具替代浏览器操作，提升自动化程度
