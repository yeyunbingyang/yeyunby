# 环境搭建与配置指南

## 1. 前置依赖

### 1.1 系统要求

## 2. Hermes 配置

### 2.1 基础配置

```bash
# 设置 Hermes 工作目录
export HERMES_HOME="$HOME/.hermes"

# 初始化 Hermes（如未初始化）
hermes init

# 配置 GitHub Token
hermes config set github.token "ghp_xxxxxxxxxxxxxxxxxxxx"

# 配置 Webhook 服务端口
hermes config set webhook.port 8080

# 配置 Gateway（通知通道）
hermes config set gateway.wechat.enabled true
hermes config set gateway.telegram.enabled true
hermes config set gateway.telegram.bot_token "123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11"
hermes config set gateway.telegram.chat_id "-1001234567890"
```

### 2.2 完整配置文件示例

```yaml
# ~/.hermes/config.yaml
webhook:
  port: 8080
  github:
    secret: "your-webhook-secret"

github:
  token: "ghp_xxxxxxxxxxxxxxxxxxxx"
  review:
    auto_merge_threshold: 90
    max_diff_size: 500000  # 最大审查文件大小（字节）
    excluded_paths:
      - "package-lock.json"
      - "yarn.lock"
      - "*.min.js"
      - "vendor/"

gateway:
  wechat:
    enabled: true
    webhook_url: "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"
  telegram:
    enabled: true
    bot_token: "123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11"
    chat_id: "-1001234567890"

mcp:
  github:
    command: "npx @modelcontextprotocol/server-github"
    args:
      - "--token"
      - "ghp_xxxxxxxxxxxxxxxxxxxx"
```

## 3. GitHub Webhook 配置

### 3.1 在仓库中配置 Webhook

**方式一：通过 GitHub Web 界面**

1. 进入仓库 → **Settings** → **Webhooks** → **Add webhook**
2. 填写以下信息：

| 字段 | 值 |
|------|-----|
| Payload URL | `http://your-server:8080/webhook/github` |
| Content type | `application/json` |
| Secret | `your-webhook-secret`（可选但推荐） |
| SSL verification | Enable（如使用 HTTPS） |
| Events | 勾选 **Pull requests** |

**方式二：通过 GitHub CLI**

```bash
# 安装 gh CLI
winget install GitHub.cli

# 登录
gh auth login

# 创建 Webhook
gh api repos/:owner/:repo/hooks \
  --method POST \
  --field name="web" \
  --field active=true \
  --field config[url]="http://your-server:8080/webhook/github" \
  --field config[content_type]="json" \
  --field config[secret]="your-webhook-secret" \
  --field events[]="pull_request"
```

### 3.2 Hermes Webhook 配置

```yaml
# .hermes/webhooks/github-pr.yaml
name: github-pr-review
events:
  - pull_request.opened
  - pull_request.synchronize
  - pull_request.reopened
  - pull_request.ready_for_review
endpoint: /webhook/github
handler: code-review-agent
config:
  secret: "your-webhook-secret"
  validate_signature: true
```

## 4. MCP GitHub 配置

### 4.1 安装 MCP GitHub Server

```bash
# 通过 npm 安装
npx @modelcontextprotocol/server-github

# 或全局安装
npm install -g @modelcontextprotocol/server-github
```

### 4.2 配置 MCP 服务

```yaml
# .hermes/mcp/github.yaml
name: github
transport: stdio
command: npx
args:
  - "@modelcontextprotocol/server-github"
  - "--token"
  - "${GITHUB_TOKEN}"
env:
  GITHUB_TOKEN: "ghp_xxxxxxxxxxxxxxxxxxxx"
```

### 4.3 验证 MCP 连接

```bash
# 测试 MCP 连接
hermes mcp test github

# 预期输出：
# ✅ MCP 服务 "github" 连接成功
# 可用工具: list_pull_requests, get_pull_request, create_review, merge_pull_request, ...
```

### 4.4 MCP GitHub 可用工具列表

| 工具名 | 功能 | 使用场景 |
|--------|------|----------|
| `list_pull_requests` | 列出仓库 PR | 获取待审查 PR 列表 |
| `get_pull_request` | 获取 PR 详情 | 读取 PR 描述、diff、文件变更 |
| `create_review` | 创建审查评论 | 提交审查结果到 PR |
| `merge_pull_request` | 合并 PR | 自动合并通过审查的 PR |
| `add_labels` | 添加标签 | 标记审查状态 |
| `get_file_contents` | 获取文件内容 | 读取具体代码文件 |
| `search_code` | 搜索代码 | 查找相关代码模式 |

## 5. Profile 创建

### 5.1 创建审查者 Profile（reviewer）

```bash
# 创建 Profile
hermes profile create reviewer

# 设置 Profile 配置
hermes profile config reviewer set role "code-reviewer"
hermes profile config reviewer set model "gpt-4"
hermes profile config reviewer set max_tokens 4096
hermes profile config reviewer set temperature 0.3
```

**SOUL.md 配置**：
```markdown
# SOUL.md - Reviewer Profile

## 身份
你是一个专业的代码审查 Agent，负责对 GitHub Pull Request 进行全面的代码审查。

## 核心职责
1. 审查代码变更，发现潜在问题
2. 生成结构化的审查报告
3. 确保代码质量和安全性
4. 提供建设性的改进建议

## 审查原则
- 严格但不苛刻：指出问题，同时提供解决方案
- 关注重点：优先处理安全问题和逻辑错误
- 风格次要：代码风格问题作为建议而非阻塞项
- 客观量化：基于规则和标准，而非主观偏好

## 输出格式
- 使用 Markdown 格式
- 按严重程度分类（🔴 必须修复 / 🟡 建议改进 / ✅ 通过）
- 包含具体行号和代码引用
- 给出总体质量评分
```

### 5.2 创建审批者 Profile（approver）

```bash
# 创建 Profile
hermes profile create approver

# 设置 Profile 配置
hermes profile config approver set role "merge-approver"
hermes profile config approver set model "gpt-4"
hermes profile config approver set max_tokens 2048
hermes profile config approver set temperature 0.2
```

**SOUL.md 配置**：
```markdown
# SOUL.md - Approver Profile

## 身份
你是一个代码合并审批 Agent，基于审查结果做出合并决策。

## 核心职责
1. 评估审查报告的质量和完整性
2. 根据评分模型做出合并决策
3. 执行自动合并或请求修改
4. 通知相关干系人

## 决策原则
- 安全优先：任何安全问题都阻止合并
- 质量门槛：低于阈值的 PR 必须修改后重新审查
- 增量改进：小步快跑，避免过度审查阻塞开发
- 上下文感知：考虑 PR 规模和影响范围
```

### 5.3 切换 Profile

```bash
# 切换到 reviewer Profile 执行审查
hermes profile use reviewer

# 切换到 approver Profile 执行审批
hermes profile use approver
```

## 6. 工具限制

### 6.1 MCP GitHub 限制

| 限制项 | 说明 | 应对策略 |
|--------|------|----------|
| API 速率限制 | 5000 次/小时（认证用户） | 实现请求队列和缓存 |
| 文件大小限制 | 单文件最大 100MB | 跳过超大文件，仅审查 diff |
| 评论长度限制 | 单条评论最大 65536 字符 | 分多条评论发布 |
| 并发请求 | 无明确限制但建议控制 | 串行化关键操作 |

### 6.2 Hermes 限制

| 限制项 | 说明 | 应对策略 |
|--------|------|----------|
| Webhook 超时 | 默认 30 秒 | 异步处理，立即返回 200 |
| 技能执行时间 | 受 LLM 响应时间影响 | 设置合理超时，分步执行 |
| Memory 容量 | 受存储空间限制 | 定期清理过期记忆 |
| Gateway 消息频率 | 微信/Telegram 有限制 | 合并通知，避免刷屏 |

### 6.3 静态分析工具限制

| 工具 | 限制 | 应对策略 |
|------|------|----------|
| ESLint | 仅支持 JS/TS | 多语言时使用对应工具 |
| PyLint | 仅支持 Python | 扩展支持更多语言 |
| 规则配置 | 需手动维护 | 使用共享配置文件 |

## 7. SOUL.md 配置

### 7.1 项目级 SOUL.md

```markdown
# SOUL.md - Code Review Agent

## 项目定位
基于 Hermes Agent 的自动化代码审查系统，为开发团队提供即时、全面、一致的代码质量反馈。

## 核心能力
- PR 自动监听与触发
- 多语言静态代码分析
- AI 驱动的语义代码审查
- 安全漏洞自动扫描
- 质量评分与合并决策
- 多通道实时通知

## 工作模式
1. **被动模式**（默认）：通过 Webhook 监听 PR 事件，自动触发审查
2. **主动模式**：通过命令行手动触发审查指定 PR
3. **批量模式**：定时扫描所有待审查 PR

## 质量要求
- 审查响应时间 < 30 秒
- 误报率 < 10%
- 安全扫描覆盖率 100%
- 评论可操作性评分 > 80%

## 协作方式
- 开发者：提交 PR → 接收审查反馈 → 修改代码
- 审查 Agent：自动审查 → 生成报告 → 合并决策
- 团队 Lead：审查 Agent 配置 → 规则维护 → 结果复核
```
