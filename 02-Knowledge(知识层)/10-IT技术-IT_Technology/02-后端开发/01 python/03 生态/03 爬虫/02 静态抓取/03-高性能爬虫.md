# 02 高性能爬虫 — 多线程、多进程与协程异步

## 一句话结论

> 单线程爬虫是起点不是终点。IO 密集型场景升级路线：`单线程 → 多线程(Queue 解耦) → 异步协程(aiohttp)`，每升一级吞吐量翻 5-10 倍。CPU 密集型（数据解析/计算）才上多进程。异步协程是爬虫性能优化的终局——单线程即可支撑数百并发请求。

---

## 一、单线程爬虫（基线）

单线程串行：发请求 → 等响应 → 解析 → 存储 → 下一个请求。CPU 大部分时间在等 IO。

```python
import requests
import time

def single_thread_crawl(urls):
    results = []
    for url in urls:
        resp = requests.get(url)       # 阻塞等待 IO
        results.append(resp.text)
    return results

# 100 个页面，每个 0.5s → 总计 50s
```

**瓶颈**：99% 的时间在等待网络 IO，CPU 完全闲置。

> 单线程代码是后续所有优化方案的**对照基线**——先跑通单线程，再逐步升级。

---

## 二、多线程爬虫（threading + Queue）

### 2.1 核心模式：生产者-消费者 + Queue 解耦

爬虫天然适合多线程——将步骤拆分为独立线程，通过 Queue 通信：

```
URL 队列 → [线程池: 发请求] → JSON 队列 → [线程池: 解析] → 数据队列 → [线程: 存储]
   ↑ 生产者              ↑ 消费者+生产者        ↑ 消费者+生产者       ↑ 消费者
```

**为什么用 Queue**：
- 线程安全——无需手动加锁
- 自动阻塞——队列空时消费者等待，队列满时生产者等待
- `task_done()` + `join()` 实现优雅退出

### 2.2 Queue 核心 API

```python
from queue import Queue

q = Queue(maxsize=100)

# 放入
q.put(item)          # 队列满时阻塞等待
q.put_nowait(item)   # 队列满时立即报错

# 取出
item = q.get()       # 队列空时阻塞等待
item = q.get_nowait()  # 队列空时立即报错

# 计数与等待
q.qsize()            # 当前队列长度
q.task_done()        # 标记一个任务完成（计数 -1）
q.join()             # 阻塞直到队列计数归零
# 规则：put 时计数 +1；get + task_done 一起才 -1
```

### 2.3 完整实现模板

```python
import threading
import requests
from queue import Queue

class ThreadSpider:
    def __init__(self):
        self.url_queue = Queue()       # URL 队列
        self.data_queue = Queue()      # 解析结果队列
        self.headers = {'User-Agent': 'Mozilla/5.0 ...'}

    def produce_urls(self):
        """生产者：生成所有待爬 URL"""
        for page in range(1, 50):
            self.url_queue.put(f'https://example.com/api?page={page}')

    def fetch(self):
        """消费者：发请求，拿到响应后放入下一级队列"""
        while True:
            url = self.url_queue.get()
            try:
                resp = requests.get(url, headers=self.headers, timeout=10)
                self.data_queue.put(resp.json())
            except Exception as e:
                print(f'请求失败: {url}, {e}')
            finally:
                self.url_queue.task_done()   # ← 必须配对 get()

    def parse(self):
        """消费者：解析数据并存储"""
        while True:
            data = self.data_queue.get()
            for item in data['list']:
                self.save(item)
            self.data_queue.task_done()

    def save(self, item):
        # 存入数据库/文件
        pass

    def run(self):
        # 启动各阶段线程
        t_list = []
        t_list.append(threading.Thread(target=self.produce_urls))

        for _ in range(3):   # 3 个请求线程
            t_list.append(threading.Thread(target=self.fetch))

        for _ in range(2):   # 2 个解析线程
            t_list.append(threading.Thread(target=self.parse))

        for t in t_list:
            t.setDaemon(True)   # 守护线程：主线程结束自动回收
            t.start()

        # 等待队列清空
        self.url_queue.join()
        self.data_queue.join()
```

### 2.4 关键细节

| 要点 | 说明 |
|------|------|
| `setDaemon(True)` | 子线程设为守护——主线程结束时自动回收，防止僵尸线程 |
| `task_done()` 位置 | 放在 `finally` 中——即使请求异常也要计数 -1，否则 `join()` 永久阻塞 |
| 线程数 | 请求线程 3-5 个即可（瓶颈在网络，非 CPU） |
| Queue 容量 | 设 `maxsize` 防止内存爆——生产者太快时自动刹车 |

## 三、多进程爬虫（multiprocessing）

### 3.1 什么时候用

| 场景                               | 方案       |
| -------------------------------- | -------- |
| IO 密集型（网络请求）                     | 多线程 / 协程 |
| **CPU 密集型（加解密、大量正则/XPath、图片处理）** | **多进程**  |

> 爬虫 90% 场景是 IO 密集型——多线程和协程就够。多进程用于数据清洗/加密逆向等计算环节。

### 3.2 基础用法

```python
from multiprocessing import Process, Queue

def worker(q):
    while True:
        url = q.get()
        if url is None:
            break
        # 处理...
        resp = requests.get(url)

if __name__ == '__main__':
    q = Queue()
    for url in urls:
        q.put(url)

    processes = []
    for _ in range(4):
        p = Process(target=worker, args=(q,))
        p.start()
        processes.append(p)

    for p in processes:
        p.join()
```

> `multiprocessing.Queue` 和 `queue.Queue` 是不同的——前者用于进程间通信。

## 四、异步协程爬虫（asyncio + aiohttp）

### 4.1 为什么协程是爬虫终局

```
多线程：100 个请求 → 100 个线程 → 每个线程占用 ~8MB 内存 = 800MB
协程：  100 个请求 → 1 个线程   → 每个协程占用 ~1KB 内存 = 100KB
```

> 协程 = 单线程内的高并发——没有线程切换开销、没有 GIL 竞争、内存占用极低。

### 4.2 核心概念

```
async def       # 定义协程函数
await           # 挂起当前协程，等待 IO 完成（不阻塞线程）
asyncio.create_task()   # 将协程包装为 Task，并发调度
asyncio.wait()          # 等待一组 Task 全部完成
asyncio.gather()        # 并发执行多个协程，返回结果列表
```

**执行流程**：

```
协程 A: 发请求 → await(挂起) ─────────────────→ 响应到 → 继续执行
协程 B: 发请求 → await(挂起) ─────→ 响应到 → 继续执行
协程 C: 发请求 → await(挂起) → 响应到 → 继续执行
        ↑                        ↑
      同一线程内，一个在等 IO 时另一个接管 CPU
```

### 4.3 aiohttp 完整模板

```python
import asyncio
import aiohttp
import time
import random

class AsyncSpider:
    def __init__(self):
        self.headers = {'User-Agent': 'Mozilla/5.0 ...'}
        self.url = 'https://example.com/api?page={}'

    async def fetch_page(self, session, page):
        """异步请求单个页面"""
        async with session.get(self.url.format(page)) as resp:
            return await resp.json()

    async def parse_item(self, session, item_id):
        """异步请求详情"""
        detail_url = f'https://example.com/detail/{item_id}'
        async with session.get(detail_url) as resp:
            return await resp.json()

    async def save(self, data):
        """异步存储（以 aiomysql 为例）"""
        # pool = await aiomysql.create_pool(...)
        # async with pool.acquire() as conn:
        #     async with conn.cursor() as cursor:
        #         await cursor.execute(sql, data)
        #         await conn.commit()
        pass

    async def crawl_page(self, session, page):
        """爬取单页：列表 → 并发抓详情 → 并发存储"""
        list_data = await self.fetch_page(session, page)

        # 并发抓取所有详情
        tasks = []
        for item in list_data['items']:
            task = asyncio.create_task(self.parse_item(session, item['id']))
            tasks.append(task)
        details = await asyncio.wait(tasks)

        # 并发存储
        save_tasks = [asyncio.create_task(self.save(d)) for d in details]
        await asyncio.wait(save_tasks)

    async def run(self):
        """主调度"""
        async with aiohttp.ClientSession(headers=self.headers) as session:
            tasks = []
            for page in range(1, 30):
                task = asyncio.create_task(self.crawl_page(session, page))
                tasks.append(task)
                # 随机延时——控制并发速率，防止被封
                await asyncio.sleep(random.uniform(0.5, 0.8))
            await asyncio.wait(tasks)


if __name__ == '__main__':
    start = time.time()
    spider = AsyncSpider()
    asyncio.run(spider.run())
    print(f'总耗时: {time.time() - start:.2f}s')
```

### 4.4 异步关键细节

| 要点 | 说明 |
|------|------|
| `ClientSession` | 连接池——必须在 `async with` 内使用，复用 TCP 连接 |
| `create_task` vs `gather` | `create_task` 提交即忘 + `wait` 等待全部；`gather` 提交并返回结果列表 |
| 限速 | `await asyncio.sleep(random(...))` 放在 `create_task` 之后——控制任务提交速率 |
| `asyncio.run()` | Python 3.7+ 推荐入口，等价于 `loop.run_until_complete()` |
| 异常处理 | 单个协程异常不影响其他——用 `return_exceptions=True` 收集错误 |

## 五、四种方案对比

| | 单线程 | 多线程 | 多进程 | 异步协程 |
|------|--------|--------|--------|---------|
| **并发模型** | 串行 | 多线程并行 | 多进程并行 | 单线程并发 |
| **适用场景** | 小规模/调试 | IO 密集型 | CPU 密集型 | IO 密集型（最佳） |
| **内存占用（100 并发）** | ~50MB | ~800MB | ~2GB | ~50MB |
| **切换开销** | 无 | 中（线程切换） | 高（进程切换） | 极低（协程切换） |
| **编码复杂度** | ⭐ | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ |
| **GIL 影响** | 无影响 | 受限 | 不受限 | 不受限 |
| **推荐场景** | 原型验证 | 中等规模 | 数据清洗 | 大规模生产 |

## 六、升级路线决策

```
单线程跑通 → 数据量 < 1000 页？ → 单线程够用，不用升级
                            → 数据量 > 1000 页？
                                   ├→ 纯 IO（请求+存储） → 上异步协程（aiohttp）
                                   ├→ IO + 轻量解析       → 异步协程（主）+ 少量线程（解析）
                                   └→ IO + 大量 CPU 计算   → 异步协程（请求）+ 多进程（计算）
```

---

## 关键概念

- **生产者-消费者模式**：上游线程生产数据放入 Queue → 下游线程从 Queue 取数据处理——线程间零耦合
- **Queue.join()**：阻塞直到队列计数归零——`put` 计数 +1，`get`+`task_done` 计数 -1
- **`await`**：协程的"挂起点"——遇到 IO 让出控制权，不阻塞线程
- **`aiohttp.ClientSession`**：HTTP 连接池——复用 TCP 连接，是异步爬虫的性能核心
- **`asyncio.create_task`**：将协程注册到事件循环，立即返回不阻塞，事件循环自动调度

## 可行动建议

- 先单线程跑通再优化——不要一开始就上协程，调试困难
- Queue 的 `task_done()` 必须放在 `finally` 里——否则一个异常就永久阻塞
- 协程的 `ClientSession` 必须用 `async with`——自动管理连接池生命周期
- 请求线程数不要超过 5——瓶颈在网络带宽，不是线程数
- 异步爬虫必须加 `asyncio.sleep` 限速——否则瞬间几百并发直接触发反爬
