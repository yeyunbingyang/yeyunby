# Selenium 实战 — 斗鱼直播数据爬取

## 一句话结论

> 斗鱼直播列表页是典型的 Ajax 分页——"下一页"按钮无 href、URL 不变，只能用 Selenium 模拟点击翻页。核心踩坑：点击下一页前必须 `execute_script` 滚动到底，否则 `click()` 无效（按钮被遮挡）；翻页终止条件用 XPath 定位"下一页"元素——最后一页该元素不存在。

---

## 一、案例背景

**目标**：爬取斗鱼直播（`https://www.douyu.com/directory/all`）全部在线房间的：

| 字段 | 说明 |
|------|------|
| 标题 | 直播间标题 |
| 类别 | 直播分类（如"英雄联盟"） |
| 主播 | 房间主人名称 |
| 热度 | 观看人数 |
| 封面 | 封面图片 URL |

平台特点：房间数量动态变化（凌晨少、晚上多），**不能写死页数**。

---

## 二、页面分析

### 2.1 翻页机制

```
⇢ 点击"下一页" → 页面不刷新、URL 不变 → Ajax 加载新数据
```

右键检查"下一页"按钮：

```html
<!-- 下一页没有任何 href，无法用 requests 构造 URL -->
<a class="dy-Pagination-next ...">下一页</a>
```

**结论**：requests 方案不可行——获取不到下一页 URL，只能 Selenium 模拟点击。

### 2.2 Ajax 接口（更高效但课程未采用）

抓包发现翻页实际请求的是：

```
GET https://www.douyu.com/gapi/rkc/directory/...  → 返回 JSON
```

> 生产环境建议直接调 Ajax 接口（比 Selenium 快 10 倍），本案例以 Selenium 练习为目的。

### 2.3 翻页终止条件

- 有下一页时：XPath 可定位到 `class` 含 `dy-Pagination-next` 的元素
- 最后一页时：该元素消失或 class 改变 → `find_element` 抛异常 → `break`

## 三、核心代码

### 3.1 整体架构

```python
class DouyuSpider:
    def __init__(self):
        self.driver = webdriver.Chrome()
        self.all_data = []

    def run(self):
        """主流程：循环翻页"""
        self.driver.get('https://www.douyu.com/directory/all')
        while True:
            self.parse_page()         # 提取当前页数据
            if not self.go_next():    # 翻页，失败则终止
                break
        self.save_data()
        self.driver.quit()
```

### 3.2 页面数据提取

```python
def parse_page(self):
    """提取当前页所有房间信息"""
    rooms = self.driver.find_elements(By.XPATH, '//ul[@id="listAll"]/li')
    for room in rooms:
        data = {
            'title':  room.find_element(By.XPATH, './/h3').text,
            'category': room.find_element(By.XPATH, './/span[contains(@class, "tag")]').text,
            'host':   room.find_element(By.XPATH, './/span[contains(@class, "name")]').text,
            'heat':   room.find_element(By.XPATH, './/span[contains(@class, "heat")]').text,
            'cover':  room.find_element(By.XPATH, './/img').get_attribute('src'),
        }
        self.all_data.append(data)
```

### 3.3 翻页逻辑（含滚动）

```python
def go_next(self):
    """点击下一页，返回 True 成功 / False 已到最后一页"""
    try:
        # ⚠️ 关键：先滚到底，否则按钮被遮挡 click() 无效
        self.driver.execute_script('window.scrollTo(0, 1000000)')

        next_btn = self.driver.find_element(
            By.XPATH,
            '//a[contains(@class, "dy-Pagination-next")]'
        )
        next_btn.click()
        import time; time.sleep(2)   # 等待 Ajax 加载
        return True
    except:
        return False   # 最后一页，定位不到 next 按钮
```

## 四、踩坑记录

### 4.1 点击下一页无效

**现象**：`find_element` 定位成功（打印出了元素），但 `click()` 后页面没翻。

**原因**：和链家案例一样——按钮在可视区外或被其他元素遮挡，触发 `ElementClickInterceptedException`（被 try/except 静默吞掉了）。

**解决**：点击前先 `execute_script('window.scrollTo(0, 1000000)')` 一把拉到底。

```python
# ❌ 直接点击——大概率失败
next_btn.click()

# ✅ 先滚动再点击
driver.execute_script('window.scrollTo(0, 1000000)')
next_btn.click()
```

### 4.2 翻页后数据还是旧页面

**原因**：点击下一页后 Ajax 还没返回，`parse_page()` 读到的仍是旧 DOM。

**解决**：`click()` 后加 `time.sleep(2)` 等待加载完成。生产环境推荐用显式等待：

```python
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

next_btn.click()
WebDriverWait(driver, 10).until(
    EC.staleness_of(next_btn)   # 等待旧按钮"过期"=新页面已加载
)
```

### 4.3 房间数量动态变化

斗鱼房间数受时段影响巨大（凌晨 vs 黄金档），**不能硬编码页数**。必须用"下一页按钮是否存在"作为循环终止条件。

## 关键概念

- **Ajax 翻页**：URL 不变、无 href——只能模拟点击，不能构造请求
- **翻页终止条件**：用"下一页"元素的**存在性**判断，不硬编码页数
- **click 前先滚动**：`execute_script('window.scrollTo(0, 1000000)')` 是 Selenium 翻页的标配操作
- **静默失败陷阱**：`try/except` 包住翻页逻辑时，click 失败被吞掉 → 看起来"没报错但没翻页" → 排查时去掉 try 看原始异常

## 可行动建议

- 爬到数据后优先检查翻页是否真的生效（看数据是否重复/是否只有第一页）
- 调试时关掉 try/except——让 click 失败的原始异常暴露出来
- 生产环境优先调 Ajax 接口而非 Selenium 翻页（性能差 10 倍）
- 翻页等待不要只靠 `sleep`——用 `WebDriverWait` + `staleness_of` 更稳健
