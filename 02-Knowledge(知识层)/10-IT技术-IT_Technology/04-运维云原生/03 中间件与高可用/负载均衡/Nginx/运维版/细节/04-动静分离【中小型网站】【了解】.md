在 Nginx 中，动静分离配置可以通过将动态请求（如 PHP、Java 应用）和静态请求（如图片、CSS、JS 文件）分别处理来实现。通常，动态请求由后端服务器处理，而静态请求由 Nginx 本身提供。

#### 配置反向代理

反向代理是 Nginx 将客户端的请求转发给后端应用服务器的一种方式。配置如下：

```
location / {
    proxy_pass http://127.0.0.1:8080;  # 将动态请求转发到后端应用
    root   html;                        # 静态资源根目录
    index  index.html index.htm;        # 默认页面
}
```

- **proxy_pass**：将客户端的请求转发到指定的后端服务器（例如 [http://127.0.0.1:8080）。](http://127.0.0.1:8080）。/)
- **root**：指定静态文件的根目录。
- **index**：指定默认的首页文件。

#### 为每个 `location` 添加不同的路径处理

静态资源（如 CSS、图片、JS 文件）可以通过指定不同的路径来处理：

```
# CSS 资源
location /css {
    root   /usr/local/nginx/static;  # 指定静态文件存放的根目录
    index  index.html index.htm;     # 默认文件
}

# 图片资源
location /images {
    root   /usr/local/nginx/static;
    index  index.html index.htm;
}

# JS 资源
location /js {
    root   /usr/local/nginx/static;
    index  index.html index.htm;
}
```

- **location /css** 等：根据请求路径 `/css`、`/images`、`/js` 匹配相应的资源。
- **root**：指定存放静态文件的根目录。

#### 使用单一的 `location` 配置

可以使用正则匹配来简化配置，避免为每个静态资源分别配置一个 `location` 块。例如：

```
location ~*/(css|img|js) {
    root   /usr/local/nginx/static;  # 所有静态文件都放在这个根目录下
    index  index.html index.htm;
}
```

- **~*******：表示正则匹配，且不区分大小写。匹配 `/css`、`/img`、`/js` 等路径下的静态文件。

#### `location` 配置的匹配规则

Nginx 中，`location` 匹配顺序如下：

1. **精确匹配（**`=`**）**：优先匹配，必须完全匹配 URL 路径。
2. **非正则匹配（**`^~`**）**：如果有 `^~` 类型的 `location`，且匹配成功，Nginx 将不再继续匹配后续的正则 `location`。
3. **正则匹配（**`~` **和** `~\*`**）**：根据正则表达式匹配 URL。
4. **普通匹配**：最大前缀匹配。

##### 匹配顺序总结：

1. `=` 精确匹配 > `^~` 前缀匹配 > `~` 正则匹配 > 普通（最大前缀匹配）

例如：

```
location = /exact-match {
    # 精确匹配请求路径 "/exact-match"
}

location ^~ /prefix {
    # 匹配以 "/prefix" 开头的请求路径
}

location ~* \.(jpg|jpeg|png|gif)$ {
    # 正则匹配图片类型文件
}

location / {
    # 默认匹配所有其他请求
}
```

#### `alias` 和 `root` 的区别

在配置静态资源时，`alias` 和 `root` 用于指定文件的根目录，但两者的使用场景不同。

1. **root**：指定一个基本的根目录，后面可以加上请求的 URI 路径进行拼接。比如：

```
location /css {
    root /usr/local/nginx/static;  # /css 会拼接到 root 指定的路径后面
    index index.html index.htm;
}
```

- 如果请求路径是 `/css/style.css`，Nginx 会去 `/usr/local/nginx/static/css/style.css` 路径查找文件。

2. **alias**：指定一个具体的目录，`location` 中的路径会直接映射到该目录。比如：

```
location /css {
    alias /usr/local/nginx/static/css;  # /css 请求会直接映射到指定目录
    index index.html index.htm;
}
```

- 如果请求路径是 `/css/style.css`，Nginx 会去 `/usr/local/nginx/static/css/style.css` 查找文件，而不会拼接 `location` 路径。

#### `alias` 使用的注意事项

- 在使用 `alias` 时，`location` **配置的路径后必须带上斜杠** `/`，否则会导致配置不生效。
- `alias` 中无法使用 `rewrite` 的 `break`，因为 `alias` 会直接映射请求路径到指定的目录。

#### 示例：使用 `alias` 和 `root` 的静态文件配置

```
# 使用 alias
location /css {
    alias /usr/local/nginx/static/css;  # 直接映射到该目录
    index index.html index.htm;
}

# 使用 root
location /images {
    root /usr/local/nginx/static;  # /images 拼接到该目录后面
    index index.html index.htm;
}
```

#### 总结

- **动静分离** 通过将动态请求（例如由后端处理的请求）和静态请求（例如图片、JS、CSS 文件）分开处理，提高性能。
- 使用 `location` 配置可以根据不同的路径类型处理不同的请求，可以使用正则、精确匹配、最大前缀匹配等策略。
- **root** 和 **alias** 用来指定文件的根目录，`root` 会拼接 `location` 的路径，`alias` 则会直接映射路径。
- **proxy_pass** 用于反向代理，将请求转发到后端服务器处理。
