# Watch Notes

把视频的语音证据和画面证据组织成一篇可长期使用的笔记。不要把它做成逐字稿堆积，也不要按固定数量机械抽帧。

## 核心约束

1. **永远单篇**：无论视频多长，都只生成一篇主笔记。长内容用目录、二级和三级标题组织，禁止自动拆成系列笔记。
2. **Whisper 为主**：时间戳、章节边界和内容判断以 Whisper 转写为主。已有文稿只校正错字、专名和断句，不替代时间轴，也不添加音频中没有的结论。
3. **默认直接嵌图**：自动识别必要画面、提取、筛选、保存并嵌入相应段落。只有用户明确说“候选、联系表、让我选、先别嵌入”等，才生成候选联系表并等待选择。
4. **画面必须有证据价值**：界面步骤、参数、提示词、表格、流程图、前后对比、案例结果、清单和总结页优先。单纯讲师头像、重复画面、转场、模糊帧不保留。
5. **默认 Obsidian**：若目标位于 Obsidian vault，遵循该库的 frontmatter、wikilink 和附件规范；否则输出普通 Markdown。

## 执行前

完整读取并遵循 `watch` 技能。`watch` 负责下载/读取视频、Whisper 转写和抽帧；本技能负责语义分析、必要画面决策、笔记组织、持久化和验证。不要复制或修改 `watch`。

若用户提供 API key，禁止把密钥写进笔记、日志或技能文件。只使用环境变量或 `watch` 已支持的安全配置，并在输出中遮蔽。

## 工作流

### 1. 确定输入与输出

收集或合理推断：

- 视频本地路径或 URL；
- 可选的已有文稿；
- 输出目录和格式；
- 可选的时间范围、语言、详细程度；
- 是否明确要求候选模式。

默认在目标目录建立：

```text
视频标题/
├── 视频标题.md
└── 附件/
    ├── KF-001_00-03-12.jpg
    └── ...
```

普通 Markdown 也保持单篇与同级 `附件/`，但图片使用相对 Markdown 链接。

### 2. 生成主时间轴

使用 `watch` 检查环境，并以 Whisper 获取带时间戳转写。对 URL，必要时先由 `watch` 下载为本地媒体，再对本地音轨运行 Whisper，不能仅因存在平台字幕就跳过 Whisper。

推荐先做低图像成本的转写：

```powershell
$env:PYTHONUTF8 = "1"
python "<watch目录>\scripts\setup.py" --check
python "<watch目录>\scripts\watch.py" "<视频>" --detail transcript --whisper groq --out-dir "<临时目录>\transcript"
```

Windows 下处理中文路径和中文字幕时应保留 `PYTHONUTF8=1`，避免默认代码页导致媒体探测或 JSON 解析异常。

如果 Groq 不可用，使用 `watch` 支持的其他 Whisper 后端。只有所有 Whisper 后端均不可用时，才把平台字幕作为降级方案，并在笔记的信息边界中注明。

将 Whisper 片段聚合成语义章节。章节应由话题变化、阶段总结和操作转换决定，不按固定分钟数切割。

### 3. 对齐已有文稿

若存在文稿：

- 以 Whisper 时间戳为骨架；
- 用文稿纠正人名、产品名、术语、数字和明显识别错误；
- 文稿和音频冲突时保留音频含义，并在确有必要时标注差异；
- 文稿中没有音频证据的扩写不能冒充课程原话。

### 4. 识别“必须看画面”的语义点

逐章扫描下列信号：

- 指示语：看这里、屏幕上、如下图、这个按钮、这个节点；
- 操作语：点击、打开、选择、拖入、配置、填写、导出；
- 视觉资产：提示词、模板、表格、清单、流程图、分镜、参数；
- 结果证据：前后对比、生成结果、错误提示、案例成片、数据结果；
- 结构证据：章节总览、关键结论页、完整工作流。

为每个信号记录：时间戳、所属章节、画面理由、优先级。优先级为：

- P0：没有画面就难以执行或理解；
- P1：画面明显提高复现性或可信度；
- P2：仅装饰或重复，不提取。

将 P0/P1 写入 JSON 后，可用：

```powershell
python "<本技能目录>\scripts\prepare_cues.py" cues.json --output cue-plan.json
```

脚本会去重相邻提示点并生成中心点及邻近候选时间。随后用 `watch --timestamps` 定点抽取，不先做大规模均匀采样。

### 5. 选择最终关键帧

每个提示点检查中心点附近约前 1 秒、中心点、后 1.5 秒的画面，选择一张最清晰且内容最完整的帧。必要时扩大到前后 3 秒。

评分顺序：

1. 与语音论点一致；
2. 关键文字、按钮或结果完整可见；
3. 清晰、非转场、非黑屏；
4. 与已选图片不重复；
5. 能放在一个具体段落旁，而非只能充当装饰。

参考预算而非硬配额：

- 10 分钟以内：通常 4–12 张；
- 10–40 分钟：通常 8–24 张；
- 40 分钟以上：通常 12–40 张。

没有必要画面时允许少于预算，禁止为了“凑数”保留无信息图片。

文件名按视频时间递增：`KF-001_HH-MM-SS.jpg`。保存原始清晰度或宽度不低于 1280 像素；源视频更低时不虚假放大。

### 6. 写成单篇笔记

默认结构按内容裁剪，不要求每节都出现：

```markdown
---
title:
summary:
source:
created:
updated:
tags:
---

# 标题

> [!summary] 一句话结论

## 信息边界
## 课程地图
## 核心方法
### 章节一
### 章节二
## 可执行流程
## 常见失败与修正
## 检查清单
## 时间戳索引
```

写作要求：

- 结论先行，合并口语重复；
- 区分“视频明确表达”“根据画面可确认”“整理者推导”；
- 每张图紧跟它证明或帮助执行的段落，并写一句用途说明；
- 不连续堆放多张无解释图片；
- 保留关键时间戳，方便回看；
- 外部平台收益、市场数据和产品能力标为“视频观点”，除非另行核验。

Obsidian 嵌入：

```markdown
![[附件/KF-003_00-14-32.jpg|720]]
```

普通 Markdown：

```markdown
![提示词界面（00:14:32）](附件/KF-003_00-14-32.jpg)
```

如 vault 有 `AGENTS.md`、`SCHEMA.md` 或模板，先读取并服从其字段和命名规则。新笔记应链接相关 MOC，但仍保持单篇内容。

### 7. 安全更新

由本技能生成的正文用边界标记包裹：

```markdown
%% watch-notes:start %%
...
%% watch-notes:end %%
```

再次运行时，只替换该区块并同步其附件。不得覆盖边界外的用户内容。若同名旧笔记没有边界标记，保留原文件，另建 `标题-watch-notes.md`，除非用户明确要求覆盖。

先把新图片写完整并验证，再替换笔记链接；最后才清理本技能旧区块已不再引用的附件。不要删除附件目录中的未知文件。

### 8. 验证

运行：

```powershell
python "<本技能目录>\scripts\validate_note.py" "<笔记路径>" --mode obsidian
```

普通 Markdown 使用 `--mode markdown`。必须确认：

- 只有一篇目标笔记；
- 所有图片链接均存在且能解码；
- 附件命名、编号和时间戳递增；
- 没有重复嵌入或本技能生成的孤儿图片；
- 每张图位于相关章节；
- frontmatter 和本地 vault 规范有效。

验证失败时修复后重跑，不以“文件已生成”代替完成。

## 候选模式

仅当用户明确要求时启用。此时：

1. 按语义提示点生成候选，而不是固定间隔铺满全片；
2. 生成带编号、时间戳、章节和推荐原因的联系表；
3. 暂不写入正式附件或笔记；
4. 用户回复编号后，再保存选中原图、嵌入相关段落并验证；
5. 验收后清理未选候选。

用户没有明确要求候选时，禁止把选择工作转嫁给用户。
