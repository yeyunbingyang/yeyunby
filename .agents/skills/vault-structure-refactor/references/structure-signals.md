# 目录结构信号

## 需要拆分

- 单个 MOC 的人工链接超过 10 条，并已形成两个以上稳定子主题。
- 单目录直接包含超过 20 篇知识笔记，或超过 50 个混合类型文件。
- 同一目录同时承担知识、项目运行数据、附件和历史归档等三种以上职责。
- 新文件经常无法快速判断归属。

数量是审查信号，不是自动拆分命令。只有主题边界稳定时才建立目录。

## 需要合并

- 多个目录名称不同但内容边界高度重叠。
- 多个 MOC 指向几乎相同的一组笔记。
- 目录长期只有一篇普通笔记且没有明确增长计划。
- 同主题出现“新版、最终版、完整版、V2”等并列权威文件。

## 需要降维

- 目录按状态、平台、年份、成熟度等频繁变化的属性分类。
- 同一笔记为满足多个分类而被复制。
- 层级很深，但每层只包含一个子目录。

把易变维度迁移到 Frontmatter、标签、MOC 或 Bases。

## 项目独立化信号

- 具有独立入口、规范、运行记录、附件资产、维护数据和历史归档。
- 存在脚本、JSON、CSV 等非知识笔记产物。
- 内容生命周期与所属知识主题不同。

达到上述信号时，应把它视为“领域下的项目单元”，而不是继续塞入普通案例目录。
