# 数据提取基础 — 响应内容分类与解析方法概览

## 一句话结论

> 爬虫拿到 `response.content` 后，先判断是结构化还是非结构化数据——JSON/XML 按层级直接提取，HTML 需要 XPath/lxml 定位，普通文本用正则；再结合「骨骼·肌肉·皮肤」三文件模型，快速锁定数据到底藏在哪个请求里。

---

## 一、结构化数据 vs 非结构化数据

这是数据提取的第一个判断维度——比按文件格式分类更本质：

| 分类         | 定义               | 示例          | 提取方式                        |
| ---------- | ---------------- | ----------- | --------------------------- |
| **结构化数据**  | 数据按固定层次组织，遵循同一规则 | JSON、XML    | 按层级路径直接提取（jsonpath / XPath） |
| **非结构化数据** | 没有固定层次结构，格式不统一   | HTML 页面、纯文本 | 需解析器定位后提取（XPath+lxml / 正则）  |

```python
# 结构化（JSON）——层级固定，直接定位
import jsonpath
data = {"store": {"book": [{"title": "Python"}, {"title": "Java"}]}}
jsonpath.jsonpath(data, "$.store.book[*].title")  # ['Python', 'Java']

# 非结构化（HTML）——需要解析器 + 路径表达式
from lxml import etree
html = '<html><body><h1>标题</h1><p>内容</p></body></html>'
tree = etree.HTML(html)
tree.xpath("//h1/text()")  # ['标题']
```

> 简单记忆：**结构化 = 自己能描述自己长什么样**（JSON 的 `{}`、XML 的标签树）；**非结构化 = 需要额外工具去理解它的结构**。

## 二、数据藏在哪：「骨骼·肌肉·皮肤」三文件模型

这是爬虫分析数据来源的核心心智模型——帮你从茫茫 Network 请求中快速定位数据：

| 比喻     | 文件类型              | Network 过滤     | 特征                | 数据特征                     |
| ------ | ----------------- | -------------- | ----------------- | ------------------------ |
| **骨骼** | Document（HTML 页面） | Doc            | 浏览器地址栏的 URL，第一个请求 | 数据**可能**直接嵌入在 HTML 源码中   |
| **肌肉** | XHR / Fetch（Ajax） | XHR            | 页面加载后异步发出的数据请求    | **最常含数据**——JSON 格式，结构清晰  |
| **皮肤** | JS / CSS / 图片     | JS / CSS / Img | 渲染辅助文件            | 通常不含目标数据，但 JS 可能含数据或接口逻辑 |

### 分析流程

```
打开网页 → F12 → Network → 清空 → 刷新页面
    ↓
第 1 步：看骨骼（第一个 Document 请求）
    → Ctrl+F 搜索目标关键词 → 找到了？→ 数据在 HTML 中 → XPath 提取
    → 没找到？→ 继续 ↓
    ↓
第 2 步：看肌肉（切到 XHR 筛选）
    → 逐个查看 Ajax 请求的 Response → 找到含数据的 JSON 接口
    → 直接请求该接口 → jsonpath 提取
    ↓
第 3 步：如果 XHR 也没有？
    → 数据可能在 JS 中硬编码 → 搜 JS 文件 → 正则提取
    → 或需要点击/滚动才触发 → 补抓对应操作后的请求
```

### 实战：今日头条

1. 打开 `https://www.toutiao.com/` → F12 → Network → XHR
2. 在页面上 `Ctrl+F` 搜索某个新闻标题——在骨骼（Document）中**找不到**
3. 切到 XHR 列表，逐个点击查看 Response → 找到返回 JSON 的接口，数据就在里面
4. 记下接口 URL → 用 `requests` 直接请求 → jsonpath 提取

```python
# 头条的数据不在 HTML 中，而在 Ajax 接口返回的 JSON 里
# 思路：先找到接口 → 直接请求接口 → jsonpath 提取
import requests
from jsonpath import jsonpath

api_url = "https://www.toutiao.com/api/pc/list/feed"  # 实际 URL 需抓包确认
resp = requests.get(api_url, headers=headers)
data = resp.json()

titles = jsonpath(data, "$..title")
print(titles)
```

## 三、响应内容的四种格式分类

| 类型        | Content-Type                   | 常见场景             | 解析工具                |
| --------- | ------------------------------ | ---------------- | ------------------- |
| JSON      | `application/json`             | REST API、Ajax 接口 | `json()` / jsonpath |
| HTML      | `text/html`                    | 网页源码、模板页面        | XPath / lxml / BS4  |
| XML       | `application/xml` / `text/xml` | RSS、SOAP、配置文件    | XPath / lxml        |
| 纯文本 / 二进制 | `text/plain` 等                 | 日志、图片、文件下载       | re 正则 / 文件写入        |

### 如何判断类型

```python
import requests

resp = requests.get(url, headers=headers)

# 方法一：看 Content-Type 响应头
content_type = resp.headers.get("Content-Type", "")

# 方法二：看内容前 200 字节
raw = resp.content[:200]
if raw.startswith(b'{') or raw.startswith(b'['):
    print("→ JSON 数据")
elif raw.startswith(b'<'):
    if b'<!DOCTYPE html>' in raw or b'<html' in raw:
        print("→ HTML 页面")
    else:
        print("→ XML 文档")
else:
    print("→ 纯文本或其他格式")
```

### 选择流程图

```
拿到 response.content
    ↓
是 JSON？ → jsonpath / response.json()
    ↓
是 HTML？ → XPath + lxml / BeautifulSoup4
    ↓
是 XML？  → XPath + lxml
    ↓
纯文本？   → re 正则 / 字符串方法
```

## 四、XML 与 HTML 的区别

| | XML | HTML |
|---|-----|------|
| 全称 | eXtensible Markup Language | HyperText Markup Language |
| 目的 | **存储和传输数据** | **展示数据**（网页） |
| 标签 | **自定义**，无预定义标签 | **预定义标签**（`<p>`、`<div>`、`<a>`） |
| 严格性 | **极其严格**——标签必须闭合、大小写敏感 | 较宽松——标签可不闭合、属性可不加引号 |
| 命名空间 | 支持 | 不支持 |

**对比示例**：

```xml
<!-- XML：数据导向，自定义标签 -->
<bookstore>
    <book category="技术">
        <title>Python 爬虫</title>
        <author>张三</author>
        <price>59.00</price>
    </book>
</bookstore>
```

```html
<!-- HTML：展示导向，预定义标签 -->
<div class="book">
    <h2>Python 爬虫</h2>
    <span>张三</span>
    <em>59.00</em>
</div>
```

> HTML 标签可能不闭合、嵌套混乱 → lxml 的 `etree.HTML()` 会**自动补全缺失标签**（容错处理），所以 XPath 同样能用于 HTML。

## 五、常用数据解析方法总览

| 方法                 | 适用格式     | 语法                               | 难度  | 性能    | 推荐场景          |
| ------------------ | -------- | -------------------------------- | --- | ----- | ------------- |
| **re 正则**          | 文本       | 正则表达式                            | ⭐⭐  | ⭐⭐⭐ 快 | 简单文本提取、无结构数据  |
| **jsonpath**       | JSON     | `$.store.book[0].title`          | ⭐   | ⭐⭐    | JSON API 接口数据 |
| **XPath + lxml**   | HTML/XML | `//div[@class="item"]/h2/text()` | ⭐⭐  | ⭐⭐⭐ 快 | 网页结构化提取       |
| **BeautifulSoup4** | HTML/XML | `soup.select('.item h2')`        | ⭐   | ⭐     | 快速原型、简单页面     |

### 各方法一句话

- **正则**：万能但脆弱——HTML 一变就崩，仅作**最后手段**
- **jsonpath**：JSON 专用，路径表达式比手写 `data["a"]["b"][0]` 清晰百倍
- **XPath + lxml**：HTML/XML 提取的**工业标准**，C 底层性能极高
- **BS4**：API 友好适合新手，但性能不如 lxml

### 选型速查

```
JSON 数据 → jsonpath
HTML/XML  → XPath + lxml（首选）/ BS4（备选）
纯文本    → re 正则
```

## 六、正则提取入门

```python
import re

html = '''
<div class="item"><h2>Python 爬虫</h2><span class="price">59.00</span></div>
<div class="item"><h2>Java 编程</h2><span class="price">79.00</span></div>
'''

titles = re.findall(r'<h2>(.*?)</h2>', html)
prices = re.findall(r'<span class="price">(.*?)</span>', html)
print(titles)  # ['Python 爬虫', 'Java 编程']
print(prices)  # ['59.00', '79.00']
```

> 黄金法则：用 `.*?` 非贪婪匹配，否则会吞掉中间所有内容。

## 关键概念

- **结构化 vs 非结构化**：数据提取的第一判断——决定了用路径表达式还是解析器
- **骨骼·肌肉·皮肤**：数据定位的三文件模型——骨骼(HTML)、肌肉(Ajax JSON)、皮肤(JS/CSS/Img)
- **XHR 筛选**：DevTools 中最常用的过滤器，快速定位返回 JSON 的 Ajax 接口
- **lxml 容错**：`etree.HTML()` 自动补全缺失标签——这是 HTML 也能用 XPath 的原因

## 可行动建议

- 第一步：判断数据在骨骼还是肌肉——`Ctrl+F` 搜关键词在 HTML 中找不到？切 XHR
- 第二步：判断结构化还是非结构化——JSON 用 jsonpath，HTML 用 XPath
- 结构化数据利用层级固定优势，非结构化数据利用解析器定位能力
- 正则能不用就不用——结构化的内容交给 XPath/jsonpath
