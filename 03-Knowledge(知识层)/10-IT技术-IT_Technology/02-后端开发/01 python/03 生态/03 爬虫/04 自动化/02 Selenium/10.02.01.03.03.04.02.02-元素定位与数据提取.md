# Selenium 元素定位与数据提取

## 一句话结论

> Selenium 定位元素的核心是 `find_element(By.XXX, "表达式")`——XPath 和 CSS 选择器覆盖 95% 场景；提取数据用 `.text`（文本）和 `.get_attribute()`（属性），配合等待机制确保元素已加载。

---

## 一、八种定位方式详解

### 1.0 两种 API 风格

Selenium 4.x 统一使用 `By` 的方式：

```python
from selenium import webdriver
from selenium.webdriver.common.by import By

driver = webdriver.Chrome()

# ✅ 推荐（4.x 统一写法）
driver.find_element(By.ID, 'kw')
driver.find_element(By.XPATH, '//input[@id="kw"]')

# ❌ 旧版（已弃用，但老教程中常见——遇到了要知道是在干什么）
driver.find_element_by_id('kw')
```

下面 8 种方式全部基于这份示例 HTML 演示：

```html
<html>
<body>
    <div id="search-box" class="form-container">
        <form action="/search" method="get">
            <!-- 搜索框 -->
            <input type="text" id="kw" name="wd" class="s_ipt" placeholder="请输入关键词">

            <!-- 搜索按钮 -->
            <input type="submit" id="su" value="百度一下" class="btn-search">

            <!-- 导航链接 -->
            <a href="https://news.baidu.com" class="nav-link">新闻</a>
            <a href="https://tieba.baidu.com" class="nav-link">贴吧</a>
            <a href="https://zhidao.baidu.com" class="nav-link">知道</a>

            <!-- 列表 -->
            <ul class="result-list">
                <li class="result-item" data-id="101">
                    <h3><a href="/detail/101">Python 爬虫教程</a></h3>
                    <p class="desc">从零开始学 Python 爬虫</p>
                    <span class="tag">技术</span>
                </li>
                <li class="result-item" data-id="102">
                    <h3><a href="/detail/102">Selenium 自动化</a></h3>
                    <p class="desc">浏览器自动化测试与爬虫</p>
                    <span class="tag">技术</span>
                </li>
            </ul>
        </form>
    </div>
</body>
</html>
```

### 1.1 By.ID — 按 id 属性定位

**HTML 中的样子**：`<input type="text" id="kw" name="wd">`

```python
# ====== 基本用法 ======
search_box = driver.find_element(By.ID, 'kw')
search_btn = driver.find_element(By.ID, 'su')

# ====== 操作 ======
search_box.send_keys('Python')
search_btn.click()
```

**适用场景**：`id` 在 HTML 规范中是**全局唯一**的——只要元素有 id，优先用它。

**优点**：最快、最简单、不依赖页面结构变化。

**⚠️ 常见陷阱**：

```python
# ❌ 有些页面 id 是动态生成的——每次都变
driver.find_element(By.ID, 'comp-3a7f2b1c')   # 刷新后变成 comp-8d4e9a2f

# ✅ 换用其他方式
driver.find_element(By.XPATH, '//input[@placeholder="请输入关键词"]')
```

---

### 1.2 By.NAME — 按 name 属性定位

**HTML 中的样子**：`<input type="text" name="wd">`

```python
# ====== 基本用法 ======
search_box = driver.find_element(By.NAME, 'wd')

# ====== name 常用于表单字段 ======
driver.find_element(By.NAME, 'username').send_keys('admin')
driver.find_element(By.NAME, 'password').send_keys('123456')
driver.find_element(By.NAME, 'email').send_keys('test@example.com')
```

**适用场景**：表单元素——`<input>`、`<select>`、`<textarea>` 几乎都有 `name`。

**优点**：表单场景极其稳定，`name` 通常不会变。

**⚠️ 常见陷阱**：

```python
# ❌ 单选框/复选框多个元素共用同一个 name——find_element 只返回第一个
driver.find_element(By.NAME, 'gender')   # 只点到第一个

# ✅ 用 find_elements 拿全部，再筛选
all_gender = driver.find_elements(By.NAME, 'gender')
all_gender[1].click()   # 点第二个
```

---

### 1.3 By.CLASS_NAME — 按 class 属性定位

**HTML 中的样子**：`<input class="s_ipt">`、`<li class="result-item">`

```python
# ====== 基本用法 ======
search_box = driver.find_element(By.CLASS_NAME, 's_ipt')

# 获取所有同 class 元素
all_items = driver.find_elements(By.CLASS_NAME, 'result-item')
print(f'共 {len(all_items)} 条结果')

# 拿到第一个结果的描述
first_desc = driver.find_element(By.CLASS_NAME, 'desc')
print(first_desc.text)   # 从零开始学 Python 爬虫
```

**适用场景**：页面中有一组同类元素时（列表项、卡片等）。

**⚠️ 常见陷阱**：

```python
# ❌ CLASS_NAME 不支持复合 class（含空格）
driver.find_element(By.CLASS_NAME, 'result-item active')
# 报错：Compound class names not permitted

# ✅ 换用 CSS 选择器
driver.find_element(By.CSS_SELECTOR, '.result-item.active')

# ✅ 或 XPath contains
driver.find_element(By.XPATH, '//li[contains(@class, "result-item")][contains(@class, "active")]')

# ✅ 或只用一个 class 名
driver.find_element(By.CLASS_NAME, 'result-item')
```

---

### 1.4 By.TAG_NAME — 按标签名定位

**HTML 中的样子**：`<input>`、`<a>`、`<li>`、`<h3>`

```python
# ====== 基本用法 ======

# 拿到页面上所有的链接
all_links = driver.find_elements(By.TAG_NAME, 'a')
for link in all_links:
    print(f'{link.text} → {link.get_attribute("href")}')

# 所有输入框
all_inputs = driver.find_elements(By.TAG_NAME, 'input')
print(f'页面有 {len(all_inputs)} 个 input')

# 第一个 h3 标签
first_title = driver.find_element(By.TAG_NAME, 'h3')
print(first_title.text)   # Python 爬虫教程
```

**适用场景**：统计/遍历某类标签时——几乎不用于定位单个特定元素。

**优点**：简单直接。  
**缺点**：太宽泛——`driver.find_element(By.TAG_NAME, 'div')` 可能返回几百个。

> `TAG_NAME` 几乎永远用 `find_elements`（复数），极少用 `find_element`。

---

### 1.5 By.LINK_TEXT — 按链接的完整文本定位

**HTML 中的样子**：`<a href="...">新闻</a>`

```python
# ====== 基本用法（文本精确匹配）======

# 点"新闻"链接
driver.find_element(By.LINK_TEXT, '新闻').click()

# 点"贴吧"链接
driver.find_element(By.LINK_TEXT, '贴吧').click()

# 点"知道"链接
driver.find_element(By.LINK_TEXT, '知道').click()
```

**适用场景**：导航栏、分页链接、侧边栏菜单——文本明确的 `<a>` 标签。

**优点**：语义清晰——`LINK_TEXT, "下一页"` 比 `XPATH, '//a[text()="下一页"]'` 更简洁。

**⚠️ 常见陷阱**：

```python
# ❌ 文本必须完全一致——多一个空格都不行
driver.find_element(By.LINK_TEXT, ' 新闻 ')     # 前后有空格，失败
driver.find_element(By.LINK_TEXT, '新闻 ')      # 后面有空格，失败

# ✅ 精确匹配——去除空白后对比
driver.find_element(By.LINK_TEXT, '新闻')

# ✅ 不确定完整文本时用 PARTIAL_LINK_TEXT
driver.find_element(By.PARTIAL_LINK_TEXT, '新闻')
```

---

### 1.6 By.PARTIAL_LINK_TEXT — 按链接的部分文本定位

**HTML 中的样子**：`<a href="...">Python 爬虫教程</a>`

```python
# ====== 基本用法（模糊匹配）======

# 只要链接文本包含"Python"就能定位
driver.find_element(By.PARTIAL_LINK_TEXT, 'Python').click()

# 包含"爬虫"的链接
driver.find_element(By.PARTIAL_LINK_TEXT, '爬虫').click()

# 包含"Selenium"的链接
driver.find_element(By.PARTIAL_LINK_TEXT, 'Selenium').click()
```

**适用场景**：链接文本较长、或只想匹配关键词时。

**⚠️ 常见陷阱**：

```python
# ❌ 匹配到第一个包含"教程"的链接——可能不是你要的
driver.find_element(By.PARTIAL_LINK_TEXT, '教程')
# 如果页面有两个链接「Python 教程」和「Java 教程」，定位的是前者

# ✅ 有多个匹配时用 find_elements 筛选
links = driver.find_elements(By.PARTIAL_LINK_TEXT, '教程')
links[1].click()   # 点第二个
```

### 1.7 By.XPATH — 按 XPath 表达式定位（最灵活）

**HTML 中的样子**：任意元素

```python
# ====== 按属性定位 ======
driver.find_element(By.XPATH, '//input[@id="kw"]')
driver.find_element(By.XPATH, '//input[@name="wd"]')
driver.find_element(By.XPATH, '//input[@placeholder="请输入关键词"]')

# ====== 按文本定位 ======
driver.find_element(By.XPATH, '//a[text()="新闻"]')
driver.find_element(By.XPATH, '//a[text()="贴吧"]')

# ====== 模糊匹配（contains）======
driver.find_element(By.XPATH, '//input[contains(@class, "s_ipt")]')
driver.find_element(By.XPATH, '//li[contains(@class, "result-item")]')
driver.find_element(By.XPATH, '//a[contains(text(), "Python")]')
driver.find_element(By.XPATH, '//h3[contains(text(), "爬虫")]')

# ====== 按层级定位 ======
# div#search-box > form > input#kw
driver.find_element(By.XPATH, '//div[@id="search-box"]//input[@id="kw"]')

# ====== 按位置定位 ======
driver.find_element(By.XPATH, '(//li[@class="result-item"])[1]')    # 第一条
driver.find_element(By.XPATH, '(//li[@class="result-item"])[2]')    # 第二条
driver.find_element(By.XPATH, '(//li[@class="result-item"])[last()]')  # 最后一条

# ====== 按属性值定位 ======
driver.find_element(By.XPATH, '//li[@data-id="101"]')
driver.find_element(By.XPATH, '//span[@class="tag" and text()="技术"]')

# ====== 按父/子关系 ======
driver.find_element(By.XPATH, '//h3/parent::li')        # h3 的父级 li
driver.find_element(By.XPATH, '//li/child::h3')         # li 的直接子级 h3
driver.find_element(By.XPATH, '//li[1]/following-sibling::li')  # 第一个 li 之后的同级 li

# ====== 多条件组合 ======
driver.find_element(By.XPATH, '//input[@type="text" and @name="wd"]')
driver.find_element(By.XPATH, '//li[@class="result-item" and @data-id="101"]')
```

**适用场景**：**万能**——能根据任意属性、文本、层级、位置定位。

**优点**：
- 最灵活——属性、文本、层级、位置、组合条件全支持
- 有 XPath Helper 插件实时验证
- 可通过浏览器 Elements 面板右键 → Copy → Copy XPath 快速生成

**缺点**：
- 语法稍复杂
- 极长 XPath 对页面结构变化敏感

**⚠️ 常见陷阱**：

```python
# ❌ 浏览器 Copy XPath 生成的绝对路径太死板
driver.find_element(By.XPATH, '/html/body/div[3]/div[2]/ul/li[1]/h3/a')
# 页面改一个 div 就失效

# ✅ 自己写相对路径，按语义定位
driver.find_element(By.XPATH, '//h3/a[contains(text(), "Python")]')

# ❌ XPath 下标从 1 开始（不是 0）
driver.find_element(By.XPATH, '(//li)[0]')   # 无效！XPath 没有 [0]
driver.find_element(By.XPATH, '(//li)[1]')   # ✅ 第一个

# ❌ 循环中用 // 开头——从文档根搜索
for item in items:
    item.find_element(By.XPATH, '//h3')   # ❌ 永远取到页面第一个 h3
    item.find_element(By.XPATH, './/h3')  # ✅ 从当前 item 下搜索
```

### 1.8 By.CSS_SELECTOR — 按 CSS 选择器定位

**HTML 中的样子**：任意元素

```python
# ====== 按 id ======
driver.find_element(By.CSS_SELECTOR, '#kw')
driver.find_element(By.CSS_SELECTOR, '#su')

# ====== 按 class ======
driver.find_element(By.CSS_SELECTOR, '.s_ipt')
driver.find_element(By.CSS_SELECTOR, '.result-item')
driver.find_element(By.CSS_SELECTOR, '.result-item .desc')    # 后代

# ====== 按属性 ======
driver.find_element(By.CSS_SELECTOR, 'input[name="wd"]')
driver.find_element(By.CSS_SELECTOR, 'input[type="text"]')
driver.find_element(By.CSS_SELECTOR, '[placeholder="请输入关键词"]')
driver.find_element(By.CSS_SELECTOR, 'li[data-id="101"]')

# ====== 按标签 + class ======
driver.find_element(By.CSS_SELECTOR, 'input.s_ipt')           # input 且 class 含 s_ipt
driver.find_element(By.CSS_SELECTOR, 'li.result-item')        # li 且 class 含 result-item
driver.find_element(By.CSS_SELECTOR, 'span.tag')              # span 且 class 含 tag

# ====== 按层级 ======
driver.find_element(By.CSS_SELECTOR, '#search-box input')     # id=search-box 下的 input
driver.find_element(By.CSS_SELECTOR, 'ul.result-list > li')   # 直接子元素
driver.find_element(By.CSS_SELECTOR, 'li h3 a')               # li 下的 h3 下的 a

# ====== 按位置（伪类）======
driver.find_element(By.CSS_SELECTOR, 'li.result-item:nth-child(1)')   # 第一个
driver.find_element(By.CSS_SELECTOR, 'li.result-item:nth-child(2)')   # 第二个
driver.find_element(By.CSS_SELECTOR, 'li.result-item:last-child')     # 最后一个
driver.find_element(By.CSS_SELECTOR, 'li.result-item:first-child')    # 第一个

# ====== 按文本（CSS 不直接支持，需组合）======
# CSS 没有 text() 函数 → 文本匹配用 XPath 更合适

# ====== 按部分属性匹配 ======
driver.find_element(By.CSS_SELECTOR, 'input[class*="s_i"]')          # class 包含 s_i
driver.find_element(By.CSS_SELECTOR, 'input[class^="s_"]')           # class 以 s_ 开头
driver.find_element(By.CSS_SELECTOR, 'input[class$="ipt"]')          # class 以 ipt 结尾
driver.find_element(By.CSS_SELECTOR, 'a[href^="https://news"]')      # href 以 https://news 开头
```

**适用场景**：熟悉前端 CSS 的开发者首选——语法和写样式表完全一致。

**优点**：
- 语法比 XPath 更简洁（`#kw` vs `//input[@id='kw']`）
- 前端开发者零学习成本
- 复杂 class 组合天然支持（`.result-item.active`）

**缺点**：
- **不支持文本定位**——`CSS_SELECTOR` 没有 `text()` 等价物
- 不支持通过子元素反查父元素（XPath 有 `parent::`）

**⚠️ 常见陷阱**：

```python
# ❌ CSS 选择器不支持文本匹配
driver.find_element(By.CSS_SELECTOR, 'a:contains("新闻")')   # 语法错误！

# ✅ 文本匹配改用 XPath 或 LINK_TEXT
driver.find_element(By.XPATH, '//a[text()="新闻"]')
driver.find_element(By.LINK_TEXT, '新闻')

# ❌ 多 class 用 . 连接即可（不需要特殊处理）
driver.find_element(By.CSS_SELECTOR, '.result-item.active')
# 等同于 XPath 的：
driver.find_element(By.XPATH, '//*[contains(@class, "result-item") and contains(@class, "active")]')
```

### 1.9 八种方式全景对比

| # | 方式 | 示例页面中的定位 | 最佳场景 | 局限 |
|---|------|----------------|---------|------|
| 1 | `By.ID` | `(By.ID, "kw")` → 搜索框 | id 唯一且固定 | id 可能是动态的 |
| 2 | `By.NAME` | `(By.NAME, "wd")` → 搜索框 | 表单字段 | 非表单元素通常没 name |
| 3 | `By.CLASS_NAME` | `(By.CLASS_NAME, "s_ipt")` → 搜索框 | 同类元素批量获取 | 不支持复合 class |
| 4 | `By.TAG_NAME` | `(By.TAG_NAME, "input")` → 所有 input | 统计/遍历标签 | 太宽泛，极少单用 |
| 5 | `By.LINK_TEXT` | `(By.LINK_TEXT, "新闻")` → 新闻链接 | 导航/分页链接 | 文本必须完全一致 |
| 6 | `By.PARTIAL_LINK_TEXT` | `(By.PARTIAL_LINK_TEXT, "Python")` → Python 教程 | 长文本链接模糊匹配 | 可能匹配到多个 |
| 7 | `By.XPATH` | `(By.XPATH, '//input[@id="kw"]')` → 搜索框 | **万能**——文本/层级/属性全支持 | 语法稍长 |
| 8 | `By.CSS_SELECTOR` | `(By.CSS_SELECTOR, "#kw")` → 搜索框 | **简洁**——熟悉 CSS 的首选 | 不支持文本匹配 |

### 1.10 选型决策树

```
元素有固定 id？
    → 是 → By.ID（最快）
    → 否 ↓
元素是表单字段（有 name）？
    → 是 → By.NAME
    → 否 ↓
元素是 <a> 链接，文本固定？
    → 是 → By.LINK_TEXT
    → 否 ↓
需要按文本内容定位？
    → 是 → By.XPATH（唯一支持文本的）
    → 否 ↓
熟悉 CSS 选择器？
    → 是 → By.CSS_SELECTOR（简洁）
    → 否 → By.XPATH（最全面）
```

## 二、find_element vs find_elements

| 方法 | 返回 | 未匹配时 |
|------|------|---------|
| `find_element` | 第一个匹配的**单个**元素 | **抛出异常** `NoSuchElementException` |
| `find_elements` | 所有匹配元素的**列表** | 返回**空列表** `[]` |

```python
# find_element —— 找不到就报错
try:
    el = driver.find_element(By.ID, 'nonexistent')
except Exception as e:
    print(f'未找到: {e}')

# find_elements —— 找不到返回空列表，安全
els = driver.find_elements(By.CLASS_NAME, 'item')
if els:
    for el in els:
        print(el.text)
else:
    print('没有找到任何 item')
```

> **推荐**：不确定元素是否存在时，用 `find_elements` 判断列表长度。

## 三、提取数据

### 3.1 提取文本

```python
element = driver.find_element(By.ID, 'title')

# .text —— 元素可见文本（最常用）
print(element.text)

# .get_attribute('textContent') —— 完整文本（含隐藏文字）
print(element.get_attribute('textContent'))

# .get_attribute('innerText') —— 渲染后的文本
print(element.get_attribute('innerText'))
```

> `.text` 只返回**页面上可见**的文本——隐藏文字（`display: none`）不会出现。

### 3.2 提取属性

```python
link = driver.find_element(By.TAG_NAME, 'a')

href = link.get_attribute('href')        # 链接地址（自动补全为绝对路径）
cls = link.get_attribute('class')         # class 属性
title = link.get_attribute('title')       # title 属性
data_id = link.get_attribute('data-id')   # 自定义属性
```

### 3.3 提取 HTML 源码

```python
html = driver.page_source                        # 整个页面的 HTML
el_html = element.get_attribute('outerHTML')      # 含自身标签
el_inner = element.get_attribute('innerHTML')     # 不含自身标签
```

## 四、遍历多个元素

```python
items = driver.find_elements(By.CLASS_NAME, 'result-item')

results = []
for item in items:
    title = item.find_element(By.TAG_NAME, 'h3').text
    link = item.find_element(By.TAG_NAME, 'a').get_attribute('href')
    desc_els = item.find_elements(By.CLASS_NAME, 'desc')
    desc = desc_els[0].text if desc_els else ''

    results.append({'标题': title, '链接': link, '描述': desc})

print(f'共 {len(results)} 条结果')
```

> ⚠️ 循环内用 `item.find_element` 而非 `driver.find_element`——否则每次从整个页面搜索。

## 五、等待机制

### 5.1 为什么需要等待

JS 动态渲染的页面，元素不是瞬间出现的：

```python
# ❌ 页面还在加载，这个元素还没出来
driver.get('https://spa.example.com')
el = driver.find_element(By.ID, 'dynamic-content')   # 大概率报错

# ❌ 笨办法：sleep 固定时间
import time; time.sleep(3)   # 太短报错，太长浪费
```

### 5.2 隐式等待（全局）

```python
driver.implicitly_wait(10)   # 每次 find_element 最多等 10 秒
```

### 5.3 显式等待（推荐——精准控制）

```python
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

# 等待元素出现
el = WebDriverWait(driver, 10).until(
    EC.presence_of_element_located((By.ID, 'dynamic-content'))
)

# 等待元素可见
el = WebDriverWait(driver, 10).until(
    EC.visibility_of_element_located((By.CLASS_NAME, 'result'))
)

# 等待元素可点击
btn = WebDriverWait(driver, 10).until(
    EC.element_to_be_clickable((By.XPATH, '//button[text()="提交"]'))
)

# 等待 loading 消失
WebDriverWait(driver, 10).until(
    EC.invisibility_of_element_located((By.CLASS_NAME, 'loading'))
)
```

### 5.4 常用等待条件

| 条件 | 含义 |
|------|------|
| `presence_of_element_located` | 元素存在于 DOM（最常用）|
| `visibility_of_element_located` | 元素可见 |
| `element_to_be_clickable` | 元素可点击 |
| `text_to_be_present_in_element` | 元素文本包含指定内容 |
| `invisibility_of_element_located` | 元素不可见（如 loading 消失）|
| `alert_is_present` | 弹窗出现 |

## 关键概念

- **By 定位体系**：8 种定位方式——XPath 最全面，CSS 最简洁，ID 最快
- **XPath vs CSS**：需要文本匹配 → XPath；class 组合 → CSS；复杂层级 → 都行
- **find_element vs find_elements**：前者找不到抛异常，后者返回空列表——防御性编程用后者
- **`.text` vs `.get_attribute()`**：前者取可见文本，后者取属性值或完整 HTML
- **隐式等待 vs 显式等待**：前者全局生效省事，后者精准控制靠谱
- **元素内部搜索**：用 `item.find_element()` 而非 `driver.find_element()`

## 可行动建议

- 定位优先级：`By.ID` > `By.NAME` > `By.CSS_SELECTOR` / `By.XPATH` > 其他
- 文本定位只能用 XPath 或 LINK_TEXT——CSS 不支持
- 不确定元素是否存在时用 `find_elements` + `if result:` 防御
- 动态页面必加显式等待
- 循环遍历必须用 `item.find_element()` 限定范围
- 浏览器 Copy XPath 给的绝对路径很脆弱——自己写相对路径
- XPath 下标从 1 开始，CSS 的 nth-child 也从 1 开始
