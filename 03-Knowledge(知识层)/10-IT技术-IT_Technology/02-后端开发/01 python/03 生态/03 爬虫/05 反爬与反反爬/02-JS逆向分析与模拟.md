# JS 逆向分析与模拟 — 登录加密参数逆向实战

## 一句话结论

> JS 逆向是反爬最硬核的环节——通过 Chrome DevTools 定位加密入口 → 追踪调用链 → 找到加密函数 → 下载 JS 文件在 Python 中用 `js2py` 执行 → 本地生成加密参数。核心难点不在代码，而在**定位加密函数**和**处理 JS 文件间的依赖关系**。

---

## 一、JS 逆向是什么 & 什么时候用

### 1.1 定义

JS 逆向 = 分析前端 JavaScript 的加密/混淆逻辑，用 Python 复现，从而在本地生成合法请求参数。

```
用户浏览器：输入明文密码 → JS 加密 → 发送密文 → 服务器验证密文
爬虫逆向后：Python 调用加密函数 → 生成密文 → 构造请求 → 服务器验证密文
```

### 1.2 决策树

```
需要登录？ → 否 → 不需要逆向
         → 是 → Selenium send_keys 够用？ → 是 → 用 Selenium（成本低）
                                      → 否 → 抓包分析是否有加密参数？
                                               → 无 → 直接 requests 登录
                                               → 有 → JS 逆向 or RPC
```

> Selenium 方案的优势：不用分析 JS，直接模拟输入点击。劣势：速度慢、不适合高并发。如果登录频率低，**先用 Selenium，别急着逆向**。

## 二、逆向环境与工具

| 工具 | 用途 |
|------|------|
| **Chrome DevTools** | 断点调试、查看调用栈、搜索 JS 源码 |
| **Network 面板** | 抓包——看请求参数中哪些是加密的 |
| **Sources → Event Listener Breakpoints** | 在事件触发处断点（如 `submit`） |
| **js2py** / **PyExecJS** | Python 中执行 JS 代码 |
| **在线 JS 格式化** | 反混淆压缩后的 JS |

## 三、逆向五步流程

### Step 1：定位加密入口

目标：找到密码在提交前被哪个函数处理的。

**方法一——Event Listener 断点**：

```
F12 → Sources → Event Listener Breakpoints → Mouse → click（或 submit）
→ 在页面上点击"登录"按钮 → 代码停在事件处理函数处
```

**方法二——Search 搜索关键字**：

```
F12 → Sources → 左侧搜索栏 → 搜索 `password` / `encrypt` / `enc` / `pwd`
→ 找到可疑的加密函数调用
```

### Step 2：追踪调用链

在断点处使用 **Step Into（F11）** 逐层进入，追踪参数变换：

```
点击登录
  → handleLogin()                 # 事件处理函数
    → var pwd = encryptPwd(password)  # 加密函数调用 ← 关键！
      → RSA.encrypt(password, publicKey)   # 具体加密实现
    → $.post('/api/login', {password: pwd})  # 发送加密后的密码
```

**常用调试操作**：

| 操作 | 快捷键 | 作用 |
|------|--------|------|
| Step Over | F10 | 跳过当前行（不进入函数内部） |
| Step Into | F11 | 进入函数内部 |
| Step Out | Shift+F11 | 跳出当前函数 |
| Resume | F8 | 继续执行到下一个断点 |
| Watch | 右侧 Watch 面板 | 添加变量查看值变化 |

### Step 3：定位加密函数源码

找到加密函数名后（如 `getBarrett`、`encrypt`、`RSA.encrypt`）：

```
F12 → Sources → 左侧搜索（Ctrl+Shift+F）→ 输入函数名 → 找到定义位置
```

点击搜索结果跳转到对应 JS 文件，记下文件 URL。复制加密函数的**完整定义**。

典型案例：在 `isA.js` 中找到加密函数它调用了 `Barrett.js` 中的方法——说明这两个文件有依赖关系。

### Step 4：下载依赖 JS 文件

加密函数往往依赖其他 JS 文件中的工具函数。需要把所有依赖文件下载并加载。

```python
import requests

js_files = {
    'barrett': 'https://example.com/static/js/barrett.js',
    'isA':     'https://example.com/static/js/isA.js',
}

for name, url in js_files.items():
    resp = requests.get(url, headers={'User-Agent': '...'})
    with open(f'{name}.js', 'w', encoding='utf-8') as f:
        f.write(resp.text)
```

> **关键原则**：JS 文件的加载顺序必须与依赖关系一致——被依赖的先加载。

### Step 5：Python 模拟执行

用 `js2py` 加载 JS 文件，创建 JS 执行环境，调用加密函数：

```python
import js2py

# 1. 创建 JS 执行上下文
context = js2py.EvalJs()

# 2. 按依赖顺序加载 JS 文件（被依赖的先加载）
with open('barrett.js', 'r', encoding='utf-8') as f:
    context.execute(f.read())

with open('isA.js', 'r', encoding='utf-8') as f:
    context.execute(f.read())

# 3. 调用加密函数
password = '123456'
encrypted_pwd = context.getEncryptFunc(password)  # 具体函数名以逆向结果为准
print(f'加密后: {encrypted_pwd}')
```

### 补充示例：RSA + BigInt 双文件加载与上下文变量注入

当加密依赖多个 JS 文件（如 RSA 加密依赖 BigInt 大数运算库），且 JS 内部引用了页面中的全局变量（如公钥 `n`、指数 `t`）时，需要在加载 JS 后将变量注入到执行上下文中：

```python
import js2py
import requests

session = requests.Session()

# Step 1：获取前置 JS 代码（直接抓 URL，无需落盘）
rsa_js = session.get('http://s.xnimg.cn/a85738/wap/mobile/wechatLive/js/RSA.js').content.decode()
bigint_js = session.get('http://s.xnimg.cn/a85738/wap/mobile/wechatLive/js/BigInt.js').content.decode()

# Step 2：创建 JS 环境对象
context = js2py.EvalJs()

# Step 3：按依赖顺序加载 —— BigInt 是基础库，先加载
context.execute(bigint_js)
context.execute(rsa_js)

# Step 4：注入 JS 所需的全局变量（如 RSA 公钥的 n 和指数 t）
# n 和 t 从页面源码或抓包中提取
context.n = n    # 公钥模数（hex 字符串）
context.t = t    # 公钥指数（通常为 "10001"）

# Step 5：调用加密函数
encrypted = context.RSA.encrypt('myPassword123')
print(f'加密结果: {encrypted}')
```

> **关键点**：JS 文件从 URL 直接 `.content.decode()` 加载比先落盘再 `open()` 更干净——少一次 IO。`context.n = n` 这步是将 Python 变量注入 JS 作用域，对应 JS 侧 `var n = '...'` 的全局声明。




以下为一个典型的 AES/RSA 混合加密登录的完整流程。

### 4.1 抓包分析

打开登录页 → F12 Network → 保持日志 → 输入账号密码 → 点击登录 → 查看 POST 请求。

观察到请求体：

```json
{
  "username": "admin",
  "password": "dGhpcyBpcyBhbiBlbmNyeXB0ZWQgcGFzc3dvcmQ=...",
  "token": "abc123",
  "timestamp": 1680000000
}
```

其中 `password` 是一长串密文——这是加密入口。

### 4.2 定位加密逻辑

1. Event Listener → `submit` 断点 → 停在登录表单提交处
2. Step Into → 发现调用了 `encryptPassword(inputPwd)`
3. 在 `encryptPassword` 内部 → 发现使用了 RSA 公钥加密

```javascript
// 逆向还原出的加密逻辑（伪代码）
function encryptPassword(pwd, pubKey) {
    var key = new RSAKey();
    key.setPublic(pubKey, "10001");  // 指数通常是 10001
    return key.encrypt(pwd);          // RSA 加密
}
```

4. 搜索 `RSAKey` → 找到 `rsa.js` 文件
5. 搜索 `setPublic` → 确认在 `barrett.js` 中

**依赖链**：`login.js` → `isA.js` → `rsa.js` → `barrett.js`

### 4.3 下载 JS 并本地执行

```python
import js2py
import requests

# 下载 JS 文件
libs = {
    'barrett.js': 'https://example.com/static/js/barrett.js',
    'rsa.js':     'https://example.com/static/js/rsa.js',
    'isA.js':     'https://example.com/static/js/isA.js',
}

for filename, url in libs.items():
    resp = requests.get(url, headers={'User-Agent': 'Mozilla/5.0 ...'})
    with open(filename, 'w', encoding='utf-8') as f:
        f.write(resp.text)

# 创建 JS 执行环境（按依赖顺序加载）
ctx = js2py.EvalJs()
ctx.execute(open('barrett.js', encoding='utf-8').read())
ctx.execute(open('rsa.js', encoding='utf-8').read())
ctx.execute(open('isA.js', encoding='utf-8').read())

# 获取公钥（从页面源码或 JS 中提取）
public_key = '...'  # 从抓包或 JS 变量中获取

# 调用加密
encrypted = ctx.encryptPassword('myPassword123', public_key)
print(encrypted)
```

### 4.4 构造请求并登录

```python
import requests

session = requests.Session()

# 第一步：GET 登录页，获取 token 和 Cookie
login_page = session.get('https://example.com/login')
token = re.search(r'name="csrf_token" value="(.*?)"', login_page.text).group(1)

# 第二步：构造加密密码
form_data = {
    'username': 'admin',
    'password': encrypted,      # JS 逆向生成的密文
    'token': token,
    'timestamp': int(time.time()),
}

# 第三步：POST 登录
resp = session.post('https://example.com/api/login', data=form_data)
print(resp.json())  # {"code": 0, "msg": "登录成功", "data": {...}}

# 第四步：携带登录态访问数据
data_resp = session.get('https://example.com/api/user_data')
```

## 五、常见问题与解决

### 5.1 js2py 执行报错

**常见错误**：`dict object has no attribute 'rk'` 等属性访问错误。

**原因**：JS 中的对象（`context.r`）返回的是 JS 对象，Python 不能直接用 `.` 访问。

**解决**：JS 返回值需要用 JS 侧的方法转换后再传给 Python。

```javascript
// 在 JS 侧完成后返回纯字符串
return context.r.toString();  // 或 .toDict()
```

或在 Python 侧用 `js2py` 的内置方法转换：

```python
result = ctx.someFunc()
# js2py 返回的可能是 JsObjectWrapper，需要用 str() 包裹
encrypted_str = str(result)
```

### 5.2 依赖文件缺失

**现象**：`ReferenceError: Barrett is not defined`

**原因**：`barrett.js` 没加载或加载顺序错了。

**解决**：在 Sources 面板搜索函数名，找到所有引用该函数的文件，全部下载并按依赖顺序加载。

### 5.3 加密结果与服务端对不上

**排查步骤**：

1. 用浏览器 DevTools Console 手动调用加密函数，对比输出
2. 检查公钥/key 是否获取正确（有时会变）
3. 检查是否有随机盐值（salt）或时间戳参与加密
4. 确认字符编码一致（UTF-8）

### 5.4 JS 反混淆

生产环境的 JS 通常是压缩混淆的：

```javascript
// 混淆后（难以阅读）
function a(b){var c=...;return d.e(f(g(h(b))))}

// 在线格式化后（可读）
function encryptPassword(input) {
    var key = new RSAKey();
    key.setPublic(modulus, exponent);
    return key.encrypt(input);
}
```

> 先用在线 JS 格式化工具还原缩进和变量名，再分析。

## 六、JS 逆向方案选型

| 方案              | 原理                             | 优点             | 缺点               |
| --------------- | ------------------------------ | -------------- | ---------------- |
| **js2py**       | 纯 Python 实现的 JS 解释器            | 纯 Python，无外部依赖 | 速度慢，不支持 ES6+复杂语法 |
| **PyExecJS**    | 调用本地 Node.js / PhantomJS 执行 JS | 支持完整 JS 语法     | 需要本机装 Node.js    |
| **Selenium 注入** | 在浏览器 Console 执行 JS 拿结果         | 100% 兼容，无需分析依赖 | 慢，需要开浏览器         |
| **RPC 远程调用**    | 浏览器注入 JS 暴露函数 → Python 远程调     | 无需逆向、100% 准确   | 架构复杂，需要浏览器常驻     |
| **调加密接口**       | 部分网站的加密是独立 API，直接调             | 最简单干净          | 不常有这种好事          |

**推荐路线**：js2py 尝试 → 语法不兼容换 PyExecJS → 太复杂换 Selenium → 极高频需求考虑 RPC。

## 七、逆向工作流总结

```
┌─────────────────────────────────────────────────────┐
│                  JS 逆向标准工作流                      │
├── 1. 抓包 ─→ 确认哪些参数被加密                          │
├── 2. 定位 ─→ Event Listener 断点 + Search 定位加密入口     │
├── 3. 追踪 ─→ F11 Step Into 逐层跟进，找到加密函数           │
├── 4. 提取 ─→ 复制加密函数及其依赖文件                      │
├── 5. 加载 ─→ 按依赖顺序用 js2py 加载 JS 文件               │
├── 6. 调用 ─→ Python 调用加密函数，对比浏览器输出验证          │
├── 7. 集成 ─→ 将加密结果拼入 requests POST 请求              │
└─────────────────────────────────────────────────────┘
```

> 一个中等难度的 JS 逆向通常需要 2-4 小时——定位 60% 时间，调通 40% 时间。耐心和 F11 是你最重要的工具。

## 关键概念

- **调用栈（Call Stack）**：函数调用层级——从事件触发到加密执行的完整路径
- **断点（Breakpoint）**：让 JS 在指定位置暂停——逆向调试的核心手段
- **js2py**：纯 Python 的 JS 解释器，用于在 Python 中执行 JS 代码
- **依赖加载顺序**：被依赖的 JS 文件必须先加载——顺序错 = 函数未定义
- **反混淆**：将压缩混淆的 JS 还原为可读格式——分析的第一步

## 可行动建议

- 逆向前先确认 Selenium 方案是否够用——一个登录逆向可能花 4 小时，Selenium 可能只要 10 分钟
- 定位加密入口用 Event Listener + Search 双管齐下——一个不行换另一个
- 追踪调用链时记录每个关键变量值（Watch 面板）——方便后续 Python 实现时对比
- JS 文件按依赖顺序加载——用 Sources 面板的搜索功能确认调用关系
- 逆向完成后对比浏览器 Console 和 Python 的输出——一致才是正确的
