# AI掘金头条 — 缓存和调用模型

> Redis 缓存策略 与 通义千问 QWen 大模型调用

---

## 一、缓存概述

### 为什么需要缓存

当 1000 人同时查询数据库时，数据库压力极大，响应变慢。缓存通过高速临时存储来解决这个问题。

```
用户 / 前端 → FastAPI 服务器 → 数据库（慢）
                    ↕
              缓存 Redis（快）
```

### 缓存的核心作用

| 优势 | 说明 |
|------|------|
| 提升性能 | 减少耗时计算和数据库查询 |
| 降低延迟 | 内存读取远快于磁盘 |
| 减轻负载 | 减少数据库并发压力 |
| 节省成本 | 减少服务器资源消耗 |

### 项目中的缓存流程

```
前端请求数据 → 服务器查缓存
                    → 有缓存：直接返回
                    → 无缓存：查数据库 → 写入缓存 → 返回数据
```

## 二、Redis

Redis 是一种高性能的 Key-Value 存储系统，数据存储在内存中，读写速度极快，非常适合作为应用层的缓存服务。

### Redis 使用四步骤

```
1. 安装 Redis 服务端 → 2. 配置 Redis 客户端 → 3. 封装缓存操作 → 4. 设计缓存策略
```

---

### 2.1 安装 Redis 服务端

| 平台 | 安装方式 |
|------|----------|
| Mac | `brew install redis` |
| Windows | 双击 `.msi` 安装文件 |

**验证：**
- Mac：`redis-server`
- Windows：`redis-cli ping`（返回 PONG 表示成功）

默认端口号：**6379**

---

### 2.2 配置 Redis 客户端

```bash
pip install redis
```

```python
import redis.asyncio as redis

# 配置 Redis 客户端
r = redis.Redis(
    host="localhost",       # Redis 服务器地址
    port=6379,              # 端口号
    db=0,                   # 数据库编号（0~15）
    decode_responses=True   # 将字节流解码为字符串
)
```

---

### 2.3 封装缓存操作

缓存操作就是围绕 Redis 做"存、取、删、判断、过期"等操作。

Redis 存储数据格式：**key-value**

| 方法 | 参数 | 描述 |
|------|------|------|
| `setex` | key, expire(秒), value | 设置缓存并指定过期时间 |
| `get` | key | 获取缓存值。不存在返回 None |
| `delete` | key | 删除指定的缓存键 |
| `exists` | key | 检查缓存键是否存在，返回布尔值 |

---

### 2.4 设计缓存策略 — 旁路缓存（Cache-Aside）

最常见的缓存策略：**应用程序主动管理缓存。**

- **读**：先查缓存，有则返回；没有则查数据库 → 写入缓存 → 返回
- **写**：更新数据库后，更新或删除缓存数据

#### 代码示例

```python
async def get_categories(db: AsyncSession, skip: int = 0, limit: int = 100):
    # 1. 尝试从缓存获取
    cached_categories = await get_cached_categories()
    if cached_categories:
        return cached_categories

    # 2. 如果缓存没有，从数据库中查询
    stmt = select(Category).offset(skip).limit(limit)
    result = await db.execute(stmt)
    categories = result.scalars().all()

    # 3. 缓存查询结果
    if categories:
        categories = jsonable_encoder(categories)
        await cache_categories(categories)

    return categories
```

---

#### 缓存过期时间策略

**不同类型的数据，缓存时间不同，否则会出现缓存雪崩。**

| 数据类型 | 缓存时间 | 说明 |
|----------|----------|------|
| 分类、配置 | 7200s（2小时） | 数据稳定，变更少 |
| 列表数据 | 600s（10分钟） | 更新频率中等 |
| 详情数据 | 1800s（30分钟） | 介于分类和列表之间 |
| 验证码 | 120s（2分钟） | 时效性要求最高 |

> 核心原则：数据越稳定，缓存越久；数据变化越快，缓存越短。

---

#### 新闻列表缓存设计

```python
# 缓存 Key（唯一）：news:list:分类ID:页码:每页数量
cache_key = f"news:list:{category_id}:{page}:{page_size}"

# 缓存 Value：新闻列表 JSON
```

**流程：**

```
前端请求新闻列表 → 查缓存(news:list:分类id:页码:每页数量)
                   → 有缓存：返回缓存数据
                   → 无缓存：查数据库 → 写缓存 → 返回
```

## 三、调用大模型 — QWen

### 阿里云百炼模型广场

在前端页面中有模型请求的接口指定，支持千问（Qwen）系列模型。

**使用步骤：**

1. 登录阿里云百炼模型广场
2. 选择模型（通义千问3-Max）
3. API 参考 → 获取 HTTP 请求地址 + API Key
4. 前端调用

### 前端配置大模型

```
前端项目 → src/ → config/ → api.js
替换：大模型 HTTP 请求地址 + API Key + 模型名称
```

> 注意：前端直接调用阿里云百炼 API，不需要通过 FastAPI 后端中转。

## 总结

| 组件 | 核心要点 |
|------|----------|
| **Redis 服务端** | 端口 6379，内存 Key-Value 存储 |
| **Redis 客户端** | `redis.asyncio`，`setex`/`get`/`delete`/`exists` |
| **缓存策略** | 旁路缓存（Cache-Aside），先查缓存再查数据库 |
| **过期策略** | 分类 2h / 列表 10min / 详情 30min / 验证码 2min |
| **缓存 Key 设计** | `模块:子资源:参数1:参数2:...` 格式 |
| **QWen 大模型** | 阿里云百炼 → 获取 API Key → 前端直接调用 |
