# 异常处理

## 概述

Python 有两种错误：

| 类型 | 发生时机 | 示例 |
|------|---------|------|
| **语法错误** | 解析阶段，程序根本无法运行 | 缺少冒号、缩进错误 |
| **异常** | 运行阶段，语法正确但执行出错 | 除零、变量未定义、类型错误 |

```python
# 语法错误 —— 解析期报错
while True print(1)   # SyntaxError: invalid syntax

# 异常 —— 运行期报错
print(var1)           # NameError: name 'var1' is not defined
```

## 常见异常类型

| 异常                  | 触发条件              |
| ------------------- | ----------------- |
| `BaseException`     | 所有异常的基类           |
| `Exception`         | 常规异常的基类（自定义异常继承它） |
| `SyntaxError`       | 语法错误              |
| `NameError`         | 访问不存在的变量          |
| `TypeError`         | 不同类型间的无效操作        |
| `ValueError`        | 传入类型正确但值无效的参数     |
| `IndexError`        | 序列索引超出范围          |
| `KeyError`          | 字典中查找不存在的 key     |
| `ZeroDivisionError` | 除数为零              |
| `FileNotFoundError` | 文件不存在             |
| `AttributeError`    | 访问对象不存在的属性        |
| `AssertionError`    | assert 断言条件为假     |

## try-except

### 基本结构

```python
try:
    # 可能出错的代码
except 异常类型1:
    # 处理异常类型1
except 异常类型2 as e:
    # 处理异常类型2，e 为异常对象
except:
    # 兜底捕获所有异常（不推荐）
```

**执行流程：**

1. 执行 try 块 — 无异常 → 跳过 except，执行 else（如有）
2. 出现异常 → 立即停止 try，从上往下匹配 except
3. 匹配成功 → 执行对应 except，不再往下匹配
4. 匹配失败 → 异常向外层传递，或程序终止
5. finally 无论是否异常都会执行

### 捕获示例

```python
try:
    result = 3 / 0
    print("这行不会执行")
except ZeroDivisionError as e:
    print(e)            # division by zero
print("程序继续运行")
```

### 合并捕获多个异常

```python
try:
    result = 10 / 0
except (ZeroDivisionError, TypeError) as e:
    print("捕获异常：", e)
```

## else 子句

try 块无异常时执行，用于将正常逻辑与异常处理分离：

```python
try:
    result = 10 / 2
except ZeroDivisionError as e:
    print(e)
else:
    print("结果：", result)   # 无异常时执行
```

## finally 子句

**无论是否发生异常都会执行**，即使 except 匹配不上也会先执行 finally 再抛出：

```python
try:
    f = open("test.txt", "r")
    content = f.read()
except FileNotFoundError:
    print("文件不存在")
finally:
    f.close()   # 确保文件关闭
```

对比：把 `f.close()` 放在 try-except 外部 — 如果异常未被捕获导致程序终止，外部代码不会执行。finally 保证无论什么情况都会执行。

## raise 抛出异常

手动抛出指定类型的异常：

```python
def int_add(x, y):
    if isinstance(x, int) and isinstance(y, int):
        return x + y
    raise TypeError("参数类型错误")

print(int_add(1, 2))       # 3
print(int_add("1", "2"))   # TypeError: 参数类型错误
```

### assert 断言

用于调试，表达式为 False 时抛出 `AssertionError`：

```python
assert 表达式, "异常描述"
# 等价于：
if not 表达式:
    raise AssertionError("异常描述")
```

```python
def int_add(x, y):
    assert isinstance(x, int) and isinstance(y, int), "参数类型错误"
    return x + y

print(int_add("1", "2"))  # AssertionError: 参数类型错误
```

> assert 默认可在运行时用 `-O` 参数禁用，不要用它做生产环境的参数校验，只用于调试。

## 自定义异常

继承 `Exception` 即可：

```python
class MyCustomError(Exception):
    """简单自定义异常"""
    pass

def divide(a, b):
    if b == 0:
        raise MyCustomError("除数不能为零")
    return a / b

try:
    divide(10, 0)
except MyCustomError as e:
    print(f"捕获到自定义异常: {e}")
```

### 带参数的自定义异常

```python
class ValidationError(Exception):
    def __init__(self, field, message):
        self.field = field
        self.message = message
        super().__init__(f"{field} 验证失败: {message}")

def validate_age(age):
    if not isinstance(age, int):
        raise ValidationError("age", "年龄必须是整数")
    if age < 0 or age > 150:
        raise ValidationError("age", "年龄必须在 0-150 之间")

try:
    validate_age(-5)
except ValidationError as e:
    print(f"字段: {e.field}, 错误: {e.message}")
```

## 异常的传递

内层异常未被捕获时，逐层向外传递，直到被处理或程序终止：

```python
try:
    try:
        try:
            print(1 / 0)            # 最内层
        except NameError:           # 不匹配 ZeroDivisionError
            print("第三层")
    except TypeError:               # 也不匹配
        print("第二层")
except Exception as e:              # 匹配！
    print("第一层", type(e), e)
# 输出: 第一层 <class 'ZeroDivisionError'> division by zero
```

## with 上下文管理

封装了 try-except-finally，自动管理资源获取和释放：

```python
with expression as variable:
    # 代码块
```

- `expression` 必须是上下文管理器（实现了 `__enter__` 和 `__exit__`）
- 进入 with 调用 `__enter__`，退出时调用 `__exit__`（无论是否异常）

**文件操作对比：**

```python
# 常规 —— 异常时文件可能未关闭
file = open("test.txt", "w")
file.write("hello")
file.close()

# try-finally —— 确保关闭
file = open("test.txt", "w")
try:
    file.write("hello")
finally:
    file.close()

# with —— 最简洁（推荐）
with open("test.txt", "w") as f:
    f.write("hello")
# 自动调用 f.close()，即使 write 抛异常也会关闭
```

## 速查

| 结构 | 用途 | 执行时机 |
|------|------|---------|
| `try` | 包裹可能出错的代码 | 始终 |
| `except 类型` | 捕获匹配的异常 | 有匹配异常时 |
| `except` | 兜底捕获所有 | 无其他 except 匹配时 |
| `else` | 无异常时的后续逻辑 | try 无异常时 |
| `finally` | 清理/释放资源 | 无论是否异常 |
| `raise` | 手动抛出异常 | 代码主动触发 |
| `assert` | 调试断言 | 条件为 False 时 |
| `with` | 上下文管理 | 等价 try-finally |

## 常见陷阱

- 裸 `except:` 会吞掉 `KeyboardInterrupt` 等系统异常 → 至少用 `except Exception`
- `finally` 中的 `return` 会覆盖 try 中的 `return` 和异常
- assert 可在 `-O` 模式下被禁用，不要用于生产环境校验
- 捕获太宽（如 `except Exception`）可能掩盖 bug，尽量捕获具体类型
- 异常处理有开销，不要用 try-except 做正常流程控制
