### 获取历史版本RPM包的途径

Jenkins 官方将历史版本的 RPM 包存放在 `**archives.jenkins.io**` 站点上。你可以通过以下模式直接下载所需版本的RPM文件：

```
https://archives.jenkins.io/redhat-stable/jenkins-<版本号>-1.1.noarch.rpm
```

例如，要下载 `2.426.2` 版本，链接为：`https://archives.jenkins.io/redhat-stable/jenkins-2.426.2-1 .1.noarch.rpm`

### 报错

Job for jenkins.service failed because the control process exited with error code.

See "systemctl status jenkins.service" and "journalctl -xeu jenkins.service" for details.

排查

1. jdk + 文件配置jdk路径
2. 端口占用
3. 文件权限

明白，你已经确认防火墙不再阻止 Jenkins 的端口访问，那么现在就不用考虑端口被拦截的问题了。

结合前面信息，你的 Jenkins 服务启动失败，**最可能原因是日志目录** `**/var/log/jenkins**` **不存在**，导致 Jenkins 启动即退出。

---

推荐操作顺序（在防火墙关闭情况下）

1. **创建日志目录并设置权限【不用】**

```
sudo mkdir -p /var/log/jenkins
sudo chown jenkins:jenkins /var/log/jenkins
sudo chmod 755 /var/log/jenkins
```

2. **确认 Java 环境**

```
which java
java -version
echo $JAVA_HOME
```

如果 `$JAVA_HOME` 未设置，在 `sudo find / -name "jenkins.service"` 或 `/etc/default/jenkins` 中加：

```
sudo find / -name "jenkins.service"

vi

/opt/jdk-17.0.2

# The Java home directory. When left empty, JENKINS_JAVA_CMD and PATH are consulted.
Environment="JAVA_HOME=/opt/jdk-17.0.2"

# The Java executable. When left empty, JAVA_HOME and PATH are consulted.
#Environment="JENKINS_JAVA_CMD=/etc/alternatives/java"

# Arguments for the Jenkins JVM
Environment="JAVA_OPTS=-Djava.awt.headless=true"

# IP address to listen on for HTTP requests.
# The default is to listen on all interfaces (0.0.0.0).
#Environment="JENKINS_LISTEN_ADDRESS="

# Port to listen on for HTTP requests. Set to -1 to disable.
# To be able to listen on privileged ports (port numbers less than 1024),
# add the CAP_NET_BIND_SERVICE capability to the AmbientCapabilities
# directive below.
Environment="JENKINS_PORT=8088"
```

3. **重载 systemd 并启动 Jenkins**

```
sudo systemctl daemon-reload
sudo systemctl restart jenkins
sudo systemctl status jenkins
```

4. **查看 Jenkins 日志（确认是否正常启动）**

**关键提醒**

- **防火墙**：如果系统防火墙（如 `firewalld`）已开启，需要放行新端口：

```
sudo firewall-cmd --permanent --add-port=8088/tcp
sudo firewall-cmd --reload
```

**SELinux**：对于 RHEL/CentOS，如果启用了 SELinux，需要为自定义端口添加标签：

- sudo semanage port -a -t http_port_t -p tcp 8081

## 插件安装问题

**先不急着登录**， 因为`**Jenkins**` 默认的插件更新源地址是 `**https://updates.jenkins.io/update-center.json**`。不过，由于网络原因，国内用户访问 Jenkins 官方插件更新源可能会比较慢，甚至出现超时的情况。因此，通常建议将 `**Jenkins**` 的插件更新源更换为国内的镜像源，以提高下载速度和稳定性。

以下是一些常用的国内 Jenkins 插件更新源地址：  
清华大学：`**https://mirrors.tuna.tsinghua.edu.cn/jenkins/updates/update-center.json**`  
华为开源镜像站：`**https://mirrors.huaweicloud.com/jenkins/updates/update-center.json**`  
腾讯云：`**https://mirrors.cloud.tencent.com/jenkins/updates/update-center.json**`  
中国科学技术大学：`**https://mirrors.ustc.edu.cn/jenkins/updates/update-center.json**`  
北京理工大学：`**https://mirror.bit.edu.cn/jenkins/updates/update-center.json**`

配置原理:  
默认情况下，Jenkins 的配置文件位于 `**/var/jenkins_home/updates/default.json**`, 如果该文件不存在，可能会使用 `**/var/lib/jenkins/hudson.model.UpdateCenter.xml**`。

## docker安装【推荐开发、测试】

![[附件/77df41cf57.png]]

[https://hub.docker.com/r/jenkins/jenkins](https://hub.docker.com/r/jenkins/jenkins)

[https://github.com/jenkinsci/docker](https://github.com/jenkinsci/docker)

```
docker pull jenkins/jenkins
```

这是 Jenkins 官方提供的 Docker 镜像使用说明，主要描述如何拉取不同版本和类型的 Jenkins 镜像。以下是逐步解读和补充说明：

---

### **1. 拉取最新的 LTS 版本**

```
docker pull jenkins/jenkins:lts-jdk17

docker run -p 8080:8080 -p 50000:50000 --restart=on-failure -v jenkins_home:/var/jenkins_home jenkins/jenkins:lts-jdk21
```

- 说明：

- `lts` 表示长期支持 (Long-Term Support) 版本。
- `jdk17` 表示镜像内包含的 JDK 版本为 Java 17。
- 工作区会以 `/var/jenkins_home` 格式存储。所有 Jenkins 的数据都存放在里面——包括插件和配置。

- 适用场景：

- 稳定性优先，适合生产环境。

---

### **2. 拉取最新的每周版本**

```
docker pull jenkins/jenkins:jdk17
```

- 说明：

- 这是 Jenkins 的每周版本 (Weekly Release)，包含最新特性和修复，但可能相对不稳定。
- `jdk17` 表示镜像使用 Java 17。

- 适用场景：

- 适合实验性使用或尝鲜新功能的场景。

---

### **3. 拉取轻量化的镜像**

- **说明**：

- Jenkins 提供基于 **Alpine** 的轻量化镜像，以及适用于 Windows 或其他 JDK 的版本。
- Alpine 镜像的标签可能是类似 `lts-jdk17-alpine`。

- **示例**：

```
docker pull jenkins/jenkins:lts-jdk17-alpine
```

**优点**：

**注意**：

- 更小的镜像体积。
- 更快的下载和启动速度。
- 由于轻量化的特性，某些插件或功能可能需要额外配置。

---

### **4. 拉取特定版本的镜像（推荐固定版本）**

```
docker pull jenkins/jenkins:<version>-<jdk>
```

- 说明：

- 指定 Jenkins 的确切版本和 JDK 版本，确保镜像版本一致性，适合生产环境。
- 例如：

```
docker pull jenkins/jenkins:2.414.3-jdk17
docker pull jenkins/jenkins:2.430-jdk21
```

- 适用场景：

- 避免意外升级导致的不兼容性问题。
- 确保版本一致性和可预测性。

---

### 安装

```
docker run -p 8080:8080 -p 50000:50000 --restart=on-failure jenkins/jenkins:lts-jdk21
```

注意：请阅读下方 [_“连接代理_](https://github.com/jenkinsci/docker#connecting-agents)”部分，了解 `50000` 端口映射的作用。注意：请阅读 [_DNS 配置_](https://github.com/jenkinsci/docker#dns-configuration)部分，以防看到“此 Jenkins 实例似乎离线”的提示。

这样工作区会以 `/var/jenkins_home` 格式存储。所有 Jenkins 的数据都存放在里面——包括插件和配置。你可能需要把它设为一个显式卷，这样你可以管理它并附加到另一个容器进行升级：

```
docker run -p 8080:8080 -p 50000:50000 --restart=on-failure -v jenkins_home:/var/jenkins_home jenkins/jenkins:lts-jdk21
```

这会自动在主机上创建一个“jenkins_home”[docker 卷](https://docs.docker.com/storage/volumes/)。即使容器被停止、启动或删除，Docker 卷仍保留其内容。

注意：避免将主机上的文件夹绑[定挂载](https://docs.docker.com/storage/bind-mounts/)映射到 `/var/jenkins_home`，因为这可能导致文件权限问题（容器内的用户可能没有主机上该文件夹的权限）。如果你 _真的_需要绑定挂载 jenkins_home，确保主机上的目录容器内的 Jenkins 用户（jenkins user - uid 1000）能够访问，或者使用 docker `run` 的 `-u some_other_user` 参数。

```
docker run -d -v jenkins_home:/var/jenkins_home -p 8080:8080 -p 50000:50000 --restart=on-failure jenkins/jenkins:lts-jdk21

chown -R 1000:1000 /data/jenkins
```

这样可以让 Jenkins 以分离模式运行，并添加端口转发和音量。你可以用命令“docker logs CONTAINER_ID”访问日志，以便检查首次登录令牌。容器的 ID 将从上述命令输出中返回。

或者，直接打印初始管理员密码，使用：

```
docker exec <jenkins_container_id_or_name> cat /var/jenkins_home/secrets/initialAdminPassword
```

用<jenkins_container_id_or_name>你实际的 Jenkins 容器 ID 或名称替换。

要访问 Jenkins 并完成初始设置，请按照[安装指南](https://www.jenkins.io/doc/book/installing/docker/#setup-wizard)中的说明操作。
