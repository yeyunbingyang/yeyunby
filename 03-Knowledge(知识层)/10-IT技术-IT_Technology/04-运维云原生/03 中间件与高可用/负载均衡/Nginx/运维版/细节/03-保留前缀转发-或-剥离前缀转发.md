在 Java 项目和 Nginx 的实际配合中，如果你的请求都带有 `/api` 前缀（例如 `example.com/api/user/login`），通常有两种处理策略：**保留前缀转发** 或 **剥离前缀转发**。

根据你的需求，这里是两种最常用的配置方案：

---

### 方案一：保留 `/api` 前缀（后端代码处理）

如果你的 Java 项目（Spring Boot）本身就定义了 `context-path: /api` 或者 Controller 上自带 `@RequestMapping("/api")`，那么 Nginx 只需要原样转发即可。

Nginx

```
upstream shop {
    server 192.168.1.101:8080;
    server 192.168.1.102:8080;
}

server {
    listen 80;

    # 匹配所有以 /api 开头的请求
    location /api/ {
        proxy_pass http://shop; # 注意：这里 shop 后面没有斜杠
        
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

- **效果**：用户请求 `http://domain.com/api/login` -> 转发给后端 `http://shop/api/login`。
- **用户访问**：`/api/user/list`
- **Nginx 行为**：发现匹配到了 `/api/`，于是把 `/api/user/list` 原封不动传给后端。
- **后端收到的请求**：`http://shop/api/user/list`
- **适用场景**：你的 Java 项目代码里，Controller 的路径本身就带有 `/api` 前缀（例如 `@RequestMapping("/api/user")`）。

---

### 方案二：剥离 `/api` 前缀（后端代码不带 api）

如果你的 Java 代码里定义的路径是 `/login`，但前端为了区分静态资源和接口请求加了 `/api`，那么 Nginx 需要在转发时把 `/api` 去掉。

**方法 A：利用** `**proxy_pass**` **的路径替换（最推荐，简单可靠）**

在 `proxy_pass` 的目标地址后面加上斜杠 `/`，Nginx 会自动进行路径替换。

Nginx

```
location /api/ {
    # 重点：shop 后面加了 /
    proxy_pass http://shop/; 
    
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

- **效果**：用户请求 `/api/login` -> 转发给后端 `/login`。【已经匹配的去除】

- **用户访问**：`/api/user/list`
- **Nginx 行为**：

1. 匹配到 `/api/`。
2. 把请求路径中的 `/api/` 剥离，剩下 `user/list`。
3. 把 `user/list` 拼接到 `http://shop/` 后面。

- **后端收到的请求**：`http://shop/user/list`
- **适用场景**：前端为了区分接口加了 `/api`，但你的 Java 后端代码里并没有 `/api` 前缀（例如 `@RequestMapping("/user")`）。

**方法 B：使用** `**rewrite**` **指令（更灵活）**

如果你需要更复杂的正则匹配，可以使用 `rewrite`。

Nginx

```
location /api/ {
    # 将 /api/(.*) 替换为 /$1，最后 break 表示停止匹配继续转发
    rewrite ^/api/(.*)$ /$1 break;
    proxy_pass http://shop;
}
```

---

### 避坑指南：关于“斜杠”的细节⭐⭐⭐

在 Nginx 中，`proxy_pass` 末尾有没有斜杠差异巨大，这是最容易出错的地方：

1. **没有斜杠**：`proxy_pass http://shop;`

- 会将 `location` 匹配到的路径**完整地**追加到后端地址。

2. **有斜杠**：`proxy_pass http://shop/;`

- 会将 `location` 匹配到的路径部分**替换**为斜杠。

### 总结建议

对于 Java 项目，通常推荐**方案二（方法 A）**。这样你的 Java 代码可以专注于业务逻辑路径（如 `/user/info`），而不需要在每个 Controller 里都硬编码一个 `/api` 前缀，同时也方便前端进行跨域处理或接口聚合。
