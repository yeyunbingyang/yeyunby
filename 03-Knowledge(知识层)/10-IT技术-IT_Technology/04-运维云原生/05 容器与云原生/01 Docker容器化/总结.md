## 一、核心思想：容器 vs 虚拟机

| 特性  | 虚拟机          | Docker 容器                 |     |
| --- | ------------ | ------------------------- | --- |
| 内核  | 每个 VM 拥有独立内核 | 共享宿主机 Linux 内核            |     |
| 启动  | 分钟级          | 秒级                        |     |
| 资源  | 重（GB 级）      | 轻（MB 级）                   |     |
| 隔离  | 硬件虚拟化，强隔离    | Namespace + Cgroups，进程级隔离 |     |
| 适用  | 硬件运维、多OS环境   | 软件开发、微服务、CI/CD            |     |

> 一句话：**容器是“打包好的进程”，虚拟化的是操作系统；虚拟机虚拟化的是硬件。**

---

## 二、三大核心对象

### 1. 镜像（Image）
- **只读模板**，包含应用 + 依赖 + 文件系统。
- 常用命令：`search`、`pull`、`images`、`rmi`、`save`/`load`、`tag`。

### 2. 容器（Container）
- **镜像的运行实例**，可读写，进程隔离。
- 生命周期：`run` → `start/stop/restart` → `rm`  
- 关键选项：
  - `-p` 端口映射  
  - `-v` 挂载卷  
  - `-d` 后台运行  
  - `-it` 交互式  
  - `--name` 命名  
  - `--restart` 重启策略  
  - `--network` 指定网络  

### 3. 仓库（Repository）
- 存储和分发镜像：Docker Hub、Harbor 等。
- 命令：`login`、`tag`、`push`。

## 三、容器关键操作速查

| 动作 | 命令示例 |
|------|----------|
| 查看运行中容器 | `docker ps` |
| 查看所有容器 | `docker ps -a` |
| 运行并进入交互 | `docker run -it --name mybox ubuntu /bin/bash` |
| 后台运行服务 | `docker run -d -p 8080:80 nginx` |
| 查看日志 | `docker logs -f --tail 100 容器名` |
| 进入运行中的容器 | `docker exec -it 容器名 /bin/bash` |
| 复制文件到宿主机 | `docker cp 容器名:/app/log.txt ./` |
| 导出容器文件系统 | `docker export 容器名 > backup.tar` |
| 提交新镜像 | `docker commit 容器名 新镜像:tag` |

## 四、网络模式（重点）

| 模式 | 说明 | 场景 |
|------|------|------|
| `bridge`（默认） | NAT 方式，容器通过 docker0 网桥通信 | 单机开发 |
| `host` | 直接使用宿主机网络栈 | 高性能、端口紧缺场景 |
| `none` | 无网络 | 极安全、离线处理 |
| `container` | 共享另一个容器的网络 | 紧密辅助容器（如日志收集） |

**企业推荐**：自定义 bridge 网络  
- `docker network create mynet`  
- 同一 network 下的容器**可直接用容器名通信**，无需 `--link`（已废弃）。

## 五、Dockerfile 最佳实践

1. **FROM** 最小基础镜像（alpine、slim）
2. **合并 RUN** 减少镜像层数
3. **利用构建缓存**：先 COPY 依赖文件，后 COPY 源码
4. **多阶段构建**：最终镜像只留运行所需文件
5. **指定标签**，避免 `latest`
6. 用好 **.dockerignore** 文件

## 六、资源限制（防止“吵闹邻居”）

| 资源 | Docker 参数 | 后果超出限制 |
|------|-------------|----------------|
| 内存 | `-m` / `--memory` | OOM Kill |
| CPU | `--cpus` / `--cpu-shares` | 限流、延迟 |
| 磁盘 I/O | `--device-read/write-bps` | 读写阻塞 |
| 进程/文件数 | `--pids-limit` / `--ulimit nofile` | 创建失败 |

## 七、Docker Compose 核心逻辑

- **工程（Project）**：一个目录 + `docker-compose.yml`
- **服务（Service）**：定义一个容器的配置（镜像、端口、卷、环境、依赖）
- **容器（Container）**：服务启动后的实例

**常用命令**（在 docker-compose.yml 目录下执行）：
```bash
docker compose up -d          # 启动所有服务
docker compose down -v        # 停止并删除数据卷
docker compose ps             # 查看状态
docker compose logs -f        # 查看日志
docker compose exec 服务名 bash   # 进入某服务容器
```

> 注意：`depends_on` 只控制启动顺序，不保证服务已就绪（需要应用层健康检查）。

## 八、常见小技巧与避坑

- **镜像导入导出**：`save`/`load` 用于镜像，`export`/`import` 用于容器快照。
- **容器重命名**：`docker rename 旧名 新名`
- **修改容器配置**：`docker update`（如 CPU/内存限制），但网络、端口等需重建。
- **清理**：`docker system prune -a` 删除未使用的镜像、容器、网络。
- **查看详细信息**：`docker inspect 容器/镜像/网络` 输出 JSON。
