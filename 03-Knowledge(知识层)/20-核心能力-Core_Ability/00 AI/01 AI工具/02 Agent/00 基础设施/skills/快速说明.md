## 一、Agent Skills 是什么？

**一句话总结**：Agent Skills 是一种**带目录的说明书**，或者说是一种**渐进式披露提示词**的机制。

### 核心设计：三层结构
| 层级                    | 说明                | 加载方式             |
| --------------------- | ----------------- | ---------------- |
| **元数据（Metadata）**     | Skill 的名字、描述、调用时机 | **必定加载**进 AI 上下文 |
| **指令层（Instructions）** | 具体的任务指令、操作步骤      | **按需加载**         |
| **资源层（Resources）**    | 辅助文件（脚本、文档、图片等）   | **按需加载**         |

**类比**：元数据 = 书的**目录**，指令层 = **正文**，资源层 = **附录**。

### 核心优势
- **大幅降低 Token 消耗**：只加载目录，需要时才加载正文
- **降低提示词复杂度**：避免一次性塞入过多内容
- **渐进式披露**：AI 根据判断决定是否需要深入调用

## 二、文件结构与配置

### 1. 目录结构（以 Claude Code 为例）
```
项目根目录/
└── .cloud/
    └── skills/
        └── 技能名称/
            ├── skill.md      ← 定义文件（必须）
            ├── scripts/      ← 可执行脚本（可选）
            ├── references/   ← 参考文档（可选）
            └── assets/       ← 图片等资源（可选）
```

### 2. skill.md 文件格式
```markdown
---
name: 技能名称
description: 描述AI应该在什么时机调用此skill
---

# 指令部分
用 Markdown 详细描述任务要求...
```

- 文件名必须是 `skill.md`（S 大写）
- 元数据用 `---` 包裹
- 描述中**必须写清楚调用时机**

## 三、实战案例

### 案例 1：字幕转 Markdown
- **功能**：将 SRT 字幕文件转为 Markdown 笔记
- **要点**：禁止删减，保留所有文字，在关键位置插入截图占位符
- **调用过程**：用户提问 → Claude Code 扫描元数据 → AI 判断调用 skill → 加载指令 → 执行任务


### 案例 2：选题灵感生成
- **功能**：视频创作选题枯竭时提供灵感
- **用法**：提供历史数据较好的视频选题，让 AI 生成 10-15 个类似灵感
![[Pasted image 20260512001947.png]]

### 案例 3：视频截图（资源层 - scripts）
- **进阶**：在 skill 文件夹下新建 `scripts/` 目录，放入 Python 脚本
- **流程**：
  1. 先生成带截图占位符的 Markdown
  2. 调用 `scripts/` 下的 Python 脚本（如调用 FFmpeg 截图）
  3. 替换占位符为实际图片链接
- **注意**：脚本代码**不作为上下文传递给 AI**，仅由 AI 调用执行，进一步节省 Token

### 案例 4：写作助手（资源层 - references）
- **功能**：结合用户材料进行文案写作
- **特殊逻辑**：若材料是 AI/软件/计算机相关，先阅读 `references/` 下的范文，学习行文风格
- **流程**：AI 读取指令 → 判断需要学习风格 → 按需加载 references 中的范文 → 综合生成文案

## 四、AI 调用流程总结

```
用户提问
    ↓
Agent（Claude Code/Codex）扫描所有 skill.md 的元数据
    ↓
元数据 + 用户提问 → 发送给 AI 大模型（占用上下文极少）
    ↓
AI 判断：
  ├─ 不使用 skill → 直接回答
  └─ 使用某个 skill → 通知 Agent 加载该 skill 的指令细节
    ↓
Agent 将指令层（skill.md 下半部分）发送给 AI
    ↓
如需资源层（scripts/references/assets）→ 按需加载
    ↓
AI 综合所有信息生成完整回答
```

## 五、Agent Skills vs MCP

| 维度 | Agent Skills | MCP |
|------|-------------|-----|
| **侧重点** | 提示词管理 | 工具调用 |
| **类比** | 带目录的说明书 | 标准化的工具箱 |
| **加载方式** | 渐进式披露，按需加载 | 一次性塞入上下文 |
| **Token 消耗** | **更低** | 较高 |
| **主体** | Markdown 文本 | Node.js / Python 软件包 |
| **执行可靠性** | 脚本受环境差异影响，失败率较高 | 软件包执行成功率更高 |
| **编写难度** | **简单**，写一个 Markdown 即可 | **较难**，需搭建完整开发环境 |
![[Pasted image 20260512002518.png]]


### 协作方式（Skills + MCP）
- **Skills 负责**：提示词管理、任务流程定义、渐进式披露
- **MCP 负责**：具体工具调用（如 GitHub API、文件系统操作等）

**实战示例**：写作 skill 生成文案后，通过 GitHub MCP Server 自动创建仓库并上传文件备份。
