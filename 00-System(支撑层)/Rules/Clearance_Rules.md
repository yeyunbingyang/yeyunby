# 清空规则

## Inbox 清理频率

| 频率 | 规则 |
|------|------|
| **每日** | 处理当天新增内容，判断去向 |
| **每周** | Inbox 必须清空至 0，否则本周任务未完成 |

## Inbox 内容去向判断

```
新内容进入 Inbox
    ↓
是否有长期价值？
    ├─ 是 → 移入 03-Knowledge 对应域，补写 frontmatter
    ├─ 工具/素材 → 移入 04-Resources
    ├─ 输出成果 → 移入 05-Output
    └─ 否（灵感/碎片/过期） → 直接删除 或 移入 06-Archive
```

## 笔记归档触发条件

满足以下任一条件，将笔记移入 `06-Archive/`：

1. `status: 归档` — 内容已过时，不再使用
2. 超过 6 个月未更新且 `status != 稳定`
3. 与新笔记内容重复，被更完整的版本替代
4. 旧版本结构文件（如被替换的 MOC）

## 归档操作步骤

1. 将笔记 frontmatter 中 `status` 改为 `归档`
2. 将文件移动到 `06-Archive/`
3. 在原位置（如果有链接依赖）可保留一行重定向注释：  
   `> 此笔记已归档，新版本见 [[新笔记名]]`

## 禁止行为

- 不直接删除有内容的笔记（先归档，再评估是否删除）
- 不用"改名"替代归档（改名会破坏已有的 `[[链接]]`）
