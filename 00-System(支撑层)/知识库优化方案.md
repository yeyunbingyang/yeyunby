# 知识库优化方案

## 设计目标

这套知识库采用轻量结构：少目录、强导航、靠模板和标签承载状态。一级目录只保留 System / 日常流 / Knowledge / Resources 四个角色，避免目录过多导致维护成本上升。归档通过 `status: 归档` 标记，无需独立目录。

## 实际目录结构

```
MOC知识地图.md               # 顶级知识库导航入口
00-System(支撑层)/           # 系统规则、模板、规范、工作流
├── Rules/                   # 命名规范、标签系统、清空规则
├── Templates/               # 所有模板 (6种)
└── Runtime_Data/            # 项目/技能仪表盘、笔记统计
01-日常流(日常流层)/        # 日记、复盘、流入、阶段规划
├── 流入/                    # 新内容第一落点，目标每日清空
├── 日记/                    # 每日笔记
├── 周复盘/                  # 每周回顾
└── 阶段规划/                # 学习/阶段计划
02-Knowledge(知识层)/        # 长期知识资产（三大域）
├── 10-IT技术-IT_Technology/
├── 20-核心能力-Core_Ability/
└── 30-认知层-Cognition/
03-Resources(资源层)/        # 工具、素材、课程、网站、AI 平台
```

## 知识领域分类

```
02-Knowledge(知识层)/
├── 10-IT技术-IT_Technology/
├── 20-核心能力-Core_Ability/
└── 30-认知层-Cognition/
```

## 四个目录的职责

`00-System(支撑层)`：放系统说明、frontmatter 规范、操作工作流、模板和知识库维护规则。

`01-日常流(日常流层)`：时间维度的统一容器。流入/ 是新内容第一落点（目标每日清空），日记/ 放每日记录，周复盘/ 每周回顾，阶段规划/ 存放学习/项目计划。

`02-Knowledge(知识层)`：放长期知识结论、方法论、SOP、项目复盘、案例和可复用经验。两大域：IT 技术（工程开发）、核心能力（能力与认知，含 AI 应用与思维人文）。

`03-Resources(资源层)`：放工具、素材、课程、网站、AI 平台和外部参考。资源库只保存"可再次调用的外部材料"。趋势内容不再独立维护，高价值信息提炼入知识层。

## 被合并/移除的旧目录

- `01-Inbox` → 合并入 `01-日常流/流入/`
- `04-Trends` → 已移除，高价值内容提炼入 Knowledge
- `05-Archive` → 已移除，通过 `status: 归档` 标记，无需独立目录

## 资源库定位

`03-Resources(资源层)` 必须保留，但它只放资源索引，不放最终知识结论。

适合放入资源库：

- 软件工具、插件、平台、网站。
- 课程、教程、书单、文章、视频清单。
- 图片、封面、图表、案例、提示词素材。
- AI 工具、模型平台、创作工具和前沿资讯。

加工后的去向：

- 学到的结论进入 `02-Knowledge(知识层)`。
- 可复用步骤进入 `02-Knowledge(知识层)`，并标记 `SOP`。
- 当天使用记录进入 `01-日常流(日常流层)`。
