# 知识库优化方案

## 设计目标

这套知识库采用轻量结构：少目录、强导航、靠模板和标签承载状态。一级目录只保留 `System / Inbox / MOC / Knowledge / Resources / Daily` 六个角色，避免目录过多导致维护成本上升。

## 推荐目录结构

```text
KnowledgeBase/
├── 01-MOC.md        # 顶级知识库导航入口
├── 00-System/       # 系统规则、模板、规范、工作流
│   └── Templates/   # 所有模板
├── 01-Inbox/        # 临时入口，收集未处理内容
├── 03-Knowledge/    # 长期知识资产
├── 05-Resources/    # 工具、素材、课程、网站、AI 平台
└── 08-Daily/        # 日记、复盘、每日输入输出
```

## 知识领域分类

```text
03-Knowledge/
├── 01-IT技术/
├── 02-认知思维/
├── 03-人文社科/
├── 04-商业财经/
├── 05-职业能力/
├── 06-创作表达/
└── 07-生活基础设施/
```

## 六个目录的职责

`00-System`：放系统说明、frontmatter 规范、操作工作流、模板和知识库维护规则。

`01-Inbox`：放所有还没判断价值的新内容，包括截图、网页剪藏、灵感、链接和临时想法。

`01-MOC.md`：顶级导航入口，直接指向各目录、领域 MOC、系统文档和模板。

领域 MOC：直接放在对应的 `03-Knowledge/<编号-领域>/` 目录下，作为该领域的子导航。

`03-Knowledge`：放长期知识结论、方法论、SOP、项目复盘、案例和可复用经验。

`05-Resources`：放工具、素材、课程、网站、AI 平台和外部参考。资源库只保存“可再次调用的外部材料”。

`08-Daily`：放每日记录、复盘、输入输出、短期行动和当天灵感。

## 被合并的旧目录

`Active` 合并进 `08-Daily` 和 `03-Knowledge`：当天推进记录放 Daily，沉淀后的项目经验放 Knowledge。

`Assets` 合并进 `03-Knowledge`：SOP、概念卡、方法论、框架都用标签管理。

`Output` 合并进 `03-Knowledge` 和 `08-Daily`：成果记录可以挂到相关领域 MOC，发布过程放 Daily。

`Archive` 不再单独建一级目录：通过 `status: 归档` 或 `tags: [归档]` 表达状态。

`Templates` 归入 `00-System/Templates`。

## 资源库定位

`05-Resources` 必须保留，但它只放资源索引，不放最终知识结论。

适合放入资源库：

- 软件工具、插件、平台、网站。
- 课程、教程、书单、文章、视频清单。
- 图片、封面、图表、案例、提示词素材。
- AI 工具、模型平台、创作工具和前沿资讯。

加工后的去向：

- 学到的结论进入 `03-Knowledge`。
- 可复用步骤进入 `03-Knowledge`，并标记 `SOP`。
- 当天使用记录进入 `08-Daily`。
