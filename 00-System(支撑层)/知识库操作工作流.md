# 知识库操作工作流

## 总流程

```text
收集 -> 判断 -> 加工 -> 导航 -> 复盘
```

## 1. 收集

所有未处理内容先进入 `01-日常流(日常流层)/流入/`。

适合放入 Inbox：

- 临时想法、截图、网页剪藏、视频链接。
- 待读文章、书单、课程、工具链接。
- 项目问题、报错、灵感和待办。

规则：

- 先收集，不纠结分类。
- 每天快速扫一遍。
- 尽量 24 小时到 7 天内清空。

## 2. 判断去向

整理 Inbox 时只做四种判断。

放入 `02-Knowledge(知识层)/`：已经形成理解，值得长期复用。

放入 `03-Resources(资源层)/`：只是工具、素材、课程、网站或外部链接。

放入 `01-日常流(日常流层)/`：当天记录、临时行动、复盘、灵感来源。

放入 `00-System(支撑层)/`：模板、规范、规则、工作流。

## 3. 加工知识

一条知识从粗糙到稳定，建议经过四步。

```text
原始材料 -> 一句话结论 -> 适用场景/边界 -> 挂到 MOC
```

加工标准：

- `summary` 写核心结论，不写"关于什么的笔记"。
- 至少说明：它是什么、解决什么问题、什么时候不适用。
- 能变成步骤的，用 `tags: [SOP]` 标记。
- 能变成案例的，用 `tags: [案例]` 标记。
- 加工完成后，把链接补到对应领域 MOC。

## 4. 使用资源库

`03-Resources(资源层)/` 只负责"找得到"和"可调用"。

资源条目建议记录：

- 名称
- 链接或位置
- 类型：工具 / 课程 / 网站 / 素材 / AI 平台
- 用途
- 适用场景
- 评价
- 关联领域

资源加工后：

- 学到的知识进入 `02-Knowledge(知识层)/`。
- 使用过程或当天产出进入 `01-日常流(日常流层)/`。
- 长期有用的工具保留在 `03-Resources(资源层)/`。

## 5. 维护 MOC

MOC 只做导航，不写长正文。

维护规则：

- 新增重要知识笔记后，回到对应 MOC 添加链接。
- 每个 MOC 保留主题方向、笔记索引、关键问题和待整理入口。
- 当一个主题链接超过 10 条，可以拆出专题 MOC。

## 6. 每周复盘

每周检查一次：

- `01-日常流(日常流层)/流入/` 是否清空。
- `03-Resources(资源层)/` 是否有高价值资源需要加工。
- `02-Knowledge(知识层)/` 是否有新笔记没有挂到 MOC。
- `01-日常流(日常流层)/` 是否有内容需要迁移到 Knowledge。
- `00-System(支撑层)/Templates/` 是否需要新增或优化模板。
