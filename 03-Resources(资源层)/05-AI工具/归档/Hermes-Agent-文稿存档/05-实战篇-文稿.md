# 实战篇 文稿

## 43. 实战篇_案例介绍

大家好，学完了前面所有的知识之后，最后进入第五个模块——**实战篇**。

实战篇是一个综合性案例：使用 AI 驱动来完成一个**技术博客的自动发布系统**。这个发布系统会串联 Hermes 前面讲到的 25 项以上的全部功能。

这个自动发布的技术博客对文章的要求非常高，不是随便写一篇就行。它需要从选题开始，进行研究调研、文章拟写、人工审核，再到最终的自动发布，后续还有持续维护的全流程。这是一个真实的企业级大型案例，更多是为了演示在 Hermes 当中学到的各种功能。

为了照顾直接来做实战的朋友，也为了让环境尽量保持一致，我把整个 Hermes 重装了。重装 Hermes 非常简单，把 Hermes 根目录下的所有文件全部删除即可。它就在 `%LOCALAPPDATA%\HERMES` 文件夹中，全部清空就彻底删除。

**涉及的功能清单：**
- **Profile**：创建多个 Agent 角色进行协同工作（创建了 4 个）
- **Provider**：选择不同供应商，调研用 DeepSeek（便宜），写作用 Claude（质量高）
- **Skill**：技能系统、Skill Manager、Curator 维护
- **Memory**：记住 Markdown 风格偏好
- **Session Search**：跨会话搜索
- **Cron**：定时任务
- **Context From**：上下文衔接
- **Delegation**：任务委派
- **Kanban**：看板一键创建、拆解子任务
- **Gateway**：消息网关
- **MCP**：MCP 服务
- **Tools**：工具集
- **Hooks**：钩子
- **Plugins**：插件
- **Dashboard**：仪表盘
- **TUI / API Server**：终端和 API
- **No Agent**：无 Agent 的 Cron 定时任务
- **SOUL.md**：上下文文件
- **上下文压缩**

这是一个非常大型的案例，会把学过的 Hermes 绝大多数内容都涵盖进去。

## 44. 实战篇_创建 4 个独立的 Profile Agent

大家好，接下来进入**环境搭建**环节。

**第一步：配置模型。** 主要用到 DeepSeek 和 Claude。Claude 可以通过国际中转商 Open Router 访问。使用 GitHub 账号登录 Open Router，创建 API Key。推荐使用 Sonnet 4.6（性价比高），如果不想用国外模型，统一用 DeepSeek 也可以。

**第二步：创建四个独立的 Hermes Profile。**

1. **调研员（Researcher）**：负责查阅文档、源码和网络资料，使用低成本模型（DeepSeek v4 Flash）。限制工具——只能使用 Web 搜索和终端。定制人格：简洁、结构化输出。

2. **拟稿员（Writer）**：负责写作，使用较贵的模型。安装专门的写作 Skill（`writer skills install`）。定制专属人格。

3. **审核员（Reviewer）**：负责审查文档和代码变更。配置模型和人格。

4. **发布员（Publisher）**：负责发布到 GitHub 或邮件。限制工具——只能使用终端操作和 MCP 服务，不能使用网络搜索。

创建命令：`hermes profile create <name> --description <desc> --clone`。创建后使用 `setup` 配置 API Key 和模型，限制工具，定制 SOUL.md 人格。

## 45. 实战篇_配置微信的消息平台

大家好，接下来配置**网关与推送**。使用国内的微信。

**配置步骤：**
1. 如果网关未安装，执行 `hermes gateway setup` 安装
2. 执行交互式配置，选择微信（3）
3. 选择二维码登录
4. 用微信扫描二维码
5. 授权完成后，按默认选项一直回车
6. 启动网关

**授权用户配置：** 在 env 文件中配置允许的用户。可以把 `allow_all_users` 设为 `true`，或者把当前用户 ID 添加到 `allow_user`。修改后重启网关。

配置完成后，在微信中可以看到 Hermes 机器人，可以正常沟通。

## 46. 实战篇_完成 GitHub 的推送并持久记忆

大家好，配置完微信平台后，接下来配置**GitHub 推送**。

**创建 GitHub Token：**
1. 登录 GitHub，进入 Settings → Developer settings → Personal access tokens
2. 创建 Token（经典），起名 "Hermes"
3. 勾选所有权限（个人使用）
4. 复制 Token

**配置 Token：** 在 env 文件中找到 GitHub Token 相关配置，取消注释并填入 Token。

**测试推送：** 进入 Hermes 对话，告诉它 env 中配置了 GitHub Token，让它测试是否能完成账号的读取和推送功能。

**注意事项：** Hermes 的安全等级比较高，会自动把 Token 隐藏掉。需要明确告诉它"直接使用 Token，别再隐藏为暗码"。否则在多个 Agent 协同工作时，Token 不传递会导致运行失败。

**配置持久记忆：** 告诉 Hermes 记住以下信息：
- 博客使用 GitHub Pages + Hugo 静态站点
- 仓库地址
- 文章用 Markdown 格式

它会通过 memory 的形式记录下来，后续写文章时直接使用。

## 47. 实战篇_使用定时推送完成筛选选题

大家好，在设计好 GitHub 推送之后，最好的办法是把整个工作流设计出来，让 Hermes 执行一遍。第一次手动执行成功后，后续都可以让 Hermes 保存成技能，通过微信直接派发任务。

**使用看板：** 创建专用的博客看板（`hermes kanban init blog`），创建用于分发任务、拆解任务的 Orchestrator Profile。

**工作流设计：**
- Cron 定时任务每天早上 7 点、7 点半、8 点搜集任务
- 结果发到微信上
- 用户查看后挑选感兴趣的选题，让 Hermes 自动发布

**创建定时任务：** 使用自然语言告诉 Hermes "创建一个定时任务，用于技术博客选题流水线，7 点一个、7 点半一个、8 点一个，结果投递到微信"。Hermes 会自动创建三个 Cron 任务。

**执行效果：** 第一次手动执行后，微信会收到采集的热点、筛选的选题和生成的简报。如果简报字数太多被微信限制，可以修改定时任务限制输出字数（500 字以内），只让任务三（生成简报）发送到微信。

## 48. 实战篇_使用 Kanban 多任务协作完成任务设计

大家好，在完成选题定时任务之后，接下来演示**日常运行逻辑**。

**日常运行流程：**
1. 在微信上发送新文章任务
2. 使用看板 Swarm 一键启动协作拓扑
3. Orchestrator 拆解任务
4. 并行执行 Research 调研任务
5. Writer 编写文章
6. Reviewer 审核
7. Publisher 自动发布

**记忆配置：** 通过记忆方式告诉 Hermes 后续的执行逻辑。新建会话，告诉它：
- 通过微信接收博客编写主题
- 触发看板 Swarm 一键启动拓扑
- 先使用 Orchestrator 拆解任务
- 安排 Research Profile 执行调研
- 使用 Writer Profile 编写文章（2000 字）
- 使用 Reviewer 检查语法错误
- 使用 Publisher 发布到 GitHub

Hermes 会把这些流程记录到持久记忆中。

## 49. 实战篇_完成复杂任务的协同工作

大家好，接下来演示**日常运行**。

**准备工作：** 在 SOUL.md 中明确告诉 Hermes：收到微信请求时，不要自己回答问题或写文章，而是交给看板 Swarm 流程。需要重置会话（`/new`）才能加载新的记忆。

**执行过程：**
1. 在微信中发送写博客的请求
2. Hermes 走看板流程，创建看板任务
3. 先进行任务拆分
4. Research 搜索资料
5. Writer 写作（可能阻塞，需要人工 unblock）
6. Reviewer 审核
7. Publisher 发布到 GitHub

**常见问题：** 第一次执行时可能不流畅，会出现阻塞。需要人工介入使用 `hermes kanban unblock` 解除阻塞。运行完成后，让 Hermes 把整个流程记忆下来，做成 Skill，后续就会更加顺畅。

**最终效果：** 在 GitHub 仓库中可以看到发布的最新文章。

## 50. 实战篇_进化和监控维护功能

大家好，在演示完完整流程之后，还有一些额外的 Hermes 功能可以进行持续的进化和监管维护。

1. **Skill 自动沉淀**：等不及自动沉淀的话，可以直接调用 Skill Manager 把流程做成技能永久存储。后续如果有文章大获成功，也可以再次调用 Skill 把技巧记录下来。

2. **Curator 管理维护**：系统自动创建的技能会被 Curator 进行管理和维护。长时间使用后重复的技能会自动整理、删除或合并。

3. **Memory 记忆更新**：一直在使用的记忆功能，可以自动更新。

4. **Dashboard 任务监控**：启动 Dashboard（`hermes dashboard --port 8080`），可以监控实际运行情况，查看模型、定时任务、Profile 等。

5. **No Agent 定时任务**：检查博客站点是否正常，不需要走大模型，直接检查输出。

6. **Hooks 记录 Token 消耗**：创建脚本钩子函数监控 Token 消耗。不过桌面客户端也有用量查看功能，更方便。

7. **SEO 检查插件**：定义 SEO 检查插件，在 Review 审核文章时自动调用。创建插件需要两个文件（`plugin.yaml` 和 `__init__.py`），启用后可以复制给 Review Profile 使用。

## 51. 实战篇_总结实战案例

大家好，在整个案例实战篇的最后，总结一下串联起来的完整工具链。

**工作流程：**
1. 人工通过**微信网关**与 Agent 交互，发送任务目标和审核指令
2. Agent 创建**看板任务**
3. 任务给到**Orchestrator Profile**（协调拆分者），加上 SOUL.md 进行职责限制
4. 拆分为四个 Agent Profile：
   - **Research**：检索信息
   - **Writer**：编写文章（2000 字）
   - **Reviewer**：校验文章（可加入 SEO 插件做基础校验）
   - **Publisher**：通过 MCP 发布到 GitHub
5. 它们之间共享记忆、Skills 技能和 Curator 管理

**案例意义：** 展示了 Hermes Agent 可以作为一套完整的 Agent 操作系统，在真实场景中将多个功能模块协同起来。第一次运行可能不太聪明，这是正常的。后续不断优化对应的信息，就会更加顺畅。

**进一步扩展方向：**
- 接入更多消息平台，实现多渠道审核
- 使用外部记忆提供商（免费/收费）
- 将 SEO 插件扩展为完整的文章质量评分系统
- 使用 MCP Server 将 Hermes 工作流暴露给 VS Code 等工具
- 用不同语言和主题构建不同 Profile 体系，收集多语言资讯
