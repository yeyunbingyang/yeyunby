# 协作篇 文稿

## 34. 协作篇_消息网关使用邮箱

大家好，接下来我们进入模块四——**协作篇**的内容。如果说前面的功能是小打小闹，那么协作篇的内容是真正能够应用在工作与生活中的功能。

第一个功能叫做**消息网关**。它可以直接对接日常生活使用的各种消息平台。国内使用最多的是微信和邮箱。Hermes 都可以直接对接，使用起来非常方便。

**什么是消息网关？** 消息网关就是把 Hermes 通过带加密系统的消息平台释放出去。你现在看着 Hermes 在 Windows 电脑上部署，只能在操作这台电脑时才能跟它打交道。实际上 Hermes 有非常强大的网关功能，通过网关把指令释放出去，让其他信息平台都可以发消息给 Hermes——可以是邮件，可以是微信。

**配置邮箱网关：**
1. 在 Hermes 设置 → 消息平台 → 邮箱，填写配置项
2. 登录邮箱（以 163 邮箱为例），进入设置 → POP3/SMTP/IMAP
3. 开启授权服务功能
4. 新增授权密码，复制作为密码使用
5. 在 Hermes 中填写：邮箱账号、IMAP 地址、SMTP 地址、允许的用户、SMTP 端口号（163 邮箱为 465）
6. 保存配置

**安装和启动网关：**
1. 执行 `hermes gateway install` 安装网关服务
2. 执行 `hermes gateway start` 启动网关
3. 启动后，Hermes 就可以使用邮件功能了

**基础功能——发送邮件：** 配置完成后，可以让 Hermes 发送邮件。例如，让定时任务收集的 AI 资讯作为邮件发送到指定邮箱。Hermes 会检查定时任务的输出数据，编写 Python 脚本来发送邮件。

## 35. 协作篇_消息网关邮件调用 Hermes

大家好，刚才演示了配置完邮箱后网关的基础功能——发送邮件。但这并不是最核心的功能。既然它是消息网关，最核心的功能应该是：**Hermes 能够接收邮件发来的消息，作为智能体给邮件回复**。

**配置接收邮件：** 取决于 `allow_user` 配置。如果使用 `allow_all_users: true`，谁发都会回复；如果使用 `allow_user`，只有指定邮箱发送才会回复。

**演示：**
1. 登录 QQ 邮箱
2. 写信给部署了 Hermes 网关的邮箱
3. 主题写"Hermes 消息"，正文写"帮我写一篇 800 字的作文，题目是科技创新"
4. 发送后，网关会接收到消息并处理
5. 处理完成后，QQ 邮箱会收到回复邮件

**实际意义：** 配置完成后，就不需要待在计算机旁使用 Agent 了。除了回消息，让它处理本地的代码也可以实现。例如公司出了 bug 需要重启，以前得爬起来开电脑连接公司网络，现在直接发个邮件让 Agent 来做就可以了。这就是网关消息平台最大的意义。

## 36. 协作篇_微信配置消息网关

大家好，在演示完邮箱的 Hermes 消息平台网关之后，接下来演示**微信**。微信是大家使用最多的手机软件，如果微信也能直接连接到电脑或服务器上的 Hermes，日常办公会变得非常方便。

**推荐配置方式：** 不建议在消息平台页面或 env 文件中配置微信，建议使用**扫描二维码**的方式。

**配置步骤：**
1. 查看官方文档，搜索微信配置
2. 安装依赖（两个命令都执行，以便使用二维码登录）
3. 执行交互式配置向导命令
4. 在网关设置页面选择微信（12）
5. 选择使用二维码登录（y）
6. 弹出二维码，用微信扫描
7. 授权完成后，会得到 Account ID
8. 按默认选项一直回车即可

**授权配置：** 配置完成后，需要在 env 文件中设置允许的用户。有两种选择：
- 把当前用户添加到 `allow_user`
- 把 `allow_all_user` 改为 `true`

修改后需要重启网关。

**微信网关功能演示：**
1. 在微信中给 Hermes 机器人发消息
2. Hermes 会回复
3. 可以让它执行实际工作，如"读取今天定时任务采集的 AI 资讯发给我"
4. 也可以让它把资讯做成 PPT 保存到桌面
5. 在手机上操作的效果与在电脑上操作一样

**注意事项：** 执行一些需要权限的操作时，Hermes 会在微信中询问是否批准，需要回复确认。

## 37. 协作篇_Profile 功能介绍和演示

大家好，接下来学习协作篇的第二个内容——**Profile 多实例**。

现在本地部署的 Hermes Agent 可以运行多个会话，但这些会话使用的是同一套配置文件、同一套环境文件、同一套 SOUL.md 灵魂文件。本质上它还是一个 Agent，只是可以在不同地方进行沟通。

**Profile 的作用：** 它可以复制出多个完全不同、完全独立的 Hermes Agent。创建时可以使用各自的配置文件、各自的环境文件。这就是 Profile。

**实际使用场景：** 当你希望 Agent 实现完全独立的效果时，就会用到 Profile。

**Profile 命令：**
- `hermes profile create <name> --description <desc>`：创建 Profile
- `hermes profile clone <name>`：克隆当前配置
- `hermes profile clone --all`：克隆所有状态
- `hermes profile clone --from <profile>`：从指定 Profile 克隆
- `hermes profile delete <name>`：删除

**使用步骤：**
1. 创建 Profile（如 `coder`）
2. 添加描述
3. 克隆配置（把 YAML、env、SOUL.md 复制过去）
4. 创建完成后，在 `profiles/` 目录下可以看到新的 Profile 文件夹
5. 使用 `coder` 命令（不再是 `hermes`）进入这个独立的 Agent

**效果：** 不同的 Profile 有完全独立的人格、配置、会话历史。例如，可以给 coder 设置卡哇伊人格，而默认的 Hermes 保持专业风格，两者互不影响。

## 38. 协作篇_任务委派展示

大家好，继续学习协作篇的第三部分——**Delegation 任务委派**。

任务委派的意思是：当 Hermes 执行工作任务时，如果任务特别复杂，不想让它一步一步来执行（速度慢），希望它能一次性同时执行多个任务，就可以使用 Delegation。

**单个任务委派：** 只有一个目标，如"调试为什么测试失败"，给子 Agent 环境上下文和工具集。

**并行批量执行：** 在委派任务时，task 直接是一个列表，每个元素有目标和工具集。例如：任务 1 搜索主题 A（Web 搜索），任务 2 搜索主题 B（Web 搜索），任务 3 整理构建（终端和文件）。

**Delegation 的特点：**
- 默认开启，不需要额外配置
- 子 Agent 启动时拥有全新的对话，不知道之前的任何内容
- 唯一接收的是目标和上下文两个字段
- 子 Agent 不能继续委派（禁止中间商）
- 不能与用户交互、不能问权限
- 不写入共享的持久记忆
- 只能做比较简单的工作

**配置参数：** 在 `config.yaml` 的 `delegation` 部分，可以设置最大子 Agent 数量（默认 3 个）和委派深度（默认 1，即子 Agent 不能再委派）。

**演示：** 使用任务委派方式同时搜索 ChatGPT、Claude、DeepSeek 最新模型的参数。Hermes 会创建三个子任务同时搜索，完成后回收结果进行总结。相比一个一个执行，效率高很多。

## 39. 协作篇_Kanban 意义和架构

大家好，接下来学习协作篇的最后一部分内容——**看板（Kanban）**。

看板比任务委派更适合处理大型任务。任务委派适合相对比较短的、能自己包含推理的子任务，不能实现多个 Agent 之间的协作。

**看板的定位：** 当任务足够复杂，需要在一台电脑或服务器上部署多个专家型 Agent，这些 Agent 又可以在自己内部再任务细分委派，这时就要使用看板。

**看板 vs 其他：**
- **Profile 多实例**：构建出完全不一样环境、不一样配置的多个 Agent
- **任务委派**：在一个 Agent 里面委派子任务，实现并发
- **看板**：让多个 Profile 以异步方式协作，实现更复杂的拓扑结构

**看板架构——三层架构：**

1. **控制层（Controller）**：与用户交互，用户提交看板级别的任务
2. **状态层（State）**：通过 SQLite 数据库 + 调度器，时刻监督提交的任务执行状态
3. **执行层（Executor）**：有专门的 Worker 去执行任务

**工作流程：**
1. 用户提交看板任务
2. 任务先存到 SQLite 数据库中（即使 Agent 正在执行其他任务也可以提交）
3. 调度器每 60 秒扫描一次数据库
4. Worker 有空时，从调度器读取能执行的任务
5. 执行完成后，把完成标签写到数据库
6. 调度器知道任务已完成

**Worker 来源：** 使用默认的 Hermes 实例，加上 Delegation 委派的子 Agent（默认 3 个），就是 3 个 Worker。

## 40. 协作篇_Kanban 核心概念介绍

大家好，在看完看板的架构之后，接下来看它的核心概念。

1. **任务板（Board）**：存储任务的容器，包含一个数据库存储提交的任务，一个 `work_service` 目录，以及一个调度器。初始化看板后，会在 Hermes 根目录下创建一个看板的数据库。

2. **任务（Task）**：看板的基本工作单元。一个 Task 只能注册给一个 Profile 去执行。Task 有以下状态：
   - 准备被认领（准备执行）
   - 可执行（Running）
   - 等待人工输入或外部条件（阻塞）
   - 已完成

3. **依赖（Link）**：Task 之间的父子依赖关系。有些任务不能并行执行，如收集数据要先执行，制作 PPT 要后执行。

4. **评论与交接记录（Comment）**：人类和 Agent 在 Task 上追加的持久信息，是跨 Agent 交接的协议。

5. **事件（Event）**：审计日志，记录 Task 执行过程中经过的事情。

6. **工作空间（Workspace）**：Task 绑定的工作目录，后续创建的内容都会放在这里。

**六种协作模式：**
1. 一个目标拆分成多个同级的 Task 并行执行（类似任务委派）
2. Pipeline 流水线：上游完成，下游启动（依赖关系）
3. 多个 Task 汇总到一个聚合 Task
4. 同一个 Profile 通过定时任务在共享 Workspace 中反复处理（日报、周报）
5. Human in Loop：人参与到循环中，添加反馈信息
6. 一个 Profile 单独出来管理其他 Profile（多账号管理、多服务器巡检）

**调度器（Dispatcher）：** 每 60 秒检查一次数据库，扫描任务状态。处理异常任务，将依赖满足的任务推进到 Ready 状态，通过比较并交换的方式在 SQL 中更新认领的任务。

## 41. 协作篇_Kanban 任务执行演示

大家好，在介绍完看板的核心概念之后，接下来测试使用一下。

**初始化看板：** 执行 `hermes kanban init`，它会创建底层的数据库。初始化时会发现已有的 Profile，可以指定委派者。

**创建看板任务：** 使用 `hermes kanban create` 命令，后面跟任务目标和委派对象。例如："阅读 Hermes Agent 文档并小结，重点看 Agent Loop、Skills 和 Gateway 三个部分，交给 default 执行"。

**查看任务：**
- `hermes kanban list`：查看所有任务
- `hermes kanban show <task_id>`：查看单个任务详情

**执行结果：** 任务执行完成后，会输出到 Markdown 文档中。默认保存在临时位置，任务完成后可能被删除。如果需要持久文件，要明确告诉任务输出到特定位置。

**注意事项：** 电脑上不能安装有 Python 的其他版本，否则会导致虚拟环境 Python 3.11 的包损坏或版本不匹配。可以让 Hermes 帮忙解决，或者手动执行虚拟环境安装包。

## 42. 协作篇_Kanban 任务键分配

大家好，在演示完看板执行任务之后，再添加一些看板的辅助功能。

**Operator Profile（指挥官 Profile）：** 可以专门创建一个单独的 Profile Agent，由它作为看板的编排者，负责拆解高层任务、创建任务并指派给真实存在的 Profile。它只做协调，不执行工作。

**创建步骤：**
1. 创建 Operator Profile
2. 禁用它的执行工具（命令行、文件、浏览器等）
3. 在配置文件中设置为专门在看板中拆分任务的 Profile

**一键实现拓扑（0.15 版本新功能）：** 使用 `hermes kanban swarm` 命令，可以一键生成看板任务拓扑。指定目标、Worker 和上下文，它会自动拆分成多个子任务（调研、编写、校验、总结等）。

**演示：** 一键创建 5 个任务（根任务 + 3 个调研 + 1 个校验 + 1 个总结），同时分配给不同的 Worker 执行。完成后在桌面上生成多个结果报告。

**注意：** 使用多 Agent 运行时，Token 消耗很大。缓存命中率低（约 70-80%），而单 Agent 配置好可达 99%。缓存命中率直接影响价格——命中时 0.025 元/百万 Token，未命中时 3 元/百万 Token，价格差 100 多倍。所以只有特别大型、特别复杂的任务才适合用看板。
