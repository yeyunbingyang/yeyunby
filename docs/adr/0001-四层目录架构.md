# ADR 0001：四层目录架构

## 状态

已接受（2026-08-02 确认）。

## 决策

知识库顶层固定四个职责目录：`00-System(支撑层)/`（规则与模板）、`01-日常流(日常流层)/`（时间流与收集）、`02-Knowledge(知识层)/`（长期知识）、`03-Resources(资源层)/`（外部资源）。不设 Inbox、Trends、Archive 等独立顶层目录；归档通过 `status: 归档` 标记，不建归档目录。`MOC知识地图.md` 是全库目录树的唯一真相来源，新增或重组目录时必须同步更新。

## 背景

早期存在 `01-Inbox`、`04-Trends`、`05-Archive` 等独立目录，内容四处存放，归档需要移动文件并重写链接，维护成本高。轻量结构靠导航与 frontmatter 承载状态，减少目录层级。

## 权衡

- 备选：按主题细分多层目录。目录即分类看似直观，但跨主题笔记无处安放，移动与改名成本高。
- 备选：归档独立目录。会断开 wikilink、丢失原位上下文。
- 代价：目录职责必须靠规则约束，角色外的内容需要人工判断去向，不能靠目录本身自解释。

## 后果

新目录角色必须先更新 `MOC知识地图.md` 再建目录；`00-System` 是规则与规范的唯一真相来源。
