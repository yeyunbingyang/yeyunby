# ADR 0002：MOC 导航模式

## 状态

已接受（2026-08-02 确认）。

## 决策

每个领域维护一篇 `领域名-MOC.md` 轻量导航，只做链接与摘要，不写长文；主题链接超过 10 条时拆出子 MOC。MOC 使用 Dataview 按 status、domain、tags 自动聚合笔记；新建知识笔记必须链接回相关 MOC，向 MOC 添加笔记时同步更新链接列表与 Dataview 查询。

## 背景

早期多层索引导致同一规则多处维护、超长总笔记，导航与正文职责不清。MOC 模式的目的是让"找得到"与"读得懂"分离：MOC 负责导航，笔记负责正文。

## 权衡

- 备选：一篇巨型 MOC 覆盖整个领域。阅读路径短，但链接数增长后维护成本爆炸，加载变慢。
- 备选：纯目录导航，不建 MOC。文件树无法表达主题聚合与跨目录关系。
- 代价：主题边界需要人工维护；拆分子 MOC 时需迁移链接并保持旧链接可解析。

## 后果

MOC 不保存长正文、评分表、完整图链或清单；正文职责归权威笔记。骨架领域的 MOC 可以先建立导航，再逐步补充知识笔记。
