# ADR 0005：多上下文领域建模与维护层

## 状态

已接受（2026-08-02 确认）。

## 决策

全库采用多上下文领域模型：根级 `CONTEXT-MAP.md` 映射各上下文；每个项目子域在维护层（`90-维护与数据/`）维护自己的 `CONTEXT.md` 术语表与 `docs/adr/`；ADR 编号按所属库上下文独立从 0001 计数；根级 `docs/adr/` 只记录跨上下文的全库决策。

## 背景

AI人物身份参考资产库与丝袜商品效果图生成已用 grill-with-docs 形成术语表与 ADR，且出现 `S`、`P`、`E`、`C` 等编号在多个库中重载。全库单一术语表无法表达"同一编号在不同库中含义不同"的事实。

## 权衡

- 备选：单一根级 `CONTEXT.md` 汇总所有术语。术语互相污染，编号重载无解。
- 备选：不建领域模型。决策与术语散落在各处，后续 Agent 无法复用。
- 代价：同一编号在不同库含义不同，引用时必须带库名限定；术语冲突时需要先确认所属上下文。

## 后果

新项目上下文沿用同一惯例；术语冲突先更新所属库 `CONTEXT.md`；全库规则变化先记根级 ADR 再改文档。编号命名空间按 [[丝袜商品效果图生成-领域术语]] 的既有规则在各自库内解析。
