# 个人书签管理工具 PRD

## 1. 项目概述

一句话描述：**一款支持智能整理、安全加密存储、可离线运行的个人书签与密码管理一体化工具。**
智能为链接笔记 打标签

---

## 2. 目标用户

| 用户画像 | 描述 | 核心痛点 |
|---------|------|---------|
| **技术从业者** | 开发者、运维、架构师等 | 浏览器书签杂乱，技术文档/工具站点多，需要结构化整理 |
| **数字游民/多设备用户** | 经常切换设备工作 | 需要跨设备同步书签，且要求数据隐私可控 |
| **信息安全敏感用户** | 对数据隐私要求高 | 不信任云端密码管理器，希望本地加密存储 |
| **知识管理者** | 重度笔记/资料收集者 | 书签数量庞大（1000+），需要智能标签分类和检索 |

### 4.4 本地加密存储

#### 用户故事
> 作为一名隐私敏感用户，我希望所有数据（包括书签信息和密码）都以加密形式存储在本地文件中，使用我设置的主密码保护，确保即使文件泄露也无法被破解。

#### 验收标准

| 编号 | 验收标准 | 优先级 |
|-----|---------|-------|
| AC-4.1 | 使用 AES-256-GCM 对称加密算法加密整个数据文件 | P0 |
| AC-4.2 | 密钥派生使用 Argon2id（或 PBKDF2 至少 600,000 轮次），防止暴力破解 | P0 |
| AC-4.3 | 加密后的数据文件为 JSON 格式（或二进制封装），包含：加密数据、盐值、IV、认证标签 | P0 |
| AC-4.4 | 主密码仅用于派生加密密钥，**绝不以任何形式存储**（包括哈希） | P0 |
| AC-4.5 | 支持修改主密码：使用旧密码解密后，用新密码重新加密全部数据 | P1 |
| AC-4.6 | 数据文件结构自描述，包含版本号、加密参数元数据，便于未来格式升级 | P1 |
| AC-4.7 | 提供自动备份机制：每次保存时保留最近 N 个版本的历史备份文件 | P1 |

**数据文件结构（解密后）：**
```json
{
  "version": "1.0.0",
  "last_modified": "2026-07-21T22:13:00Z",
  "bookmarks": [
    {
      "id": "uuid",
      "title": "Python 官方文档",
      "url": "https://docs.python.org",
      "description": "Python 编程语言官方文档",
      "folder_id": "folder_uuid",
      "tags": ["python", "docs", "programming"],
      "credentials": {
        "username": "myuser",
        "password": "encrypted_string",
        "note": "2FA via Authenticator app"
      },
      "created_at": "2026-07-01T10:00:00Z",
      "updated_at": "2026-07-21T22:13:00Z",
      "visit_count": 15,
      "is_favorite": false
    }
  ],
  "folders": [...],
  "tags": [...],
  "settings": {...}
}
```

### 4.5 主密码认证

#### 用户故事
> 作为一名用户，我希望工具启动时要求输入主密码，且主密码需要足够安全，防止他人轻易破解我的数据。

#### 验收标准

| 编号 | 验收标准 | 优先级 |
|-----|---------|-------|
| AC-5.1 | 首次启动强制设置主密码，密码长度至少 8 位，建议 12 位以上 | P0 |
| AC-5.2 | 主密码强度实时检测：显示弱/中/强评级，要求至少包含大小写字母+数字 | P0 |
| AC-5.3 | 连续 5 次输入错误主密码后，锁定 5 分钟，并指数增长锁定时间 | P1 |
| AC-5.4 | 支持设置自动锁定：闲置 N 分钟后自动锁定，需重新输入主密码 | P1 |
| AC-5.5 | 提供密码提示功能（用户可设置可选的密码提示问题/答案） | P2 |
| AC-5.6 | 支持生物识别解锁（如系统支持 TouchID/FaceID/Windows Hello） | P2 |

### 4.6 智能标签整理（AI 智能体）

#### 用户故事
> 作为一名书签数量庞大的用户，我希望有一个 AI 助手能够帮我自动分析书签内容，生成合理的标签体系，并建议标签合并、去重和分类优化，让我的书签库保持整洁有序。

#### 验收标准

| 编号 | 验收标准 | 优先级 |
|-----|---------|-------|
| AC-6.1 | AI 智能体可读取本地书签数据（通过解密后的内存数据，**绝不传输原始数据到外部**） | P0 |
| AC-6.2 | 智能体分析书签标题、URL、描述，自动生成建议标签 | P1 |
| AC-6.3 | 智能体检测重复/相似书签，建议合并或删除 | P1 |
| AC-6.4 | 智能体检测标签冗余（如 "js" 和 "javascript"），建议标签合并映射 | P1 |
| AC-6.5 | 智能体生成文件夹重组建议，基于标签聚类 | P1 |
| AC-6.6 | 所有 AI 建议需用户确认后执行，支持批量确认或逐项审核 | P1 |
| AC-6.7 | 智能体操作记录审计日志，支持撤销最近 N 次操作 | P2 |
| AC-6.8 | 支持配置 AI 分析深度（仅标题/标题+描述/尝试抓取网页内容摘要） | P2 |

**AI 智能体数据安全约束：**
- 智能体通过本地 API/SDK 调用（如本地 Ollama、LM Studio 等）
- 敏感数据（密码字段）在传递给 AI 前必须脱敏处理
- 若使用云端 AI，必须先进行本地匿名化处理（去除 URL 中的个人标识、用户名等）
- 用户可完全禁用 AI 功能，工具 100% 离线可用

## 6. 数据模型

### 6.1 核心实体关系

```
[Folder] 1---* [Bookmark] *---* [Tag]
                |
                1---0..1 [Credential]
```

### 6.2 存储方案对比

| 方案 | 优点 | 缺点 | 推荐度 |
|-----|------|------|-------|
| **加密 JSON 文件** | 简单透明、易备份、跨平台、可版本控制 | 大文件读写性能一般 | ⭐⭐⭐⭐⭐ **推荐** |
| SQLite + SQLCipher | 结构化查询、性能优秀、成熟方案 | 依赖二进制库、文件不透明 | ⭐⭐⭐⭐ |
| 纯 Markdown 文件 | 人类可读、可直接编辑 | 结构化困难、加密复杂 | ⭐⭐⭐ |
| 混合方案（JSON 元数据 + Markdown 笔记） | 灵活、可扩展 | 复杂度较高 | ⭐⭐⭐⭐ |

**推荐采用：加密 JSON 文件作为主存储格式**，原因：
1. 用户要求使用 md 或 json 存储，JSON 更适合结构化数据
2. 单个加密文件便于备份和迁移
3. 完全透明，用户可用任何文本编辑器查看元数据（解密后）
4. 实现简单，不引入额外依赖

## 7. 技术栈建议

| 层级 | 推荐方案 | 备选方案 |
|-----|---------|---------|
| **前端/桌面端** | Tauri (Rust + Web) | Electron, Flutter |
| **加密库** | Rust: `ring` / `aes-gcm` + `argon2` | Node: `crypto-js`, `bcrypt` |
| **本地 AI** | Ollama API (本地 LLM) | LM Studio, 完全禁用 |
| **数据存储** | 加密 JSON 文件 | SQLite + SQLCipher |
| **搜索索引** | 内存 Fuse.js / 本地 IndexedDB | MiniSearch, FlexSearch |

---

## 8. 风险与约束

| 风险 | 影响 | 缓解措施 |
|-----|------|---------|
| 用户忘记主密码 | 高：数据永久丢失 | 提供密码提示、强烈建议用户记录恢复码 |
| AI 智能体数据泄露 | 高：敏感信息暴露 | 本地 AI 优先、云端必须匿名化、密码字段脱敏 |
| 加密文件损坏 | 中：数据丢失 | 自动多版本备份、定期提醒用户手动备份 |
| 大文件性能问题 | 低：体验下降 | 分页加载、虚拟滚动、异步索引构建 |
