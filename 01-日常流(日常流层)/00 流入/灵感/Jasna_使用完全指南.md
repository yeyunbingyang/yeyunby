## 一、软件概述

### 1.1 什么是 Jasna

Jasna 是一款基于深度学习的 **JAV 视频马赛克修复工具**，由社区开发者 Kruk2 维护，受 Lada 启发并深度优化。

**核心能力**:
- 自动检测视频中的马赛克区域
- 使用 AI 模型修复马赛克，恢复被遮挡内容
- 支持视频和静态图像修复
- 提供实时流媒体播放（无需等待完整处理）

### 1.2 与 Lada 的核心差异

| 维度 | Jasna | Lada |
|------|-------|------|
| **处理架构** | 纯 GPU 流水线 + TensorRT | CPU+GPU 混合 |
| **处理速度** | **快 2-3 倍** | 基准 |
| **GUI 界面** | ✅ 原生中文 GUI | ❌ 命令行为主 |
| **二级修复** | ✅ unet-4x / RTX SR / TVAI | ❌ 无 |
| **静态图像修复** | ✅ SD 1.5 实验模型 | ❌ 无 |
| **流媒体支持** | ✅ 实时串流 | ❌ 无 |
| **首次运行** | 需 15-60 分钟 TensorRT 编译 | 即开即用 |

### 1.3 技术架构

```
输入视频
    ↓
[检测模型] → 定位马赛克区域（RF-DETR / YOLO）
    ↓
[裁切] → 256×256 小块
    ↓
[一级修复] → mosaic_restoration_1.2 模型（TensorRT 加速）
    ↓
[二级修复]（可选）→ 放大到 512/1024（unet-4x / RTX SR / TVAI）
    ↓
[融合] → 时间重叠 + 交叉淡化 → 贴回原视频
    ↓
输出视频
```

## 二、安装与环境配置

### 2.1 系统要求

| 组件 | 最低要求 | 推荐配置 |
|------|---------|---------|
| **GPU** | NVIDIA 计算能力 7.5+ | RTX 4060 / 4070 / 3060 及以上 |
| **显存** | 6GB | **12GB+**（8GB 可用但需调参） |
| **驱动版本** | 591.x | **610+** |
| **系统内存** | 16GB | 32GB |
| **硬盘空间** | 10GB（含模型） | 50GB+（处理大文件） |
| **安装路径** | **纯 ASCII 字符**（无中文/空格） | `D:\Jasna` 或 `D:\jasna-v0.8.1` |

> ⚠️ **GTX 10 系列（1050/1060/1070/1080）不支持**，计算能力太旧。

### 2.2 下载与解压

1. 从官方渠道下载最新发行包（Windows NVIDIA 版）
2. 解压到纯英文路径，例如：
   ```
   ✅ F:\Jasna_0.8.1\jasna-windows-nvidia-0.8.1
   ❌ F:\软件\Jasna 中文版\jasna
   ❌ F:\My Tools\Jasna v0.8.1
   ```
3. 确保路径中无中文、无空格、无特殊字符

### 2.3 依赖组件（已内置）

Windows 发行包已包含：
- `ffmpeg`（主版本 8）
- `ffprobe`
- `mkvmerge`

无需额外安装。

### 2.4 NVIDIA 控制面板优化设置

推荐修改 CUDA 系统内存回退策略以获得更稳定性能：

1. 右键桌面 → **NVIDIA 控制面板**
2. 3D 设置 → 管理 3D 设置
3. 找到 **"CUDA - 系统内存回退政策"**（CUDA Sysmem Fallback Policy）
4. 改为 **"偏好无系统内存回退"**（Prefer No Sysmem Fallback）
5. 点击应用，重启电脑

## 三、首次运行与系统检查

### 3.1 启动软件

双击 `jasna.exe`，首次启动会自动进行系统检查。

### 3.2 系统检查项详解

| 检查项 | 状态 | 说明 |
|--------|------|------|
| Install Path | ✅ 通过 | 路径为 ASCII-only |
| FFprobe | ✅ 通过 | 检测到 ffmpeg 工具链 |
| GPU | ✅ 通过 | 识别到 NVIDIA GPU |
| GPU Runtime | ✅ 通过 | CUDA 版本和计算能力 |
| GPU Driver Version | ✅ 通过 | 驱动 ≥591（推荐 610+） |
| CUDA Sysmem Fallback Policy | ⚠️ 警告（可选） | 建议改为"偏好无系统内存回退" |

**检查结果解读**:
- **全部通过**: 显示 "Ready to go"，点击 **Get Started** 进入主界面
- **有失败项**: 显示 "Required checks failed"，需修复后才能使用

### 3.3 主界面按钮说明

| 按钮 | 功能 |
|------|------|
| **Get Started** | 进入 Jasna 主程序，开始使用 |
| **Support** | 打开支持页面，获取帮助文档 |
| **Unifans** | 打开 Unifans 社区页面（支持者平台） |

### 3.4 首次 TensorRT 编译（关键！）

首次处理视频时，Jasna 会针对您的 GPU 编译 TensorRT 引擎：

| 项目 | 说明 |
|------|------|
| **耗时** | 15-60 分钟（取决于 GPU 性能） |
| **期间** | 关闭所有其他应用，避免使用电脑 |
| **表现** | GPU 占用 90%+，风扇高速运转，进度可能显示 0% |
| **缓存位置** | `model_weights/` 文件夹 |
| **后续运行** | 复用缓存，秒开 |
| **升级迁移** | 可将旧版本引擎文件复制到新版本 |

> 💡 **进度 0% 不一定是卡死**，可能是正在编译。打开任务管理器查看 GPU 占用确认。

## 四、核心参数详解

### 4.1 参数总览

| 参数类别 | 参数名 | 作用 | 默认值 | 推荐值 |
|----------|--------|------|--------|--------|
| **检测** | 检测模型 | 识别马赛克的 AI 模型 | rfdetr-v5 | rfdetr-v5 |
| **检测** | 检测阈值 | 马赛克识别灵敏度 | 0.25 | 0.15-0.25 |
| **处理** | 最大片段大小 | 每批处理帧数 | 90/180 | 60（8GB）|
| **处理** | 时间重叠 | 减少片段边界闪烁 | 8 | 6-15 |
| **处理** | 交叉淡化 | 片段间平滑过渡 | 开启 | ✅ 始终开启 |
| **质量** | 二级修复 | 修复后放大清晰化 | 无 | rtx-super-res |
| **性能** | BasicVSR++ 编译 | TensorRT 编译加速 | 开启 | 8GB 显存建议关闭 |
| **输出** | 输出格式 | 视频封装格式 | mkv | mkv/mp4 |

### 4.2 检测模型选择

| 模型 | 特点 | 适用场景 |
|------|------|----------|
| **rfdetr-v5** | 最新，通用性好，大多数场景表现优秀 | **默认推荐**，真人视频 |
| **lada-yolo-v4** | 对 2D 动画、特定类型视频可能更好 | 动画、rfdetr 漏码严重时尝试 |

**切换建议**: 先用 rfdetr-v5，如有漏码问题再试 lada-yolo-v4。

### 4.3 检测阈值详解

控制马赛克识别的严格程度：

| 阈值 | 检测范围 | 漏码风险 | 误检风险 | 显存影响 |
|------|---------|---------|---------|---------|
| 0.35 | 保守 | 高 | 极低 | 基准 |
| **0.25** | **平衡** | **中** | **低** | **基准** |
| **0.15** | **激进** | **低** | **中** | **+10-20%** |
| 0.10 | 非常激进 | 极低 | **高** | **+20-40%** |

**阈值与 GPU 的关系**:
- 阈值越低 → 检测到的马赛克区域越多 → 需要修复的区域越多 → **显存占用增加、速度变慢**
- RTX 4060 8GB 建议 **0.15 为安全下限**，0.10 极易爆显存

**误检表现**: 将正常皮肤、阴影、纹理误判为马赛克，导致过度修复、画面失真。

### 4.4 最大片段大小（Max Clip Size）

每批送入 GPU 处理的帧数，**最影响显存占用的参数**。

| 片段大小 | 显存占用（含编译） | 显存占用（无编译） | 处理速度 | 适用显存 |
|----------|-------------------|-------------------|---------|---------|
| 30 | ~6-7GB | ~5-6GB | 较慢 | 6GB |
| **60** | **~8-9GB** | **~7-8GB** | **中等** | **8GB（RTX 4060）** |
| 90 | ~10-11GB | ~8-9GB | 较快 | 10GB+ |
| 180 | ~12GB+ | ~9-10GB | 最快 | 12GB+ |

**选择原则**:
- 显存允许范围内选最大
- 爆显存时优先降低此参数
- 4K 视频建议用较小片段（60 或 90）

### 4.5 时间重叠（Temporal Overlap）

相邻处理片段之间的重叠帧数，用于减少边界闪烁。

| 片段大小 | 推荐重叠 | 说明 |
|----------|---------|------|
| 30 | 4 | 较低 VRAM |
| 60 | 6 | 8GB 推荐 |
| 90 | 8 | 平衡设置 |
| 180 | 15 | 高质量，需 12GB+ |

> 超过 20 通常没有明显收益，但处理时间显著增加。

### 4.6 二级修复（Secondary Restoration）

解决 256×256 修复区域贴回原视频后的模糊问题。

**工作原理**:
```
原始视频（4K）
    ↓
检测到马赛克区域 → 裁切 256×256
    ↓
一级修复（AI 去码）
    ↓
二级修复：256→512 或 256→1024 放大
    ↓
缩小到原始尺寸 → 贴回视频
    ↓
输出（清晰无码）
```

| 二级类型 | 放大倍数 | 质量 | 速度 | 额外显存 | 费用 |
|----------|---------|------|------|---------|------|
| **无** | — | 一般 | 最快 | 0 | 免费 |
| **RTX Super Resolution** | 2×-4× | 尚可 | **非常快** | +1-2GB | 免费 |
| **unet-4x** | **4×（256→1024）** | **最佳** | 较快 | +2-3GB | **支持者专属** |
| **TVAI (Topaz Video AI)** | 可变 | 接近 unet-4x | **极慢** | +1-2GB | 需购买 Topaz |

**何时需要二级修复**:
- ✅ 大特写镜头
- ✅ 厚码（马赛克块很大）
- ✅ 4K 高分辨率视频
- ✅ 追求最佳画质

**RTX 4060 8GB 建议**:
- 片段大小 60 + RTX Super Resolution = 可能刚好够用
- 片段大小 30 + RTX Super Resolution = 较安全
- unet-4x 对 8GB 太紧张，建议 12GB+ 使用

### 4.7 BasicVSR++ 编译

将修复模型编译为 TensorRT 子引擎，加速处理但增加显存占用。

| 编译状态 | 引擎显存占用（片段60） | 引擎显存占用（片段180） | 处理速度 |
|----------|----------------------|----------------------|---------|
| **编译** | ~1.9GB | ~5.4GB | **快** |
| **不编译** | ~1.2GB | ~1.2GB | 慢 |

**建议**:
- 12GB+ 显存：保持编译开启
- **8GB 显存（RTX 4060）**：建议关闭，避免爆显存

## 六、CLI 命令行指南

### 6.1 基础命令

```bash
# 处理单个视频
jasna --input input.mp4 --output output.mkv

# 处理图片
jasna --input photo.png --output restored.png

# 批量处理文件夹
jasna --input input_folder --output output_folder

# 自定义输出文件名模板
jasna --input input_folder --output output_folder --output-pattern "{original}_restored.mp4"
```

### 6.2 完整参数命令

```bash
# RTX 4060 8GB 推荐配置
jasna --input "D:\video.mp4" --output "D:\output.mkv" \
  --detection-model rfdetr-v5 \
  --detection-threshold 0.15 \
  --max-clip-size 60 \
  --temporal-overlap 6 \
  --enable-crossfade \
  --secondary-restoration rtx-super-res \
  --no-compile-basicvsrpp

# 12GB+ 显存高性能配置
jasna --input "D:\video.mp4" --output "D:\output.mkv" \
  --detection-model rfdetr-v5 \
  --detection-threshold 0.25 \
  --max-clip-size 180 \
  --temporal-overlap 15 \
  --enable-crossfade \
  --secondary-restoration unet-4x

# 最低显存模式（6GB）
jasna --input "D:\video.mp4" --output "D:\output.mkv" \
  --max-clip-size 30 \
  --temporal-overlap 4 \
  --no-compile-basicvsrpp \
  --detection-threshold 0.20
```

## 七、性能优化与显存管理

### 7.1 显存管理策略

Jasna 内置自动显存管理：当 GPU 显存不足时，等待处理的帧会自动移动到系统内存（RAM），需要时再移回。

**但手动优化更有效**。

### 7.2 爆显存排查流程

```
进度卡住或报错
    ↓
检查任务管理器 → GPU 专用内存是否满载？
    ↓
是 → 按优先级调整：
    1. 降低最大片段大小（180→90→60→30）
    2. 禁用 BasicVSR++ 编译
    3. 关闭二级修复
    4. 降低检测阈值（0.10→0.15，减少检测区域）
    5. 关闭浏览器等占用显存的程序
    6. 重启电脑释放显存
    ↓
否 → 可能是 TensorRT 编译中，等待 15-60 分钟
```

### 7.3 不同显存配置推荐

| 显存 | 片段大小 | 重叠 | 编译 | 二级修复 | 适用分辨率 |
|------|---------|------|------|---------|-----------|
| 6GB | 30 | 4 | 关闭 | 无 | 1080p |
| **8GB** | **60** | **6** | **关闭** | **RTX SR（可选）** | **1080p** |
| 10GB | 90 | 8 | 开启 | RTX SR | 1080p/2K |
| 12GB | 180 | 15 | 开启 | unet-4x | 2K/4K |
| 16GB+ | 180 | 15 | 开启 | unet-4x | 4K |

### 7.4 4K 视频特殊处理

4K 视频显存占用显著增加，建议：
- 片段大小降至 60 或 90
- 关闭二级修复，或仅用 RTX Super Resolution
- 预处理降分辨率（如不需要 4K 输出）：
  ```bash
  ffmpeg -i input_4k.mp4 -vf scale=1920:1080 -c:v libx264 -crf 18 input_1080p.mp4
  ```

### 7.5 速度优化

| 优化手段 | 效果 | 代价 |
|----------|------|------|
| 增大片段大小 | 速度提升 | 显存增加 |
| 启用 BasicVSR++ 编译 | 速度提升 20-30% | 首次编译耗时，显存增加 |
| 关闭二级修复 | 速度提升 30-50% | 画质下降 |
| 降低时间重叠 | 速度提升 | 可能增加闪烁 |
| 使用 faster 检测模型 | 速度提升 | 精度可能下降 |

## 八、修复效果优化

### 8.1 漏码问题（检测不全）

**表现**: 部分马赛克区域未被修复，仍有方块残留。

**解决步骤**（按优先级）：

1. **降低检测阈值**（最有效）
   - 0.25 → 0.15 → 0.10
   - RTX 4060 8GB 建议不低于 0.15

2. **切换检测模型**
   - rfdetr-v5 ↔ lada-yolo-v4
   - 某些视频类型（如动画）YOLO 可能更好

3. **增大片段大小**
   - 更大上下文有助于检测边缘马赛克
   - 但受显存限制

4. **预处理视频**
   - 轻微调整对比度让马赛克更明显：
   ```bash
   ffmpeg -i input.mp4 -vf "eq=contrast=1.1:brightness=0.05" -c:v libx264 -crf 18 temp.mp4
   ```

### 8.2 模糊问题（修复后不清晰）

**表现**: 修复区域模糊、涂抹感重、细节丢失。

**解决步骤**：

1. **开启二级修复**（最有效）
   - RTX Super Resolution（免费，快速）
   - unet-4x（最佳，需支持者密钥）

2. **增大片段大小**
   - 更大片段 = 更多上下文 = 更好修复质量

3. **调整时间重叠**
   - 增大到 15-20 减少边界模糊

### 8.3 闪烁问题（片段边界闪烁）

**表现**: 修复区域边缘闪烁、颜色跳动。

**解决步骤**：

1. **确保交叉淡化开启**
2. **增大时间重叠**
   - 片段 60 → 重叠 6-8
   - 片段 180 → 重叠 15
3. **降低片段大小**
   - 小片段边界更多，但每个边界影响范围更小

### 8.4 误检问题（非马赛克区域被修复）

**表现**: 正常皮肤、阴影、纹理被错误修复，画面失真。

**解决步骤**：

1. **提高检测阈值**
   - 0.10 → 0.15 → 0.25
2. **切换检测模型**
   - 尝试另一个模型看是否改善

### 8.5 效果验证流程

```
1. 截取 30 秒-1 分钟测试片段
2. 用不同参数组合处理
3. 对比结果：
   - 漏码情况
   - 清晰度
   - 闪烁情况
   - 误检情况
4. 选择最佳参数处理完整视频
```

## 九、常见问题排查

### 9.1 进度一直 0%

| 原因 | 判断方法 | 解决 |
|------|---------|------|
| **TensorRT 首次编译** | GPU 占用 90%+，风扇狂转 | **等待 15-60 分钟，正常** |
| **爆显存** | 任务管理器 GPU 内存满 | 降低片段大小，关闭编译 |
| **路径含中文** | 文件路径有中文/空格 | 移到纯英文路径 |
| **格式不支持** | 尝试换 MP4/MKV | ffmpeg 转封装 |

### 9.2 爆显存（Out of Memory）

```
1. 最大片段大小: 180→90→60→30
2. 禁用 BasicVSR++ 编译
3. 关闭二级修复
4. 提高检测阈值（减少检测区域）
5. 关闭浏览器等程序
6. 重启电脑
```

### 9.3 激活/密钥问题

Jasna 基础功能**完全免费**，支持者密钥解锁额外模型：
- unet-4x 二级修复
- SD 1.5 图像修复模型

获取方式：通过 Unifans 或 Buy Me a Coffee 累计贡献 15 USD+。

### 9.4 处理速度过慢

| 检查项 | 优化方法 |
|--------|---------|
| 是否首次运行？ | 首次编译后后续会快 |
| 片段大小是否太小？ | 增大到显存允许的最大值 |
| 是否开启了二级修复？ | 关闭或换更快的 RTX SR |
| 是否禁用了编译？ | 开启编译（显存够时）|
| 硬盘是否为 SSD？ | 机械硬盘会拖慢读写 |

### 9.5 输出文件无法播放

- 尝试更换播放器（VLC、PotPlayer）
- 检查输出格式是否为 MKV，尝试 MP4
- 使用 ffmpeg 重新封装：
  ```bash
  ffmpeg -i output.mkv -c copy output_fixed.mp4
  ```
