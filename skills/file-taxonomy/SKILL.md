# 知识库分类规划器

为当前知识库提供可审查、可渐进执行的分类方案。规划与执行严格分离，本 Skill 不承担自动移动文件的职责。

## 开始前必须读取

1. 根目录 `AGENTS.md`
2. `MOC知识地图.md`
3. `00-System(支撑层)/SCHEMA.md`
4. `00-System(支撑层)/知识库操作工作流.md`
5. 与目标范围有关的 MOC、README 和模板

## 稳定架构

保留现有四层主骨架：

- `00-System(支撑层)`：规范、模板、工作流和仪表盘
- `01-日常流(日常流层)`：流入、日记、复盘和阶段规划
- `02-Knowledge(知识层)`：已经形成理解、值得长期复用的知识
- `03-Resources(资源层)`：工具、素材、课程、网站和外部资源

除非用户另行明确批准，不提出推倒重建式迁移。

## 工作流程

1. 只读扫描目标范围，统计目录、文件类型、笔记数量和附件分布。
2. 检查笔记归属、命名、Frontmatter、MOC 连接和归档状态。
3. 按“笔记结构 → 链接完整性 → 附件”的顺序形成建议。
4. 为每项建议标注置信度、理由、风险和预期结果。
5. 输出变更预览；未经确认不得执行。

## 分类置信度

- 高：内容、Frontmatter 和现有 MOC 一致，只有一个合理归属。
- 中：存在首选归属，但也有可信备选；同时列出首选、备选和取舍。
- 低：信息不足或跨域明显；进入待确认清单，不建议自动处理。

置信度不是执行授权。所有变更仍需确认。

## 归档规则

- 优先原位设置 `status: 归档`，保留 wikilink 和历史上下文。
- 从活跃 MOC 或仪表盘中隐藏，或放入归档分组。
- 只有明确属于冷资源且引用安全时，才建议移动到资源归档位置。
- 默认不删除归档内容。

## 默认输出结构

```markdown
# 分类规划报告

## 范围与现状
## 保持不变的结构
## 高置信度建议
## 中置信度建议
## 低置信度待确认项
## MOC 与 Frontmatter 问题
## 链接风险
## 附件治理建议
## 分阶段变更预览
## 验证与回滚方法
```

每条变更建议至少包含：当前路径、建议动作、目标位置或状态、置信度、理由、链接风险和验证方法。

## 安全边界

- 不自动移动、删除或覆盖文件。
- 不用目录迁移替代 `status: 归档`。
- 不在附件治理前破坏 `![[附件]]` 或 Markdown 图片引用。
- 不把未确认的分类推断写入 Frontmatter。
- 后续若由其他执行流程应用方案，必须先 dry-run，保存移动日志与回滚清单，并逐项验证 wikilink、附件引用和 MOC 查询。
