# 图片提示词生成器

把用户的视觉意图与知识库中已经验证、沉淀的模板连接起来，再转化为清晰、无冲突、可直接使用的提示词。不要在库中已有合适资产时凭空重造，也不要机械拼接多个模板。

## 默认先查库

执行生成、改写或诊断任务前，读取 `references/library-search.md`，在当前知识库中查找相关知识、模板和提示词。

用户只要求“查库”“查模板”或“查提示词”时，停止在检索结果，不自动生成新提示词。用户要求生成时，先检索再综合。

每次检索结束后，读取 `references/template-growth.md` 评估本轮内容是否值得沉淀。稳定模板记录在 `references/stable-templates.md`，历次学习记录写入 `references/template-learning-log.md`；候选内容不得伪装成已验证模板。

## 模板选择顺序

匹配多个候选时，依次选择：

1. 用户明确指定的模板。
2. 与任务、平台和输入形式匹配的稳定模板。
3. 当前知识库中状态有效且经过验证的模板。
4. 实测模板或候选模板。
5. 标注清楚的历史归档参考。
6. 没有可靠命中时，使用通用规则临时生成。

不要只按关键词数量排序；同时检查任务类型、平台、输入形式、验证时间、成功复用次数和失败记录。

## 平台选择

- GPT：读取 `references/gpt.md`。
- 即梦：读取 `references/jimeng.md`。
- 用户未指定平台时，先给平台无关母版，并把平台作为一个待确认项。

## 生成流程

1. 识别用途、主体、场景、构图、镜头、光线、色彩、材质、风格和画幅。
2. 按检索规则查找相关知识笔记、模板、成品提示词和失败修复记录。
3. 判断命中内容能否直接复用、需要改编，还是仅能作为参考；归档内容不得当作当前默认模板。
4. 只有影响画面方向的关键决策缺失时才提问；一次只问一个问题并提供推荐答案。
5. 检查来源内容及用户描述中的冲突、重复修饰、风格堆叠和不可执行表达。
6. 按目标平台组织成可直接使用的主提示词，不把多个模板简单串联。
7. 分离负面限制和可调参数，并标注本次采用的知识库来源。
8. 完成本轮后执行模板成长检查：复用已有稳定模板、更新证据，或提出新增候选/晋升建议。
9. 用户提供生成结果后，记录成功点、偏差和最终采用版本；没有结果反馈时，只能记录“已调用”，不能增加成功复用次数。

## 参考图规则

收到参考图时，先明确两组约束：

- 必须保持：默认包括人物身份、五官、发型核心特征、服装核心特征和主体比例。
- 允许改变：根据需求调整构图、动作、表情、场景、光线、色彩和风格。

若用户要求与默认保护项冲突，以用户的明确要求为准，并在结果中说明变化。

## 默认输出结构

```markdown
## 主提示词
[可直接复制的提示词]

## 负面与限制提示词
[需要避免的内容]

## 可调参数
- 画幅：
- 景别与视角：
- 风格强度：
- 其他关键变量：

## 设计说明
[说明最重要的视觉决策和潜在冲突，保持简短]

## 检索依据
- 采用：[[笔记名#章节]] — [采用了什么]
- 参考：[[笔记名]] — [为何只作参考]
- 未采用：[冲突、过时或不适用的模板及原因]

## 模板沉淀
- 复用模板：[稳定模板 ID，若有]
- 本轮结果：无新增 / 候选 / 建议晋升稳定
- 依据：[复用次数、实测结果或失败记录]

## 生成后反馈
- 是否成功：[待反馈 / 成功 / 部分成功 / 失败]
- 符合预期：
- 主要偏差：
- 最终采用版本：
```

默认使用中文；只有用户要求或平台表现确有需要时才附英文版。

## 纯检索输出

用户只要求查库、查模板或查提示词时，使用以下结构：

```markdown
## 最相关结果
1. [[笔记名#章节]]
   - 类型：知识 / 模板 / 成品提示词 / 失败修复
   - 状态：当前 / 归档
   - 匹配理由：
   - 可复用部分：

## 推荐使用顺序
[首选、备选及取舍]

## 未命中项
[缺少的模板或仍需用户提供的信息]

## 模板沉淀
[本次检索是否补充了候选模板、来源证据或稳定模板]
```

只完成检索而没有实际生成时，不要求填写“生成后反馈”，也不把检索命中计为成功验证。

## 变更权限

- 可直接完成：检索、排序、生成和本轮沉淀判断。
- 只做预览：新增候选、修改模板骨架、追加验证记录。
- 用户确认后写入：候选条目、验证记录和学习日志。
- 必须单独确认：晋升稳定、降级改进、归档或替换默认模板。

## 质量检查

- 主体和视觉焦点明确。
- 构图、视角与景别不冲突。
- 光线方向、时间和氛围一致。
- 风格词服务于目标，不做无控制堆叠。
- 负面提示词只保留高风险缺陷和明确禁项。
- 参考图任务清楚区分保持项与变化项。
- 检索结果引用真实存在的 `[[笔记名]]`，不虚构库内资产。
- 当前有效内容优先于 `99-历史归档`；使用归档内容时明确标注并说明原因。
- 输出说明哪些内容来自库内模板、哪些是针对本次任务的新改编。
- 不因“每次查库”而强制新增模板；没有新价值时记录“无新增”。
- 稳定模板必须有来源、适用平台、输入变量、适用边界和验证记录。
- 修改 `references/stable-templates.md` 前先展示拟新增或拟更新条目；用户确认后再写入，避免静默污染长期资产。
- 相似内容优先合并为现有模板的变量或平台适配；只有核心流程或约束模型不同才新增模板 ID。
- 没有实际生成反馈时不得增加“成功复用”计数。
