# 图片提示词知识库检索

在生成前检索当前 Obsidian 知识库，复用已经沉淀的知识、模板、提示词和失败修复经验。检索是为了减少重复和提高一致性，不是把所有命中内容拼进一个提示词。

## 搜索范围与优先级

1. 当前主题目录的 MOC、README 和状态非归档笔记。
2. `02-Knowledge(知识层)/20-核心能力-Core_Ability/30 创作能力-Creative_Capability/02 AIGC/01-AI绘画与图像/`
3. 其中的工作流案例、提示词附录、角色设定规范、平台实测和失败修复记录。
4. `03-Resources(资源层)/04-素材库/` 中的可调用素材与提示词。
5. 通用提示工程知识仅用于结构检查，不替代图片领域模板。
6. `99-历史归档/` 最后检索，只作补充证据；不得默认覆盖当前有效模板。

## 三类检索

### 查库

查找与主题相关的知识资产、MOC、工作流、规范和素材。适合用户问“库里有没有关于人物身份锁定的资料”。

### 查模板

优先搜索包含变量槽位、固定结构、使用条件或平台适配的可复用模板。适合用户问“有没有即梦角色设定模板”。

### 查提示词

搜索可直接使用或可改编的成品提示词，同时检查其任务、平台、状态和失败风险。适合用户问“找一个古风男子特写提示词”。

## 检索方法

1. 从用户需求提取 3～8 个关键词，至少覆盖主题、任务类型和平台。
2. 先按文件名搜索，再在 Markdown 正文中搜索关键词和同义词。
3. 命中 MOC 或索引后，沿其中的 wikilink 读取最相关的少量笔记。
4. 检查 Frontmatter 的 `status`、`updated`、`verified`、`review_after` 和 `summary`。
5. 对候选内容分类：知识、模板、成品提示词、失败修复、素材。
6. 最多保留 3～5 个强相关候选；若结果不能收敛，改变关键词或请求用户确认方向，不做大范围内容倾倒。

## 复用判断

- 直接复用：平台、目标、输入形式和约束基本一致。
- 改编复用：核心结构适用，但主体、场景、平台或参数需要替换。
- 仅作参考：包含有用模块或失败经验，但状态归档、平台不同或目标不一致。
- 不采用：内容互相冲突、过时、缺少来源或会破坏用户要求。

## 来源规则

- 使用 Obsidian `[[wikilink]]` 标注真实来源，能定位章节时写 `[[笔记名#章节]]`。
- 不声称库内存在未实际找到的模板或提示词。
- 归档来源必须标注“归档参考”。
- 若没有有效命中，明确说“当前知识库未找到直接可复用内容”，再基于通用规则生成，不伪造检索依据。
