# 提示词模板成长机制

每次查库、生成、改写或失败修复后，都检查是否产生了可复用的新知识。目标是让 Skill 逐步积累稳定模板，而不是无上限复制提示词。

## 生命周期

```text
检索命中 → 候选模板 → 实测模板 → 稳定模板 → 改进或归档
```

### 候选模板

满足以下条件即可进入候选区：

- 解决了明确、可重复出现的图片任务。
- 能抽象出变量，而不是绑定一次性的角色或场景。
- 来源真实可追溯。
- 与现有稳定模板不重复。

候选不代表有效，不应作为默认首选。

### 实测模板

候选模板至少有一次真实生成结果或明确失败记录，并记录：

- 平台与模型
- 输入类型：文生图或参考图编辑
- 成功之处
- 失败之处
- 调整内容
- 验证日期

### 稳定模板

满足以下条件后才能建议晋升：

- 至少在两个不同任务中复用成功，或用户明确认定为稳定模板。
- 输入变量、冻结项和可变项明确。
- 适用平台与不适用边界明确。
- 常见失败和修复方式已有记录。
- 不依赖虚构参数、失效平台能力或互相冲突的风格词。

用户明确确认后，才把模板写入 `stable-templates.md` 的稳定区。

## 每轮成长检查

1. 本轮是否复用了现有稳定模板？若是，追加一条验证记录或说明失败。
2. 是否发现现有模板缺少变量、平台适配或失败约束？若是，提出更新建议。
3. 是否产生可跨任务复用的新结构？若是，整理为候选模板。
4. 是否只是一次性内容或已有模板的同义改写？若是，记录“无新增”。
5. 写入前展示拟变更内容和理由，等待用户确认。

## 反馈证据

模板被调用不等于模板有效。只有获得真实生成结果后，才能更新验证状态。

每次反馈尽量记录：

- 是否成功：成功 / 部分成功 / 失败
- 符合预期的元素
- 主要偏差
- 最终采用的版本
- 平台、模型和日期
- 是否经过人工修改

没有反馈时标记为“已调用、待反馈”，不增加成功复用次数。

## 去重与归并流程

新增模板前依次比较：

1. 任务类型是否相同。
2. 输入形式是否相同。
3. 输入变量是否可以并入已有模板。
4. 冻结项和可变项是否相同。
5. 差异是否仅来自 GPT/即梦平台适配。

若核心流程相同，更新已有模板；场景、服装、风格等差异做成变量。只有核心约束模型不同才创建新模板 ID。

## 晋升与降级

### 晋升稳定

- 至少两个不同任务获得成功或部分成功结果，且核心目标均达成；或用户明确认定稳定。
- 最近一次验证仍符合当前平台能力。
- 已记录输入变量、边界和常见失败修复。

### 降级改进

- 连续两次真实生成失败。
- 平台能力、模型或输入方式发生明显变化。
- 新证据表明模板存在系统性偏差。

### 归档

- 已有更可靠模板完整替代。
- 目标平台不再支持相关能力。
- 模板依赖失效资产且无法修复。

晋升、降级和归档都必须展示理由与拟变更内容，并取得用户确认。

## 去重原则

- 同一任务只保留一个核心模板，用平台适配段表示差异。
- 场景、服装、风格等可替换内容应做成变量，不复制成多个近似模板。
- 失败修复写入对应模板，不另建大量零散负面提示词。
- 来源笔记仍保留在知识库，Skill 只沉淀可执行骨架和验证结论。

## 稳定性维护

- 平台能力变化或连续两次失败时，将模板标为 `改进`。
- 被更可靠模板替代时标为 `归档`，保留历史记录，不直接删除。
- 每次更新保留来源和验证日期，避免无法判断模板为何有效。
- 每次确认后的变化同时写入 `template-learning-log.md`，保留模板演进依据。
